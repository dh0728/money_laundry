# 룰엔진 참고 임계값 조사 — 법정 규제값 · 공개 가이드라인 · 연구 통용값

작성일: 2026-08-16 · GNN 기반 AML 모니터링 프로젝트 조사 자료

## 목적과 전제

- GNN 모델과 비교할 **룰엔진 베이스라인**을 만들기 위해, 공개적으로 사용 가능한 임계값·시나리오 원천을 정리한다.
- 은행이 실무에서 쓰는 시나리오 임계값은 우회(회피 세탁) 방지를 위해 **기관별 기밀**이다. 따라서 공개 원천은 세 계층뿐이다: ① 법정 보고 기준(정의상 공개), ② 감독기구·국제기구의 공개 가이드라인(시나리오 구조), ③ 연구·벤치마크 관행(캘리브레이션 방법).
- **주의**: 우리가 쓰는 IBM AMLworld는 합성 데이터라 금액·빈도 분포가 실세계와 다르다. 아래 절대값(1천만 원, $10,000 등)은 "룰의 구조와 정당성 근거"로 쓰고, 실제 임계값은 §4의 방법대로 **데이터 분포에서 캘리브레이션**한다. 이는 편법이 아니라 실무 임계값 튜닝 절차(초기값을 통계 percentile로 설정 → 백테스트로 조정 → 근거 문서화)의 재현이다.

## 2. 공개 가이드라인·typology (시나리오의 구조)

임계값 숫자가 아니라 **"어떤 행위 패턴을 룰로 만들 것인가"**의 공개 원천. 우리 룰엔진의 시나리오 목록 근거로 인용 가능.

| 원천 | 내용 | 링크 |
|---|---|---|
| FFIEC BSA/AML Examination Manual | 미 감독당국 검사 매뉴얼. 거래 모니터링 요건과 red flag(위험 징후) 목록 공개 — 분할거래, 급속 자금이동, 휴면 후 급증, 다수 계좌 집중 등 전형 시나리오의 원전 | [bsaaml.ffiec.gov/manual](https://bsaaml.ffiec.gov/manual) |
| FATF typologies 보고서 | 자금세탁 수법 유형(placement–layering–integration, 경유계좌, 순환 등) 사례집 | [FATF publications](https://www.fatf-gafi.org/en/publications.html) |
| Wolfsberg Group | 글로벌 은행 협의체의 모니터링·스크리닝 성명 및 AI/ML 활용 원칙 | [wolfsberg-group.org](https://wolfsberg-group.org/) |
| KoFIU 의심거래 참고유형 | 국내 STR 참고 유형 안내 | [kofiu.go.kr](https://www.kofiu.go.kr/kor/policy/amls03.do) |

**상용 제품이 공개한 구체 파라미터 예시** — Hawk AI가 제품 자료에 공개한 경유계좌(pass-through) 시나리오 설명은 드물게 실측 구조를 보여준다:

> "유출액이 임계값(EUR 5,000) 이상 / 3개월 평균 대비 급증(임계 100% 초과) / 자금이 N일(≤3일) 내 통과 / 유입·유출 금액 차이 ≤10%"

→ "짧은 체류 기간 + 유입·유출 균형 + 평소 대비 급증"이라는 pass-through 룰의 표준 파라미터 구성을 확인할 수 있다.
출처: [Hawk AI Transaction Monitoring Product Sheet (PDF)](https://25875848.fs1.hubspotusercontent-eu1.net/hubfs/25875848/Hawk%20AI%20-%20Product%20Brochure%20-%20Transaction%20Monitoring.pdf)

## 3. 연구·벤치마크에서 쓰는 값

### 우리 데이터셋(IBM AMLworld)의 패턴 정의

AMLworld 생성 논문이 세탁 패턴을 명시적으로 정의한다 — 우리 룰이 잡아야 할(또는 못 잡는) 대상의 공식 정의:

- 패턴 8종: **FAN-OUT, FAN-IN, CYCLE, BIPARTITE, STACK, SCATTER-GATHER, GATHER-SCATTER, RANDOM**
- 패턴 규모는 Patterns.txt에 명시 (예: "Max 16-degree Fan-Out" — fan 차수 최대 16)
- HI/LI 변형 = 세탁 비율 높음/낮음. 세탁 거래는 전체의 ~0.1% 수준(극단 불균형)

출처:
- Altman et al., *Realistic Synthetic Financial Transactions for Anti-Money Laundering Models*, NeurIPS 2023 Datasets & Benchmarks — [arXiv:2306.16424](https://arxiv.org/abs/2306.16424)
- [Kaggle — IBM Transactions for Anti Money Laundering](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)

### GNN 벤치마크와 그래프 특징(=룰이 쓰는 통계) 정의

- Egressy et al., *Provably Powerful Graph Neural Networks for Directed Multigraphs*, AAAI 2024 — AMLworld 표준 벤치마크. 평가지표 **minority-class F1**. 베이스라인으로 그래프 특징 + GBT 사용 — [arXiv:2306.11586](https://arxiv.org/abs/2306.11586) · [github.com/IBM/Multi-GNN](https://github.com/IBM/Multi-GNN)
- Blanuša et al., *Graph Feature Preprocessor* — 거래 그래프에서 실시간 추출하는 특징을 정의: **fan-in/out 차수, 입출금 횟수·금액 통계, 단순 cycle(길이 제한), scatter-gather 구성원 여부** 등. "룰/특징이 계산하는 통계량"의 공개 레퍼런스 — [arXiv:2402.08593](https://arxiv.org/abs/2402.08593)
- IBM AMLSim (AMLworld의 전신 시뮬레이터) — 설정 파일에 패턴별 파라미터(구성 계좌 수, 기간, 금액 범위) 예시가 공개돼 있어 합성 환경 룰 파라미터의 참고가 됨 — [github.com/IBM/AMLSim](https://github.com/IBM/AMLSim)

### 연구·실무 공통의 캘리브레이션 관행

- **초기 임계값 = 분포 percentile**: 금액·빈도·차수 임계값을 정상 분포의 95/99/99.9 percentile로 설정하고 시작. (FFIEC 매뉴얼의 모니터링 시스템 요건 및 업계 ATL/BTL(above/below-the-line) 튜닝 관행)
- **ATL/BTL 백테스트**: 임계값 위/아래 구간의 알림을 표본 검토해 오탐률·미탐률로 임계값을 조정하고 근거를 문서화. 실무 임계값 튜닝이 "별도의 큰 업무"인 이유.
- **알림 예산(budget) 기준 비교**: 조사 인력이 소화 가능한 상위 K건 기준으로 모델·룰을 비교(Precision@K, budget recall). 우리 기획서의 Precision@K 지표와 일치.

## 4. 우리 룰엔진 적용 지침 (제안)

AMLworld 분포에 맞춘 초기값 설정 방법. †는 학습 구간(시간상 앞부분) 데이터로만 캘리브레이션.

| 시나리오 | 파라미터(초기값 제안) | 값의 근거 |
|---|---|---|
| 단건 고액 | 금액 ≥ 99.9 percentile† | percentile 초기화 관행 (§3) |
| 분할거래(structuring) | "보고 기준액 T" = 금액 상위 1% 경계†로 정의 후, T의 90~100% 구간 거래가 **7일 내 3건 이상** | 31 U.S.C. §5324 구조 + 한국 CTR 1일 합산 개념 (§1) |
| FAN-OUT / FAN-IN | 시간창(48h) 내 거래 상대 계좌 수 ≥ 정상 분포 99.9 percentile† | AMLworld 패턴 정의(최대 16차수) + GFP 특징 (§3) |
| 급속 자금이동(pass-through) | 유입 후 **3일 내** 유출, 유출/유입 비율 ≥ 90%, 유입·유출 차 ≤ 10% | Hawk 공개 파라미터 (§2) |
| 휴면 후 급증 | 직전 3개월 평균 대비 K배 (K는 백테스트로) | FFIEC red flag 구조 (§2) |
| 고위험 통화·결제수단 조합 | (선택) Payment Format별 이상 비율 분석 후 결정 | 데이터 탐색 필요 |

공정 비교 프로토콜:

1. 룰 임계값도 학습 구간에서 성능 최대화(minority F1 또는 고정 알림 예산 하 recall)로 튜닝한다 — 허수아비 베이스라인 방지.
2. 평가는 시간상 뒤쪽 구간에서 룰/GNN 동일 조건으로 수행한다.
3. 핵심 주장 지표: **룰 대비 룰+GNN의 추가 탐지(incremental recall)**, 특히 CYCLE·SCATTER-GATHER처럼 다홉 연결 구조라 룰의 표현력 밖인 패턴에서의 증분.
