Lucinity Case Manager
UI와 실제 운영 흐름 분석

제공된 24페이지 PDF의 Lucinity 화면을 원본 그대로 분리해, 각 화면에서 무엇을 보고 어떤 결정을 내리는지 한국어로 정리했습니다. 번호는 원본 캡처의 실제 영역 중앙에 배치했고, 바로 아래 와이어프레임과 같은 번호로 연결했습니다.

제공 PDF 열기 Lucinity Case Management 인터랙티브 제품 데모
✓
네, 이 자료도 찾던 AML 모니터링·조사 UI 레퍼런스가 맞습니다.정확히는 탐지 모델 자체보다, 여러 탐지 시스템에서 생성된 Alert를 받아 조사하고 Case로 처리하며 SAR 제출과 QA까지 운영하는 Case Management 계층을 잘 보여줍니다. GNN 기반 AML 모델의 결과를 현업 분석가가 소비하는 제품 UI를 설계할 때 특히 유용합니다.
용어 주의: Lucinity 화면의 Actor는 고객·법인·계좌 관련 주체, Focal Actor는 현재 사건의 중심 조사 대상, Observation은 거래·스크리닝 같은 개별 위험 관찰 항목을 뜻합니다. Case는 이 근거와 작업을 하나로 묶는 조사 단위입니다.

1. Workspace — 통합 경보·사건 작업대

제공 PDF 3쪽 · Lucinity Workspace

화면 출처:PDF 3쪽제품 인터랙티브 데모공식 Case Management 페이지
  1. 1Overview
    경보 제목·행동 유형과 Case 식별자를 보여줍니다.
  2. 2Case ID / Level
    사건 번호와 조사 단계를 구분합니다.
  3. 3Source
    Lucinity, 외부 TM, Fraud 등 발생 원천입니다.

  5. 5새 항목

이 화면의 성격

대시보드보다는 운영 큐입니다. 필터, 정렬, 저장된 보기로 내 업무만 보거나 특정 시나리오·단계·SLA 위반 건을 분리합니다.

GNN risk scoreRule scoreQueueSLA를 별도 열로 제공하고, 모델 버전과 산출 시각도 추적해야 합니다.

2. Case Summary — 고객 360형 사건 조사 화면

제공 PDF 3쪽 · Fraud Activity Burst Case

화면 출처:PDF 3쪽제품 인터랙티브 데모
  1. 1Overview
    CDD 위험점수, 총 거래금액, 관련 사건 수와 생성일입니다.
  2. 2Abstract
    의심 이유와 핵심 인사이트를 조사 서술형으로 요약합니다.
  3. 3Actor 360
    중심 고객의 KYC/CDD, 거래 통계, 수입·지출 성격과 관찰 건수입니다.
  4. 4Associations
    중심 주체·연관 주체와 연결된 계좌·Case를 따라갑니다.
  5. 5Escalate
    사건을 다음 조사 단계나 관리 큐로 승격합니다.
왜 고객 360인가? 고객 기본정보만 보여주는 CRM형 프로필이 아니라, 현재 사건을 중심으로 고객 위험도·거래 패턴·관계망·과거 사건·작업 이력을 결합하기 때문입니다. GNN 결과는 ③과 ④에 “위험 연결 경로”로 들어가는 것이 가장 자연스럽습니다.

4. Sanctions Investigation — 제재 목록 후보 비교

제공 PDF 6쪽 · Sanctions Match

화면 출처:PDF 6쪽제품 인터랙티브 데모

    제재 의심 주체와 거래 상대국을 확인합니다.
  2. 2Screening Matches
    어떤 제재 목록에서 후보가 나온 것인지 봅니다.
  3. 3조사 체크리스트

추천 MVP 플로우

  1. GNN·Rule 엔진이 고객/계좌 단위 위험 Alert와 근거 subgraph를 생성
  2. Workboard가 위험도·금액·SLA로 우선순위를 계산하고 담당자에게 배정
  3. 분석가가 고객 360에서 KYC, 거래, 과거 사건을 확인
  4. 그래프 화면에서 1~3 hop 위험 관계와 자금 흐름을 검증
  5. 추가 정보 요청 또는 Case 승격 후 결론·이유코드·서술형 의견 기록
  6. 의심 건은 STR 초안으로 연결하고 승인·제출, 오탐은 모델 개선 데이터로 환류
