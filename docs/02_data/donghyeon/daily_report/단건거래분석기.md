## 실험1
- 거래방식, 통화, 요일, 시간대, 금액, 계좌 이력 등 가능한 피처를 폭넗게 사용
- Logistic Regression PR-AUC가 0.009499로 비교적 높게 나왔지만, 피처를 확인해보니 `Payment Format=ACH`, 요일 주말같은 피처의 영향이 컸음
- 즉, 모델이 실제 자금세탁 행동보다 HI-Small 데이터 생성 규칙을 학습했을 가능성이 있음

## 실험2
- `Payment Format` 저거
- 날짜·요일·주말 제거
- 모든 금액을 고정환율로 USD 환산
- 정확한 날짜 대신 하루 안의 시간대만 사용

- Logistic PR-AUC는 0.002469로 크게 감소했고 Random Forest는 0.006819가 나온걸 보아 첫 번째 실험의 높은 성능 상당 부분이 ACH와 날짜 규칙에서 나온 것임을 확인

## 실험3
- HI-Small의 Patterns.txt에는 Is Laundering=0인 보조 거래가 없고, 3,209건 모두 자금세탁 라벨이라는 것도 확인
- v2에서는 패턴 자금세탁을 최종 모델 표본에서는 제외했지만, 과거 이력 피처를 계산할 때는 이전 거래로 포함 -  이거 둘다 뺐어야 하는거 아닌가?
- 자금세탁 정보가 계좌 이력 피처에 영향을 줬을 가능성을 확인하기 위해, v3에서는 패턴 자금세탁을 이력 계산 전에 제거
그 결과:
- Logistic PR-AUC: `0.002469 → 0.002464`
- Random Forest PR-AUC: `0.006819 → 0.006797`

따라서 계좌 이력 신호가 패턴 자금세탁 거래가 섞여 생긴 결과는 아니라는 것을 확인

## 실험4
계좌 이력 피처가 실제로 성능에 기여하는지 확인하기 위해 다음 다섯 개 피처를 모두 제거
- sender_prev_count_log
- receiver_prev_count_log
- pair_prev_count_log
- hours_since_sender_prev_log
- amount_vs_sender_history_usd

그결과:
- Logistic PR-AUC 약 79% 감소
- Random Forest PR-AUC 약 84% 감소

계좌 이력 피처를 제거하면 성능이 무작위 수준에 가까워졌음.
따라서 패턴 외 자금세탁에는 현재 거래 금액만으로 설명하기 어려운 계좌·거래쌍의 과거 행동 신호가 존재한다고 판단됨

## 실험5
v4에서는 이력 피처 다섯 개를 한꺼번에 제거했기 때문에 어떤 이력 묶음이 중요한지는 알 수 없었음

그래서 다음과 같이 그룹별로 추가
- H0: 이력 없음
- H1: 거래쌍 이력(동일 송금자→수취자 거래쌍의 반복 이력) - `pair_prev_count_log`
- H2: 송금·수취 계좌 활동량 `sender_prev_count_log`,`receiver_prev_count_log`
- H3: 직전 거래 시간과 과거 평균 대비 금액 `hours_since_sender_prev_log`, `amount_vs_sender_history_usd`
- H4: 이력 피처 전체

- 중복 수취액과 통화 관련 피처 모델에서 제거

결과는:
- Logistic Regression: H1 거래쌍 이력이 최고
- Random Forest: H4 전체 이력이 최고

-> pair_prev_count_log는 두 모델에서 모두 일관되게 중요한 피처

## 실험6

P0: 거래쌍 피처 없음
P1: is_new_pair
