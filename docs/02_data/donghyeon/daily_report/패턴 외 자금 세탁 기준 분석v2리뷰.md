# 패턴 외 자금세탁 기준 분석 v2 리뷰

## 분석 목적

- `Patterns.txt`에 포함되지 않은 자금세탁 거래가 정상거래와 구분되는 특징을 갖는지 확인한다.
- 패턴 외 자금세탁을 처음부터 단건 또는 다건으로 단정하지 않고, 우선 거래 단위 분류 가능성을 살펴본다.
- 첫 번째 실험에서 성능에 큰 영향을 준 `Payment Format`, 날짜·요일 등의 데이터 생성 규칙을 제거한 뒤에도 의미 있는 신호가 남는지 확인한다.

## 실험 정의

| 구분 | 기준 |
|---|---|
| 양성 (`target=1`) | `Is Laundering == 1`이면서 `Patterns.txt`에 없는 거래 |
| 음성 (`target=0`) | `Is Laundering == 0`인 정상거래 |
| 제외 | `Patterns.txt`에 포함된 자금세탁 거래 |
| 패턴 보조 거래 | `Patterns.txt`에 포함돼도 `Is Laundering == 0`이면 1차 실험에서는 원본 라벨에 따라 음성으로 유지 |
| Reinvestment | 초기 잔액 설정 성격이므로 481,056건 제외 |
| 모델링 데이터 | 총 4,593,618건 |
| 분석 기간 | 2022-09-01~2022-09-10 |
| 시간 분할 | 학습 1~7일, 검증 8일, 테스트 9~10일 |
| 불균형 처리 | 학습 데이터에서만 정상거래를 양성의 10배까지 무작위 추출 |

> 학습 데이터에는 정상거래 언더샘플링과 `class_weight="balanced"`가 동시에 적용됐다. 따라서 모델 점수와 Threshold는 실제 자금세탁 확률로 해석하면 안 된다. Threshold는 검증 데이터에서 F1이 최대가 되는 지점이다.

## v1 대비 변경 사항

| 항목 | v2 적용 내용 | 이유 |
|---|---|---|
| 시간 분할 | 학습 1~7일, 검증 8일, 테스트 9~10일 | 학습 기간을 하루 늘리고 테스트 기간은 유지 |
| 거래 방식 | `Payment Format` 제외 | HI-Small 자금세탁 대부분이 ACH인 생성기 특성 제거 |
| 절대시간 | 원본 `Timestamp`, 날짜 제외 | 특정 날짜를 외우는 현상 방지 |
| 달력 정보 | 요일, 주말 여부 제외 | 짧은 10일 데이터의 날짜 생성 규칙 의존 방지 |
| 시간 피처 | `hour_sin`, `hour_cos`와 과거 거래 이후 경과시간만 사용 | 하루 안의 시간대와 거래 이력만 표현 |
| 금액 | 고정환율로 모두 USD 환산 | 통화별 숫자 단위 차이 통제 |

## 사용 피처

### 숫자형 피처

| 피처 | 설명 |
|---|---|
| `log_amount_paid_usd` | 송금액을 USD로 환산한 후 `log1p` 변환한 값 |
| `log_amount_received_usd` | 수취액을 USD로 환산한 후 `log1p` 변환한 값 |
| `log_amount_ratio_usd` | USD 기준 수취액과 송금액의 로그 비율 |
| `is_cross_bank` | 송금 은행과 수취 은행이 다르면 1 |
| `is_self_transfer` | 송금·수취 은행과 계좌가 모두 같은 자기거래이면 1 |
| `is_cross_currency` | 지급 통화와 수취 통화가 다르면 1 |
| `hour_sin` | 거래 시각의 24시간 순환성을 사인값으로 표현 |
| `hour_cos` | 거래 시각의 24시간 순환성을 코사인값으로 표현 |
| `sender_prev_count_log` | 현재 거래 전까지 송금 계좌가 송금한 횟수의 `log1p` |
| `receiver_prev_count_log` | 현재 거래 전까지 수취 계좌가 수취한 횟수의 `log1p` |
| `pair_prev_count_log` | 같은 송금 계좌→수취 계좌 조합의 과거 거래 횟수의 `log1p` |
| `hours_since_sender_prev_log` | 해당 송금 계좌의 직전 송금 이후 경과시간의 `log1p` |
| `amount_vs_sender_history_usd` | 현재 USD 송금액이 해당 송금자의 과거 평균보다 얼마나 큰지 나타내는 로그 차이 |

### 범주형 피처

|---|---|
| `Payment Currency` | 송금자가 지급한 통화 |

## Logistic Regression 결과

### Confusion matrix

| 실제값 | 정상 예측 (`pred_0`) | 자금세탁 예측 (`pred_1`) | 합계 |
|---|---:|---:|---:|
| 정상거래 (`actual_0`) | 852,141 | 9,691 | 861,832 |
| 패턴 외 자금세탁 (`actual_1`) | 352 | 19 | 371 |
| 합계 | 852,493 | 9,710 | 862,203 |

해석:

- 패턴 외 자금세탁 371건 중 19건을 찾고 352건을 놓쳤다. 즉 약 94.9%를 놓쳤다.
- 자금세탁으로 경고한 9,710건 중 실제 자금세탁은 19건이다.
- 자금세탁 1건을 찾기 위해 평균 약 511건의 경고를 확인해야 하므로 조사 효율이 매우 낮다.

### 평가 지표

| 지표 | 값 | 해석 |
|---|---:|---|
| Threshold | 0.953749 | 검증 데이터에서 F1이 가장 높았던 분류 기준이며 실제 확률 95.4%를 뜻하지 않는다. |
| PR-AUC | 0.002469 | 무작위 기준보다 약 5.7배 높지만 절대적인 순위 품질은 낮다. |
| Precision | 0.001957 | 경고 거래 중 실제 자금세탁은 약 0.20%이다. |
| Recall | 0.051213 | 전체 자금세탁의 약 5.12%인 19건만 탐지했다. |
| F1 | 0.003769 | Precision과 Recall을 함께 본 전체 분류 성능이 매우 낮다. |
| Precision@100 | 0.000000 | 위험도 상위 100건에 실제 자금세탁이 없다. |
| Recall@100 | 0.000000 | 전체 양성 중 상위 100건에서 찾은 거래가 없다. |
| Precision@500 | 0.002000 | 상위 500건 중 자금세탁은 1건이다. |
| Recall@500 | 0.002695 | 전체 양성 371건 중 1건을 찾았다. |
| Precision@1000 | 0.001000 | 상위 1,000건 중 자금세탁은 1건이다. |
| Recall@1000 | 0.002695 | 상위 범위를 1,000건으로 늘려도 추가 양성을 찾지 못했다. |

PR-AUC가 무작위보다 높으므로 약한 신호는 있지만, 상위 100건에 양성이 없고 상위 1,000건에도 1건뿐이다. 실제 조사 우선순위 모델로 사용하기에는 부족하다.

## Random Forest 결과

### Confusion matrix

| 실제값 | 정상 예측 (`pred_0`) | 자금세탁 예측 (`pred_1`) | 합계 |

| 패턴 외 자금세탁 (`actual_1`) | 346 | 25 | 371 |
| 합계 | 860,047 | 2,156 | 862,203 |

해석:

- 전체 자금세탁 371건 중 25건을 찾고 346건을 놓쳤다.
- 경고 2,156건 중 실제 자금세탁은 25건으로, 자금세탁 1건당 평균 약 86건의 경고가 발생한다.
- Logistic Regression보다 양성 6건을 더 찾으면서 정상거래 오탐은 7,560건 줄였다.
- 그래도 양성의 약 93.3%를 놓치므로 최종 탐지 모델로 사용하기에는 부족하다.

해석:

- Random Forest의 PR-AUC는 무작위 기준보다 약 15.8배, Logistic Regression보다 약 2.8배 높다.

- 상위 100건에서 2건, 상위 500건에서 4건, 상위 1,000건에서 8건을 찾았다.
- 선형 결합만 사용하는 Logistic Regression보다 계좌 이력·상대방 이력·금액 사이의 비선형 관계가 도움이 된 것으로 보인다.
- 다만 PR-AUC 0.006819와 Recall 6.74%는 여전히 매우 낮다. Random Forest가 상대적으로 낫다는 것과 실제 사용 가능한 성능이라는 것은 다른 이야기다.

## 통화 식별자 의존 여부

USD 환산 금액만으로 성능이 유지되는지 확인하기 위해 `Payment Currency`, `Receiving Currency`, `is_cross_currency`를 제거한 Logistic Regression을 추가로 학습했다.

### 통화 정보 제거 모델 Confusion matrix

| 실제값 | 정상 예측 (`pred_0`) | 자금세탁 예측 (`pred_1`) | 합계 |
|---|---:|---:|---:|
| 정상거래 (`actual_0`) | 852,026 | 9,806 | 861,832 |
| 패턴 외 자금세탁 (`actual_1`) | 350 | 21 | 371 |
| 합계 | 852,376 | 9,827 | 862,203 |

### 성능 비교

| 모델 | Threshold | PR-AUC | Precision | Recall | F1 | P@100 | R@100 | P@500 | R@500 | P@1000 | R@1000 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 통화 정보 포함 Logistic | 0.953749 | 0.002469 | 0.001957 | 0.051213 | 0.003769 | 0.000 | 0.000000 | 0.002 | 0.002695 | 0.001 | 0.002695 |
| 통화 정보 제거 Logistic | 0.951928 | 0.002482 | 0.002137 | 0.056604 | 0.004118 | 0.000 | 0.000000 | 0.002 | 0.002695 | 0.001 | 0.002695 |

해석:

- 통화 정보를 제거해도 PR-AUC와 상위 K 성능이 거의 그대로 유지됐다.
- Precision, Recall, F1은 오히려 소폭 증가했지만 차이가 매우 작아 의미 있는 개선보다는 표본 변동으로 보는 편이 안전하다.
- 현재 결과에서는 통화 이름 자체가 유용한 탐지 신호라는 근거가 없다. USD 환산 금액만 남기고 통화 범주형 피처와 `is_cross_currency`를 제거해 모델을 단순화해도 된다.
- 제거 모델은 양성 1건당 평균 약 468건의 경고가 필요해 Logistic Regression의 근본적인 성능 문제는 그대로다.

## v1과 v2 비교

| 실험 | 주요 피처 조건 | PR-AUC | Precision | Recall | F1 | P@100 | P@500 | P@1000 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| v1 전체 Logistic | Payment Format·요일·주말 포함, 환산 전 금액 | 0.009499 | 0.021674 | 0.078167 | 0.033938 | 0.030 | 0.030 | 0.022 |
| v1 생성기 피처 제거 Logistic | 시간 피처·Payment Format 제거 | 0.002466 | 0.003257 | 0.547170 | 0.006476 | 0.000 | 0.002 | 0.001 |
| v2 Logistic | Payment Format·절대 날짜·요일 제거, USD 환산 | 0.002469 | 0.001957 | 0.051213 | 0.003769 | 0.000 | 0.002 | 0.001 |
| v2 Random Forest | v2와 같은 피처, 비선형 모델 | 0.006819 | 0.011596 | 0.067385 | 0.019786 | 0.020 | 0.008 | 0.008 |

> v1과 v2는 학습·검증 기간이 달라 완전히 동일한 조건의 비교는 아니다. 다만 테스트 기간은 9~10일로 같으므로 방향성 확인에는 참고할 수 있다.

해석:

- v2 Logistic의 PR-AUC는 v1에서 시간·Payment Format을 제거한 모델과 사실상 같다. 생성기 피처를 제외하면 남는 선형 신호가 매우 약하다는 결과가 재현됐다.
- v1 전체 Logistic의 상대적으로 높은 성능은 ACH, 요일, 주말 등 생성 규칙에 크게 의존한 결과로 보는 것이 타당하다.
- v2 Random Forest는 같은 정제 피처를 사용한 Logistic보다 확실히 낫다. 계좌 활동량, 거래쌍 반복, 경과시간, 과거 대비 금액 사이의 비선형 관계에는 추가 신호가 있다.
- 그러나 Random Forest도 양성 대부분을 놓치므로 현재 거래 단위 피처만으로 패턴 외 자금세탁을 안정적으로 분류하기는 어렵다.

## v2 결론

- `Payment Format`과 절대 날짜·요일을 제거하자 Logistic Regression 성능이 낮아졌다. 첫 번째 실험의 성능 상당 부분이 데이터 생성 규칙에 의존했다는 판단을 지지한다.
- 가장 일관된 구조적 단서는 **송금자·수취자는 활동 이력이 많지만 해당 송금자→수취자 조합의 과거 거래는 적은 경우**다.
- Random Forest가 Logistic Regression보다 모든 핵심 지표에서 좋아 비선형 상호작용의 가능성은 확인됐다. 다만 PR-AUC 0.006819, Recall 0.067385로 최종 모델 수준은 아니다.
- 통화 이름을 제거해도 성능이 유지됐으므로 고정환율로 환산한 USD 금액만 사용해도 충분하다.
- 패턴 외 자금세탁을 모두 단건으로 볼 필요는 없다. 다음 단계에서는 거래 하나의 분류보다 계좌·상대방·짧은 시간창을 기준으로 거래를 묶어 행동 구조를 만들어야 한다.

## 다음 실험 우선순위

1. 중복 피처를 줄인다.
   - 대부분 같은 `log_amount_received_usd`는 제거하고 `log_amount_paid_usd` 하나만 유지한다.
   - `Payment Currency`, `Receiving Currency`, `is_cross_currency`를 제거한다.
2. `hour_sin`, `hour_cos` 제거 실험을 추가한다.
   - Random Forest가 시간대 생성 규칙에 의존하는지 확인한다.
3. 불균형 처리 방법을 분리해서 비교한다.
   - `언더샘플링 + class_weight`를 동시에 쓰지 않고, `언더샘플링만 사용`과 `전체 학습 데이터 + class_weight`를 각각 비교한다.
4. 행동·그래프 피처를 추가한다.
   - `is_new_pair`: 처음 등장한 송금자→수취자 조합 여부
   - 최근 1시간·24시간 거래 횟수와 금액 합계
   - 송금자의 최근 고유 수취인 수
   - 수취인의 최근 고유 송금자 수
   - 송금자의 신규 상대방 거래 비율
5. 운영 관점에서는 고정 Threshold보다 하루 조사 가능 건수에 맞춘 `Precision@K`, `Recall@K`를 중심으로 비교한다.
6. Small 데이터에서는 코드와 분석 절차를 검증하고, Large 데이터에서는 여러 시간 구간으로 반복 검증해 결과가 유지되는지 확인한다.
