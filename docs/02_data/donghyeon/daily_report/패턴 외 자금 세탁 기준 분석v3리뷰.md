# 패턴 외 자금세탁 기준 분석 v3 리뷰

## 분석 목적

- `Patterns.txt`에 포함되지 않은 자금세탁 거래가 정상거래와 구분되는 특징을 갖는지 확인한다.
- 패턴 외 자금세탁을 단건 또는 다건으로 미리 단정하지 않고 거래 단위 분류 가능성을 먼저 살펴본다.
- v2에서는 패턴 자금세탁을 최종 모델 표본에서 제외했지만, 과거 행동 피처를 계산할 때는 이전 거래 이력에 포함했다.
- v3에서는 패턴 자금세탁을 과거 행동 피처 계산 전에 제거하고, 이 차이가 패턴 외 자금세탁 탐지 결과에 미치는 영향을 확인한다.

## 실험 정의

| 구분 | 기준 |
|---|---|
| 양성 (`target=1`) | `Is Laundering == 1`이면서 `Patterns.txt`에 없는 거래 |
| 음성 (`target=0`) | `Is Laundering == 0`인 정상거래 |
| 사전 제거 | `Patterns.txt`에 있으면서 `Is Laundering == 1`인 패턴 자금세탁 |
| 패턴 내 0 라벨 | 역할을 추정하지 않고 제거하지 않으며 원본 정상 라벨을 유지 |
| Reinvestment | 초기 잔액 설정 성격이므로 481,056건 제외 |
| 모델링 데이터 | 총 4,593,618건 |
| 분석 기간 | 2022-09-01~2022-09-10 |
| 시간 분할 | 학습 1~7일, 검증 8일, 테스트 9~10일 |
| 불균형 처리 | 학습 데이터에서만 정상거래를 양성의 10배까지 무작위 추출 |
| 모델 | Logistic Regression, Random Forest |

> 학습 데이터에는 정상거래 언더샘플링과 `class_weight="balanced"`가 동시에 적용됐다. 따라서 모델 점수와 Threshold는 실제 자금세탁 확률로 해석하면 안 된다. Threshold는 검증 데이터에서 F1이 최대가 되는 지점이다.

## v2 대비 변경 사항

| 항목 | v2 | v3 |
|---|---|---|
| 모델 표본의 패턴 자금세탁 | 제외 | 제외 |
| 과거 이력 계산의 패턴 자금세탁 | 이전 거래로 포함 | 계산 전에 제거 |
| 패턴 내 0 라벨 거래 | 원본 정상 라벨 유지 | 원본 정상 라벨 유지 |
| 모델·피처·시간 분할 | 기준 조건 | 동일하게 유지 |

v2와 v3의 모델 표본 수는 같다. 달라지는 것은 `sender_prev_count_log`, `receiver_prev_count_log`, `pair_prev_count_log`, 직전 거래 이후 시간과 과거 평균 금액처럼 과거 거래를 이용해 만든 피처다.

## 패턴 파일과 제거 대상 확인

| 항목 | 거래 수 |
|---|---:|
| 전체 거래 | 5,078,336 |
| 전체 자금세탁 | 5,177 |
| 패턴 파일 전체 거래 | 3,209 |
| 패턴 자금세탁 | 3,209 |
| 패턴 내 0 라벨 거래 | 0 |
| 패턴 외 자금세탁 | 1,968 |
| 전체 정상거래 | 5,073,159 |

해석:

- HI-Small의 `Patterns.txt` 거래 3,209건은 모두 `Is Laundering == 1`이다.
- 패턴 안에 `Is Laundering == 0`인 거래는 없다. 따라서 확인되지 않은 보조·환전 거래를 제거했다는 해석은 적용되지 않는다.
- 분석 기간인 1~10일 안에서 과거 이력 계산 전에 제거된 패턴 자금세탁은 2,554건이다.
- 전체 패턴 자금세탁 3,209건 중 나머지 655건은 11일 이후 거래이므로 분석 기간을 제한할 때 이미 제외된다.

- v2와 양성·음성 표본 수가 모두 같다. 따라서 두 실험의 성능 차이는 표본 수가 아니라 과거 이력 피처의 재계산에서 발생한다.

## 사용 피처

### 숫자형 피처

| 피처 | 설명 |
|---|---|
| `log_amount_paid_usd` | 송금액을 USD로 환산한 후 `log1p` 변환한 값 |
| `log_amount_received_usd` | 수취액을 USD로 환산한 후 `log1p` 변환한 값 |
| `log_amount_ratio_usd` | USD 기준 수취액과 송금액의 로그 비율 |
| `is_cross_bank` | 송금 은행과 수취 은행이 다르면 1 |
| `is_self_transfer` | 송금·수취 은행과 계좌가 모두 같은 자기거래이면 1 |
| `is_cross_currency` | 지급 통화와 수취 통화가 다르면 1 |
| `hour_sin` | 거래 시각의 24시간 순환성을 사인값으로 표현 |
| `hour_cos` | 거래 시각의 24시간 순환성을 코사인값으로 표현 |
| `sender_prev_count_log` | 현재 거래 전까지 송금 계좌가 송금한 횟수의 `log1p` |
| `receiver_prev_count_log` | 현재 거래 전까지 수취 계좌가 수취한 횟수의 `log1p` |
| `pair_prev_count_log` | 같은 송금 계좌→수취 계좌 조합의 과거 거래 횟수의 `log1p` |
| `hours_since_sender_prev_log` | 해당 송금 계좌의 직전 송금 이후 경과시간의 `log1p` |
| `amount_vs_sender_history_usd` | 현재 USD 송금액이 해당 송금자의 과거 평균보다 얼마나 큰지 나타내는 로그 차이 |

### 범주형 피처

| 피처 | 설명 |
|---|---|
| `Payment Currency` | 송금자가 지급한 통화 |
| `Receiving Currency` | 수취인이 받은 통화 |

`Payment Format`, 원본 `Timestamp`, 날짜, 요일과 주말 여부는 모델 피처에서 제외했다.

- 자금세탁 1건을 찾기 위해 평균 약 510건의 경고를 확인해야 하므로 조사 효율이 매우 낮다.

### 평가 지표

| 지표 | 값 | 해석 |
|---|---:|---|
| Threshold | 0.953739 | 검증 데이터에서 F1이 가장 높았던 기준이며 실제 확률 95.4%를 뜻하지 않는다. |
| PR-AUC | 0.002464 | 무작위 기준보다 약 5.7배 높지만 절대적인 순위 품질은 낮다. |

| F1 | 0.003776 | Precision과 Recall을 함께 본 전체 성능이 매우 낮다. |

해석:

- Random Forest의 PR-AUC는 무작위 기준보다 약 15.8배, Logistic Regression보다 약 2.8배 높다.

- 그러나 검증 데이터에서 선택한 Threshold에서는 Recall이 2.70%로 Logistic Regression의 5.12%보다 낮다. Random Forest가 더 보수적인 경고 모델이 됐다.
- 상위 100건에는 양성이 없고, 상위 500건에는 3건, 상위 1,000건에는 9건이 포함된다.
- PR-AUC는 모든 Threshold의 순위 품질을 요약하고, Confusion matrix는 선택된 Threshold 한 지점의 결과다. 따라서 PR-AUC가 더 높아도 선택한 Threshold의 Recall은 더 낮을 수 있다.
- 절대 성능은 여전히 낮아 최종 탐지 모델로 사용할 수준은 아니다.

## v3 결론

- HI-Small의 `Patterns.txt`에는 0 라벨 거래가 없다. 따라서 보조·환전 거래를 임의로 제거하는 실험이 아니라, 확인된 패턴 자금세탁만 과거 행동 이력에서 제외한 실험이다.
- 패턴 자금세탁을 과거 이력 계산 전에 제거해도 Logistic Regression과 통화 제거 Logistic 결과는 거의 변하지 않았다.
- Random Forest의 PR-AUC도 거의 같아 전체 순위 신호는 유지됐다. 다만 검증 Threshold가 보수적으로 바뀌면서 Recall과 F1, 상위 100·500 성능은 낮아졌다.
- 패턴 거래가 과거 이력에 포함됐던 것이 v2의 낮은 성능이나 잔여 신호의 주원인이라는 근거는 없다.
- 가장 일관된 후보 신호는 여전히 **송금자·수취자 활동 이력과 송금자→수취자 거래쌍의 낮은 반복성**이다.
- 통화 이름을 제거해도 성능이 유지되므로 고정환율로 환산한 USD 금액만 사용하는 방향이 타당하다.
- 현재 거래 단위 피처만으로는 패턴 외 자금세탁 대부분을 놓치므로 단일 거래 분류만으로 충분하지 않다.

## 방법론상 주의점

- v3는 `Patterns.txt`라는 정답 정보를 사용해 과거 거래 이력에서 패턴 자금세탁을 제거한 진단 실험이다.
- 실제 탐지 시점에는 과거 거래가 패턴 자금세탁인지 미리 알 수 없다.
- v2의 과거 이력 피처는 패턴 라벨을 사용하지 않고 당시 관측 가능한 거래 횟수와 금액만 계산하므로 그 자체로 미래 라벨 누수라고 보기는 어렵다.
- 따라서 운영과 가까운 기준 모델에는 v2 방식이 더 자연스럽고, v3는 패턴 자금세탁 이력의 영향 여부를 확인하는 비교 실험으로 남기는 것이 적절하다.

## 다음 실험 우선순위

1. 불균형 처리 방법을 분리한다.
   - 언더샘플링만 사용하고 `class_weight=None`
   - 전체 학습 데이터와 `class_weight="balanced"`
   - 현재의 언더샘플링과 `class_weight="balanced"` 동시 적용
2. 중복·저효용 피처를 제거한다.
   - 대부분 같은 `log_amount_received_usd` 제거
   - `Payment Currency`, `Receiving Currency`, `is_cross_currency` 제거
3. `hour_sin`과 `hour_cos` 제거 실험으로 시간대 생성 규칙 의존 여부를 확인한다.
4. 신규 상대방과 짧은 시간창 행동 피처를 추가한다.
   - `is_new_pair`
   - 최근 1시간·24시간 거래 횟수와 금액 합계
   - 최근 고유 수취인·송금자 수
   - 송금자의 신규 상대방 거래 비율
5. 고정 Threshold보다 실제 조사 가능 건수에 맞춘 `Precision@K`와 `Recall@K`를 중심으로 모델을 비교한다.
6. Small에서는 분석 절차를 검증하고 Large에서는 여러 시간 구간의 순차 검증으로 결과의 재현성을 확인한다.
