# 패턴 외 자금세탁 기준 분석 v4 리뷰

## 분석 목적

- 패턴 외 자금세탁과 정상거래를 구분할 때 계좌·거래쌍 과거 이력 피처가 실제 성능에 기여하는지 확인한다.
- v3와 데이터, 타깃, 시간 분할, 학습 표본 구성과 모델 설정을 동일하게 유지한다.
- v4에서는 과거 거래를 이용해 만든 다섯 개 피처만 모델 입력에서 제거한다.
- 성능이 크게 하락하면 계좌 이력 피처에 구분 신호가 있었다고 해석하고, 거의 같으면 추가 정보가 적었다고 판단한다.

## 실험 정의

| 구분 | 기준 |
|---|---|
| 양성 (`target=1`) | `Is Laundering == 1`이면서 `Patterns.txt`에 없는 거래 |
| 음성 (`target=0`) | `Is Laundering == 0`인 정상거래 |
| 학습 제외 | `Patterns.txt`에 포함된 자금세탁 거래 |
| 패턴 내 0 라벨 | 역할을 추정하지 않고 원본 정상 라벨을 유지 |
| Reinvestment | 초기 잔액 설정 성격이므로 481,056건 제외 |
| 모델링 데이터 | 총 4,593,618건 |
| 분석 기간 | 2022-09-01~2022-09-10 |
| 시간 분할 | 학습 1~7일, 검증 8일, 테스트 9~10일 |
| 불균형 처리 | 학습 데이터에서만 정상거래를 양성의 10배까지 무작위 추출 |
| 모델 | Logistic Regression, Random Forest |

> 학습 데이터에는 정상거래 언더샘플링과 `class_weight="balanced"`가 동시에 적용됐다. 모델 점수와 Threshold는 실제 자금세탁 확률로 해석하면 안 된다. Threshold는 검증 데이터에서 F1이 최대가 되는 지점이다.

## v3 대비 변경 사항

| 항목 | v3 | v4 |
|---|---|---|
| 데이터와 타깃 | 패턴 외 자금세탁 대 정상거래 | 동일 |
| 시간 분할 | 학습 1~7일, 검증 8일, 테스트 9~10일 | 동일 |
| 학습 정상거래 표본 | 양성의 10배 | 동일 |
| 거래 자체 피처 | 사용 | 동일하게 사용 |
| 계좌·거래쌍 과거 이력 피처 | 사용 | 전부 제거 |
| Logistic·Random Forest 설정 | 기준 설정 | 동일 |

v4는 계좌 이력 피처를 계산하지 않으며 모델 입력에도 포함하지 않는다. 따라서 v3와 v4의 성능 차이를 이력 피처의 기여도로 해석할 수 있는 제거 실험이다.

## 제거한 계좌 이력 피처

| 피처 | 제거된 정보 |
|---|---|
| `sender_prev_count_log` | 송금자의 이전 송금 횟수 |
| `receiver_prev_count_log` | 수취인의 이전 수취 횟수 |
| `pair_prev_count_log` | 동일 송금자→수취자 조합의 이전 거래 횟수 |
| `hours_since_sender_prev_log` | 송금자의 직전 송금 이후 경과시간 |
| `amount_vs_sender_history_usd` | 송금자의 과거 평균 금액 대비 현재 금액 |

## 남아 있는 피처

### 숫자형 피처

| 피처 | 설명 |
|---|---|
| `log_amount_paid_usd` | 송금액을 USD로 환산한 후 `log1p` 변환한 값 |
| `log_amount_received_usd` | 수취액을 USD로 환산한 후 `log1p` 변환한 값 |
| `log_amount_ratio_usd` | USD 기준 수취액과 송금액의 로그 비율 |
| `is_cross_bank` | 송금 은행과 수취 은행이 다르면 1 |
| `is_self_transfer` | 송금·수취 은행과 계좌가 모두 같은 자기거래이면 1 |
| `is_cross_currency` | 지급 통화와 수취 통화가 다르면 1 |
| `hour_sin` | 거래 시각의 24시간 순환성을 사인값으로 표현 |
| `hour_cos` | 거래 시각의 24시간 순환성을 코사인값으로 표현 |

### 범주형 피처

| 피처 | 설명 |
|---|---|
| `Payment Currency` | 송금자가 지급한 통화 |
| `Receiving Currency` | 수취인이 받은 통화 |

`Payment Format`, 원본 `Timestamp`, 날짜, 요일과 주말 여부는 이전 실험과 동일하게 제외했다. 계좌번호와 Entity ID 자체도 모델에 넣지 않았다.

## 데이터 분할

| 구분 | 정상거래 | 패턴 외 자금세탁 | 전체 |
|---|---:|---:|---:|
| 학습 원본 | 3,247,586 | 1,386 | 3,248,972 |
| 검증 | 482,232 | 211 | 482,443 |
| 테스트 | 861,832 | 371 | 862,203 |
| 학습 표본 | 13,860 | 1,386 | 15,246 |

- 정상거래 언더샘플링은 학습에서만 적용했다.
- 검증과 테스트는 원래 불균형 비율을 유지했다.
- 테스트 양성 비율은 약 0.0430%이므로 무작위 순위 모델의 PR-AUC 기준값은 약 0.000430이다.
- v3와 표본 수가 모두 같아 성능 차이가 데이터 수 변화 때문은 아니다.

## Logistic Regression 결과

### Confusion matrix

| 실제값 | 정상 예측 (`pred_0`) | 자금세탁 예측 (`pred_1`) | 합계 |
|---|---:|---:|---:|
| 정상거래 (`actual_0`) | 509,741 | 352,091 | 861,832 |
| 패턴 외 자금세탁 (`actual_1`) | 148 | 223 | 371 |
| 합계 | 509,889 | 352,314 | 862,203 |

해석:

- 패턴 외 자금세탁 371건 중 223건을 찾아 Recall은 60.11%로 높게 나타났다.
- 그러나 정상거래 352,091건을 자금세탁으로 잘못 경고했다. 정상거래의 약 40.9%를 오탐한 결과다.
- 경고 352,314건 중 실제 자금세탁은 223건뿐이다.
- 자금세탁 1건을 찾기 위해 평균 약 1,580건의 경고를 확인해야 한다.
- 높은 Recall은 양성을 정확히 구분한 결과가 아니라 매우 넓은 범위의 거래를 자금세탁으로 예측한 결과다.

### 평가 지표

| 지표 | 값 | 해석 |
|---|---:|---|
| Threshold | 0.501616 | 검증 데이터에서 F1이 가장 높았던 기준이며 실제 확률 50.2%를 뜻하지 않는다. |
| PR-AUC | 0.000524 | 무작위 기준 0.000430보다 약 1.2배로, 순위 신호가 매우 약하다. |
| Precision | 0.000633 | 경고 거래 중 실제 자금세탁은 약 0.063%이다. |
| Recall | 0.601078 | 실제 자금세탁의 약 60.11%인 223건을 탐지했다. |
| F1 | 0.001265 | 높은 Recall에 비해 Precision이 지나치게 낮아 전체 성능도 낮다. |
| Precision@100 | 0.000000 | 위험도 상위 100건에 실제 자금세탁이 없다. |
| Recall@100 | 0.000000 | 전체 양성 중 상위 100건에서 찾은 거래가 없다. |
| Precision@500 | 0.002000 | 상위 500건 중 자금세탁은 1건이다. |
| Recall@500 | 0.002695 | 전체 양성 371건 중 1건을 찾았다. |
| Precision@1000 | 0.001000 | 상위 1,000건 중 자금세탁은 1건이다. |
| Recall@1000 | 0.002695 | 상위 1,000건에서도 추가 양성을 찾지 못했다. |

PR-AUC가 무작위 기준에 매우 가까우며 상위 K 성능도 낮다. 따라서 Recall 60.11%를 모델의 구분 성능으로 해석하면 안 된다.

- 자금세탁 1건당 평균 약 451건의 경고를 확인해야 한다.
- Logistic보다 경고 수는 크게 적지만 Recall도 4.58%로 낮다.

- 송금액과 수취액은 대부분 같은 값이므로 사실상 같은 금액 정보를 중복 제공한다.
- 계좌 이력을 제거하자 Random Forest가 금액과 시간대에 크게 의존했다. 남은 PR-AUC가 실제 행동 신호인지 데이터 생성기의 금액·시간 규칙인지 추가 제거 실험이 필요하다.
- 불순도 기반 중요도에는 영향 방향이 없으며, 중요도가 높다고 자금세탁의 원인이라는 뜻은 아니다.

## v4 결론

- 계좌 이력 피처를 제거하자 모든 모델의 PR-AUC와 F1이 크게 감소했다.
- Logistic PR-AUC는 약 79%, Random Forest PR-AUC는 약 84% 감소했다.
- Random Forest 상위 500·1,000건의 양성 수도 각각 3→1건, 9→3건으로 줄었다.
- 따라서 패턴 외 자금세탁에는 현재 거래 금액·통화만으로 설명하기 어려운 **계좌 활동과 거래쌍 이력 신호**가 존재한다.
- 특히 이전 실험에서 일관되게 중요했던 `pair_prev_count_log`, `sender_prev_count_log`, 경과시간과 과거 평균 대비 금액이 성능에 실제로 기여한 것으로 볼 수 있다.
- 다만 다섯 피처를 동시에 제거했으므로 어느 하나가 얼마나 기여했는지는 아직 구분할 수 없다.
- 이력 피처가 있어도 절대 성능은 낮았으므로 “신호가 있다”는 것과 “실제 탐지 모델로 충분하다”는 것은 구분해야 한다.
- v4에 남은 약한 신호는 금액과 시간대에 대부분 의존하며, 시간대 생성 규칙 가능성을 추가로 확인해야 한다.

## 방법론상 주의점

- `class_weight="balanced"`와 1:10 언더샘플링을 동시에 사용해 Threshold와 모델 점수는 실제 확률이 아니다.
- Recall이 높아도 경고 범위가 지나치게 넓으면 운영 성능은 좋지 않다. PR-AUC, Precision과 Precision@K를 함께 봐야 한다.
- Random Forest 불순도 중요도는 연속형 피처를 선호할 수 있고 영향 방향을 알려주지 않는다.
- 송금액과 수취액처럼 중복된 피처는 Logistic 계수와 Random Forest 중요도를 나누어 가져 해석을 왜곡할 수 있다.
- HI-Small에서 확인한 이력 신호가 다른 기간·LI·Large에서도 유지되는지 검증해야 한다.
