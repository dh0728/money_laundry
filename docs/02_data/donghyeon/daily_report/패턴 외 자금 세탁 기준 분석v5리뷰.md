# 패턴 외 자금세탁 기준 분석 v5 리뷰

## 분석 목적

- 패턴 외 자금세탁과 정상거래를 구분할 때 다섯 개 계좌·거래쌍 이력 피처 중 어떤 묶음이 실제 성능에 기여하는지 분리해서 확인한다.
- 중복된 USD 수취액 피처와 통화 식별자 피처를 먼저 제거해 모든 실험의 기본 피처를 동일하게 맞춘다.
- 이력 피처가 없는 H0를 기준으로 거래쌍 이력, 계좌 활동량 이력, 시간·금액 이력을 각각 추가한다.
- Logistic Regression과 Random Forest에서 같은 그룹이 유효한지 비교해 선형 신호와 비선형 신호를 구분한다.

## 실험 정의

| 구분 | 기준 |
|---|---|
| 양성 (`target=1`) | `Is Laundering == 1`이면서 `Patterns.txt`에 없는 거래 |
| 음성 (`target=0`) | `Is Laundering == 0`인 정상거래 |
| 사전 제거 | `Patterns.txt`에 포함된 자금세탁 거래 |
| 패턴 내 0 라벨 | HI-Small에는 해당 거래가 없음 |
| Reinvestment | 초기 잔액 설정 성격이므로 481,056건 제외 |
| 모델링 데이터 | 총 4,593,618건 |
| 분석 기간 | 2022-09-01~2022-09-10 |
| 시간 분할 | 학습 1~7일, 검증 8일, 테스트 9~10일 |
| 불균형 처리 | 학습 데이터에서만 정상거래를 양성의 10배까지 무작위 추출 |
| 모델 | Logistic Regression, Random Forest |

> 학습 표본에는 정상거래 언더샘플링과 `class_weight="balanced"`가 동시에 적용됐다. 따라서 모델 점수와 Threshold를 실제 자금세탁 확률로 해석하면 안 된다. Threshold는 검증 데이터에서 F1이 최대가 되는 지점이다.

## v5 변경 사항

### 모든 그룹에서 제거한 피처

| 피처 | 제거 이유 |
|---|---|
| `log_amount_received_usd` | USD 환산 후 송금액과 수취액이 사실상 같아 중복 정보를 제공함 |
| `Payment Currency` | 이전 제거 실험에서 성능 기여가 확인되지 않은 통화 식별자 |
| `Receiving Currency` | 이전 제거 실험에서 성능 기여가 확인되지 않은 통화 식별자 |
| `is_cross_currency` | 이전 제거 실험에서 제거해도 성능이 유지된 통화 관련 피처 |

`log_amount_received_usd`는 `log_amount_ratio_usd`를 계산하기 위한 중간값으로는 만들어지지만 모델 입력에는 포함되지 않는다.

### 공통 기본 피처

| 피처 | 설명 |
|---|---|
| `log_amount_paid_usd` | 송금액을 USD로 환산하고 `log1p` 변환한 값 |
| `log_amount_ratio_usd` | USD 기준 수취액과 송금액의 로그 비율 |
| `is_cross_bank` | 송금 은행과 수취 은행이 다르면 1 |
| `is_self_transfer` | 송금·수취 은행과 계좌가 모두 같은 자기거래이면 1 |
| `hour_sin` | 거래 시각의 24시간 순환성을 사인값으로 표현 |
| `hour_cos` | 거래 시각의 24시간 순환성을 코사인값으로 표현 |

H0의 “없음”은 모델 피처가 전혀 없다는 뜻이 아니라 위 기본 피처만 사용하고 과거 이력 피처를 사용하지 않는다는 뜻이다.

### 이력 피처 그룹

| 실험 | 추가 이력 피처 | 확인하려는 정보 |
|---|---|---|
| H0 | 없음 | 현재 거래 속성만 사용한 기준 성능 |
| H1 | `pair_prev_count_log` | 동일 송금자→수취자 거래쌍의 반복 이력 |
| H2 | `sender_prev_count_log`, `receiver_prev_count_log` | 송금·수취 계좌의 과거 활동량 |
| H3 | `hours_since_sender_prev_log`, `amount_vs_sender_history_usd` | 직전 송금 이후 시간과 과거 평균 대비 현재 금액 |
| H4 | 위 이력 피처 5개 전체 | 이력 정보의 결합 및 상호작용 |

- 모든 그룹은 동일한 학습·검증·테스트 행과 동일한 학습 표본을 사용했다.
- 이력 피처는 현재 거래보다 앞선 거래만 이용해 계산했다.
- Random Forest는 그룹별 피처 수가 달라도 한 분기에서 검토하는 피처 수가 같도록 `max_features=3`으로 고정했다.
- 이번 실험에는 `is_new_pair`를 추가하지 않았고 `hour_sin`, `hour_cos`도 유지했다.

### H0: 이력 피처 없음

- PR-AUC는 0.000544로 무작위 기준의 약 1.26배에 불과하다.
- Recall은 68.73%지만 정상거래 366,386건을 함께 경고했다.
- 경고 366,641건 중 실제 자금세탁은 255건으로, 자금세탁 1건을 찾기 위해 약 1,438건의 경고를 확인해야 한다.
- 높은 Recall은 현재 거래 속성만으로 양성을 잘 구분한 결과가 아니라 Threshold가 테스트 거래의 약 42.5%를 양성으로 분류한 결과다.

### H1: 거래쌍 이력만 추가

- PR-AUC는 0.005970으로 H0의 약 10.98배, 무작위 기준의 약 13.87배다.
- F1은 0.019636으로 Logistic 그룹 중 가장 높다.
- 자금세탁 371건 중 194건을 찾았고 정상거래 오탐은 19,195건이다.
- Precision은 약 1.00%이며 실제 자금세탁 1건당 약 100건의 경고가 발생한다.
- 상위 100건에는 양성 1건, 상위 500건에는 2건, 상위 1,000건에는 6건이 포함됐다.
- 하나의 `pair_prev_count_log`만 추가했는데 순위와 Threshold 기반 성능이 모두 크게 좋아졌다. Logistic에서는 거래쌍 반복 이력이 가장 직접적인 구분 신호다.

### H2: 계좌 활동량 이력만 추가

- PR-AUC는 0.001667로 H0의 약 3.07배지만 H1보다 낮다.
- 선택된 Threshold에서는 자금세탁을 8건만 찾았고 363건을 놓쳤다.
- 상위 1,000건에도 양성이 1건뿐이므로 Logistic의 선형 점수로는 계좌 활동량 신호를 충분히 정렬하지 못했다.
- H0보다는 개선됐으므로 정보가 전혀 없는 것은 아니지만 단독 선형 피처로서의 효과는 제한적이다.

### H3: 시간·금액 이력만 추가

- PR-AUC는 0.000741로 H0의 약 1.36배이며 무작위 기준에 가깝다.
- 선택된 Threshold에서 실제 양성을 1건만 탐지했다.
- 상위 500건과 1,000건에는 양성이 각각 2건 포함돼 H0보다 약간 나아졌지만 절대 성능은 낮다.
- Logistic만 보면 직전 거래 이후 시간과 과거 평균 대비 금액의 단순 선형 결합은 강한 구분 신호가 아니다.

### H4: 이력 피처 전체

- PR-AUC는 0.002478로 H0의 약 4.56배지만 H1의 0.005970보다 낮다.
- 자금세탁 21건을 찾으면서 정상거래 9,794건을 오탐했다.
- H1보다 피처가 많아졌는데 Logistic 성능은 오히려 하락했다.
- 이는 H2·H3 피처가 무조건 불필요하다는 뜻이 아니다. 상관된 이력 피처를 선형으로 동시에 결합하면서 계수가 서로 조정되거나, 학습 기간의 관계가 테스트 기간에 같은 선형 형태로 유지되지 않았을 가능성이 있다.

## Logistic Regression 계수 비교

숫자형 피처를 표준화했으므로 같은 그룹 안에서는 계수의 상대적 크기를 비교할 수 있다. 양수는 다른 피처가 같을 때 양성 점수를 높이는 방향이고 음수는 정상거래 방향이다.

| 피처 | H0 | H1 | H2 | H3 | H4 |
|---|---:|---:|---:|---:|---:|
| `log_amount_paid_usd` | 0.291531 | 0.162192 | 0.297887 | 0.647442 | 0.505184 |
| `log_amount_ratio_usd` | -0.015233 | -0.040679 | -0.024504 | -0.018257 | -0.046126 |
| `is_cross_bank` | 0.100883 | 0.140925 | 0.088211 | 0.088826 | 0.077810 |
| `is_self_transfer` | -0.974058 | -0.883831 | -0.980275 | -0.970620 | -0.940487 |
| `hour_sin` | -0.023910 | -0.026625 | -0.038519 | -0.020116 | 0.016196 |
| `hour_cos` | -0.042360 | -0.086781 | -0.041910 | -0.034526 | -0.110926 |
| `sender_prev_count_log` | - | - | 0.266669 | - | 1.007348 |
| `receiver_prev_count_log` | - | - | -0.515483 | - | 0.652159 |
| `pair_prev_count_log` | - | -0.992896 | - | - | -2.534432 |
| `hours_since_sender_prev_log` | - | - | - | 0.162399 | 0.072894 |
| `amount_vs_sender_history_usd` | - | - | - | -0.583249 | -0.448749 |

해석:

- `pair_prev_count_log`는 H1과 H4에서 모두 강한 음수다. 같은 송금자→수취자 조합의 이전 거래가 많을수록 정상거래 방향이고, 이전 거래가 없거나 적을수록 자금세탁 점수가 높아지는 경향이다.
- 이 결과는 다음 실험에서 `is_new_pair = (pair_prev_count == 0)`를 직접 비교할 근거가 된다.
- H2에서는 `receiver_prev_count_log`가 음수지만 H4에서는 양수로 바뀐다. 이는 거래쌍·송금자 활동량 등 상관된 피처를 함께 넣었을 때 조건부 계수가 재분배된 결과이므로 “수취 활동이 많으면 위험하다/안전하다”라고 단독 해석하면 안 된다.
- `amount_vs_sender_history_usd`는 H3와 H4에서 음수다. 현재 송금액이 송금자의 과거 평균보다 상대적으로 작을수록 양성 방향이라는 경향이며 클래스 중앙값과도 일치한다.
- `is_self_transfer`는 모든 그룹에서 일관되게 음수지만 두 클래스 모두 중앙값은 0이다. 일부 자기거래 표본에서 나타난 조건부 관계이므로 빈도 확인 없이 강한 정상 규칙으로 사용하면 안 된다.
- `log_amount_ratio_usd`의 계수는 모든 그룹에서 작다. USD 환산 후 송금액과 수취액 비율이 대부분 1인 데이터 특성과 일치한다.

### H1: 거래쌍 이력만 추가

### H2: 계좌 활동량 이력만 추가

- PR-AUC는 0.004707로 H0의 약 5.25배다.

- 송금자·수취자 활동량은 단순 선형 관계보다 구간, 임계값 또는 두 활동량 사이 상호작용 형태로 작동할 가능성이 있다.

### H3: 시간·금액 이력만 추가

- PR-AUC는 0.005880으로 H0의 약 6.56배이며 H1의 0.006030에 가깝다.

- 상위 500건에는 양성 6건, 상위 1,000건에는 12건이 포함됐다.
- Logistic H3는 거의 무작위 수준이었지만 Random Forest H3는 크게 개선됐다. 시간 간격과 과거 평균 대비 금액은 비선형 관계로 사용할 때 구분 신호가 있는 것으로 보인다.

### H4: 이력 피처 전체

- PR-AUC는 0.007063으로 Random Forest 그룹 중 가장 높다.
- H0의 약 7.88배이며 무작위 기준의 약 16.41배다.
- Precision은 약 1.56%, Recall은 약 8.63%, F1은 0.026446으로 Random Forest 그룹 중 가장 높다.
- 경고 2,049건 중 실제 자금세탁은 32건으로 실제 양성 1건당 약 64건의 경고가 발생한다.
- 상위 100건에는 양성 1건, 상위 500건에는 7건, 상위 1,000건에는 15건이 포함됐다.
- H1보다 선택된 Threshold의 탐지 건수는 적지만 오탐이 크게 줄고 전체 순위와 상위 1,000건 성능이 좋아졌다.
- Random Forest에서는 다섯 이력 피처를 결합했을 때 가장 좋은 결과가 나와 각 이력 그룹 사이의 보완 관계와 비선형 상호작용 가능성을 보여준다.

## v5 결론

- 패턴 외 자금세탁에는 현재 거래 금액과 시간대만으로는 얻기 어려운 과거 거래 이력 신호가 존재한다.
- 가장 명확하고 모델 간 일관성이 높은 신호는 동일 송금자→수취자 조합의 이전 거래 횟수인 `pair_prev_count_log`다.
- `pair_prev_count_log`가 강한 음수라는 결과는 반복 거래쌍보다 신규 또는 반복이 적은 거래쌍에서 패턴 외 자금세탁이 더 많이 나타나는 경향을 뜻한다.
- 송금자·수취자 활동량과 시간·과거 평균 대비 금액도 Random Forest 성능을 크게 올려 비선형 신호와 상호작용 가능성이 확인됐다.
- Logistic Regression에서는 H1이 최고이고 Random Forest에서는 H4가 최고이므로 목적에 따라 피처 구성을 다르게 볼 수 있다.
  - 설명이 단순한 선형 기준 모델: H1
  - 비선형 관계까지 활용하는 비교 모델: H4
- 피처가 많을수록 항상 성능이 좋아지는 것은 아니다. 특히 상관된 이력 피처를 Logistic에 모두 넣으면 H1보다 일반화 성능이 낮아졌다.
- 이 결과는 패턴 외 거래가 모두 단건이라는 뜻도, 여러 거래가 하나의 자금세탁 시나리오로 묶였다는 뜻도 아니다. 거래 단위 분류에서 “신규 거래쌍과 계좌 행동 이력”이 유효한 구분 정보라는 의미다.

## 방법론상 주의점

- 학습 언더샘플링과 `class_weight="balanced"`를 동시에 사용해 Threshold와 예측 점수는 실제 확률이 아니다.
- 검증일 하루에서 선택한 Threshold이므로 날짜가 바뀌면 경고 수와 Recall이 크게 달라질 수 있다.
- PR-AUC가 H0보다 여러 배 높아도 양성 비율 자체가 매우 작아 절대 Precision은 낮다.
- Logistic 계수는 다른 피처를 고정했을 때의 조건부 관계다. 그룹에 따라 부호가 바뀌는 피처를 단독 위험 규칙으로 사용하면 안 된다.
- Random Forest 중요도에는 영향 방향이 없고 연속형 피처를 선호할 수 있다.
- `hour_sin`, `hour_cos`가 여전히 포함돼 있으므로 남은 성능 일부가 시뮬레이션 시간대 생성 규칙에 의존할 가능성이 있다.
- HI-Small의 10일만 사용한 결과이므로 LI와 Large의 다른 시간 구간에서도 같은 기여 순서가 유지되는지 확인해야 한다.
