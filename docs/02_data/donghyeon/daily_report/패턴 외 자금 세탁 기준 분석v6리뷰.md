# 패턴 외 자금세탁 기준 분석 v6 리뷰

## 분석 목적

- v5에서 가장 일관된 신호였던 동일 송금자→수취자 거래쌍 이력을 더 단순한 형태로 표현할 수 있는지 확인한다.
- 거래쌍이 처음 등장했는지만 나타내는 `is_new_pair`와 이전 거래 횟수 전체를 나타내는 `pair_prev_count_log`를 비교한다.
- 두 피처를 함께 넣었을 때 추가 성능이 있는지 확인해 중복 피처 여부를 판단한다.
- Logistic Regression과 Random Forest에서 같은 결론이 유지되는지 비교한다.

## 실험 정의

| 구분 | 기준 |
|---|---|
| 양성 (`target=1`) | `Is Laundering == 1`이면서 `Patterns.txt`에 없는 거래 |
| 음성 (`target=0`) | `Is Laundering == 0`인 정상거래 |
| 사전 제거 | `Patterns.txt`에 포함된 자금세탁 거래 |
| 패턴 내 0 라벨 | HI-Small에는 해당 거래가 없음 |
| Reinvestment | 초기 잔액 설정 성격이므로 481,056건 제외 |
| 모델링 데이터 | 총 4,593,618건 |
| 분석 기간 | 2022-09-01~2022-09-10 |
| 시간 분할 | 학습 1~7일, 검증 8일, 테스트 9~10일 |
| 불균형 처리 | 학습 데이터에서만 정상거래를 양성의 10배까지 무작위 추출 |
| 모델 | Logistic Regression, Random Forest |

> 학습 표본에는 정상거래 언더샘플링과 `class_weight="balanced"`가 동시에 적용됐다. 모델 점수와 Threshold는 실제 자금세탁 확률이 아니다. Threshold는 검증 데이터에서 F1이 최대가 되는 지점이다.

## v6 피처 정의

송금자와 수취자는 계좌번호만 사용하지 않고 은행 ID까지 결합해 구분했다.

```python
source_node = From Bank + "::" + Account
target_node = To Bank + "::" + Account.1
```

현재 거래보다 앞선 동일 `source_node → target_node` 거래만 이용한다.

| 피처 | 계산 | 의미 |
|---|---|---|
| `pair_prev_count_log` | `log1p(이전 동일 거래쌍 거래 횟수)` | 반복 횟수 전체를 연속형으로 표현 |
| `is_new_pair` | 이전 동일 거래쌍 거래 횟수가 0이면 1 | 신규 거래쌍인지 여부만 이진형으로 표현 |

두 피처는 독립된 정보가 아니다.

```python
is_new_pair = (pair_prev_count_log == 0)
```

- `pair_prev_count_log`가 0이면 반드시 `is_new_pair=1`이다.
- `is_new_pair`는 0회와 1회 이상만 구분한다.
- `pair_prev_count_log`는 신규 여부뿐 아니라 1회, 2회, 10회처럼 반복 정도까지 보존한다.
- 두 피처를 같이 넣은 P3는 신규 여부의 별도 경계와 반복 횟수의 기울기를 동시에 표현하는 구성이다.

## 비교 구성

| 실험 | 공통 기본 피처 외 추가 피처 | 확인 목적 |
|---|---|---|
| P0 | 없음 | 거래쌍 정보가 없는 기준 성능 |
| P1 | `is_new_pair` | 신규 여부만으로 충분한지 확인 |
| P2 | `pair_prev_count_log` | 반복 횟수 전체가 추가 정보를 주는지 확인 |
| P3 | 두 피처 모두 | 두 표현을 같이 넣을 실익이 있는지 확인 |

### 모든 구성의 공통 기본 피처

| 피처 | 설명 |
|---|---|
| `log_amount_paid_usd` | USD 환산 송금액의 `log1p` 값 |
| `log_amount_ratio_usd` | USD 기준 수취액과 송금액의 로그 비율 |
| `is_cross_bank` | 송금 은행과 수취 은행이 다르면 1 |
| `is_self_transfer` | 송금·수취 은행과 계좌가 모두 같으면 1 |
| `hour_sin` | 거래 시각의 24시간 순환 사인값 |
| `hour_cos` | 거래 시각의 24시간 순환 코사인값 |

### 계속 제외한 피처

| 피처 | 제외 이유 |
|---|---|
| `log_amount_received_usd` | USD 송금액과 중복 |
| `Payment Currency`, `Receiving Currency` | 이전 실험에서 성능 기여가 확인되지 않음 |
| `is_cross_currency` | 이전 제거 실험에서 성능이 유지됨 |
| `Payment Format` | HI-Small 양성 대부분이 ACH인 생성 규칙 의존 가능성 |
| 날짜·요일·주말 | 절대 날짜와 데이터 생성 기간을 외우지 않게 제외 |
| 계좌번호·Entity ID | 식별자를 직접 암기하지 않게 제외 |

### 전체 기간 클래스별 통계

해석:

- 패턴 외 자금세탁의 약 62.75%가 이전에 거래한 적 없는 신규 송금자→수취자 조합이다.
- 정상거래의 신규 거래쌍 비율은 약 14.44%다.
- 전체 기간 기준 양성의 신규 거래쌍 비율은 정상의 약 4.35배다.
- 양성 `pair_prev_count_log` 중앙값이 0이므로 절반 이상이 신규 거래쌍이다.
- 정상 중앙값 1.945910은 `log1p(6)`에 해당하므로 중앙 거래는 이전 동일 거래쌍 거래가 약 6회 존재한다.

- 이 변화는 미래 정보를 사용한 누수는 아니다. 현재 시점 이전 거래만 사용했기 때문이다. 다만 시뮬레이션이 진행되며 정상 네트워크가 빠르게 고정되는 생성 규칙의 영향일 가능성은 별도로 확인해야 한다.

### P0: 거래쌍 정보 없음

- PR-AUC는 0.000544로 무작위 기준의 약 1.26배다.
- Recall은 68.73%지만 정상거래 366,386건을 오탐했다.

- 거래쌍 정보가 없으면 현재 거래 피처만으로 유효한 위험 순위를 만들기 어렵다.

### P1: `is_new_pair`만 사용

- PR-AUC는 0.005752로 P0의 약 10.58배, 무작위 기준의 약 13.37배다.
- Precision 1.016%, Recall 53.37%, F1 0.019941로 Threshold 기반 Logistic 지표 중 가장 좋다.
- 자금세탁 198건을 찾으면서 정상거래 19,290건을 오탐했다.
- 양성 1건당 약 98건의 경고가 발생한다.
- 상위 100건에는 양성 1건, 상위 500건에는 2건, 상위 1,000건에는 7건이 포함됐다.
- 신규 여부 하나만 추가해도 v5의 거래쌍 이력 효과 대부분을 재현했다.

### P2: `pair_prev_count_log`만 사용

- PR-AUC는 0.005970으로 P1보다 약 3.79% 높다.
- Precision 1.001%, Recall 52.29%, F1 0.019636으로 P1과 거의 같다.
- 자금세탁 194건을 찾으면서 정상거래 19,195건을 오탐했다.
- 상위 1,000건에는 양성 6건이 포함돼 P1의 7건보다 1건 적다.
- 반복 횟수의 크기가 전체 PR 곡선에는 소폭 추가 정보를 주지만 선택된 Threshold와 상위 1,000건에서는 P1보다 좋지 않았다.

### P3: 두 피처 모두 사용

- PR-AUC는 0.006010으로 숫자상 가장 높다.
- 그러나 P2보다 증가율은 약 0.67%에 불과하다.
- Precision, Recall, F1은 모두 P1보다 낮고 상위 1,000건 성능도 P1보다 낮다.
- 자금세탁 165건을 찾으면서 정상거래 16,656건을 오탐했다.
- 경고 범위는 P1·P2보다 작지만 놓친 양성이 증가했다.
- PR-AUC의 매우 작은 차이만으로 두 피처를 모두 유지할 근거는 부족하다.

- 상위 100건에 양성 2건, 상위 500건에 4건, 상위 1,000건에 10건이 포함됐다.
- 상위 100건과 1,000건 성능은 P2보다 오히려 좋았다.

### P2: `pair_prev_count_log`만 사용

- PR-AUC는 0.006030으로 P1보다 약 7.81% 높다.

### P3: 두 피처 모두 사용

- PR-AUC는 0.006076으로 숫자상 가장 높지만 P2보다 약 0.76% 높을 뿐이다.
- F1은 0.014281로 P2보다 낮고 Recall도 5.39%에 그쳤다.
- 상위 500건에는 양성 5건으로 가장 많지만 상위 1,000건에는 P1의 10건보다 적은 9건이다.
- `pair_prev_count_log` 하나만으로도 나무가 0과 0보다 큰 값을 분기해 신규 여부를 만들 수 있으므로 `is_new_pair`를 같이 넣어 얻는 새 정보는 없다.
- `max_features=3`에서 같은 거래쌍 정보를 두 컬럼으로 넣으면 분기 후보에 거래쌍 정보가 선택될 가능성이 달라진다. 따라서 0.76%의 작은 PR-AUC 상승을 독립 정보의 기여로 해석하면 안 된다.

## 핵심 비교 해석

1. **신규 거래쌍 여부만으로 거래쌍 이력 효과의 대부분을 설명할 수 있다.** P1은 두 모델 모두에서 P0보다 약 6~11배 높은 PR-AUC를 보였다.
2. **반복 횟수에도 소폭 추가 정보가 있다.** P2는 P1보다 Logistic PR-AUC가 약 3.79%, Random Forest PR-AUC가 약 7.81% 높았다.
3. **두 피처를 동시에 넣는 실익은 거의 없다.** P3의 P2 대비 PR-AUC 증가는 두 모델 모두 1% 미만이고 F1과 상위 1,000건 성능은 개선되지 않았다.
4. **P3의 숫자상 최고 PR-AUC를 실질적 우위로 보기 어렵다.** 테스트 양성이 371건뿐이고 두 피처가 같은 원본 횟수에서 파생됐기 때문에 작은 차이는 표본과 모델 분기 변화에 민감하다.
5. **설명 목적에는 P1이 가장 단순하다.** “이전에 거래하지 않은 상대방인가”라는 명확한 규칙으로 결과를 설명할 수 있고 Logistic의 F1과 상위 1,000건도 가장 좋았다.
6. **모델 입력 하나를 선택한다면 P2가 더 적절하다.** P2는 신규 여부를 0값으로 이미 포함하면서 반복 정도도 보존하고, 두 모델 모두 P1보다 전체 PR-AUC가 높았다.
7. **P1과 P2를 함께 유지할 필요는 없다.** P3에서 추가 성능이 사실상 없고 계수·중요도 해석만 중복된다.

## v6 결론

- 패턴 외 자금세탁은 정상거래보다 신규 송금자→수취자 조합에서 발생하는 비율이 매우 높다.
- 테스트 기간 신규 거래쌍 비율은 정상거래 4.18%, 패턴 외 자금세탁 56.06%로 약 13.4배 차이가 났다.
- v5에서 확인한 `pair_prev_count_log`의 강한 기여 중 대부분은 신규 또는 반복이 적은 거래쌍이라는 특성에서 나온다.
- 신규 여부만 사용해도 강한 성능 개선이 있지만 반복 횟수 전체가 소폭 더 많은 순위 정보를 제공한다.
- 최종적으로는 `pair_prev_count_log` 하나를 유지하고 `is_new_pair`는 별도 모델 피처로 중복 추가하지 않는 구성이 가장 합리적이다.
- 다만 보고서와 설명용 통계에서는 `is_new_pair` 비율을 계속 사용하는 것이 직관적이다.
- 이 결과는 패턴 외 자금세탁이 모두 단건이라는 뜻이 아니다. 동일 송금자→수취자 조합의 과거 반복이 적다는 거래 단위 경향을 확인한 것이다.
- 최고 PR-AUC가 무작위보다 약 14배 높아도 절대 Precision은 약 1% 수준이므로 단독 탐지 규칙으로 사용하기에는 오탐이 많다.

## 방법론상 주의점

- `is_new_pair`는 `pair_prev_count_log`에서 완전히 파생되는 피처이므로 둘을 독립된 증거로 세면 안 된다.
- P3의 Logistic 계수와 Random Forest 중요도는 같은 정보를 두 피처가 나누어 가진 결과다.
- Random Forest에서 중복 피처를 넣으면 `max_features`에 의해 해당 정보가 분기 후보로 선택될 확률까지 바뀔 수 있다.
- 정상거래의 신규 거래쌍 비율이 학습 18.74%에서 테스트 4.18%로 크게 변한다. 모델 성능 일부가 시뮬레이터의 네트워크 누적 구조에 의존할 수 있다.
- 이력값은 전체 1~10일을 시간순으로 계산한 뒤 분할했기 때문에 검증·테스트 거래는 앞선 날짜의 이력을 사용할 수 있다. 이는 온라인 환경과 맞지만 미래 구간마다 이력을 0으로 초기화하는 방식과는 결과가 다르다.
- Large에서 구간을 나눌 때도 각 검증·테스트 구간 이전의 워밍업 이력을 유지해야 한다.
- 검증일이 하루이고 테스트 양성이 371건뿐이므로 1% 미만의 PR-AUC 차이는 안정적인 차이라고 보기 어렵다.
- `hour_sin`, `hour_cos`가 남아 있으므로 거래쌍 신호가 시간대 생성 규칙 없이도 유지되는지 아직 확인해야 한다.
