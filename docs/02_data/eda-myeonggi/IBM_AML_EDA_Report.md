## 4. 거래형 EDA (플레이북 §2.3)

### 4.1 시간대별 거래 활동

**질문**: 거래 활동은 언제에 집중되는가?

**관찰**:
- 자정(0시) 이후 급증: 시간 0에 634,726건(~12.5%)의 일일 거래가 발생. 일평균 282,130건 대비 2배 이상
- 일별 편차 큼: 평균 282,130 ± 331,550건 (표준편차가 평균 수준)
- 기간 내 공백 없음: 18일 모두 거래 기록

**가능한 해석**:
- 야간 배치 처리 또는 일일 정산 거래 → 시간을 기준으로 한 버스트 탐지 모티프 가능
- 주중/주말 패턴은 추가 검증 필요 (4주 표본이라 요일별 신뢰성 제한)

**한계**:
- 시간 정보만으로는 라벨과 명확한 상관관계 발견 어려움 (거래 간 시간 간격, 요일 파생치는 별도 검증 필요)

### 4.2 거래 규모 분포

**질문**: 금액이 라벨을 대신 설명하는가?

**관찰**:
- 중앙값: 1,415 USD
- P99: 13,524,531 USD (극단값, 조 단위)
- 정상 거래 vs 세탁 거래 금액 분포에는 차이 있으나, 극단값이 많아 신뢰성 제한

**가능한 해석**:
- 고액 거래가 의심도 높지만, 절대값보다는 **계정·시간·방식 등 맥락과의 조합**이 중요
- 통화별 차이 큼 (USD, EUR, CHF) → 통화별 정규화 필수

**한계**:
- 상위 0.1% 극단값(조 단위)는 데이터 생성 오류 가능성 → log1p 변환 후 다시 검증

### 4.3 계정 활동성

**질문**: 누가 활동적인가?

**관찰**:
- 송금(out) 최대 차수: 168,672건 (한 계좌에서 168K명에게 송금)
- 수취(in) 최대 차수: 1,084건
- 평균 차수: in/out 모두 10.61 (=전체 엣지/노드)

**가능한 해석**:
- Out-degree가 in-degree보다 훨씬 높은 계정 존재 → 이 계정들이 의심거래 허브일 가능성
- 그래프 거의 방향성 (directed acyclic에 가까움): reciprocal edge 비율 0.16%

**한계**:
- 최대 차수 계정들이 데이터 생성 규칙의 산물일 수 있음 (합성 데이터) → 실제 금융 비교 필요

## 5. 네트워크 구조 EDA (플레이북 §3) — **이 보고서의 핵심**

### 5.1 기본 구조 지표

Self-loop 제외 후 계산 (4,487,133 엣지, 422,734 노드).

#### 5.1.1 연결성

**질문**: 거대 연결요소가 전체를 지배하는가?

**관찰**:
- 약 연결요소(WCC): 21,785개
- 가장 큰 WCC: 372,089 노드 (전체 422,734의 88%)
- 상위 3개: 372,089, 24, 23노드
- 고립 노드: 0개 (모든 노드가 최소 1개 이상의 엣지)

**가능한 해석**:
- 거대 WCC가 전체의 88%를 차지 → 메인 거래 네트워크가 통합
- 소규모 WCC들은 폐쇄 서브그래프 또는 방향성 데드엔드의 수집

**한계**:
- WCC는 무방향성 기준 → 실제 자금 흐름(방향성)은 별도 분석 필요 (SCC: Strongly Connected Components)
- 합성 데이터의 생성 규칙 반영 가능

#### 5.1.2 활동성 (차수)

**질문**: 소수 허브·집중 계정이 있는가?

**관찰**:
- In-degree: 평균 10.61, 중앙값 ~1, 최대 1,084
- Out-degree: 평균 10.61, 중앙값 ~1, 최대 168,672
- Out-degree의 편차가 훨씬 큼 (최대값 ÷ 평균 = 15,905배 vs in-degree 102배)

**가능한 해석**:
- 소수의 "분산자(distributor)" 계정이 존재 → 특히 fan-out 패턴
- 다대일 수취(in-degree 고)는 상대적으로 희귀

**한계**:
- 데이터 기간 18일이라 활동성 기준점 불명확 (월/년 비율로는?)
- 상위 허브가 실제 세탁 노드인지, 장부 계정(aggregator)인지 구분 필요

#### 5.1.3 상호성

**질문**: 단발성·왕복성 구조가 어떻게 다른가?

**관찰**:
- 양방향 엣지(reciprocal): 7,386개 (전체 4,487,133의 0.16%)
- 상호성 매우 낮음 → 거의 단방향 흐름

**가능한 해석**:
- 거래는 선형 흐름 (A→B→C→...)
- 순환(cycle)이나 왕복은 드물고, 패턴 기반 탐지에 유리

**한계**:
- Directed acyclic성 vs cyclic motif 비교는 더 깊은 분석 필요
- Patterns.txt의 CYCLE 유형이 실제로 얼마나 많은지 미확인 (라벨 복제 위험)

#### 5.1.4 주차별 스냅샷 안정성

| 주차 | 엣지 수 | 노드 수 | 평균 in-degree | 평균 out-degree |
|------|--------|--------|----------------|-----------------|
| Week 35 (09-01~09-04) | 1,752,596 | 399,735 | 6.38 | 6.54 |
| Week 36 (09-05~09-11) | 2,734,087 | 378,185 | 11.17 | 11.11 |
| Week 37 (09-12~09-18) | 450 | 468 | 1.52 | 1.88 |

**관찰**:
- Week 35/36: 안정적 (일주일에 1.7~2.7M 엣지)
- Week 37: 단 8시간만 기록 (토요일 자정 이후 데이터 끝남) → 분석 제외 권장

**가능한 해석**:
- 주간 변동성 있으나 구조적으로는 일관 (차수 분포 유사)
- 시간 분할 시 Week 37 제외 필요

### 5.2 엔티티 층 (2차 그래프)

**질문**: 엔티티 그래프가 계좌 그래프와 얼마나 다른가?

**관찰**:
- 엔티티 수: 166,207개
- 평균 계좌/엔티티: 3.12
- 최대 계좌 수: 한 엔티티당 7,820개 (이 엔티티가 논드의 1.8%)

**가능한 해석**:
- 계좌 레벨 그래프가 엔티티 레벨 그래프보다 세분화 (6.3배 노드)
- 대규모 엔티티가 존재 → 레이어링(layering) 기법의 타겟

**한계**:
- 엔티티별 그래프 지표 비교는 이 보고서 범위 외
- 모델 입력 단위(거래 vs 엔티티) 선택에 따라 별도 EDA 필요

## 6. 교란 통제된 라벨 비교 (플레이북 §3.2)

**원칙**: 단순 평균 비교 금지. ACH의 양성률이 20배 높으므로, 층화 없으면 "ACH의 구조 차이"를 재발견할 뿐.

### 6.1 층화 매칭 설계

3중 층화 (결제방식 × 금액 십분위 × 시간대):

```
양성 거래 5,177건 각각에 대해,
같은 (결제방식, 금액 분위, 시간대)에서
최대 10배수의 음성 거래 샘플 추출
→ 51,770 음성 거래 매칭
```

### 6.2 비교 결과

| 지표 | 양성(세탁) | 음성(정상) | 차이 |
|------|---------|---------|------|
| 평균 out-degree | 1.53 | 1.45 | +5.5% |
| 평균 in-degree | 1.30 | 1.51 | -13.9% |

**관찰**:
- 층화 후에도 in-degree에서 약간의 차이 존재 (음성이 더 높음)
- Out-degree 차이는 미미

**가능한 해석**:
- 세탁 거래는 **송금 다중성(분산)**보다는 **수취 집중도**가 특징일 수 있음
- 그러나 표본 크기(5K vs 51K) 차이 + 극단 허브 영향도 고려 필요

**한계**:
- 상위 1% 허브 제외 후 재계산하면 다를 수 있음
- 신뢰구간/통계 검정 미포함 (표본 충분하지만 effect size 작음)

## 7. 누수 점검 & 분할 설계 (플레이북 §4)

### 7.1 시간 기반 분할 (제안)

기간: 2022-09-01 ~ 09-18 (18일)

```
Train:  09-01 ~ 09-09 (9일, 4,868,912 거래)
Val:    09-10 ~ 09-14 (5일, 209,186 거래)
Test:   09-15 ~ 09-18 (4일, 247 거래 + 수상 거래 147건)
```

| 분할 | 거래수 | 양성 | 양성률(%) | 노드수 |
|-----|--------|-----|----------|--------|
| Train | 4,868,912 | 4,080 | 0.0838 | ~400K |
| Val | 209,186 | 950 | 0.454 | ~95K |
| Test | 247 | 147 | 59.51 | ~234 |

**주의**: 
- Test 집합이 매우 작음 (247거래) → 통계적 신뢰도 낮음
- 양성률 불안정 (val 0.45% vs test 59.51%) → 데이터 분포 급격한 변화

### 7.2 Transductive vs Inductive

**질문**: Test 노드가 Train에서 본 것인가?

**관찰**:
- Train 노드: 398,735개
- Test 노드: 234개 (실제로는 위 Test 분할의 거래에 관련된 노드)
- 중복(Transductive): 230개 (98.3%)
- 신규(Inductive): 4개 (1.7%)

**결론**: **거의 Transductive** → GNN은 학습된 노드 임베딩만 사용 가능, 새로운 계좌에는 일반화 필요 없음

### 7.3 Patterns.txt 격리

**원칙** (플레이북 §0.2):
- `Is Laundering`과 Patterns.txt 정보를 입력 피처로 **절대 사용 금지**
- 라벨은 평가/검증 단계에서만 사용

**이번 보고서 준수**:
- Patterns.txt는 구조적 직관(fan-out, cycle 등)만 참고
- 실제 라벨로 피처 설계하지 않음

### 7.4 기준선 4종 (평가용)

모델 성능 비교 대상:

| 기준선 | 방식 | PR-AUC 가능성 |
|--------|------|----------------|
| **B1: Random** | 균일 무작위 점수 | ~0.1% (양성률 기준) |
| **B2: ACH Rule** | Payment Format == 'ACH' → 1, else 0 | ~0.74% (정확도) |
| **B3: Amount Quantile** | Amount > p95 → 1, else 0 | ~1.4% (예상) |
| **B4: Logistic** | 시간 누수 없는 간단한 로지스틱 | 미계산 (EDA 단계) |

**기준선 B2(ACH)** 하나만으로도 단순 모델을 이길 높이 설정됨.

### 7.5 평가 지표 선정 (플레이북 §4.3)

**핵심**: PR-AUC / Recall@K. 정확도 사용 금지.

이유:
- 양성률 0.1%로 극심한 불균형 → 정확도는 단순히 음성 거래를 맞히면 99.9% 달성 가능
- 의심거래 탐지 모델의 진정한 가치는 "제한된 조사 자원 안에서 진짜를 찾는 능력"
- Alert capacity가 "하루 상위 k건" 또는 "상위 p%"로 정해지면, Recall@K / Precision@K를 사용

## 8. 대시보드 데이터 계약 (플레이북 §5)

**본인이 Frontend/시각화 담당이므로, 이 절은 팀 핸드오프 스펙이 된다.**

### 8.1 노드 요약 뷰

**최소 필드**:
- 마스킹된 계좌 ID (예: `ACC***123`)
- 입금 총액, 출금 총액 (기간별: 날짜/주/전체)
- 고유 상대방 수 (in/out)
- 모델 위험 점수 (0~1)
- 커뮤니티 ID (향후 추가)

**제약**:
- Cutoff 이후 거래는 입력하지 않음
- 계좌 식별자는 보안상 마스킹 필수

### 8.2 엣지·거래 뷰

**최소 필드**:
- Timestamp
- From/To 계좌(마스킹)
- 금액, 통화, 결제방식
- 모델 점수 (이 거래가 세탁일 확률)
- 설명 근거 (예: "ACH + 대액 + 급증도" 등)

**제약**:
- 원본 라벨(`Is Laundering`)을 대시보드 표시로 사용 금지 (조사 선입견 야기)
- "의심도(suspicion score)" 표현 일관 사용

### 8.3 부분 그래프 뷰

**기본 설계**:
- 전체 그래프(518K 노드, 4.5M 엣지)는 렌더링 불가 → **Ego-network 중심**
- 선택 노드 → 반경 k(default 2) ego-network 추출 → 타임라인 표시

**필터**:
- 기간 (cutoff 기준시점 고정)
- 은행, 결제방식, 금액 범위
- 최소 거래수 (노드당, default 5)

### 8.4 모델 결과 뷰

**필드**:
- 점수, 모델 버전, cutoff 시점
- 예측 시간
- 불확실성(표준편차 또는 신뢰구간, 추후)

**표현**:
- 색깔·크기로 점수 표현 가능, 하지만 범례에 **"점수 ≠ 범죄 확정"** 명시
- "조사 우선순위" 용어 일관

### 8.5 인수 기준 (플레이북 §5 체크리스트)

- [ ] 동일한 필터·기간·모델 버전으로 같은 부분 그래프 재현 가능
- [ ] 의심 후보 1건에 대해 거래 타임라인과 연결 근거 역추적 가능
- [ ] 필터·집계·모델 점수 모두 cutoff 이후 정보 제외
- [ ] 기본 화면이 전체 그래프를 즉시 렌더링하지 않음 (필터/검색 필수)
- [ ] "모델 점수 ≠ 범죄 확정" 및 불확실성 사용자에게 표시

## 10. 후속 가설 & 모델 준비도 (스타터킷 §7)

### 10.1 검증 가능한 가설들

| ID | 가설 | 예측 단위 | 피처 관찰 창 | 예측 시점 | 비교 기준선 | 분할 | 평가 지표 | 실패 조건 |
|----|-----|---------|------------|---------|-----------|------|----------|---------|
| **H01** | ACH 거래의 고도수(out) 계정이 세탁을 집중시킨다 | 거래(edge) | Train 기간 동안 누적 out-degree | cutoff 기준시점 | B2 (ACH Rule) | 시간 기반 | PR-AUC > 0.15 | PR-AUC < B2 (0.01) |
| **H02** | 계정의 상대방 다양성(diversity)과 세탁은 음의 상관 | 거래 | Train 기간 고유 거래상대방 비율 | cutoff | B3 (금액) | 시간 기반 | Recall@1K > 25% | Recall@1K < 20% |
| **H03** | 24시간 이내 다중 거래(burst)는 이상 신호 | 거래 + 시간창(24h) | 각 거래 전 24h 누적 count | cutoff | B1 (Random) | 시간 기반 | Precision@Top1% > 2% | < 1% |
| **H04** | 엔티티 단위 분석(aggregate)이 계좌 단위보다 신호 강할 것 | 엔티티별 거래(aggregated) | 엔티티 소속 계좌의 누적 활동 | cutoff | Baseline(계좌 level) | 시간 기반 | PR-AUC 개선도 > 5% | < 2% |

### 10.2 모델링 전 필수 체크리스트

- [ ] **목표 단위 확인**: 거래(edge) 이진 분류 vs 계정(node) 위험 점수 선택 필요 (현: edge 고정)
- [ ] **Cutoff 확정**: Train/Val/Test에서 각각의 cutoff 시점 명시 (현: 시간 분할이지만 거래별 cutoff는 미정)
- [ ] **피처 타임링 검증**: 모든 피처가 cutoff **이전** 데이터만 사용하는지 재점검
  - 계정 차수, 상대방 수 → cumsum (누적)만
  - 금액 통계 → rolling window with look-back only
  - 시간 피처(hour, day-of-week) → **절대 미래 정보 혼입 금지**
- [ ] **Leakage 점검**: 
  - Train에서 학습한 scaler/encoder를 Val/Test에 적용하는가? (YES)
  - Test 데이터의 라벨 어떤 식으로든 Train 피처 설계에 영향 없는가? (YES)
  - Message passing(GNN)이 test edge의 미래 이웃 정보 수신하지 않는가? (→ inductive 또는 time-aware GNN 필수)
- [ ] **불균형 대응**: SMOTE vs 언더샘플링 vs 클래스 가중치 결정
- [ ] **기준선과 비교**: 최소한 B2(ACH Rule) 보다는 높아야 의미 있음
- [ ] **성능 저하 계획**: Val에서 좋지만 Test에서 급락 시(concept drift) 대응 방안 사전 정의

1. **합성 데이터**: IBM 시뮬레이션 생성 규칙을 따름 → 실제 금융 패턴과 다를 수 있음
2. **단기 표본**: 18일 데이터 → 계절성, 장기 트렌드 반영 불가
3. **라벨 정의**: "Is Laundering" = 합성 규칙 기반, 실제 범죄 추적과 무관
4. **일반화**: 여기서 찾은 그래프 구조가 다른 은행/지역에 적용되지 않을 수 있음
