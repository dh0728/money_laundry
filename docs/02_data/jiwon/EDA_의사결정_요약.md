# AML 데이터셋 EDA 의사결정 요약 (지원)

대상 데이터: IBM AMLworld (HI-Small / HI-Large)

## 1. 시스템 구조: 2모델 + 그룹핑 엔진

```
거래 → [모델 A] 거래 단위 이진분류(세탁/정상)
     → [그룹핑 엔진] 의심 거래를 패턴 후보 서브그래프로 묶음
     → [모델 B] 서브그래프 단위 패턴 유형 분류(8종)
     → 분석가가 케이스 단위로 최종 판정
```

- 패턴 유형은 거래 한 건이 아니라 **그룹의 속성** → 단일 9-클래스 모델은 부적합.
  (CYCLE의 개별 거래는 단독으로 정상 송금과 구별 불가, 클래스당 양성도 너무 적어짐)
- 학계 벤치마크도 전부 이진 간선 분류로 정의 (IBM NeurIPS 2023 논문 등).
- 그룹핑은 단순 연결요소로 하면 실패 — "세탁업자 허브" 계좌 하나가 최대 32개 블록에
  걸쳐 있어 통째로 뭉침. 모티프별 추출기(스타, 시간순환, 버스트, pass-through 체인)로 접근.
- BIPARTITE는 블록 내 거래들이 계좌를 공유하지 않아 그래프 연결로 묶는 것이 원리적으로
  불가능 → 알려진 한계로 인정, 단독 알림으로 처리.

## 2. 모델 A 방침

- **GBT(XGBoost/LightGBM) + 그래프 피처**로 시작. GNN은 추후 비교 실험용.
  근거: IBM 벤치마크에서 그래프 피처 + GBT ≈ 최신 GNN (소수클래스 F1 ~60%).
  기본 컬럼만 쓰면 F1 24.5%에 불과 → 성능은 모델보다 그래프 피처가 좌우.
- 목표는 "recall 극대화"가 아니라 **알림 예산 제약 하의 recall = 순위 품질**.
  (전부 의심 처리하면 recall 100% — 그게 바로 업계 오탐 95~99% 문제의 원인)
- 지표: PR-AUC, Recall@k, 소수클래스 F1. accuracy는 사용 안 함(양성률 0.1%).
- 피처는 반드시 인과적으로(예측 시점 이전 정보만) 계산.

## 3. 데이터셋 핵심 사실

| 항목 | HI-Small | HI-Large |
|---|---|---|
| 거래 수 | 508만 | 1.8억 |
| 유효 기간 | 9/1~9/10 (10일) | 8/1~11/5 (~96일) |
| 꼬리 아티팩트 | 9/11~18: 거래 붕괴, 세탁률 58~73% | 11월 초 전환, 12월~: 세탁률 60% |
| 세탁 거래 | 5,177건 (0.10%) | 월 4.6만~7.5만 (0.08→0.14% 우상향) |
| 패턴 블록 | 370개 | 16,467개 (유형별 ~2천, 균형) |
| 블록 스팬 중앙값 | 3.1일 (최대 8.4일) | 27일 (최대 70일) |

- 라벨은 두 층: 세탁 5,177건 중 패턴 소속은 3,209건. 나머지 ~38%는 **비패턴 배경 세탁**
  → 그룹핑에서 안 묶이는 게 정상.
- 세탁의 87%가 ACH, 구조적 패턴은 사실상 100% ACH. Wire·Reinvestment는 세탁 0건.
  → Payment Format은 생성기 아티팩트성 강신호(누수 주의). 모델이 구조 대신 이것만
  배우지 않는지 확인 필요.
- 환전 거래(수취≠지급 통화) 7.2만 건 중 세탁 0건, self-loop 59.5만 건 중 세탁 22건.
- **Trans.csv는 시간순 정렬이 아님** (Large에서 확인). 정렬 가정 금지.
- Large의 패턴 활동은 2023/1/12까지인데 Trans.csv는 11/5에서 잘림
  → 후반 블록의 마무리 거래는 Trans.csv에 없음.
- **accounts.csv 조인 함정**: Trans의 은행 ID는 앞에 0이 붙고(`010`) accounts.csv는
  없음(`10`) → 복합키 그대로 조인하면 0% 매칭. 계좌번호는 전역 유일(중복 8/518K)이므로
  **계좌번호 단독 조인** 권장 (매칭률 100%).

## 4. 분할 전략 (확정)

**공통: 꼬리 아티팩트 구간은 항상 제외** (Small: 9/11~, Large: 11/1~).

### 프로토타이핑 — HI-Small
- 피처·그룹핑·모델 개발용. 시간 분할 시 경계 하나가 블록 25~28%를 자르지만,
  간선 단위 이진분류에서 부분 관측 패턴은 오염이 아니라 현실적 난이도 → 허용.

### 모델 A 최종 평가 — HI-Large embargo 분할
```
train : 8/1 ~ 8/31
val   : 9/1 ~ 9/14   (train에서 걸쳐 들어온 3,290블록의 거래는 val에서 purge)
gap   : 9/15 ~ 10/14 (학습·평가 미사용, 피처 히스토리 참조는 허용)
test  : 10/15 ~ 10/31 (train/val→test 다리 571블록의 거래 purge)
```
- 한 달 gap + 다리 purge로 train↔test 패턴 연결 완전 차단.
- train 세탁률 0.077% vs test 0.137%는 램프업에 의한 자연 드리프트 → 보정 안 함.

### 모델 B — HI-Large Patterns.txt
- 16,467블록으로 학습/평가 (Small 370개 대비 44배, 유형 균형).
- 블록끼리 계좌 공유(허브)로 누수 위험 → 블록이 아니라 **계좌 공유 군집 단위** 층화 분할.
- 그룹핑 엔진도 정답 블록 대비 일치도로 정량 평가 가능.

## 5. 계좌 프로파일 분석 결과 (HI-Small, ~9/10)

세탁 연루 5,862계좌 vs 일반 509,208계좌 비교.

| 지표 (중앙값) | 패턴 연루 | 배경 세탁 | 일반 |
|---|---|---|---|
| 총 거래수 | 24 | 20 | 6 |
| 활동일수 (10일 중) | 7 | 7 | 3 |
| 결제수단 종류 | 4 | 4 | 2 |
| 총 유입액 | 10.9만 | 13.4만 | 1.4만 |
| out-deg / in-deg | 3 / 3 | 2 / 3 | 1 / 1 |

- 세탁 계좌는 확실히 "더 바쁘다"(거래 4배, 금액 10배). **그러나 분포가 크게 겹쳐서
  단변량 임계값은 전부 실패**: 어떤 규칙도 정밀도 2~10%대 (예: 총 거래수≥10 →
  recall 69%, 오탐 21.8만 계좌 / in-degree≥12 → 정밀도 10%, recall 4%).
  → 전 기간 집계형 계좌 피처만으로는 부족. 룰 기반 오탐 95% 문제가 그대로 재현됨.
- 4개 지표 중 **in-degree가 최강 신호** (배경 세탁 계좌 in-degree p99=47, fan-in성 집중).
- **엔티티 유형은 판별력 없음** (세 그룹 모두 Partnership/Corp/SoleProp ≈ 3:3:3) → 피처 제외.

**피처 설계 방향** (판별력은 시간 국소성 + 관계성에서):
1. 시간창 피처 — 직전 24h/72h/7d의 in/out 거래수·고유상대수·금액
2. Pass-through — 받은 금액을 Δt 내 그대로 내보내는 비율, 수신→송금 시간차
3. 모티프 피처 (GFP 스타일) — temporal cycle 소속, fan 버스트, gather-scatter 참여
4. 양방향 맥락 — 거래 피처에 송신·수신 계좌 맥락 모두 부착

그룹핑 추출기도 동일 — 전역 degree 임계값 금지, 시간창+금액 조건 필수.
