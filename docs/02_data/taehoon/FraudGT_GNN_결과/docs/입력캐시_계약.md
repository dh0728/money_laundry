# 준비된 V10 입력 캐시 계약

이 학습 구현은 V10에서 이미 생성한 캐시를 읽는다. raw CSV만으로 이 패키지의 `prepare`를 실행할 수는 없다. `prepare`는 원본 피처 생성이 아니라 라벨 독립 시간 split 및 기간별 CSC 생성을 수행한다. 원본 데이터·스케일러·KYC·포트 생성 방식이 달라지면 새 실험이다.

## 기존 프로젝트 연결

`run.py connect --project <V10_project> --labels-root <original_FraudGT/assets>`를 실행하면 아래 위치를 `work/inputs.json`에 기록한다. 파일을 대량 복사하지 않고 외부 경로를 읽으며, 양성 라벨 두 파일은 work/assets에 심볼릭 링크로 연결한다. 명령 실행 후 다음 단계는 새 프로세스에서 실행한다.

| inputs.json key | project 아래 기본 경로 | 사용 |
|---|---|---|
| feature_root | experiments/v10_goal65_20261024/cache/gnn | src/dst/minute/present/z/fmt 및 nodes |
| structural_root | experiments/gnn36_structural_v8/cache/edges | x, present |
| hi_root | experiments/v10_gnn_verify_20261025/cache/hi | 시간순 CSR, paid_z, Test 보충 피처 |
| port_root | experiments/v10_fraudgt_compare_20261026/cache | incoming_ports, outgoing_ports |

다른 저장 구조는 `work/inputs.json`에 위 4개 절대 경로를 직접 지정하고 `work/assets/positive_ids.npy`, `positive_classes.npy`를 배치한다. 경로가 없으면 각각 work/data/features, structural, hi, ports를 사용한다. `inputs.json`은 Git에서 제외한다.

## 배열 정의

- features: src/dst/minute는 int32, shape=(width,). present는 관측 여부, z는 원래 금액 z-score, fmt는 0..6 및 Unknown. minute는 2022-08-01 00:00부터 분 단위다.
- features/nodes/YYYY-MM-DD.npy: shape=(nodes,19), split 종료일 스냅샷. 컬럼은 [feature_manifest](feature_manifest.json) 순서다.
- structural/x.npy: shape=(cached_width,17), structural/present.npy는 같은 길이. 14개 수치 컬럼을 선택하고 paid_currency_z를 hi/paid_z.npy로 교체한다.
- hi/complete.json: nodes, width, rows 필수. 실제 width는 170,467,586이고 관측 거래 수는 170,426,489다. ID의 빈 칸은 present로 제외한다.
- hi/{incoming,outgoing}_time_offsets.npy: int64, nodes+1개. 같은 role의 time_ids.npy는 uint32 거래 ID이며 노드별로 minute 오름차순이어야 한다. CSC C 변환기는 이 계약을 전제로 한다.
- hi/paid_z.npy: width개. structural에 없는 Test 행은 test_edge17.npy와 test_edges_complete.json의 origin을 이용해 보충한다. 원본 구조에서는 Test ID가 단순한 마지막 연속 구간이라고 가정하면 안 된다.
- ports/{incoming,outgoing}_ports.npy: width개. 기존 V10에서 만든 원본 포트 값을 그대로 읽는다.
- assets/positive_ids.npy: 오름차순·중복 없는 관측 거래 ID. positive_classes.npy는 동일 길이, 알려진 양성=1, 무패턴 양성=9. 목록에 없는 관측 거래=정상0.

dtype/shape, CSR offsets, 라벨 ID 순서, 양성 클래스, split 종료일 피처 크기를 검사한다. 대용량 입력 전체를 SHA256으로 읽지는 않으며 shape/dtype/파일 크기/mtime와 sparse label SHA256을 기록한다. 따라서 입력 전체 내용의 암호학적 동일성 검증은 별도다. 이 검사는 잘못된 시간순 정렬이나 피처 생성 의미까지 증명하지 않으므로 검증된 기존 캐시를 사용한다.

## 원본 결과 재현에 필요한 추가 자산

Git에는 대용량 캐시, 스케일러 원본, 개별 거래, 학습 가중치가 없다. 저장된 성능표는 기존 완료 실험의 집계다. 같은 가중치로 검증하려면 provenance에 기록한 체크포인트 해시와 일치하는 best.pt를 별도로 제공하고, 같은 캐시와 라이브러리 환경을 연결해야 한다. 새 학습은 동일 seed라도 하드웨어·라이브러리 차이에 따라 수치가 달라질 수 있다.
