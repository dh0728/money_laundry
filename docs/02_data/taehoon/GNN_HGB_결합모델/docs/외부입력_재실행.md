# 외부 점수 입력과 재실행

ZIP에는 거래 원본·피처 캐시·GNN/HGB 가중치·거래별 전체 점수 배열을 넣지 않았다. 결과 검토와 계수/수식 확인은 ZIP만으로 가능하고, 결합기 재학습은 외부 점수가 필요하다.

## 입력 디렉터리

```text
external_data/
  a3/ 또는 multi/
    fusion_fit/  validation/  test/
      ids.npy          # 정렬 기준 transaction ID
      labels.npy       # 0 정상, 1..8 알려진 사기, 9 무패턴 사기
      hgb_ids.npy      # HGB 점수의 transaction ID
      hgb_logits.npy   # 이미 클래스 보정을 한 HGB 사기 logit
      gnn_ids.npy      # GNN 점수의 transaction ID
      gnn_logits.npy   # GNN raw logit
      metadata.json    # 범위, 보정 상태, 각 파일 SHA-256
```

서로 다른 순서의 점수는 ID로 맞춘다. 중복·누락 ID와 구간 사이 ID 중복은 오류로 처리한다. 단순히 같은 행 번호라고 결합하지 않는다. `labels > 0`이 사기이며 무패턴을 제외하지 않는다.

## 기존 워크스페이스에서 내보내기

```bash
python tools/export_original_scores.py --workspace /path/to/handoff --output /path/to/external_data --model a3
python tools/export_original_scores.py --workspace /path/to/handoff --output /path/to/external_data --model multi
```

이 명령은 기존 완료 점수를 복사하므로 외부 출력 경로에 충분한 공간이 필요하다. 기존 실험과 학습 프로세스는 변경하지 않는다. 새 머신에서는 기존 원본 경로 구조와 점수 파일을 먼저 복원해야 한다.

02/03 노트북의 `EXTERNAL`을 입력 루트로 지정하고 `RUN_EXPERIMENT = True`로 바꾸면 실제 fit → Validation 임계값 고정 → Test가 실행된다. 결과는 `outputs/`의 새 디렉터리에 저장한다. 고정된 결과가 있는 디렉터리에는 재학습을 허용하지 않는다.

원본 거래부터 점수를 생성하려면 `reference_source/`의 score 스크립트와 실제 데이터/가중치가 추가로 필요하다. 원본 SALT와 Multi의 경로·기간·ID 정의·그래프·정규화·readout을 그대로 맞춰야 한다. 원본 plan의 과거 프로세스 중단 상태를 현재 상태로 간주해 강제로 우회하면 안 된다.
