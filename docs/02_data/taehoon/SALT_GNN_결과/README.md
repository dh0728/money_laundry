# SALT-GNN 팀 공유 노트북

2026-11-05 갱신. 원본 데이터에서 전처리·그래프 준비·학습·전체 평가를 수행하는 6개 노트북이다. CUDA 그래프 탐색과 GPU 피처 캐시, 논리 배치 8,192 / GPU 마이크로배치 최대 4,096을 기본으로 적용했다.

| 01 | [원본전처리](01_원본전처리.ipynb) | 거래·계좌·패턴 정리, 거래 입력과 일별 계좌 피처 |

| 03 | [SALT-GNN 모델학습](03_SALT_GNN_모델학습.ipynb) | A3 학습·Val·Test 후 비교 모델 학습·평가 |

| 05 | [전체흐름 스모크테스트](05_전체흐름_스모크테스트.ipynb) | 작은 합성 원본으로 전처리부터 최종 Test까지 확인 |

처음에는 **00 → 05**, 실제 실행은 **01 → 02 → 03**, 결과 조회는 **04** 순서다. 실행 소스는 각 노트북의 `SOURCES` 셀에 들어 있고, 00이 이를 읽어 새 `WORK_DIR`에 생성한다. **6개 ipynb만으로 실행 코드를 복원할 수 있다.** 이 폴더에 남아 있는 예전 보조 Python 파일·캐시 목록·provenance는 새 노트북의 실행에 사용하지 않는다.

## 환경과 실행

- Linux/WSL2, Python 3.12, GCC. CUDA 실행에는 CUDA PyTorch와 NVRTC가 필요하다. 설치 셀은 기본적으로 꺼져 있다.
- 원본: `HI-Large_Trans.csv`, `HI-Large_accounts.csv`, `HI-Large_Patterns.txt`. 00의 `RAW_DIR`를 맞춘다.
- `WORK_DIR`는 원본 밖의 새 폴더로 지정한다. 대규모 캐시 외에 DuckDB·외부 정렬의 임시 디스크 공간도 필요하다.
- 기본 GPU 설정은 기존 V100 32GB 실험에서 가져왔다. 다른 GPU에서는 00의 배치·간선 분할 기준·메모리 비율을 조정하고 02에서 다시 검증한다. 메모리 비율을 낮추는 것만으로 상주 캐시 크기가 줄지는 않는다.
- 기존 가중치를 복사하지 않고 새로 학습한다. 같은 `WORK_DIR` 안에서는 동일 코드·설정·입력에 한해 체크포인트 재개를 지원한다. 기존 실행의 코드가 다르면 새 작업 폴더를 요구한다.
- `START_TRAINING=True`로 시작하면 백그라운드 worker가 전체 순서를 수행한다. 진행률 셀은 3초마다 갱신하며, 기본 5분 표시 후 다시 실행할 수 있다. 표시 중단과 worker 중단은 별도다.
- A3만 평가할 때는 04에서 `EVALUATE_VARIANT="A3"`를 사용한다. A3의 모든 에폭·Monitor가 완료돼야 하며, 실행 중인 worker와 같은 lock을 사용한다.

## Git에 포함할 파일

`.gitignore`는 이 폴더의 **6개 노트북, README, 방법 문서, 작은 검증·측정 JSON**을 포함하도록 설정했다. 원본, 학습 결과, 체크포인트, ZIP, 로컬 경로 설정, 이전 보조 파일은 제외한다. 노트북 출력과 실행 번호는 비워 두었다. `.gitignore`는 이미 추적 중인 파일을 해제하지 않으므로, 기존 저장소에 복사할 때에는 `git status`와 `git ls-files`로 실제 업로드 대상을 확인한다.

원격 저장소로의 commit/push는 이 갱신 작업에 포함하지 않았다. `SALT_GNN_팀공유_단계별노트북.zip`은 같은 노트북과 문서를 담은 전달용 사본이다.
