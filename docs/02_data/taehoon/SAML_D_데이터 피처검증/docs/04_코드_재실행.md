# 코드 구성과 재실행

## 패키지 단독으로 되는 것

4개 노트북은 상대 경로로 원본 결과 CSV/JSON을 읽고 비교표·학습곡선·패턴표를 만든다. 새 학습을 자동으로 실행하지 않는다. `src/saml_evaluation.py`는 외부에서 준비한 전체 거래별 점수가 있을 때 지표와 패턴별 지표를 다시 계산한다.

```text
external_data/saml_scores/
  ids.npy          # 라벨·패턴의 기준 거래 ID, 1차원 정수/고유
  labels.npy       # 이진 사기 라벨 0/1
  patterns.npy     # 고정 폭 Unicode 배열, pickle/object 금지
  score_ids.npy    # logits.npy에 대응하는 고유 거래 ID
  logits.npy       # 정규화/보정 조건이 명시된 최종 raw logit
  metadata.json    # scope='saml_all', model, 각 파일 sha256
```

04 노트북의 `RUN_EXTERNAL_EVALUATION=True`, `EXTERNAL`을 지정한다. 행 수9,504,852, 양성9,873을 확인하고 ID로 정렬한다. Multi단독은 `INCLUSIVE=False`, 결합 모델은 `True`로 설정한다. 주 임계값은 logit0이며 SAML에서 임계값을 탐색하는 함수는 제공하지 않는다. 저장 결과는 새 `outputs/` 경로에 생긴다. 외부 배열은 ZIP에 포함하지 않았다.

## 원본 환경을 복원한 경우의 순서

1. 별도 복제 작업공간에 원래 데이터·캐시·형제 실험 폴더와 패키지를 복원한다. 원본 `/workspace/...` 상수와 환경변수, PyTorch/PyG/CUDA ABI를 확인한다.
2. 공통23종의 `plan.json` 및 코드 manifest는 당시 실행 조건이다. 새 실험 디렉터리에 새 계획과 해시를 기록한다. 완료 마커를 새 학습에 그대로 복사하면 파이프라인이 단계를 건너뛸 수 있다.
3. 공통23종 파이프라인의 원래 순서는 `preflight.py` → `train.py` → `evaluate.py hi_test` → `evaluate.py saml` → `report.py`다. `run_pipeline.py`가 이 순서를 관리한다. 계획·코드·입력 해시가 다르면 먼저 새 실행 조건을 확정해야 한다.
4. 원본 코드의 SALT 중단 상태 검사는 당시 자원 충돌 방지 계약이다. 현재 학습 중인 SALT를 자동 중단하거나 이 검사를 무시하지 않는다. 이 ZIP 검증에서는 원본 학습/추론 코드를 실행하지 않았다.

GPU 피처 조회는 입력값을 그대로 옮기는 최적화이며 결측을 GPU에서 새로 추정하는 과정이 아니다. 284에폭에 맞춰 cosine horizon을284로 줄이면 원래 비교와 다른 실험이 된다. 원본500을 유지한다.

## 무결성

`SOURCE_PROVENANCE.json`은 복사 전 원본 SHA와 출처, `MANIFEST.json`은 실제 배포 파일 SHA다. 문서의 ZIP 밖 파일 링크는 일반 텍스트로 바꾸고 변경 내역을 기록했다. `PACKAGE_CHECK.json`은 CPU 검증·노트북 실행·결과 집계 검증 내역이다. 대용량 추론을 새로 수행해 원본 AP를 재산출한 검증과 혼동하지 않는다.
