이 표는 사후 민감도 분석이다. SAML에서 가장 좋아 보이는 임계값을 새 운영값으로 선택하지 않았다. AP는 임계값과 관계없이 일정하다.

적용 조건과 해석

  • Multi-FraudGT는 epoch 280의 기존 SAML 전체 예측을 해시·거래 ID·정답으로 검증해 재사용했다. 원본의 전체 기간 말 누적 그래프를 유지한다.
  • SALT-GNN A3는 epoch 6, 원래 날짜별 공유 그래프와 CUDA 샘플러(cap 100), microbatch 4,096, score block 8,192를 사용했다. 노드 상태·원본 차수는 해당 날짜 말까지만 집계하고, 차수 정규화 상수는 HI 학습값으로 고정했다.
  • HGB는 기존 36개 입력 열을 이름으로 연결했다. 기존 SAML 전처리의 HI 통계·결측 0·미지원 결제수단 Unknown 매핑을 유지했다. GNN의 계좌 유형/소유 관계 9개 열과 국가 2개 열, HGB의 수취금액/소유관계 관련 열 등은 관측되지 않아 0 대치된 값이다. 실제 0과 결측을 구분하는 새 플래그를 추가하지 않았다.
  • 두 GNN은 그래프 문맥 방식이 다르므로 모델 구조 하나만 바꾼 통제 실험이나 거래 시점의 인과적 탐지 성능으로 해석할 수 없다. SALT도 일 마감 시점의 정보를 사용한다.
  • SAML은 과거에도 평가한 데이터다. Multi의 원래 HI 에폭 선택 구간과 이후 결합 학습·비교 Validation 구간이 겹친다는 기존 제한도 유지된다.
  • 성능 하락의 원인을 이 평가만으로 결측치 하나에 귀속할 수 없다. 입력 가용성, 거래 분포, 패턴, 그래프 문맥 차이를 함께 고려해야 한다.

검증과 파일

전체 거래 ID·정답 정렬, CPU/GPU 샘플 그래프·입력 일치, 모든 노드 차수의 독립 재계산, 결합식 독립 재계산, AP의 별도 구현과 sklearn 일치, 기존 Multi 지표 재현, 원본 모델 보존을 확인했다.
