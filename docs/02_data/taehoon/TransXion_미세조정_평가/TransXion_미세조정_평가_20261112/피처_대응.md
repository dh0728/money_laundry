# TransXion에서 쓸 수 없는 기존 피처와 처리 방법

기존 모델 입력 중 TransXion에 원천 정보가 없어 쓸 수 없는 것은 **계좌 유형 5종, 소유자 묶음 통계, 국가 2종, 결제방식 일부**다. 모두 입력 자리는 그대로 두고 0 또는 Unknown으로 채웠다. 새 피처는 추가하지 않았고, 고정 모델 평가와 TransXion 학습에 같은 처리를 썼다.

아래 수치는 TransXion 전체 3,029,170건·47,526계좌로 실제 만든 피처에서 확인한 값이다.

## 기존 입력 구성

- GNN 계좌 피처 19개, GNN 거래 숫자 피처 14개, 결제방식 원핫 8칸
- HGB 36개 열(거래 이력 4, 분 단위 집중도 2, 송·수신 계좌 통계 각 10, 통화·금액 흐름 10)

## 쓸 수 없는 피처

| 입력 | 해당 피처 | TransXion에 없는 이유 | 처리 | 결과 값 |
| --- | --- | --- | --- | --- |
| GNN 계좌 | `type_Corporation`, `type_Partnership`, `type_Sole Proprietorship`, `type_Country`, `type_Direct` | 법적 계좌 유형 정보가 없다. 상인의 규모·업종은 법적 유형이 아니다 | 상인은 UNKNOWN으로 두어 여섯 칸 모두 0 | 5개 열 전부 0 |
| GNN 계좌 | `type_Individual` | 개인 프로필만 대응 가능 | 개인 46,197계좌는 1, 상인 1,329계좌는 0 | 97.2%가 1 |
| GNN 계좌, HGB | `log_entity_observed_accounts` (HGB는 송·수신 2개 열) | 한 소유자가 계좌를 하나씩만 가진다 | 계산식 그대로 | 모든 계좌가 같은 값(ln 2) |
| GNN 계좌, HGB | `log_entity_out_diversity`, `log_entity_in_diversity` (HGB는 송·수신 4개 열) | 소유자와 계좌가 1:1이라 계좌 단위 통계와 같아진다 | 계산식 그대로 | `log_out_neighbors`, `log_in_neighbors`와 같은 값 |
| GNN 거래 | `same_known_country`, `both_countries_known` | 계좌 소유국 정보가 없다. 통화나 은행 번호로 국가를 추정하지 않았다 | 모든 계좌 국가를 UNKNOWN으로 | 2개 열 전부 0 |
| GNN 거래 | 결제방식 원핫 중 `ACH`, `Bitcoin`, `Cheque`, `Reinvestment` | TransXion 결제방식은 Cash, Card, Transfer, Mobile 넷뿐이다 | 대응하는 거래 없음 | 4칸 전부 0 |
| GNN 거래 | 결제방식 Mobile | 기존 7종에 대응하는 종류가 없다 | Unknown | 901,404건(29.8%)이 Unknown |

## 결제방식 대응

| TransXion | 고정 모델 평가(외부평가 기본 조건) | 미세조정 평가(이 폴더) |
| --- | --- | --- |
| Cash (665,588건) | Cash | Cash |
| Card (792,619건) | Unknown | Credit Card |
| Transfer (669,559건) | Unknown | Wire |
| Mobile (901,404건) | Unknown | Unknown |

- 외부평가 기본 조건은 의미가 확인되지 않은 대응을 하지 않아 78%가 Unknown이었다.
- 미세조정 평가에서는 네 종류가 서로 구분되도록 Card→Credit Card, Transfer→Wire로 넣었다. 이 폴더의 'HI 고정' GNN도 같은 입력으로 채점했다.
- HGB 36개 열에는 결제방식이 없어 이 대응의 영향을 받지 않는다.

## 계산은 되지만 정보가 거의 없는 피처

원천 정보는 있으나 TransXion 분포 때문에 값이 거의 변하지 않는 열이다. 따로 처리하지 않았다.

| 피처 | TransXion에서의 값 |
| --- | --- |
| `paid_outlier_fraction` (HGB는 송·수신 2개 열) | 거의 전부 0 (계좌 평균 0.00002) |
| `same_entity` (GNN 거래) | 0.0013%만 1 |
| `is_self_transfer` | 0.0013%만 1 |
| `pair_count_1h` | 평균 0.001. 같은 쌍의 1시간 내 반복이 드물다 |
| `reverse_history_count` | 평균 0.003. 되돌아오는 거래가 드물다 |
| `src_day_ccy_log_matching_in_amount`, `pair_amount_seen_before_day` | 0이 아닌 값이 0.01% 미만 |

## 그대로 쓸 수 있었던 것

- **통화**: 8개 통화 모두 기존 통화 통계에 대응했다(Yuan 95.6%). 금액 표준화에 기존 HI 통계를 그대로 썼다.
- **금액**: 지불·수취 금액이 따로 있어 둘 다 썼다.
- **시각**: 초 단위를 분 단위로 내렸다. 기존 피처 규약이 분 단위다. 같은 분의 다른 거래는 합치지 않고 모두 유지했다.
- **거래 이력·계좌 활동 피처**: 동일쌍 과거 거래 수, 직전 거래 간격, 1시간 내 거래 수, 계좌별 거래 수·상대 수·활동일 수는 모두 계산했다.

## 모델별 영향 정리

| 모델 | 전체 입력 | 정보가 없는 입력 | 비고 |
| --- | --- | --- | --- |
| GNN 계좌 피처 | 19개 | 8개 (유형 5, 소유자 통계 3) | `type_Individual`은 개인/상인 구분으로만 작동 |
| GNN 거래 숫자 피처 | 14개 | 2개 (국가) | |
| GNN 결제방식 | 8칸 | 4칸 | 나머지 4칸 중 Unknown은 Mobile 전용 |
| HGB | 36개 열 | 6개 (소유자 통계 송·수신 각 3) | 국가·유형·결제방식 열은 원래 없음 |

## 해석할 때 주의

- 0은 결측 표시가 아니다. 예를 들어 상인 계좌의 유형 여섯 칸이 모두 0인 것은 "유형 정보 없음"이지 "해당 유형이 아님"이 확인된 것이 아니다. 결측을 구분하는 별도 표시 열은 추가하지 않았다.
- 상인/개인 구분은 `type_Individual` 한 칸으로만 모델에 들어간다. 상인의 규모·업종은 쓰지 않았다.
- 고정 모델은 HI에서 이 칸들이 채워진 상태로 학습됐다. TransXion으로 학습한 모델은 같은 칸이 상수인 상태로 학습했으므로 그 칸을 사실상 쓰지 않는다.
- 상인이 보낸 거래 안에서 재학습 후에도 세탁과 정상이 구분되지 않는 것(AUC 0.51~0.61)이 이 정보 부족 때문인지는 이번 실험으로 확인하지 못했다.
