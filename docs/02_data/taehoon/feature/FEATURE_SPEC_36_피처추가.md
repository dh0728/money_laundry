# 36개 피처 명세 — ours36_z

입력피처는 **노드 19개 + 거래(엣지) 17개 = 총 36개 피처**입니다.

- 노드: 은행+계좌로 정의. A는 송신 노드, B는 수신 노드, t는 현재 거래 시각.
- L(x)=ln(1+x), G(Δ)=ln(2+Δ). Δ 단위는 분이며 과거 거래가 없으면 간격 피처는 0.
- 노드 행동 통계는 당일을 포함한 최근 30개 달력일 [D−29일,D] 전체 거래로 계산. 초기에는 관측 가능한 기간만 사용합니다. 당일 마감 모델이며 실시간 시점별 피처가 아닙니다. KYC 유형은 계좌 등록정보에서 추출합니다.
- 거래 리듬 피처는 현재 시각보다 최소 1분 이전 이력만 사용. 1시간 창은 [t−60분,t−1분]. 전체 누적 피처는 30일로 제한하지 않습니다.
- paid_currency_z: 통화별 보정 기간의 송금·수취 금액을 합쳐 기준을 적합합니다. s=양수 금액 중앙값, u=ln(1+a/s), m=median(u), q=max(IQR(u),0.001), z=clip((u−m)/q,−8,8). 보정 기간은 2022-08-01~08-07이며 기준을 고정합니다. 미관측 통화는 z=0. 표준편차 기반 z-score가 아닙니다.
- amt_z_pay_ccy: 같은 보정 기간의 **송금액만** `ln(1+paid)`로 변환하고, `payment_currency`별 평균·모표준편차(`stddev_pop`)로 표준화합니다. `clip((ln(1+paid)−μ_c)/(σ_c+1e−6),−10,10)`. 기준은 고정하며, 해당 통화의 평균 또는 표준편차가 유한하지 않으면 0으로 입력합니다.
- 모든 입력 dtype은 float32. 이진 피처도 0.0/1.0으로 입력합니다. 표 순서는 각 입력 텐서의 열 순서입니다. 노드 19개는 송신·수신·이웃 계좌에 같은 스키마를 적용하고 엣지 17개는 문맥 거래와 평가 대상 거래에 같은 스키마를 적용합니다. 추가 피처도 같은 거래 ID에는 같은 값을 사용합니다.

### 명세표의 기존 IG 읽는 법

아래 두 명세표에 **기존에 계산한 IG 순위와 평균 절대 순기여(logit 단위)**를 함께 표시했습니다. 표기 순서는 **패턴 연결 양성 / 패턴 미연결 양성 / 정상**입니다. [기존 TGNN IG 집계](../tgnn40_ig_reference/ig_summary.csv)와 기존 선정 CSV의 수치를 대조했습니다.

- IG는 **기존 40피처 TGNN**에서 계산한 값이며 현재 36피처 재학습 모델의 중요도가 아닙니다. 순위도 당시 35개 설명 단위 기준을 유지합니다.
- 유형 원핫 6열은 하나의 설명 단위입니다. 각 행의 공통 값을 더하거나 개별 피처의 기여로 해석하지 않습니다.
- 기존 IG 표본·계산식·수렴 검사·순열 교란 결과·유지 이유는 문서 뒤쪽에 보존했습니다.

## 추가 금액 피처와 기존 피처의 차이

| 항목 | 기존 `paid_currency_z` | 추가 `amt_z_pay_ccy` |
|---|---|---|
| 적용 열 | 거래 8번째 열 | 거래 17번째 열(마지막) |
| 보정 데이터 | 송금·수취 금액을 각 통화 기준으로 합침 | 송금액만 사용, `payment_currency`별 집계 |
| 보정 기간 | 2022-08-01~08-07 | 2022-08-01~08-07 |
| 금액 변환 | 양수 금액 중앙값 s로 나눈 후 `ln(1+paid/s)` | `ln(1+paid)` |
| 중심·산포 | 변환값의 중앙값·IQR | 변환값의 평균·모표준편차 |
| 분모 보정 | `max(IQR, 0.001)` | `σ + 1e−6` |
| 값 제한 | −8~8 | −10~10 |
| 통화 기준 부재 | 미관측 통화 0 | 평균·표준편차가 유한하지 않으면 0 |

두 피처는 이름만 다른 중복 열이 아니므로 병합하거나 교체하지 않습니다. `σ=0`이더라도 유한한 값이면 `1e−6`을 더한 분모로 계산한 후 제한합니다. 검증·테스트 거래로 평균이나 표준편차를 재적합하지 않습니다. 통화 원핫·원금액 log를 별도 입력 열로 추가한 51/52피처 구성과도 구분합니다.

### 실제 입력 텐서

- `x`: `[노드 수, 19]`. 송신·수신·문맥 이웃 노드에 같은 순서 적용.
- `edge_attr`: `[문맥 거래 수, 17]`.
- `target_attr`: `[분류 대상 거래 수, 17]`.
- 36은 서로 다른 피처 종류의 수입니다. 거래마다 송신·수신 노드 역할이 반복된다고 19개 노드 피처를 두 번 세지 않습니다.
- 실제 입력 차원을 줄여 재학습한 모델이며, 예전 40입력 모델에 상수 열을 복원하는 방식이 아닙니다. 모든 값은 `float32`입니다.

| 무엇과 비교하나요? | 거래마다 정상 거래 참조 16개를 사용했습니다. 대상 거래·송수신 노드는 참조 거래의 값으로, 이웃 노드·문맥 거래는 해당 날짜의 표본 값으로 기준을 구성했습니다. 연결 구조는 고정하므로 완전한 실제 정상 그래프와 비교하는 것은 아닙니다. |
| IG가 양수이면? | 그 입력·참조 조합에서 해당 피처의 기여가 설명 대상 logit을 올리는 방향입니다. 모든 거래에서 그 피처의 값이 클수록 위험하다는 뜻은 아닙니다. |
| IG가 음수이면? | 기준 입력에 비해 logit을 낮추는 방향의 기여입니다. 실제 부정확한 예측을 낮출 때 유용할 수 있지만, 음수라는 사실만으로 정상 탐지 효과가 검증되는 것은 아닙니다. |
| 표의 순위는 무엇인가요? | 16개 참조의 기여를 평균하고, 같은 피처의 노드/엣지 경로 기여를 **부호를 유지해 합산한 뒤 절댓값**을 취해 거래 집단 내 평균을 냈습니다. 이 값이 큰 순서입니다. 경로·참조 사이 상쇄가 있을 수 있습니다. |
| 순위가 낮으면 삭제해도 되나요? | 아닙니다. 특정 집단이나 날짜에서 유용할 수 있어 순열 교란과 여러 피처의 동시 상수화 검사를 함께 봤습니다. |
| 왜 IG와 AP 손실을 같이 보나요? | IG는 **현재 예측의 설명 기여**, 순열 교란은 **정보를 흐트러뜨렸을 때 평가 성능 변화**입니다. 서로 다른 질문을 측정하므로 순위가 같을 필요가 없습니다. |

계산식: `IG_i(x; b) = (x_i − b_i) × ∫₀¹ ∂F(b + α(x − b))/∂x_i dα`.
`x`는 실제 입력, `b`는 기준 입력, `F`는 모델 출력입니다. 충분히 정확하게 적분하면 기여의 합은 `F(x) − F(b)`와 일치하며, 수치 근사 잔차로 계산 정확도를 확인합니다. [Captum 완전성·수렴 설명](https://captum.ai/docs/extension/integrated_gradients)
