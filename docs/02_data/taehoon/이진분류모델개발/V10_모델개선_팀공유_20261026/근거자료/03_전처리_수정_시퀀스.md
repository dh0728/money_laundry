**Claude 시퀀스: 수치 재현**

검증 대상은 `frozen.json`에 10:11:49 UTC에 고정된 `three_peer7_seq_sequnm_l31`이다. 이후 동시에 실행 중인 propagation·과거 라벨·focal 실험은 이 수치에 포함하지 않았다. 기존 모델·임계값을 유지하고 기존 테스트 33,428,088건을 전수 재집계했다.

| 모델 | Precision | 전체 Recall | 무패턴 Recall | TP | FP | 무패턴 TP |
|---|---:|---:|---:|---:|---:|---:|
| 기존 Codex 결합기 | 71.21% | 60.00% | 9.94% | 25,611 | 10,355 | 1,810 |
| Claude 시퀀스 결합기 | 76.25% | 60.01% | 9.01% | 25,615 | 7,978 | 1,641 |

시퀀스 결합 후 전체 TP는 4건 증가, FP는 2,377건 감소했지만 무패턴 TP는 169건 감소했다. **오탐 감소는 확인되지만 무패턴 탐지 개선이라는 목표는 달성하지 못했다.**

저장 이벤트 170,420,349건의 ID와 분 시각을 원본과 전수 대조했다. 빠진 거래는 구조 필터의 6,140건과 정확히 같았고 추가 누락은 없었다. 따라서 현재 캐시에는 Parquet row-group 중단 조건에 따른 추가 누락이 없었다.

검증 96건·테스트 96건을 독립 CPU 추론했다. 검증 입력은 저장 캐시와 비트 단위로 일치했고, 두 모델 로짓의 CPU/GPU 최대 차이는 0.000002862였다. 테스트 결합 점수 96건은 저장 점수와 정확히 같았다. 전체 테스트의 TP·FP·Recall·Precision도 원 보고와 일치했다. AP 근사값과 부트스트랩 신뢰구간은 이번 재현 범위에 포함하지 않았다.

**시퀀스 모델의 한계**

- 시간 인덱스는 과거 분만 사용한다. 그러나 **문맥에서 정답 패턴 정보를 이용해 6,140건을 제외**했고, 결합 입력의 **V10 점수와 계좌 피처는 구간 종료 문맥**을 사용했다. 시퀀스의 시간순서가 맞는 것만으로 전체 모델의 누수가 해소되지는 않는다.
- 대상과 같은 분의 거래는 시퀀스에서 전부 제외한다. 하루 마감 운영에서 사용할 수 있는 정보지만 현재 구조는 활용하지 않는다.
- 최근 32개는 고유 거래 32건이 아니라 입출금 역할 이벤트 32개다. 자기계좌 거래는 두 칸을 차지한다. 검사한 384개 계좌 측 시퀀스 중 158개에서 중복 역할이 있었고 45개는 32개 경계에서 과거 동일 분 묶음이 잘렸다.
- 수취 측 환전 거래도 지급액·지급통화 기준으로 표현한다. 이것은 직접 누수는 아니지만 실제 수취 흐름의 구분력을 제한할 수 있다. 영향 크기는 추가 실험이 필요하다.
- 결합기 입력은 10열(V10 점수 1 + 기존 피처 7 + 시퀀스 점수 2)이다. 토큰 수치 8개·대상 수치 5개·결제방식 임베딩을 가진 두 Transformer를 사용하므로 전체 모델이 단순히 피처 10개만 쓰는 것은 아니다.

복원 문맥과 새 정규화를 사용하는 `sequence_input.py`도 구현했다. 기존 정책을 넣은 독립 구현은 24건에서 Claude 입력과 비트 단위로 같았고, 복원 양성 6건도 두 모델의 CPU 추론을 통과했다. 라벨 변경·미래 원천 제거 불변성도 통과했다. 호환 검증을 위해 32개 역할·이전 분이라는 기존 의미는 유지했다. 이 입력 경로는 전체 재학습용 대량 캐시 생성과 처리량 검증을 아직 거치지 않았다.

**평가 방식 추가 확인**

검증 정상 250,000건의 선택을 원래 난수 시드로 재현했다. **검증 정상 표본은 무작위 추출이며 클러스터 표본이 아니다.** 따라서 검증·테스트 Precision 차이를 “클러스터 가중치가 정밀도를 낮게 추정해서”라고 단정할 근거는 없다. 고정된 late-val 임계값과 지표도 재현했다. 해당 임계값의 late-val 정상 오탐 표본은 39건이다.

기존 시퀀스 결합기의 마지막 피어 로그 2열은 검증에서 float64, 테스트에서 float32였다. 검증 전체를 float32로 맞추는 대조에서 점수 변경 0건, 고정 임계값 판정 변경 0건, 최대 점수 차이 0였다. 기존 첫 테스트의 float64 오류 기록은 삭제하지 않았다. 새 경로는 처음부터 float32로 통일하며 새 결합기는 같은 입력 계약으로 다시 학습해야 한다.

시퀀스 에폭은 검증 앞부분, 결합 후보·임계값은 뒷부분에서 골랐지만 상위 V10 epoch15 자체는 전체 validation AP로 선택됐다. 따라서 전체 결합 파이프라인 관점에서 뒷부분이 완전히 독립적인 선택 구간은 아니다. 과거 테스트도 여러 실험에 사용됐으므로 새로운 독립 홀드아웃으로 표현하지 않는다.

별도 진행 중인 `10_pastlabel.py`는 과거 정답을 7일 뒤 확인할 수 있다고 가정한다. 현재 검증한 고정 시퀀스 후보에는 이 피처가 없다. 후속 모델에 넣으려면 실제 확정 시각과 운영 제공 여부를 확인해야 하며, 단순히 7일을 빼는 것으로 정답누수 검증을 통과한 것은 아니다.
