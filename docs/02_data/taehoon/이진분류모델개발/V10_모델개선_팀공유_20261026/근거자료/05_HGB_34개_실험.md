## 실험 범위와 해석

이번 재학습 후보는 V10의 기존 거래·계좌 피처와 새 당일 흐름 피처를 사용하는 HistGradientBoosting 모델이다. **V10 GNN 가중치를 재학습한 결과는 아니다.** 정상/패턴 양성/무패턴 양성을 나누어 학습한 후보도 최종 출력은 두 양성 확률을 합한 이진 판정이다. 다른 팀원의 8패턴 모델은 변경하지 않았다.
기존 모델은 구조 필터로 일부 양성을 제거하고, 일부 문맥을 기간 말까지 사용한 입력이었다. 아래 기존 수치의 재현은 그 입력에서의 계산을 재확인한 것이며, 수정된 하루 종료 판정 성능을 인증하지 않는다.
Oct14..31은 이전 실험에서도 사용한 역사 테스트다. 새 독립 홀드아웃으로 주장하지 않는다. Oct31 이후 데이터는 이번 개발·평가에 사용하지 않았다.

## 3. 전체 검증과 동결 테스트

전체 검증 모집단에서 선택한 임계값: `-2.164954712998408`. 검증 Precision 70.11%, Recall 63.01%.
같은 후보의 임계값을 검증 Recall 65% 이상으로만 낮추면 Precision은 56.12%가 된다. 이 값은 검증 진단이며 테스트 임계값으로 사용하지 않았다.
전체 역사 테스트: TP 27885, FP 14036; 패턴 Recall 99.33%, 무패턴 Recall 11.88%.
기존 모델과 동일한 거래 33,428,088건만 비교하면, 새 후보의 Precision 65.35%, Recall 62.01%이다. 복원된 양성 1,419건의 효과와 모델 자체의 차이를 구분하기 위한 수치다.
전체 검증은 `12_full_validation_results.json`, 모델/임계값 동결은 `12_frozen_candidate.json`, 테스트 날짜별 결과는 `13_historical_test_results.json`에 저장했다.

피처 최소화 요청을 반영해, 목표를 충족하는 후보가 없을 때는 최고 검증 Recall과 0.1%p 이내인 후보 중 피처 종류가 가장 적은 것을 선택했다. 이 규칙은 실용적 선택 기준이며 통계적 동등성을 입증했다는 뜻이 아니다. 실제로 25종 모델은 56종 결합 모델보다 검증 TP가 단 1건 적었다. 최종 선택 규칙과 변경 전 기록은 `12_final_selection_policy.json`, `12_before_feature_preference.json`에 보존했다.
선택 규칙을 최종 정리할 때 첫 테스트 실행을 중단했으며, 당시 저장된 신규 테스트 점수 파일은 0개였다. 테스트 결과를 확인해 모델을 바꾼 것이 아니며, 이후 재개한 전체 평가는 동결한 25종 모델만 사용했다. 이 중단·재실행도 events.jsonl에 남겼다.

전체 검증에서 목표 미달을 확인한 뒤, 테스트 점수를 계산하기 전에 정상 표본 확대와 혼동 정상 거래 추가 실험을 수행했다. 첫 검증 결과는 `12_round1_*`에 보존했고 최종 후보는 그 후 다시 검증에서만 선택했다. 모든 최종 테스트에는 이 최종 동결 모델·임계값을 사용했다.

## 4. 새 피처와 누수 검증

최종 후보가 실제 사용하는 모든 피처와 새 피처만의 목록은 `14_selected_feature_manifest.json`에 저장했다. 아래는 시험한 후보 피처이며 모두 최종 채택됐다는 뜻은 아니다.
최종 구성: 기존 피처 19종 + 새 피처 6종. 채택된 새 종류: `day_ccy_flow_balance`, `day_ccy_log_matching_in_amount`, `day_ccy_rate_vs_prior`, `pair_amount_seen_before_day`, `prior_ccy_amount_seen`, `prior_ccy_amount_vs_mean`.
최종 후보의 모델 입력에 KYC 의존 여부: **있음 — 과거 가용 시점 검증 제한이 남음**.
추가 후보 9종(양 끝 계좌에 적용하면 18열): 통화별 당일 입금 수, 출금 수, 입금 상대 수, 출금 상대 수, 거래액/평균 입금액 비율, 거래액/평균 출금액 비율, 입출금 총액 균형, 동일 금액 입금 반복 수, 동일 금액 출금 반복 수. 수/비율은 계약에 정의한 log1p 변환을 사용하며 균형은 0..1이다.
후속 추가 후보 6종(11열): 계좌·통화·방향별 과거 거래 수, 과거 동일 금액 존재 여부, 과거 log 금액 평균·표준편차 대비 편차, 과거 평균 금액 대비 비율, 당일 거래 수와 과거 일평균 거래 수의 차이, 송수신 쌍·통화·금액의 과거 존재 여부. 과거 집계는 판정일 전날까지이고, 빈도 비교의 당일 거래 수만 당일 전체를 사용한다.
- 문맥에서 y·패턴 종류·구조 적합성 필터를 제외했다. 라벨은 학습 정답과 평가에만 사용했다.
- 판정일 하루 전체를 허용하고 다음 날짜 거래는 제외했다. 기존 19개 계좌 피처는 각 날짜 누적으로 새로 만들었다.
- 당일 흐름은 같은 통화 안에서만 계산한다. 입금은 received/receiving currency, 출금은 paid/payment currency를 사용한다.
- 같은 분 거래를 전부 포함한다. 기존 minute peer 집계는 정의대로 self 거래를 제외하고, 새 흐름 집계는 self 거래의 입금·출금을 각각 한 번 반영한다.
- 일별 계좌 19개 피처는 7개 날짜/50개 계좌에서 독립 SQL과 최대 오차 0이었다. 새 흐름 9개 피처는 32개 endpoint 사례에서 원본 DECIMAL 금액 SQL 집계와 일치했다.
- 전체 검증 입력은 표본 입력과 모든 열을 대조했다. 신규 모델에는 과거 V10의 미래 문맥 점수를 입력하지 않았다.
- **KYC의 과거 이용 가능 시점은 원본에 이력이 없어 검증 불가**다. KYC가 필요한 모델에는 이 제한이 남으며, KYC를 제거한 29종/38종 및 흐름 10종 모델도 비교했다.
- 과거 금액 이력은 원본의 day < 판정일 조건으로 독립 재계산했다. 원본 DECIMAL 금액과 float64의 동일 금액 판정이 달라지지 않는 수치 범위도 확인했다. `17_amount_history_verification.json`을 참조한다.
- 증거: `03_control_input_verification.json`, `06_daily_input_verification.json`, `09_dayflow_verification.json`, `11_full_validation_complete.json`, `17_amount_history_verification.json`.

정상/무패턴 차이는 `10a_정상_무패턴_피처차이.csv`에 피처별로 기록했다. Sep26..Oct4 검증 표본에서 해당 송수신 쌍의 이전 거래가 없는 비율은 정상 약 2.22%, 무패턴 약 29.42%였다. 송신 계좌의 같은 통화 당일 입금이 없는 비율은 정상 약 29.05%, 무패턴 약 66.90%였다. 두 집단에 차이는 있지만 정상에도 해당 조건이 상당히 존재하므로 이 조건만으로 분류 성능을 보장하지 않는다. 단변량 AUC는 운영 Precision/Recall과 다른 분석 지표다. 거래 방식 코드는 순서가 없는 범주로 취급했다.

과거에 없던 송신 금액인 비율은 같은 검증 구간에서 정상 10.72%, 무패턴 72.90%였다. ACH 방식끼리 비교해도 정상 19.79%, 무패턴 100%로 차이가 있었다. 이는 이 구간의 표본 기술 통계이며 완전한 분리나 일반적 법칙을 뜻하지 않는다. 근거는 `16_amount_novelty_descriptive.json`, `16_amount_novelty_matched_formats.json`이다.
