# V10 무패턴 개선 실험 결과 — 2026-10-23

**목표 달성: 테스트 전체 33,428,088건에서 Precision 71.21%, Recall 60.00%.**
목표는 전체 이진분류 Precision ≥70%, Recall ≥60%의 동시 달성이다. 피처 수를 줄이는 조건도 적용했다.
최종 수치는 정상 표본에 가중치를 준 추정치가 아니라, 테스트 기간 전체 정상·패턴·무패턴 거래의 직접 집계다. 모델과 임계값은 테스트 전에 고정했다.

## 1. 최종 고정 평가

| 모델 | Precision | 전체 Recall | 패턴 Recall | 무패턴 Recall | 정상 FPR | TP | FP |
|---|---|---|---|---|---|---|---|
| 기준 V10 | 70.17% | 56.69% | 97.22% | 2.21% | 0.03081% | 24,198 | 10,286 |
| 선택 후보 | 71.21% | 60.00% | 97.24% | 9.94% | 0.03102% | 25,611 | 10,355 |

- 전체 Recall 차이: +3.31%p. 무패턴 탐지: 402 → 1,810건.
- 정확한 Recall: 60.001406%. Precision 목표까지 차이: +1.2089%p. Recall 목표까지 차이: +0.001406%p.
- Recall의 목표 대비 여유는 매우 작다. 이 기간에서 기준을 통과했다는 결과이며, 다른 기간에서도60% 이상이 유지된다는 보장은 아니다.
- 선택 모델: `three_peer7`. 고정 점수 임계값: `-2.06161937874723`. 이 값은 확률 70%를 뜻하지 않는다.
- 기준 V10도 선택 검증 구간에서 Precision ≥70%를 만족하도록 정한 임계값을 테스트에 그대로 적용했다. 기존 F1 임계값과 혼용하지 않았다.
- 이번 기준은 구조 정제 후 V10(epoch15)이다. 원본 V10(epoch10)과 가중치·알려진 패턴 대상 수가 다르다. 두 모델의 해시는 `재현코드/00_audit.json`에 있다.

## 2. 피처 수와 모델 구조

결합기는 V10 점수 1개와 피처 7개를 입력받는다. 이 중 기존 V10에 없던 추가 피처는 5개다. V10 본체는 기존 노드19·엣지17 피처(고유 유형36개, 중심 엣지와 양 끝 계좌를 펼치면55개)를 그대로 사용한다. 전체 GNN이 7개 피처만 쓰는 모델이라는 뜻은 아니다.

| 결합기 피처 | 의미 |
|---|---|
| payment_format | 결제방식: 학습에서 정한 범주 인코딩 |
| src_log_entity_observed_accounts | 송신 계좌 소유주의 관측된 계좌 수(log1p), 기존 V10 노드 피처 |
| minute_receiver_vs_prior_hour | 현재 분 외부 입금 건수의 분당 집중도 ÷ 과거1시간 입금 수준을 로그 차이로 표현 |
| minute_sender_vs_prior_hour | 현재 분 외부 출금 건수의 분당 집중도 ÷ 과거1시간 출금 수준을 로그 차이로 표현 |
| receiver_gap_minutes | 수신 계좌의 직전 거래 간격, 기존 V10 엣지 피처 |
| minute_log_src_out_peers | 송신 계좌가 같은 분에 송금한 고유 외부 상대 수(log1p) |
| minute_log_dst_in_peers | 수신 계좌가 같은 분에 입금받은 고유 외부 상대 수(log1p) |

정상·패턴·무패턴 3클래스를 예측한 뒤, 클래스 가중치를 보정한 패턴·무패턴 점수를 합쳐 이진 점수로 사용한다. 실제 추론에는 정답 라벨이나 패턴 여부를 입력하지 않는다.
V10 학습 기간은 08-01~09-25다. 결합기만 09-26~10-04 라벨로 추가 학습했고, 후보·임계값 선택은 분리한 10-05~10-13에서 수행했다. 테스트는 10-14~10-31이다.
동일 분 피처는 분 마감 후 계산해야 한다. 기존 GNN의 구간 종료 누적 문맥은 유지했으므로 엄격한 실시간 시점 평가가 아니다.

## 3. 실행 순서와 결과

### 00 — 기준 성능과 데이터 감사

전체 검증에서 기준 V10은 Precision70.01%, Recall57.23%였다. 최종 선택에 사용한 검증 뒷부분만의 동일 비교에서는 Precision 70.20%, Recall 57.02%다.
평가에서 정상은 원래 모집단을 복원하는 가중치를 사용하고, 모든 양성의 평가 가중치는1이다. 원본 전체의 패턴61%/무패턴39%를 정제·날짜분할 이후 각 집합에 그대로 적용하지 않았다.

### 01 — 유사 정상·무패턴 짝 비교

학습 무패턴46,617건에 대해 결제방식·통화·주차를 맞추고, 로그 금액·송신/수신 활동량으로 최대5개의 최근접 정상을 찾았다. 동일 계좌 비교와 모델 점수까지 맞춘 비교도 수행했다.

| 비교 | 비교 가능한 무패턴 비율 | 거래 쌍 수 |
|---|---|---|
| attributes | 99.81% | 232,068 |
| same_sender | 32.04% | 70,487 |
| score_near | 98.88% | 224,991 |

- 조건을 맞춘 미탐 거래에서는 소유주의 긴 거래 공백·낮은 최근 거래량 차이가 남았다. 거래 공백이 유사 정상보다 큰 비율은 학습 앞부분63.5%, 뒷부분62.5%였다. 이는 짝 비교 비율이며 배포 성능이나 ROC-AUC가 아니다.
- 모델 점수까지 비슷하게 맞추면 대다수 잔여 차이는 작아졌다. 같은 송신 계좌 비교는32.0%만 지원하므로 전체 무패턴에 일반화하지 않는다.
- 거래별 예시는 `01_*_거래쌍_예시.csv`, 전체 거래 쌍은 원본 실험 폴더의 `01_*_pairs.parquet`에 있다.

### 02 — 소수 피처 이진모델

트리 학습 조건을 맞추고 피처를 순차적으로 추가했다. 아래 지표는 정상·무패턴 전용 평가다. 전체 이진분류 목표와 구분한다.

| 전용 모델 | 피처 수 | 무패턴 Recall @FPR0.15% |
|---|---|---|
| unmatched8 | 8 | 22.59% |
| unmatched11 | 11 | 22.78% |
| unmatched13 | 13 | 27.42% |
| unmatched16_peer | 16 | 27.31% |

- 13개 피처 모델27.42%는 기존258개 피처 1단계 모델28.06%에 가까웠다. 완전히 같은 모델 크기·학습 설정 비교는 아니므로 피처 축소의 참고 기준이다.
- 조건별 상대값3개를 더한16개 모델은27.31%로 개선되지 않았다.

### 03 — 클러스터와 단순 무작위 추출 비교

정상1,024,066건과 양성 대상 수, 모델 설정, 입력 피처13개를 고정했다. 정상 추출 방식과 그에 맞는 포함확률 가중치만 바꿨다. 새 정상 피처는 기존 표본과 겹치는 거래에서 일치 검증했다.

| 학습 목적 | 클러스터 무패턴 Recall @FPR0.15% | 무작위 무패턴 Recall @FPR0.15% |

| 전체 양성 | 23.19% | 23.89% |

무작위 추출로 일관된 개선은 없었다. 단일 시드의 작은 피처 모델 비교이며, 클러스터 방식의 모든 영향이나 GNN 이웃 샘플링을 배제하는 증명은 아니다.

## 4. 해석과 남은 문제

- 무패턴·정상 전용 학습, 유사 거래 비교, 신규 피처, 정상 샘플링 대조, V10 결합, 피처 축소를 순서대로 수행했다.
- 소수의 동일 분 거래 집중도·상대 수를 V10 점수와 함께 사용하는 후보가 개선 방향을 보였다. 소유주 피처와 상대값을 계속 추가하는 방식은 성능 향상으로 이어지지 않았다.
- 이전 `matched_v10_known_only_20261012`는 정답 라벨로 무패턴을 학습 대상과 주변 그래프 양쪽에서 제거했다. 그 높은 성능은 전체 거래에서 바로 재현할 수 있는 비교 기준이 아니다. 이번 결합기는 무패턴 여부로 그래프를 제거하지 않았다.
- 고정된 전체 테스트에서 목표 수치를 충족했다. 새로운 독립 기간에서의 재현은 별도 과제다.
- 과거에 이미 분석한 테스트 기간이다. 결과는 이번 실행에서 고정 후 확인했지만, 새로운 독립 홀드아웃 검증으로 표현하지 않는다.
- 기존 구간 종료 그래프·노드 피처는 실시간 인과적 피처가 아니다. 새 피처는 분 마감 후 사용 가능하지만 V10 전체의 온라인 적합성을 이번에 입증한 것은 아니다.

- `candidate_model.joblib`: 검증에서 선택하고 테스트 전에 고정한 결합기. 목표 충족 여부는 최종평가.json 참조.
