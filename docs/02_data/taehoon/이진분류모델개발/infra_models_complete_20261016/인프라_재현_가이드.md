# 인프라 실행·재현 가이드

이 폴더 전체를 전달하세요. `.pt`만으로는 구조, 피처 순서, 보정값, 그래프 방향, 출력 보정이 복원되지 않습니다. 기존 무패턴 포함 학습 v10/v8 패키지이며, 진행 중인 구조 정제 재학습 결과는 아직 이 패키지에 반영하지 않았습니다.

## 구성

| 폴더/파일 | 역할 |
|---|---|
| 01_binary_v10/ | v10 이진모델 독립 실행 폴더 |
| 02_pattern_v8/ | v8 패턴모델 독립 실행 폴더 |
| 각 폴더의 00_weights_only.ipynb | 가중치 로딩과 전처리된 NPZ 입력 직접 추론 코드 |
| 각 폴더 이름의 ipynb | raw 입력 → 검증 → 피처 → 그래프 → 모델 → JSON 전체 코드 |
| assets/feature_schema.json | 순서가 고정된 피처/클래스 목록 |
| assets/feature_dictionary.json | 피처 의미 |
| assets/tensor_contract.json | GPU 전달 텐서 순서·dtype·shape |
| assets/*stats.parquet 및 CSV | 동결된 두 종류 금액 보정값과 사람이 볼 수 있는 사본 |
| examples/transactions.parquet, kyc.parquet | 합성 원본 테스트 입력 |
| examples/reference_*.npz와 JSON | 원본 모델 예측을 재현하는 전처리 그래프 2건 및 기대값 |
| tests/expected_reference_outputs.json | 기준 그래프의 모델별 기대 점수·판정·패턴 |
| tests/expected_raw_predictions.json | 합성 원본 입력을 전체 처리했을 때 18건 기대 JSON 응답 |

| manifest.json | 전달 파일 무결성 확인용 SHA-256 |

## 설치와 실행

Python 3.12 환경에서 각 모델 폴더를 작업 디렉터리로 사용합니다. 검증 환경은 PyTorch 2.10.0+cu126, CUDA runtime 12.6, Tesla V100-SXM2-32GB, NVIDIA 드라이버 580.126.20입니다. nvidia-smi의 CUDA 13.0 표시는 드라이버가 지원하는 버전이며 PyTorch runtime 12.6과 구분합니다.

```bash
python -m pip install -r requirements-cuda126.txt
python -m jupyterlab
```

requirements-cuda126.txt는 검증 환경에 맞춘 설치 명세입니다. 이 세션에서 새 환경 pip 설치까지 재검증하지는 않았습니다. CPU 실행은 환경에 맞는 CPU torch wheel과 requirements.txt를 사용합니다. 전체 정확한 버전은 environment.json과 requirements 파일에 있습니다.

GPU 실행: settings.json의 device를 `cuda`로 바꾼 뒤 노트북 전체 실행. CPU 실행은 `cpu`. 환경변수 AML_DEVICE가 있으면 settings보다 우선합니다. CUDA가 없는데 cuda로 설정하면 명시적으로 실패하며 CPU로 몰래 전환하지 않습니다.

가장 빠른 확인은 00_weights_only.ipynb입니다. 모델 구조를 선언하고 체크섬 검증 → weights_only=True 로딩 → strict state_dict 로딩 → eval/no_grad → 기준 그래프 추론을 수행합니다. 모델 아키텍처 코드는 노트북 안에 있으며 별도 프로젝트 소스가 필요 없습니다.

## 전처리부터 실행할 때

전체 노트북을 실행하면 합성 거래 81건에서 정확 중복을 제거한 80건 문맥으로 대상 18건을 예측합니다. 출력은 outputs/demo/predictions.jsonl입니다. tests/expected_raw_predictions.json과 대조하는 셀이 포함돼 있습니다. 실제 데이터를 공급할 때 settings.json의 입력 경로·기간·output_dir을 변경하세요. output_dir은 새 경로를 사용합니다. 보정 통계는 재계산하지 않습니다.

입력 테이블 필수 컬럼:

- transactions: edge_id, ts, src, dst, paid, received, payment_currency, receiving_currency, payment_format, duplicate_group_id.
- kyc: node_id, entity_id, entity_type, country.

정수 ID, timestamp, 중복 대표 ID와 KYC 검증은 노트북에 구현되어 있습니다. 거래 한 건만 전달하면 과거 거래 이력과 누적 노드 피처를 복원할 수 없습니다. 계좌 ID 매핑·원천 시간대·중복 대표 ID는 적재 단계에서 일관되게 공급해야 합니다. 전처리 상세는 [피처_순서_전처리.md](피처_순서_전처리.md)를 참고하세요.

## 기준 그래프 기대 출력

| 그래프 | v10 위험 점수 | v10 알림 | v8 보조 위험 점수 | v8 패턴 |
|---|---:|---|---:|---|
| reference_known | 0.7999657393 | true | 0.9818789363 | CYCLE |
| reference_unmatched | 0.0200011879 | false | 0.0067532081 | NORMAL |

모든 9클래스 확률은 tests/expected_reference_outputs.json에 있습니다. 점수/확률 절대 오차 2e-5, 상대 오차 0을 검증 기준으로 사용합니다. 위험 점수의 실제 측정 오차는 validation.json에 기록합니다. 패턴 확률도 동일 허용 오차로 검증합니다. fixture 2건은 모델 성능 평가가 아니라 코드·가중치 재현성 검사입니다. NPZ는 전처리가 끝난 입력이므로 raw→피처 검증은 별도의 합성 원본 입력 테스트로 확인합니다.

## 운영 연결 범위

두 모델 모두 TransformerConv 기반 2층·2홉·ego·양방향 모델입니다. 모델 인스턴스는 프로세스 시작 시 한 번 로드하고 반복 사용합니다. 그래프 문맥과 피처는 CPU에서 만들고 GPU에는 tensor만 전달합니다. 서버 API/인증/큐/DB 적재는 별도 연결 대상입니다. 이번 검증은 기능·수치 재현이며 대규모 동시 요청 처리량 검증이 아닙니다.

이진 알림은 v10, 패턴 이름은 v8 출력으로 구분합니다. v8 NORMAL에는 무패턴 자금세탁이 포함됩니다. 클래스 head를 이진 정상/이상 판정으로 대체하지 마세요. 현재 그래프 정의는 기준일 전체 누적 스냅샷이며 실시간 거래 직전 문맥으로 바꾸면 별도 성능 평가가 필요합니다.

출력 클래스 번호 상세: [출력_클래스_명세.md](출력_클래스_명세.md).

## 피처 설명·전처리 전용 실행 노트북

각 모델 폴더의 `입력피처_의미_순서_전처리.ipynb`에 의미·순서·수식 문서와 실제 전처리 코드가 함께 있습니다. 원본 예제에서 피처를 생성하고 일부 수식을 독립 대조한 뒤 GPU 전달 텐서의 형상과 자료형까지 확인합니다.
