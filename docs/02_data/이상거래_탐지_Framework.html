Team Project · Architecture Note

이상거래 탐지 → 연결계좌 분석 서비스

거래 단위 1차 분류(GBT)와 그래프 기반 2차 네트워크 분석을 잇는 2단계 파이프라인 제안. IBM AML 논문의 GBT / GNN 재현 결과를 부품으로 재사용하되, 논문의 단일 엣지분류 과제와는 목표가 다름을 전제로 한다.

작성일 2026-08-10 대상 내일 팀 회의 기반 실험 ibm-aml / HANDOFF.md
01

전체 흐름도

신규 거래가 들어온 순간부터 “연결된 계좌 그룹”이 리포트로 나가기까지의 경로. 굵은 경로가 최소 요건, 점선 경로는 리소스가 허락할 때 얹는 보강 단계다.

논문과 다른 지점. 논문/Multi-GNN 재현은 완성된 그래프 위에서 “이 엣지가 세탁인가”를 묻는 단일 엣지분류 과제다. 우리 서비스는 “거래 단위 실시간 판정”과 “연결된 계좌 그룹 탐색”이라는 두 개의 다른 과제가 순차로 연결된 구조라서, 논문 파이프라인을 그대로 얹기보다 각 단계에 맞는 부품만 재사용한다.

STAGE 1은 그래프 없이 거래 자체 피처로 판정하므로 GBT 계열이 적합하고, STAGE 2는 “누구와 연결됐는가”를 묻는 문제라 엣지분류 GNN보다 그래프 알고리즘(커뮤니티 탐지)이 본체에 가깝다.

02

데이터 전처리 프레임워크

STAGE 1은 그래프를 만들기 전 단계의 피처만 쓰고, STAGE 2로 넘어간 거래에 한해서만 그래프 통계를 계산한다 — 즉 그래프 계산 비용은 플래그된 일부 거래에만 든다.

03

모델링 프레임워크 비교

논문 재현 결과(HI-Small 기준)를 그대로 가져와 세 방식을 나란히 놓는다. 강조 열이 STAGE 1 / STAGE 2에 각각 배정한 방식.

GBT + GFP STAGE 1 GNN (Multi-GNN) 그래프 알고리즘 STAGE 2
과제 거래 단위 이진분류 엣지(거래) 단위 이진분류 계좌 그룹 탐색
그래프 필요 시점 학습 전 1회 배치 (STAGE 1엔 미적용) 학습·추론 항상 필요 플래그된 서브그래프만
실시간 대응 양호 — partial_fit 스트리밍 재설계 필요 — 정적 스냅샷 전제 양호 — 서브그래프만 계산
신규 계좌 대응 무난함 취약 — 노드 피처 상수, cold-start 무난함
해석 가능성 높음 (feature importance) 낮음 (임베딩 블랙박스) 높음 (연결 경로 직접 제시)
결과 (F1, HI-Small) LightGBM 54.3 · XGBoost 55.6 GIN 32.3 · GIN+EU 46.4 · PNA 52.0* (과제 자체가 달라 미측정)
리소스 가볍고 빠름 (CPU 가능) GPU 필수, PNA 29.5/32GB, 학습 발산 사례 있음 가볍고 빠름 (CPU 가능)

* PNA는 15/100 epoch에서 중단된 중간 결과. 출처: ibm-aml/HANDOFF.md

04

회의 논의사항

역할별 다음 액션 — 팀 체크리스트와 1:1로 매핑.

  • STAGE 1 실현 가능성 검증 — 그래프 피처 없이 9개 기본 피처만으로 GBT 성능 측정
    이진분류 모델 구축 담당 · 그래프 없이도 라벨링이 되는지가 전체 설계의 전제조건
  • STAGE 2 커뮤니티 탐지 알고리즘 후보 비교 (connected components / Louvain / label propagation)
    패턴분석 모델 구축 담당 · Patterns.txt의 fan-out/cycle/scatter-gather 라벨과 대조해 검증
  • GNN을 옵션으로 둘지, 필수로 둘지 팀 합의 — cold-start·GPU 비용 리스크 공유
    프레임워크 조사 담당 · networkx/igraph vs PyG 리소스 비교 포함
  • 플래그 임계값(threshold) 정책 결정 — STAGE 1에서 얼마나 넓게/좁게 잡을지
    넓게 잡으면 STAGE 2 그래프가 커져 알고리즘 비용 증가, 좁게 잡으면 세탁 조직을 놓칠 위험
