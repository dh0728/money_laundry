# 국내외 AML 솔루션 시장조사

조사 기준일: 2026-08-14  
조사 목적: GNN 기반 이상거래 탐지 결과를 `Alert → 조사 Case → 관계 그래프 → QA → STR` 업무로 연결하는 서비스 기획 참고

## 먼저 볼 결론

국내 공개 자료만으로 SAS나 Lucinity처럼 전체 조사 흐름을 한 제품에서 끝까지 확인하기는 어렵다. 대신 다음 조합으로 보면 기획에 필요한 화면과 운영 구조를 거의 모두 확인할 수 있다.

1. **국내 전통 금융 AML의 메뉴·보고 구조:** 옥타솔루션 AML-PRISM, 지티원 AMLXpress
2. **국내에서 공개된 실제 대시보드:** 옥타솔루션 AML-PRISM
3. **GNN 관계 그래프와 가장 가까운 국내 화면·영상:** TranSight WEB, Uppsala CATV/CARA
4. **Alert/Case/SLA/QA 운영 구조:** Lucinity, Flagright, Hawk
5. **Alert에서 SAR/STR까지 이어지는 공개 영상:** Unit21, Tookitaki FinCense

따라서 국내 제품 한 개를 그대로 벤치마킹하기보다, **옥타의 국내 AML 용어·보고 체계 + GTOne의 SaaS/룰 운영 + TranSight/Uppsala의 그래프 + Lucinity/Flagright의 조사 워크플로**를 합치는 편이 우리 기획과 맞다.

## 1. 옥타솔루션 AML-PRISM — 국내 화면 기준점

### 어떻게 서비스되는가

옥타솔루션의 풀 제품인 AML-PRISM은 금융사의 기간계·비대면 채널과 실시간으로 연결하고, AML Data Mart에 고객·거래·계좌·상품·채널 데이터를 쌓아 WLF, 고객위험평가, KYC, 거래 모니터링, STR/CTR 보고를 처리한다. 공식 고객 페이지에는 은행·증권·보험·캐피탈·전자금융·핀테크·VASP 등 여러 업권의 레퍼런스가 공개되어 있다.

별도의 **SaaS AML-PRISM**도 있으나, 공식 설명상 공개된 SaaS 범위는 기본적인 WLF와 RA가 중심이다. 즉, 풀 AML-PRISM과 경량 SaaS를 같은 범위로 보면 안 된다.

```text
기간계/비대면 채널
→ 실시간 WLF·RA·CDD/EDD
→ Data Mart에 거래·고객·계좌 적재
→ STR/CTR 룰·시나리오 실행
→ Alert 확인 / 보고 제외 / 조사·분석
→ STR·CTR 파일 생성 및 KoFIU 보고
→ 결재와 처리 이력 관리
```

공식 자료: [AML-PRISM 제품 페이지](https://octasolution.co.kr/product/finance/aml.php), [SaaS AML-PRISM](https://octasolution.co.kr/product/finance/saasAML.php), [고객 및 파트너](https://www.octasolution.co.kr/customer/customer.php)

### 공개 인터페이스

![옥타솔루션 AML-PRISM 전체 구조](assets/domestic-aml/octa-aml-architecture.png)

위 구조에서 우리 기획과 직접 연결되는 부분은 `TMS 시나리오 → Alert 관리 → 모니터링/조사분석 → STR/CTR 보고`다.

![옥타솔루션 AML-PRISM 통합 대시보드](assets/domestic-aml/octa-aml-dashboard.png)

실제 공개 대시보드의 상단 메뉴는 `WLF 관리 / 위험평가관리 / KYC 관리 / 시나리오 관리 / STR모니터링 / KoFIU보고 / 결재및관리`로 구성된다. 국내 AML 제품의 정보구조와 용어를 잡는 데 가장 직접적인 참고 화면이다.

![옥타솔루션 KYC 고객분포 화면](assets/domestic-aml/octa-kyc-dashboard.png)

### 우리 기획에 가져올 것

- 조사 화면과 별개로 **시나리오 관리, KoFIU 보고, 결재**를 1급 메뉴로 둔다.
- 위험평가와 KYC가 조사 Case의 배경정보로 이어져야 한다.
- Alert에는 `확인`, `보고 제외`, `조사·분석` 같은 명시적 처분이 필요하다.
- 다만 대시보드식 통계 UI를 그대로 복제하지 말고, 분석가의 업무 시작점은 Lucinity처럼 Queue/Workboard로 바꾸는 것이 좋다.

## 2. GTOne AMLXpress 7 — 국내 SaaS와 룰·보고 운영 기준점

### 어떻게 서비스되는가

AMLXpress는 현재 네이버클라우드 마켓플레이스에서 `이용 가능` 상태로 확인된다. 공개 구성도와 업무 흐름상 다음 범위를 제공한다.

```text
고객·거래 데이터 업로드/API 연계
→ WLF 및 고객위험평가(RA)
→ TMS 룰·시나리오와 임계치 실행
→ STR/CTR Alert 생성
→ 담당자 분배 및 내부 결재 Workflow
→ KoFIU 보고서 생성·다운로드·이력관리
```

2025년 공개된 AMLXpress 7 설명에는 RA와 STR 여부 판단을 위한 머신러닝 모델, LLM 기반 의심거래 종합보고서 생성이 포함되어 있다. 공개 보도 기준 최근 3년간 은행·증권·저축은행·카드·보험·가상자산거래소 등 약 100곳의 금융권 고객이 언급된다.

공개 자료: [네이버클라우드 AMLXpress](https://www.fin-ncloud.com/marketplace/AMLXPress), [공개 제품 설명 슬라이드](https://www.slideshare.net/slideshow/solutions-showcase-amlxpress/249964002), [AMLXpress 7과 도입 현황](https://www.etnews.com/20250618000365)

### 공개 인터페이스 수준

공개 슬라이드에는 시스템 구성도와 업무 흐름은 자세하지만, `데모 시연` 부분의 실제 조작 화면은 정적 자료에 남아 있지 않다. 따라서 **서비스 범위와 백오피스 흐름은 강하게 확인되지만 UI 벤치마크 신뢰도는 중간**이다.

### 우리 기획에 가져올 것

- 모델 점수 외에 **룰/시나리오 버전, 임계치, 적용 기간, 변경 승인자**를 관리한다.
- Alert 생성과 담당자 분배를 분리한다.
- STR 확정 전 maker-checker 결재와 버전 이력을 남긴다.
- AI가 보고서 초안을 만들더라도 근거 거래, 적용 모델·룰 버전, 수정자, 승인자를 함께 기록한다.

## 3. TranSight — 국내 공개 영상과 그래프 분석 기준점

### 어떻게 서비스되는가

TranSight는 전통 은행 AML 풀스위트가 아니라 가상자산 컴플라이언스 제품이다. 서비스는 세 층으로 나뉜다.

1. **DATA & KYT API:** 거래소 입출금 시 위험 주소를 실시간 스크리닝하고 차단
2. **TranSight WEB:** Bitcoin·Ethereum 등 멀티체인 자금 흐름을 그래프로 표시하고 Auto Trace로 홉 수·주소 수·금액 기준을 적용해 경로를 확장
3. **Expert Analysis:** 믹서·브리지·레이어2처럼 자동 추적이 어려운 사건을 전문가가 분석하고 보고서 제공

IAAN Protocol은 법집행기관과 거래소 사이의 동결 요청·정보 요청을 중계한다. 공식 사이트에는 코인원, 업비트, 경찰청, 카카오뱅크, 신한은행 등 사용·협력 기관 로고가 공개되어 있다.

공개 자료: [TranSight 공식 사이트](https://www.transight.io/ko), [2분 제품 소개 영상](https://www.youtube.com/watch?v=VIdKjliLWRg), [19분 활용 범죄 추적 사례 영상](https://www.youtube.com/watch?v=DRs4ei_mC9E)

### 우리 기획에 가져올 것

- 그래프를 무한히 펼치는 대신 `홉 수 / 노드 수 / 금액 / 시간` 제한을 먼저 받는다.
- 동일 주체로 추정되는 계좌·지갑을 Entity로 묶어 표시한다.
- 위험 노드, 거래소, 믹서, 정상 노드의 타입과 범례를 분리한다.
- 조사 결과에서 `동결 요청 / 정보 요청 / 증적 내보내기` 같은 다음 행동으로 바로 연결한다.

## 4. Uppsala Security CARA·CATV·KYT — 위험점수와 조사 보고서 기준점

Uppsala Security는 글로벌 제품이지만 한국 법인과 국내 도입 레퍼런스가 있어 국내 참고 후보에 포함했다.

### 어떻게 서비스되는가

- **CARA:** 지갑 행동, 주변 지갑 노출, 평판 데이터와 20개 이상의 지표를 이용해 위험도를 계산한다. 수동 조회와 API 연동을 지원하고 위험 이력·메모·거래 흐름이 포함된 PDF 보고서를 만든다.
- **CATV:** 주소·트랜잭션 해시·Entity 이름으로 검색하고, 거래 흐름과 Entity 관계를 인터랙티브 그래프로 조사한 뒤 데이터를 내보낸다.
- **KYT/ICF API:** 거래 전후 위험 조회와 위협 인텔리전스 연동을 담당한다.

KODA 도입 사례에서는 TRDB로 블랙리스트 주소를 대조하고, CARA로 알려지지 않은 주소의 과거 패턴을 위험 지표로 평가하며, CATV로 사후 자금 흐름을 추적하는 방식이 공개됐다.

공개 자료: [CARA 실제 제품 이미지](https://uppsalasecurity.com/cara), [CATV 그래프 이미지](https://uppsalasecurity.com/catv), [KODA 도입 및 사용 방식](https://zdnet.co.kr/view/?no=20220726210039)

### 우리 기획에 가져올 것

- GNN 점수를 단일 숫자로 끝내지 말고 위험 요인, 이웃 노드 노출, 과거 위험 변화로 분해한다.
- Case에서 조사 메모와 그래프 상태를 함께 보고서로 내보낸다.
- `검색 → 그래프 확장 → 패턴 확인 → 증적 저장 → 보고서` 순서를 단순하게 유지한다.

## 5. 이엘온소프트 GreFin AML/RBA — 최신 국내 통합 구축 후보

### 어떻게 서비스되는가

공식 제품 범위는 KYC, WLF, 고객위험평가, TMS, 전사 RBA, FIU 지표 연계다. 거래와 고객 위험을 선별하고, STR/CTR을 룰 기반으로 자동 추출하며, 결재·보고와 감사 로그를 지원한다.

2026년에는 쿠콘 eKYC와 이엘온소프트 AML을 결합해 고객 신원정보와 거래 데이터를 함께 분석하는 통합 레그테크를 추진했고, 2026년 7월에는 KSNET에 eKYC 플러그인과 올인원 AML 패키지를 공급했다는 사례가 공개됐다. 이 사례는 탐지에서 조사와 후속 조치까지 연결하는 것을 목표로 한다.

공개 자료: [GreFin AML/RBA 공식 설명](https://www.elonsoft.co.kr/solution?t=aml), [쿠콘·이엘온소프트 통합 레그테크](https://www.edaily.co.kr/News/Read?mediaCodeNo=257&newsId=04496886645386600), [KSNET 올인원 AML 구축](https://zdnet.co.kr/view/?no=20260702164256)

### 평가

현재성·국내 적용성은 높지만 공개 페이지는 기능 설명과 아이콘 위주다. **실제 UI를 보지 않고 화면 설계의 1차 레퍼런스로 쓰기에는 부족**하고, 기능 체크리스트와 국내 구축 동향 파악용으로 적합하다.

## 해외 공개 UI가 좋은 추가 후보

### SAS와 Lucinity

이미 작업 폴더에 화면별 분석이 있다.

- [SAS AML Transaction Monitoring UI 분석](SAS_AML_Transaction_Monitoring_UI_분석.html)
- [Lucinity Case Manager UI 분석](Lucinity_Case_Manager_UI_분석.html)

SAS는 대형 금융사의 탐지·네트워크 분석·조사·규제보고 기준점이고, Lucinity는 Workboard, Case, 체크리스트, SLA, QA, Narrative를 이해하기 가장 좋다.

### Flagright — Case/SLA/QA를 가장 공개적으로 보여주는 후보

공식 Case Management 페이지에서 실제 제품 이미지를 데모 신청 없이 볼 수 있다. 상태·SLA 설정, no-code Workflow, maker-checker 승인, QA 샘플링과 체크리스트, 분석가 성과, 관계 그래프, SAR 작성·제출, 멘션·댓글·문서·감사 로그까지 한 페이지에서 확인 가능하다.

공개 화면: [Flagright Case Management](https://www.flagright.com/case-management), [Regulatory Filing](https://www.flagright.com/regulatory-filing)

우리 기획에는 `New → Triage → Investigation → QA → STR → Closed` 상태와 SLA, 조사 체크리스트, QA를 설계할 때 가장 직접적인 추가 참고가 된다.

## 우리 서비스에 적용할 화면 우선순위

### 1. Alert Workboard

한 행을 거래 한 건이 아니라 **위험 에피소드 한 건**으로 둔다.

필수 열:

- Episode/Alert ID
- 중심 고객·계좌
- 시나리오명과 GNN 모델 버전
- 모델 위험점수와 업무 우선순위 점수
- 관련 거래 수·총액·기간
- 주요 위험 근거 2~3개
- SLA 상태와 due time
- 담당자, 현재 단계, Case 승격 여부

### 2. Case / 고객 360

```text
요약
├─ KYC/CDD/EDD 및 고객위험등급
├─ 관련 Alert·과거 Case
├─ 거래 타임라인
├─ GNN 관계 그래프와 자금 흐름
├─ 증적·첨부·정보요청
├─ 조사 체크리스트와 Narrative
└─ 결정·승인·감사 로그
```

### 3. 그래프 조사 화면

- seed 거래와 에피소드 경계를 명확히 구분
- 1~3 hop, 시간 범위, 최소 금액, 최대 노드 수 필터
- 그래프에서 선택한 노드·거래를 Case 증거로 고정
- 모델이 왜 포함했는지 점수 기여 요인 표시
- 입력이 잘렸다면 `input_truncated`, 정책 버전과 cutoff 시각 노출

### 4. 운영·관리 화면

- 룰·시나리오와 임계치 버전 관리
- 모델 버전과 Feature 버전
- SLA 위반·업무량·미배정 Queue
- QA 표본과 반려 이유
- STR 초안·검토·승인·제출 이력
- 오탐/의심/추가정보필요 disposition을 모델 개선 데이터로 환류

## 최종 추천 조사 순서

1. 옥타솔루션 공개 대시보드로 국내 AML 메뉴와 용어를 확정한다.
2. GTOne 공개 구성도로 국내 SaaS의 데이터 연계·룰·Alert·결재·KoFIU 흐름을 확정한다.
3. Lucinity와 Flagright로 Workboard, SLA, QA, Case 상태를 설계한다.
4. TranSight와 Uppsala로 GNN 그래프의 검색·확장·증적 저장 방식을 설계한다.
5. Unit21과 Tookitaki 영상으로 Alert에서 Case와 SAR/STR까지의 실제 클릭 흐름을 검증한다.

## 조사상 주의점

- 국내 업체의 `AML SaaS`라는 표현이 항상 풀 TMS·Case·STR까지 의미하지는 않는다. 옥타처럼 SaaS 공개 범위가 WLF/RA에 한정된 경우가 있다.
- 가상자산 KYT/추적 제품은 그래프 참고에는 매우 좋지만, 은행 AML의 고객 360·Case·QA·KoFIU 보고를 대신하지 않는다.
- 업체가 공개한 고객 로고는 제품 전체가 아니라 일부 모듈·컨설팅·과거 프로젝트일 수 있으므로, 특정 고객이 현재 어떤 모듈을 사용 중인지까지 단정하면 안 된다.
- 공개 화면의 숫자와 고객명은 데모 데이터일 수 있다. 화면 구조와 업무 흐름을 참고하되 탐지 성능의 근거로 사용하지 않는다.
