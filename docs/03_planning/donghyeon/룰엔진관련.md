## 1. AML_감독용_스크리닝_도구_챕터13_한국어_번역
서로 다른 금융기관의 거래를 수집·가명화·정규화하고 회사 및 위험정보로 보강한 뒤, 알려진 AML 유형은 설명 가능한 매개변수형 룰로 탐지하고 알려지지 않은 패턴은 그래프·이상 탐지로 보완하며, 모든 결과를 그래프와 상세정보로 제공해 전문가가 최종 조사하도록 하는 감독용 플랫폼을 제안한 논문이다. 
설계와 구현 가능성을 보여준 시스템·사례 논문”이지, 제안한 룰·그래프 탐지 방식이 실제 자금세탁을 정확하게 탐지한다고 과학적으로 입증한 성능 검증 논문은 아님

데이터셋은 슬로베니아 금융감독 환경의 비공개 거래 데이터 2종에 공공 사업자 등기소, eRTR 계좌 등록부, EU 고위험 국가목록, 외부 화이트리스트를 결합한 데이터 같음

### 데이터 보강
논문에 경우 순수 원문 데이터에서 외부 데이터를 활용해 보강을 함

1. 공 사업자 등기소
2. eRTR 공개 계좌 등록부
3. EU 고위험 제3국 목록

초기 순수 거래 데이터
```
계좌 A → 계좌 B
날짜
금액
```

#### 공 사업자 등기소 
- 회사 규모, 자본화 유형, 소유구조, 회사 등록일, 회사 폐업일 또는 예상 폐업일, 자본 출처

```
회사가 설립된 지 4개월밖에 안 됐는데
120만 유로를 두 번 받고
비슷한 금액을 개인 계좌로 보냈다.
```

#### eRTR 공개 계좌 등록부
- 계좌 등록일, 계좌 폐쇄일, 계좌 소유자, 계좌 유형, 개인, 계좌 여부, 법인 계좌 여부, 개인과 회사 양쪽에 연결되는 계좌인지

```
회사 A ──소유──> 계좌 1
회사 A ──소유──> 계좌 2
개인 P ──소유──> 계좌 3
```

#### EU 고위험 제 3국 목록
- 거래 관련 국가에 위험 등급을 붙임
예를 들어
```
전: 신설 회사가 해외에서 거액을 수취
후: 신설 회사가 고위험 국가의 계좌에서 거액을 수취
```

### 룰 기반 시나리오 장점
**설명 가능성**
- 탐지 결과를 전문가와 금융기관에 설명할 수 있습니다.
**구성 가능성**
- 금액·기간·국가위험 같은 파라미터를 변경할 수 있습니다.
**규정과의 연결**
- 기존 AML 규정 및 위험 신호와 쉽게 대응됩니다.
**현장 활용성**
- 현장 점검에서 특정 행동을 찾는 쿼리로 사용할 수 있습니다.
**유형학과의 연결**
- 전문가가 사용하는 AML 유형학 언어를 데이터베이스 쿼리로 옮길 수 있습니다.

### 시나리오 사례들 

#### 사례1: 단기간 존재한 회사의 대규모 자금 조달
탐지된 회사는 등록 후 6개월 이내에 폐업했으며, 설립 직후 비정상적으로 많은 거래를 처리했습니다.
논문이 강조하는 점은 회사가 여러 계좌를 소유할 수 있기 때문에 계좌 하나만 보면 드러나지 않는 이야기가 회사 단위에서는 보일 수 있다는 것

#### 사례2: 입금 후 계좌로 유사 금액 전달
회사가 같은 날 두 차례 약 120만 유로를 받고, 두 개의 서로 다른 개인 계좌로 거의 같은 금액을 지급합니다.
해당 회사는 4개월 미만 존재했습니다.
이 패턴은 단기 위장회사가 자금 통과 지점으로 사용됐을 가능성을 보여줍니다.

#### 사례3: 여러 개인 계좌로 개러 분산
또 다른 사례에서는 단기간 존재한 회사가 짧은 시간 동안 여러 개인 계좌로 거래를 분산합니다.
모든 거래가 국경을 넘기 때문에 자금 추적이 더 어려워집니다.
논문은 이 사례들을 다음과 연결합니다.

### 화이트리스트 사용
정상적인 사업 특성 때문에 이상 탐지에 반복적으로 걸릴 가능성이 큰 특수 법인을 별도로 표시하여, 불필요한 경보를 줄이거나 조사 화면에서 구분
예시)
- 공익사업자: 수많은 개인에게서 정기적으로 요금을 받음
- 지방자치단체: 다수 개인·기업과 다양한 자금거래가 발생
- 해외 자회사를 보유한 대기업: 정상적으로 국경 간 거래가 많음

논문에서 아래 두가지 방식을 제시하면서 2번쨰 방식을 추천함
1. 이상 탐지 계산에서 완전히 제외
2. 계산에는 포함하되 화면에서만 필터링

이떄 화이트리스트는 이 회사는 안전하다라는 뜻이 아니라
이 회사의 사업 특성상 이 거래 패턴만으로는 이상하다고 보기 어렵다라는 뜻임 
갑자기 고위험 국가의 신규 법인에 거액을 반복 송금이런 거는 예외임

```
화이트리스트 회사
→ 위험 계산은 정상 수행
→ 결과도 저장
→ 일반 화면에서는 숨기거나 별도 표시
→ 필요하면 다시 확인 가능
```

## 2. 거래 모니터링 모델의 임계값 조정
- 이건 너무 페이지가 길어서 다읽으면 머리털 다빠짐
- 내가 필요한 경우만 받아서 추천 받아서 정리했음

### 2.1.1 은행의 AML 거래 모니터링 프로세스
논문이 임계값 수학으로 들어가기 전에 “은행 AML 모니터링이 어떤 업무 안에서 이루어지는가”를 설명하는 부분

일단 은행은 모델 개발·구현·사용·검증이 한 조직에 집중될 경우 위험이 커질 수 있으므로 역할을 분리한다

#### 3선 방어 모델
#### 제1선: 비즈니스
거래 모니터링을 실제로 수행하고 운영
- 거래 모니터링 우녕
- Alert 처리
- 초기 조사
- 비즈니스 룰 사용
- 모델 결과 활용

#### 제2선: 컴플라이언스
제 1선과 독립된 입장에서 품질을 보증
- AML 정책 해석
- 모델 위험관리 절차 점검
- 제1선 운영통제
- 룰과 임계값 검토
- 결과 품질 확인

#### 제3선: 감사
제1선과 제2선이 제대로 작동하는지 독립적으로 평가
논문은 역할 분리와 함께 정기적인 직원 교육도 필요하다고 설명

#### 고객 심사와 피어 그룹
고객은 일반적으로 다음처럼 위험 등급을 갖고 있음
- 낮음
- 중간
- 높음

그리고 비슷한 특성을 가진 피어 그룹으로 나눠 예상 거래 행동 정의
```
일반 개인 고객
고액자산 개인 고객
소매업 법인
무역업 법인
공익기업
고위험 국가 관련 법인
```

피어그룹을 만드는 이유는 고객의 실제 거래가 해당 고객에 대해 은행이 알고 있는 정보와 일치하는지 판단하는 것
예를 들어 월급 생활자에게 매달 300만원이 입금되는 것은 정상일 수 있지만, 갑자기 매일 해외에서 수천만원이 입금되면 예상 프로필에서 벗어났다고 볼 수 있음

#### 위험 식별: SIRA
은행은 고객뿐 아니라 다음 요소의 위험을 식별해야 합니다.
- 고객
- 상품
- 유통·서비스 채널
- 거래 유형

논문은 이를 SIRA(Systematic Integrity Risk Analysis)라는 주기로 설명

네 가지 측면의 주기로 구성됩니다. 
1. 여러 요인을 기반으로 위험 식별
2. 위험이 위험 확률에 위험 영향을 곱한 것과 동일한 위험 분석(위험 = 발생 가능성 × 영향)
3. 정책, 절차, 시스템 및 통제를 통한 위험 관리. 
4. 위험 모니터링 및 검토. 위험 분석에 따른 조치는 은행의 위험 선호도에 따라 달라집니다

상위(ATL) 및 하위(BTL) 테스트를 통해 AML 모델을 평가

| 구분 | 검사 범위 | 주요 질문 |
|---|---|---|
| ATL | 임계값 위 | 발생한 Alert가 얼마나 유용한가? |
| BTL | 임계값 아래 | Alert 없이 놓친 관심 거래가 얼마나 되는가? |
| ATL+BTL | 위와 아래 | 전체 탐지 성능이 어떠한가? |

### 2.1.2 Alert → Case → Report
논문은 거래가 다음 세 단계를 거칠 수 있다고 설명
```
Alert 단계
→ Case 단계
→ Report 단계
```
#### Alert 단계
모든 거래가 룰과 비교됩니다.
룰에 적중한 거래는 Alert가 되고 초기 수동검토를 받습니다.
초기 확인에서 합법적인 것으로 보이면 더 이상 조사하지 않고 종료합니다.
- 관심 있음
- 관심 없음

#### Case 단계
초기검토를 통과한 Alert는 Case로 올라갑니다.
경험 있는 분석가가 다음을 폭넓게 조사합니다.
- 고객 정보
- 과거 거래
- 거래 상대방
- 자금 출처
- 거래 목적
- 관련 계좌
- 다른 Alert
- 외부정보
이 단계에서는 거래 또는 활동을 비정상적인지 아닌지 판단합니다.
#### Report 단계
비정상적인 것으로 분류된 Case는 보고 단계로 이동합니다.
최종적으로 FIU에 보고할지를 결정

### 2.2 시나리오 → 룰 → 임계값
논문은 분할입금, 즉 smurfing을 예로 들어 시나리오가 룰과 임계값으로 바뀌는 과정을 설명

#### 시나리오
분할입금 시나리오에서는 거액의 자금을 작은 거래로 구조적으로 나눈다
여기서 두 가지 관점이 있는데
**수취인 관점**
- 하나의 계좌가 여러 번 나눠진 자금을 반복해서 받습니다.
**송금인 관점**
- 신고·탐지 기준 바로 아래의 금액을 구조적으로 반복 송금합니다.

#### 시나리오를 여러 룰로 나눔
하나의 시나리오에는 하나 이상의 룰이 필요함
논문이 제시한 예는 다음과 같다.

**송금인 룰**
- 은행 고객인 송금인이 일정 기간 고위험 국가의 외국 계좌로 반복 송금합니다.
**수취인 룰**
- 은행 고객인 수취인이 일정 기간 고위험 국가의 외국 계좌에서 반복적으로 자금을 받습니다.
**각 룰에 임계값 설정**
논문은 다음 임계값을 예로 듭니다.
관찰 기간
- 1개월
- 2개월
- 그 밖의 기간
거래 빈도
- 5일마다
- 매주
- 2주마다
거래금액
- 1,000유로
- 2,000유로
- 총 이체금액
- 평균 이체금액
- 기간 중 금액 변동

논문이 제시한 전체 변환 관계는 다음과 같다.
```
범죄행동 분석
→ 범죄행동을 설명하는 시나리오
→ 시나리오를 탐지하는 하나 이상의 룰
→ 각 룰의 임계값
```

### 2.2.1 룰 백테스팅
아직 적절한 임계값이 없고 과거 지식도 거의 없다면 여러 후보 임계값을 시험해 좋은 초기값을 찾아야 함

임계값의 백테스팅은 ATL 및 BTL 테스트를 통해 수행

- 의도한 성과를 내는가
- 현재 성과지표를 충족하는가
- 고객·상품·시장 변화로 조정이 필요한가
를 정기적으로 확인

임계값을 하나 정한 뒤 다음 거래를 표본 추출
```
임계값 아래 표본 → BTL
임계값 위 표본 → ATL
```
분석가는 각각의 거래를 검토하고 관심 있음/없음으로 표시

분석가의 라벨과 룰의 Alert 여부를 결합하면 다음 네 경우가 나옴 
| 임계값 결과 | 분석가 판단 | 분류 |
|---|---|---|
| 위: Alert 발생 | 관심 있음 | TP, 진양성 |
| 위: Alert 발생 | 관심 없음 | FP, 위양성 |
| 아래: Alert 없음 | 관심 있음 | FN, 위음성 |
| 아래: Alert 없음 | 관심 없음 | TN, 진음성 |

ATL과 BTL 모두 있으면
다음을 계산할 수 있다.
- 민감도
- 특이도
- 정확도

논문은 탐지 실패 위험에 집중하기 위해 잘못된 누락률을 사용
그리고 허용 기준을 RTL(Risk Tolerance Level)이라고 정의

RTL은 임계값 아래의 거래 중 누락된 관심 거래를 은행이 최대 몇 퍼센트까지 허용할 것인지 나타냅니다.
단순히 표본에서 계산한 비율만 보는 것이 아니라 신뢰수준을 포함
```
임계값 아래에서 관심 거래가 누락되는 모집단 비율의 신뢰 상한이, 은행이 정한 최대 허용 비율보다 낮아야 한다
```

예를 들어
```
RTL = 20%
신뢰수준 = 95%
```

라면 다음 조건을 만족하는 가장 높은 임계값을 찾습니다.
```
95% 신뢰수준에서
임계값 아래 관심 거래 비율의 상한 < 20%
```

백테스트의 반복 구조
```
후보 임계값 선택
→ 임계값 아래 또는 위에서 표본 추출
→ 분석가가 관심 여부 라벨링
→ 성능지표와 신뢰구간 계산
→ RTL 충족 여부 판단
→ 더 높거나 낮은 임계값 시험
→ 가장 적절한 임계값 결정
```

### 4.2 임계값을 평가할 거래 범위
후보 임계값을 정했다고 해서 표본 범위가 자동으로 결정되는 것은 아님.
논문은 두 가지 방식을 비교합니다.
- 완전 모집단 접근법
- 버킷 접근법

#### 일단 임계값 후보를 이산 구간으로 나눔
분할입금 예시에서 일정 기간의 해외 거래량이 0~80,000유로라고 가정하면 이를 5,000유로 간격으로 나눔
```
Level 0: 0
Level 1: 5,000
Level 2: 10,000
Level 3: 15,000
...
Level 16: 80,000
```

#### 완전 모집단 접근법
BTL에서 25,000유로 임계값을 평가한다면 20,000~25,000유로만 보는 것이 아니라 0~25,000유로 전체 모집단을 표본 추출 대상으로 삼는다.

```
BTL 평가:
0 ───────────── 25,000
전체 구간에서 표본 추출
```
ATL이라면 평가 임계값부터 최대값까지 전체 구간을 표본 대상으로 삼습니다.
```
ATL 평가:
25,000 ───────── 최대값
전체 구간에서 표본 추출
```
표본에서 관심 거래 비율을 계산하고 Clopper–Pearson 신뢰구간을 구함

TL에서 다음과 같은 표현이 가능해짐
> 95% 신뢰수준에서 임계값 L 아래의 관심 거래 비율은 상한값 이하이다.

#### 버킷 접근법
버킷 방식은 평가 임계값 바로 가까운 구간만 표본 추출합니다.
25,000유로 임계값을 평가한다면
```
20,000~25,000유로만 표본 추출
```
그 이유는 임계값 가까이의 거래가 임계값 변경의 영향을 더 직접적으로 보여줄 수 있다고 보기 때문

버킷 접근법은 버킷 방식은 가까운 구간만 보기 때문에 아래쪽의 큰 관심 거래 집단을 놓쳐서 잘못된 결론을 낼 수 있어서 논문에서는 추천안함

### 4.3 Step과 Bisection
논문의 목표는 다음 조건을 만족하는 가장 높은 임계값을 찾는 것

```
임계값 아래 관심 거래 비율의 신뢰 상한 < RTL
```

#### Step 전략
전문가 또는 데이터 분석가가 가장 낮은 논리적 시작점을 정합니다.
논문 실험에서는 시작점을 전체 임계값 수준 수의 10~30% 범위에서 선택해 시뮬레이션합니다.
예를 들어 20개 후보가 있다면 Level 2~6 사이를 초기 논리적 후보로 가정합니다.

진행 규칙
현재 임계값의 신뢰 상한이 RTL보다 낮으면 한 단계 올립니다.
```
p_upper < RTL
→ 임계값 한 단계 상승
```
신뢰 상한이 RTL 이상이면 한 단계 내립니다.
```
p_upper ≥ RTL
→ 임계값 한 단계 하락
RTL을 만족하는 가장 높은 수준을 찾을 때까지 반복합니다.
```

예시 1: 임계값을 올리는 경우
Level 3부터 시작합니다.
```
Level 3: RTL 충족
→ Level 4
→ Level 5
→ Level 6
→ Level 7: RTL 충족
→ Level 8: RTL 초과
```
따라서 가장 높은 허용 수준은 Level 7입니다.

예시 2: 임계값을 내리는 경우
Level 3부터 시작했지만 RTL을 초과합니다.
```
Level 3: RTL 초과
→ Level 2
→ Level 1: RTL 충족
```
따라서 Level 1을 선택합니다.

장점
- 전문가가 적절한 범위를 이미 알고 있을 때 효율적
- 현재 임계값 근처를 재평가할 때 유리할 수 있음
- 방법이 단순함
단점
- 시작점과 최적값이 멀면 후보를 하나씩 검사해야 합니다.
- 예를 들어 Level 3에서 시작해 최적값이 Level 15라면
- 많은 거래를 반복 검토해야 합니다.

#### Bisection 전략
Bisection은 후보 범위를 계속 절반으로 줄입니다.
20개 후보 임계값이 있다면 Level 10부터 시작합니다.

현재 값이 RTL을 충족할 때
더 높은 임계값도 가능한지 보기 위해 상반부의 중간을 선택합니다.
```
Level 10 충족
→ Level 10~20의 중간인 Level 15
```

현재 값이 RTL을 초과할 때
임계값을 낮춰야 하므로 하반부의 중간을 선택합니다.
```
Level 10 초과
→ Level 0~10의 중간인 Level 5
```
매번 탐색 범위를 절반으로 줄여 최적 수준을 찾습니다.

최대 시험 횟수를 예상할 수 있음
Bisection은 후보 수가 늘어도 시험 횟수가 완만하게 증가합니다.
논문 표의 예:
| 후보 임계값 수 | 최대 시험 수준 수 |
|---:|---:|
| 5 | 3 |
| 10 | 4 |
| 20 | 5 |
| 40 | 6 |

후보를 20개에서 40개로 늘리면 임계값 구간을 더 세밀하게 나눌 수 있지만 최대 시험 횟수는 5회에서 6회로만 증가합니다.

#### Step과 Bisection 비교
최적 임계값이 시작점보다 훨씬 높은 경우 Bisection이 유리합니다.
논문 예시:
- Step: Level 3부터 Level 7까지 여러 단계 확인
- Bisection: Level 5 → Level 8 → Level 7
반대로 최적 임계값이 매우 낮은 경우 Step이 더 유리할 수 있습니다.
- Step: 낮은 논리적 시작점 근처에서 빠르게 발견
- Bisection: 중간부터 시작하여 여러 차례 아래로 이동

결론적으로 Bisection은 “항상 더 좋다”가 아니라 초기 적정 임계값을 모를 때 넓은 범위를 효율적으로 줄이는 전략이라는 뜻임

### 분석가 검토량 줄이기
- 조기 중단
    - RTL가 임계치를 넘으면 조기 종료
- 과거 검토 결과 재사용
    - 임계값이 변하면서 겹치는 범위는 그대로 재사용


이 논문이 “최적 임계값”이라고 부르는 것은 자금세탁 탐지의 절대적인 수학적 최적값이 아니다
정확히는 다음에 가깝다
> 선택한 성능지표, 표본추출 방식, 신뢰수준, 위험 허용 수준이라는 조건 아래에서 허용 가능한 가장 높은 임계값

따라서 RTL을 어떻게 정했는지, 분석가가 무엇을 관심 거래로 분류했는지, 어떤 고객군과 기간의 데이터를 사용했는지가 달라지면 선택되는 임계값도 달라짐

그리고 논문이 비교적 강하게 보여준 것은 실제 AML 탐지 정확도가 아니라 다음임

> 합성된 거래 분포와 관심 라벨이라는 실험조건에서 Bisection과 표본 재사용을 이용하면 초기 임계값을 찾는 분석가 검토량을 줄일 수 있다.

즉, 임계값 검증 절차를 설계하는 데는 매우 유용하지만, 논문의 Bisection 결과를 실제 은행 데이터에 검증 없이 그대로 적용해서는 안 된다는 뜻


## 온톨로지_전문가시스템_의심거래_한국어_번역

### Rule 구축
저자들은 파키스탄 중앙은행의 AML 지침 중 고객 거래와 관련된 내용을 선택하여 7개의 룰을 만들었습니다.
룰은 SWRL(Semantic Web Rule Language)로 작성

> SWRL(Semantic Web Rule Language) : 온톨로지에 저장된 사실을 이용해 새로운 사실을 추론하기 위한 IF–THEN 규칙 언어입니다.

#### Rule 1: 고액 입금 후 즉시 출금

자연어 의미
```
계좌에 고액이 입금되고
같은 기간에 거의 같은 금액이 출금되면
의심거래로 분류
```
SWRL 조건에는 다음이 포함됩니다.
- 활성계좌
- 같은 계좌
- 같은 기간 ID
- 입금합계 2,500,000 PKR 이상
- 입금·출금 차이가 허용범위 이하

논문의 SWRL에서는 허용 차이를 250,000 PKR로 둡니다.

#### Rule 2: 휴면계좌 활성화 후 고액 거래
자연어 의미:
```
휴면계좌가 다시 활성화된 후
고액의 입금 또는 출금이 시작되면
의심거래로 분류
```
조건:
- 휴면계좌
- 휴면 이후 기간
- 입금 또는 출금 합계 2,500,000 PKR 이상

#### Rule 3: 수표를 이용한 고액·빈번 출금
자연어 의미:
```
활성계좌에서
수표를 통해
7일 동안 3회 이상 출금하고
출금합계가 고액기준 이상이면
의심거래로 분류
```
조건:
- 활성계좌
- 수표 거래 그룹
- 출금합계 2,500,000 PKR 이상
- 출금횟수 3회 이상

#### Rule 4: 휴면계좌 활성화 후 고액 출금
- Rule 2와 비슷하지만 출금에 초점을 맞춥니다.
```
휴면계좌
AND 활성화 이후 거래
AND 고액 출금
→ 의심거래
```

#### Rule 5: 휴면계좌에서 여러 번 입금 후 유사금액 출금
자연어 설명은 다음과 같습니다.
```
휴면계좌가 활성화된 후
여러 차례 자금을 받고
누적금액이 커진 뒤
유사한 금액을 빠르게 출금하면
의심거래로 분류
```
조건에는 다음이 포함됩니다.
- 휴면계좌
- 입금거래
- 출금거래
- 입금횟수 2회 이상
- 입금·출금 차이 허용범위 이하
- 휴면 활성화 이후 짧은 기간

#### Rule 6: 신고 기준 미만 입금의 누적
자연어 의미:
```
각 입금은 CTR 신고 기준보다 작지만
일정 기간의 입금합계가 고액기준 이상이면
분할입금 가능성으로 분류
```
거래가 GM, 즉 중간금액 그룹에 속하면서 집계금액이 2,500,000 PKR 이상이면 Rule 6에 해당합니다.

#### Rule 7: 신고 기준 미만 출금의 누적
Rule 6의 출금 버전입니다.
```
각 출금은 CTR 신고 기준보다 작지만
일정 기간의 출금합계가 고액기준 이상이면
분할출금 가능성으로 분류
```

큰 금액: 2,500,000 PKR 이상(25000달러)
즉시 : 7일 이내
휴먼계좌 : 6개월 동안 거래 x
빈번함 : 7일 이내 3회 이상
CTR 신고 기준 : 파키스탄 은행에서 CTR을 생성하는 기준으로 2,500,000 PKR을 사용


기준은 금융 조직이 조정해야 한다고 명시 했지만 논문은 다음 이유로 값을 선택했습니다.
2,500,000 PKR: CTR과 관련해 의심할 만한 금액
7일: 고객 행동 변화를 자세히 볼 수 있는 짧은 간격
3회: 7일이라는 짧은 기간 안에서 빈번하다고 볼 수 있는 횟수
6개월: 휴면계좌의 표준적 정의
