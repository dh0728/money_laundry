# Alert와 Episode: 무엇을 보여주고 어떻게 묶을지

> **한 줄 요약**: Alert 화면에서 "왜 의심스러운지"를 보여주고, 그 정보로 "이어진 Alert"를 찾아 묶고, 묶은 이유를 Episode에 남긴다.

- 5번(Alert 간 관계)과 7번(상세 페이지)을 하나로 합쳐 쉽게 다시 쓴 문서다.
- 이 문서는 **무엇을 할지**만 적는다. **어떻게 만들지**는 `9.Alert와_Episode를_실제로_어떻게_구현할지.md`에 있다.

## 0. 먼저 알아둘 말

| 말 | 뜻 |
|---|---|
| 씨앗 거래 | 모델이 "의심"이라고 찍은 거래 |
| Alert | 씨앗 거래와 그 앞뒤로 이어진 거래를 **시스템이 자동으로** 묶은 것 |
| Episode | 조사자가 "이 Alert들은 한 사건"이라고 판단해 **사람이 직접** Alert 2개 이상을 묶은 것 |

## 1. 전체 흐름

```text
① Alert를 본다       ② 이어진 Alert를 찾는다     ③ 묶는다           ④ Episode를 본다
"왜 의심스럽지?"  →  "이것과 이어진 게 또 있나?"  →  "한 사건이네"  →  "왜 묶었더라?"
```

앞 단계에서 본 정보가 다음 단계의 근거가 된다.

- ①에서 보여주는 계좌·소유주 정보가 ②에서 "이어졌다"를 판단하는 재료다.
- ③에서 고른 근거가 ④에 그대로 남는다.

그래서 "어떤 정보를 보여줄지"와 "어떻게 묶을지"는 따로 설계할 수 없다.

## 2. ① Alert 화면: 조사자의 질문 6개에 답한다

| 조사자가 묻는 것 | 화면이 보여주는 것 | 예시 |
|---|---|---|
| 왜 떴나? | 씨앗 거래, 그리고 나머지 거래가 포함된 이유 | 씨앗 3건 · 돈이 들어온 쪽 7건 · 나간 쪽 4건 |
| 돈이 어떻게 움직였나? | 들어온 돈, 나간 돈, 얼마나 빨리 나갔나 | 들어온 돈의 83%가 3시간 안에 나감 |
| 어떤 모양인가? | 한 계좌로 모였나, 흩어졌나, 몇 단계를 거쳤나 | 계좌 5개 → 계좌 1개, 은행 4곳을 거침 |
| 누가 관여했나? | 계좌별 역할(출발·경유·도착), 소유주, 은행 | 계좌 c41f…: 경유, 박OO, 은행 70 |
| 전에 본 적 있나? | 같은 계좌·소유주가 나온 다른 Alert·Episode와 그 결론 | A-0987: 정상으로 종결됨 |
| 어디까지 봤나? | 시스템이 보지 못한 범위 | "전후 2일 밖의 거래는 포함하지 않음" |

화면 맨 위에는 이걸 한 문장으로 줄인 요약을 둔다.

> 28시간 동안 계좌 14개·은행 6곳에 걸친 거래 16건. 계좌 c41f…에 5개 계좌에서 유입 후 83%가 3시간 안에 유출.

지금 화면과 달라지는 점은 세 가지다.

| 지금 | 바뀐 뒤 |
|---|---|
| "씨앗 3건 · 조사 대상 12건"처럼 건수만 보임 | 거래마다 왜 포함됐는지 보임 |
| 계좌 정보가 카드 여러 장으로 흩어져 있음 | 계좌 탭의 표 하나로 모음 |
| 과거 조사 이력, 못 본 범위가 없음 | 둘 다 추가 |

## 3. ② 이어진 Alert 찾기

Alert 화면의 "연관 Alert" 탭에서 한다.

### 3.1 무엇을 "이어졌다"고 보나

두 가지를 따로 본다. **무엇으로 이어졌나(종류)**와 **얼마나 믿을 만한가(강도)**.

돈이 오가지 않았어도 연관된 Alert일 수 있다. 계좌는 다른데 소유주가 같은 경우가 그렇다. 그래서 "돈으로 이어짐"과 "사람으로 이어짐"을 구분한다.

| 종류 | 뜻 | 근거 | 합친 그래프에서 |
|---|---|---|---|
| 돈으로 이어짐 | 자금이 실제로 오갔다 | 같은 거래가 양쪽에 있음 / 같은 계좌가 양쪽에 나옴 / 한쪽 계좌에서 다른 쪽 계좌로 돈이 감 | 한 덩어리로 붙는다 |
| 사람으로 이어짐 | 돈은 안 오갔지만 주체가 같다 | 계좌는 다르고 소유주가 같음 | 덩어리는 나뉘고 점선으로 이어진다 |
| 비슷함 | 이어진 건 아니고 닮았다 | 같은 기간 / 같은 유형 | 이어지지 않는다 |

| 강도 | 뜻 | 예 |
|---|---|---|
| 강 | 근거가 분명하다 | 같은 계좌가 양쪽에서 돈을 주고받음 / 소유주가 같음 |
| 중간 | 근거가 약하다 | 겹치는 계좌가 한쪽에서는 주변 계좌일 뿐임 |
| 약 | 근거로 보기 어렵다 | 거래 상대가 아주 많은 계좌(허브)만 겹침 / 계좌를 아주 많이 가진 소유주만 겹침 |

후보에는 "돈으로 이어짐 · 강", "사람으로 이어짐 · 강"처럼 둘을 같이 붙인다.

- 약한 후보와 "비슷함"은 기본 목록에서 접어 둔다.
- 순서는 점수를 더해서 매기지 않는다. 근거 종류를 정해진 순서로 비교한다. 돈으로 이어진 근거가 먼저, 사람으로 이어진 근거가 그다음이다. "왜 이게 1등이지?"에 바로 답할 수 있어야 하기 때문이다.
- 지금 데이터로 알 수 있는 "사람" 정보는 소유주뿐이다. 실제 은행이라면 주소·연락처·기기도 쓰겠지만 IBM 데이터에는 없다.

### 3.2 화면에서 하는 일

1. **후보 목록을 본다.** 연결이 강한 순으로 나오고, 근거가 "공유 계좌 3"처럼 붙어 있다.
2. **"겹쳐 보기"를 누른다.** 두 Alert의 그래프가 합쳐져서 어디서 이어지는지 보인다.
3. **"담기"를 누른다.** 묶을 목록에 쌓인다. 개수 제한은 없다.
4. **담을 때마다 후보를 다시 계산한다.** A와는 안 이어져도, 방금 담은 B와 이어지는 C가 새로 뜬다.

합친 그래프에서는 이어지는 지점을 이렇게 표시한다.

| 표시 | 뜻 |
|---|---|
| 테두리가 있는 계좌 | 양쪽 Alert에 모두 나온 계좌 |
| 굵은 점선 | 어느 Alert에도 없지만 둘을 잇는 거래 |
| 가는 점선 | 계좌는 다르고 소유주만 같음 |

합친 그래프는 **계좌 보기**와 **소유주 보기**를 바꿔 볼 수 있다. 소유주 보기는 같은 소유주의 계좌를 한 점으로 합친다. 계좌 보기에서 두 덩어리로 나뉘던 Alert가 소유주 보기에서는 한 덩어리로 이어진다.

3개 이상 담으면 Alert를 점으로 그린 **관계도**를 같이 보여준다. 지금 보는 Alert에서 몇 단계 만에 이어지는지 보이고, 어디와도 이어지지 않는 Alert는 따로 표시된다. 사람으로만 이어진 선은 점선으로 그린다.

## 4. ③ 묶기

| 경우 | 어떻게 |
|---|---|
| 새로 묶기 | 담은 Alert로 새 Episode를 만든다 |
| 이미 있는 Episode에 붙이기 | 후보 목록에 Episode도 한 줄로 나온다. "편입 대상으로"를 고르면 그 Episode에 들어간다 |
| 3개 이상 묶기 | 담기에 제한이 없다. 관계도로 전부 이어지는지 확인한다 |

규칙은 세 가지다.

1. **Alert 하나는 Episode 하나에만 들어간다.** 그래서 편입할 Episode는 하나만 고를 수 있다.
2. **묶을 때 본 근거를 같이 저장한다.** 나중에 "왜 묶었지?"에 답하기 위해서다.
3. **다른 사람 담당 Alert는 지금 규칙으로는 내가 묶을 수 없다.** "편입 요청"을 보내는 방식을 제안한다(미정, 7장 참고).

## 5. ④ Episode 화면: 질문이 달라진다

Alert는 "왜 떴나"를 묻고, Episode는 "왜 묶었나"를 묻는다.

| 조사자가 묻는 것 | 화면이 보여주는 것 |
|---|---|
| 왜 묶었나? | 묶은 사람, 시각, 사유, 그때 본 근거 |
| 전체 이야기가 뭔가? | Alert를 시간순으로 나열, 서로 겹치는 계좌, 합친 돈 흐름 |
| 어디까지 판정했나? | Alert별 판정(의심·정상·미판정), 종결할 수 있는지 |

## 6. 모든 화면에 적용하는 규칙 4개

1. **출처를 구분해 표시한다.** 모델 예측 / 거래에서 계산한 값 / 사람 판단 / 데이터의 한계.
2. **숫자를 누르면 그 근거 거래가 나온다.** "송금 계좌 5개"를 누르면 그 거래만 걸러서 보여준다.
3. **계산하지 못한 값은 0이 아니라 "산출 불가"로 쓴다.**
4. **"이 사건이 세탁일 확률 87%" 같은 숫자는 만들지 않는다.** 모델은 거래 하나씩만 판단하기 때문이다.

## 7. 팀이 정해야 할 것

| 질문 | 선택지 | 제안 |
|---|---|---|
| 다른 담당자의 Alert를 어떻게 묶나 | 편입 요청 보내기 / 규칙을 풀어 직접 묶기 / 관리자가 재배정 | 편입 요청 |
| "시스템이 못 본 범위"를 조사자에게 보여주나 | 보여준다 / 지금처럼 개발자용으로만 둔다 | 보여준다 |
| 소유주만 같은 경우의 강도 | 강 / 중간 | 강 |
| 계좌를 몇 개부터 "아주 많이 가진 소유주"로 보나 | 기준 개수를 정한다 | 실제 데이터의 소유주별 계좌 수 분포를 보고 정한다 |
| "공통 상대방"도 근거로 넣나 (두 Alert가 같은 제3의 계좌와 각각 거래함) | 넣는다 / 나중에 | 나중에. 허브 계좌에 특히 약하다 |
| 한 Alert가 Episode 두 개와 이어지면 | 하나만 고르게 한다 / Episode 합치기 기능을 만든다 | 하나만 고르게 한다 |
| 계좌 탭을 새로 만드나 | 만든다 / 개요에 계속 둔다 | 만든다 |
