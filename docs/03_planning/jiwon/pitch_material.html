1. 문제 정의 소재 — 왜 이 문제인가

  • 업계 현황: 규칙 기반 거래 모니터링의 알람 오탐률은 90~95%에 달한다는 보고가 학계·업계에 반복 등장[1][2] — 조사 인력이 가짜 알람에 소진되는 구조가 문제의 출발점.
  • 난이도의 정량 근거: 같은 데이터셋(AMLworld)에서 GNN 계열 SOTA 도 소수클래스 F1 68.2(Multi-PNA+EU)[3] — 쉬운 문제가 아님을 문헌이 보여줌 (단, 이진 과제·꼬리 포함·튜닝 조건이라 우리 지표와 직접 비교 불가 — 내부 기록 data_notes.md에 조건 차이 명시).
  • 문제의 2층 구조 (우리 실측): 탐지(세탁이냐)와 유형 판정(어느 수법이냐)은 다른 문제다 — 기준선 혼동 분석에서 탐지 유출은 2.7%뿐인데 분류 실패의 55%가 패턴 간 혼동 (runs/run_114_nine_class.md). 유형을 알아야 조사 방향과 SAR 보고가 선다.
  • 구조적 어려움: 세탁 블록의 시간 스팬 중앙값 27일·최대 70일 (outputs/hi_large_phase0_eda.md) — 실시간 거래 단위 판단과 수법(블록) 단위 판단 사이의 간극이 본질.

선택의 논리 사슬 (가설 → 실험 → 판정)

  1. 프로토타입 전략 — 가설: "파라미터·평가 방법론 결론은 데이터 규모에 대체로 독립일 것." HI-Small(실험 1회 150초 — Large 의 1/48 비용)에서 사다리 14회로 λ·리프· 점수정의·평가 계약 확립 (runs/ run_001~014).
  2. Small 의 한계 발견 = 전환 결정타 — 시간 분할 경계에서 블록이 절단되며 학습 노출 편향 발생. 이 편향을 측정할 미노출 블록이 Small 엔 클래스당 7~73건뿐 — 클래스별 일반화 평가가 통계적으로 불가 (hi_large_transition.md §0).
  3. Medium 기각 — 블록 2,756개지만 유효 기간이 Small 과 같은 16일: 기간이 원인인 문제는 기간이 같으면 재발 (실측 근거 위 표).
  4. HI vs LI — 트랙 목적이 8패턴 분류이므로 패턴 블록 수가 결정 기준: 16,467 vs 2,218 (클래스당 ~2,058 vs ~277).
  5. Large 채택 검증 — Phase 0 전수 실측(라벨 137,936행 전수 매칭·정렬 여부·꼬리 컷) 후 3주 평가 창 설계로 미노출 블록 클래스당 수십~수백 확보, 노출 우위 소멸 실측(탐지@R0.7 99.2 vs 98.3%) (hi_large_phase0_eda.md, run_101).
  6. 사후 검증 — "Small 결론은 이식된다" 가설을 Large 에서 재확인: λ 미니 사다리 (run_108)로 λ=100 유지 성립. 프로토타입 전략의 정당성이 닫힘.

5분 마이크로배치 (설계안 08-12) → 일 배치(24h)로 팀 확정탐지·추론을 하루 1회 실행 — 단 피처 상태 갱신은 배치 안에서 이벤트 시간순을 유지TMS 는 사후 조사 지원이라 즉시성 요구가 낮음(기획 검토안 §2 논지 채택). 우리 피처 빌더는 원래 배치-스트림 구조라 무변경 적용, 블록 재구성도 하루치 단위가 자연스러움

V2 와 충돌하지 않는 것: Claim/Heartbeat/상태 머신, DLQ 의미론, 에이전트 DB 접근 금지, 허브 계좌 그래프 병목 정책(오히려 우리 허브 실측이 판정 기준의 근거를 제공).
