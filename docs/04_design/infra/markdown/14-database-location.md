## 직접 운영과 관리형 데이터베이스

같은 DB 엔진도 누가 설치, 패치, 백업과 장애 복구를 맡는지에 따라 운영 방식이 달라진다.

- **직접 운영**: 가상 서버나 컨테이너에 DB를 설치하고 모든 운영을 팀이 담당한다.
- **관리형 DB**: 클라우드 사업자가 설치, 패치, 백업과 고가용성 기능의 일부를 제공한다.

관리형이라는 말이 데이터 운영 책임 전체가 사라진다는 뜻은 아니다. 데이터 모델, 사용자 권한, 쿼리 성능, 백업 보존 정책과 실제 복구 검증은 여전히 프로젝트 책임이다.

## 같은 서버와 분리된 서버

애플리케이션과 DB를 같은 서버에 두면 비용과 네트워크 구성이 단순하다. 반면 한 서버의 장애와 자원 부족이 두 시스템에 동시에 영향을 준다.

DB를 별도 서버나 관리형 서비스로 분리하면 자원과 장애 범위를 나눌 수 있지만 비용, 네트워크, 권한과 운영 구성 요소가 늘어난다.

## 기본 용어

- **Backup**: 복구를 위해 데이터를 별도 위치에 복사한 것
- **Restore**: 백업으로부터 DB를 다시 만드는 작업
- **Snapshot**: 특정 시점의 저장 장치나 DB 상태를 저장한 복사본
- **Replication**: 데이터를 다른 DB 인스턴스에 지속적으로 복제하는 방식
- **High availability**: 일부 구성 요소가 실패해도 서비스를 계속 제공하도록 하는 구조
- **RPO**: 장애 시 허용 가능한 최대 데이터 손실 시간
- **RTO**: 장애 후 서비스를 복구하기까지 허용 가능한 시간

백업 파일이 존재하는 것만으로는 충분하지 않다. 정기적으로 별도 환경에 복구해 데이터와 절차가 실제로 유효한지 확인해야 한다.

## 주요 실행 위치

### Amazon RDS

RDS(Relational Database Service)는 AWS가 관계형 DB 인스턴스의 생성, 저장 장치, 자동 백업과 일부 패치 작업을 관리하는 서비스다. 사용자는 DB 엔진과 크기, 네트워크, 백업 기간과 파라미터를 설정하고 DB 계정과 데이터는 직접 관리한다.

### 애플리케이션 EC2의 DB 컨테이너

Backend와 같은 EC2에서 Docker 이미지로 DB 프로세스를 실행하는 구성이다. DB 데이터는 컨테이너의 임시 쓰기 영역이 아닌 Volume이나 호스트 디스크에 연결해야 컨테이너 재생성 후에도 유지된다.

### 별도 EC2의 자체 운영 DB

DB 전용 EC2를 만들고 운영체제 패키지나 Docker 컨테이너로 DB를 실행하는 구성이다. 애플리케이션 서버와 네트워크로 통신하며 설치, 백업, 복구, 복제, 패치와 모니터링을 운영 팀이 담당한다.
