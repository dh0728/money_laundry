## 애플리케이션의 파일 데이터

사용자가 올린 문서, 이미지, 모델 결과물과 대용량 데이터는 DB 행에 직접 넣기보다 파일 저장소에 보관하고 DB에는 파일 식별자와 메타데이터를 저장하는 경우가 많다.

메타데이터에는 원본 파일명, 저장 키, 크기, 콘텐츠 유형, 소유자, 생성 시각과 접근 권한 등이 포함될 수 있다.

## 저장 방식

### 파일 스토리지

디렉터리와 파일 경로를 사용한다. 일반 운영체제의 파일 시스템과 같은 방식이라 애플리케이션에서 사용하기 쉽다. 여러 서버가 공유하려면 네트워크 파일 시스템 같은 추가 구성이 필요하다.

### 블록 스토리지

서버에 디스크 장치처럼 연결하는 저장 방식이다. 운영체제가 그 위에 파일 시스템을 만들고 파일 단위로 사용한다. 특정 서버와 연결되는 성격이 강하다.

### 객체 스토리지

파일을 객체와 키로 저장하고 HTTP API를 통해 접근한다. 디렉터리 구조처럼 보일 수 있지만 실제로는 키의 접두사를 이용한 논리적 표현이다. 서버와 저장 공간을 분리하고 대용량 파일을 확장하는 데 적합하다.

## 기본 용어

- **Object key**: 객체 스토리지에서 파일을 고유하게 찾는 이름
- **Bucket**: 객체들을 보관하는 최상위 공간
- **Metadata**: 파일의 속성과 관리 정보를 담은 데이터
- **Content type**: 파일 내용의 형식을 나타내는 값
- **Presigned URL**: 제한된 시간 동안 특정 파일 작업을 허용하는 서명된 주소
- **Lifecycle policy**: 오래된 파일을 다른 저장 등급으로 옮기거나 삭제하는 규칙
- **Versioning**: 같은 키의 이전 파일 버전을 보존하는 기능

## 파일 업로드 보안

업로드된 파일명과 확장자를 그대로 신뢰하면 안 된다. 크기 제한, 실제 콘텐츠 검사, 안전한 저장 키 생성, 접근 권한과 악성 파일 처리 정책이 필요하다. 파일 저장소는 기본 비공개로 두고 필요한 사용자에게만 접근을 허용하는 방식이 안전하다.

## 주요 파일 저장 서비스와 방식

### Amazon S3

S3(Simple Storage Service)는 Bucket 안에 Key와 Object 형태로 데이터를 저장하는 AWS 객체 스토리지다. HTTP API로 파일을 업로드·다운로드하며 접근 정책, 객체 버전, 수명 주기와 암호화 설정을 제공한다.

### Amazon EBS

EBS(Elastic Block Store)는 EC2에 연결해 디스크처럼 사용하는 AWS 블록 스토리지다. 운영체제가 파일 시스템을 만든 뒤 일반 경로로 사용하며 Snapshot을 이용해 볼륨 상태를 백업할 수 있다.

### S3 호환 객체 스토리지

S3 API와 유사한 객체 작업 방식을 구현한 클라우드 또는 자체 구축 스토리지다. 애플리케이션은 Endpoint와 인증 정보를 바꾸어 접근할 수 있지만 권한, 이벤트, 버전 관리 등 세부 기능은 구현마다 다를 수 있다.
