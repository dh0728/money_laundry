1. 프로젝트 성격 및 평가 기준

구분분석 결과
팀 구성Frontend 1명, Backend 1명, DB·Data Pipeline·Infra 1명, AI·Model 2명. 거의 전원이 Python 기초 입문 수준이며 나머지 기술은 새로 학습해야 한다.
서비스 범위목업 거래 생성기 → 실시간 메시지 수집 → 배치 구성 → 2단계 모델 추론 → 저장 → API → 웹 조사 화면.
모델 구조1단계 이상거래 여부 이진분류, 2단계 이상거래 패턴 다중클래스 분류. 신규 계좌와 계속 증가하는 거래 그래프를 처리해야 한다.
핵심 제약약 4개월 내 종단간 MVP 완성이 우선이다. 따라서 새 언어와 운영 컴포넌트를 동시에 과도하게 늘리면 안 된다.
AI 경험PyTorch와 TensorFlow/Keras 모두 예제 코드를 몇 차례 따라 한 동일한 초심자 수준이다. 기반 프레임워크 친숙도에는 차등을 주지 않는다.
평가 분야Frontend, Backend, 실시간 메시지 전달, Database, AI·Model, 실행·배포의 6개 대분류만 사용한다.
후보 단위각 후보는 해당 분야의 전체 업무 범위를 맡는 완성형 선택지다. 여러 기술을 함께 쓰는 후보는 기능 이점과 운영·학습 복잡성을 같은 표에서 함께 평가한다.
평가 원칙적용 방식
분야별 기준모든 분야에 같은 기준을 강제하지 않고, 그 분야의 실제 완료 조건에 맞는 기준과 가중치를 사용한다.
전체 범위 비교일부 작업에만 강한 기술을 다른 표에서 별도로 추천하지 않는다. 해당 분야 전체를 단독 또는 조합으로 맡겼을 때의 기능 누락과 장점을 함께 채점한다.
조합 비용 반영프로세스·DB·언어·운영 컴포넌트가 늘어나는 후보는 학습량, 통합, 장애 지점, 배포 복잡성에 직접 감점을 받는다.
학습 비용 대칭팀은 Python 기초 입문 수준이고 그 위의 프레임워크는 어느 후보든 새로 학습한다. 따라서 특정 언어·프레임워크에만 "새로 배워야 한다"는 이유로 감점하지 않는다. 감점 대상은 언어 자체가 아니라 동시에 관리할 도구체인·런타임·프로세스의 개수다. AI 분야에 적용한 "기반 프레임워크 친숙도에 차등을 주지 않는다"와 같은 원칙을 전 분야에 적용한다.
포트폴리오 축 분리학습·포트폴리오 가치는 취업 시장 수요만 보는 독립 기준으로 두고, 구현 난이도에 영향을 주는 "자료·실무 설명력"(학습 자료의 양)과 분리해 이중 계상을 막는다.
결과 계산 순서후보와 분야별 기준·가중치를 먼저 고정하고 기준별 원점수를 입력한 뒤에만 최종 총점과 순위를 계산한다.
