## 문제 상황
- 1종에서 검증 확인된 17종을 base를 바탕으로 ego_id, revesed_mp, port numbering를 추가했을 때 의도와 다르게 눈에 띄는 성능 개선이 없었음
- 이미 그래프를 피처로 만들어 넣어줬기 때문에 이것으로 어느정도 잘 잡히기 때문에 이런 결과가 나온것으로 추정됨
- 두 모델을 비교했을 떄 트리는 비ACH에서 정상 오탐이 많고, GNN은 ACH에서 정상 오탐을 많이 보임
- GNN이 ACH에서 틀리는 건 이상한 게 아니야

- GNN이 ACH에서 틀리는 이유
  - 세탁이 ACH에 몰려 있음. 테스트 구간에서 ACH는 322만 건 중 세탁이 30,574건(0.95%)이고, 비ACH는 2,359만 건 중 3,886건(0.016%)임 밀도가 58배 차이 남.
  - 제대로 배운 모델이면 헷갈리는 거래도 ACH에 몰려서 세탁과 비슷해 보이는 정상 거래는 세탁이 많은 곳 근처에 있기 마련임
  - GNN 특유의 이유도 하나 추정(미확인). GNN은 거래 점수를 양끝 계좌의 주변 정보로 매김. 그래서 패턴에 낀 계좌가 같은 시기에 한 정상 거래까지 같이 높은 점수를 받을 수 있음. 트리는 거래 한 줄의 피처(쌍 이력 등)로 거래 하나하나를 구분하니까 이런 오탐이 적음.

- 트리가 비ACH에서 틀리는 게 왜지? 이게 이상함
  - 세탁이 거의 없는 곳에 알림 8천 건을 내는 건 정상적인 실수가 아니야. 게다가 검증에서는 안 그러고 테스트에서만 그럼
  - 경과 시간에 묶인 피처 (가설). 간격 피처(pair_gap_minutes 등)는 데이터가 쌓일수록 큰 값이 나올 수 있음. 학습 때는 "간격이 길고 되돌아오는 거래가 있는" 구간에 세탁만 있었는데, 시간이 지나면서 정상 거래가 그 구간에 들어오는 식이야. 트리는 값의 경계로 딱 잘라 판단하니까 이런 이동에 약해. nocum에서 누적은 뺐지만 간격 피처는 남아 있었고, 거기서 제일 많이 쓰인 피처가 pair_gap_minutes였어.
  - 테스트 2주에만 있는 거래 묶음 (가설). 10월 17~30일에 비ACH 정상 거래 중 특정 날짜나 특정 결제방식에 몰린 무언가가 있을 수 있음
  - GNN은 왜 안 당하나 (가설). GNN은 피처를 연속적인 값으로 받아서 경계에서 급변하지 않고, 판단 근거가 피처 몇 개의 극단값이 아니라 주변 거래 전체야.
  - 확인 결과 Reinvestment 거래가 오탐이 되는 문제인것을 확인
