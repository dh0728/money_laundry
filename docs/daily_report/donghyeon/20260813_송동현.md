## 실적

- SAS AML Transaction Monitoring과 Lucinity Case Manager의 UI 및 업무 흐름 조사
- 조사한 AML 솔루션 레퍼런스를 기반으로 기획안 수정사항 검토
- 현재 기획의 `거래 1건 → Alert 1건` 구조가 실제 AML 업무에 적합한지 재검토

## 문제 상황

- 레퍼런스의 서비스 방식이랑 초기 기획의 방식이 Alert 방식이 우린 거래 1건당이지만 서비스에서는 한 거래 묶음 단위로 판단해서 Alert을 울림
- IBM AML 데이터에는 실제 고객 KYC·CDD 정보가 부족하여 고객 중심보다 계좌·Entity 중심으로 에피소드를 구성해야 함
- 거래소나 정산 계좌 같은 대형 허브가 포함되면 1~2 hop 조회 범위와 거래 그래프가 과도하게 커질 가능성이 있음

## 내일 계획

- 거래 단위 Alert와 에피소드 단위 Alert 중 최종 서비스 방향을 논의
- 전체적인 구조는 비슷하지만 조금 서비스 플로우가 조금 다름 협의 필요 
  - 서비스 역할 구조나 상태관리 같은 부분
- 에피소드 Alert 변경사항이 기존 아키텍처와 유스케이스에 미치는 영향 정리
