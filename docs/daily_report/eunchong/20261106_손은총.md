1. **팀 결정 반영 — BIP · STACK 은 학습에도 안 씀**: 9칸으로 학습한 뒤 7칸으로 줄이는 판(R)은 빼고, 처음부터 7칸으로 학습한 판(R7 계열)만 쓰기로 함. 원장(주변 거래 기록)에는 BIP · STACK 거래를 그대로 둠. 운영에서는 어느 거래가 BIP · STACK 인지 몰라서 지울 수 없기 때문임. 원장에서도 지운 판(R7x)은 진단용으로만 둠.
2. **진단용 한 파일 .py 3개**: 다른 Claude 에게 '조정할 점' 진단을 맡기려고, 판마다 코드 한 파일과 실제 실행 결과를 묶음(18번 R7 운영용 · 19번 R7x 진단용 · 20번 V0 시험지). 가중치(.pt)는 학습된 숫자뿐이라 진단할 거리가 없어 넣지 않음. 원본 코드와 글자가 같은지, 같은 입력에서 모델이 낸 답이 저장된 값과 같은지(차 0), 학습 앞 2 epoch 이 원본과 같은지 확인함. 저장된 val 답을 다시 세어 보니, R7 은 정답이 BIP 인 행의 49% · STACK 인 행의 63% 를 RANDOM 으로 냄.
3. **끝난 날 나눔(3구간)으로 데이터 다시 나누기**: 기간을 train 08-01 ~ 09-27 · val 09-28 ~ 10-14 · test 10-15 ~ 11-05 셋으로 나누고, 시도(세탁 거래 묶음 하나)를 마지막 거래가 있는 날의 구간으로 통째로 보냄. 그 결과 학습 행 71,042 · val 행 32,936(패턴 6유형 + 무패턴). 11-04 나눔(학습 46,252행)보다 학습 행이 늘었는데, 09-14 ~ 09-27 에 끝난 시도까지 train 에 들어오기 때문임. val 행 가운데 10,718행은 train 기간에 시작한 시도의 앞 날짜 거래가 옮겨 온 것임. 노이즈로 표시된 train 시도 796개(1,194행)는 학습에서 뺌. 채팅 Claude 가 만든 점검기로 나눔이 정의대로인지 확인함 → 실패 0 · 기대값 모두 같음.
4. **누수 점검 · 학습 시작**: test 기간 거래를 몰래 보지 않는지 세 가지로 점검함 → 모두 통과. ① 학습 · val 용 원장에 10-15 뒤 거래가 한 줄도 없음. ② 행마다 그날 자정 뒤 원장 줄을 지우거나 섞어 바꿔도 그래프와 모델 답이 하나도 안 바뀜. ③ 새로 만든 val 그래프에서 옛 모델이 낸 답이 옛 그래프 때와 같음(겹치는 22,218행 · 차 0.0000024 이하). 비교 기준을 학습 전에 글로 고정한 뒤(15:25), 15:34 에 학습 9판을 시작함: 무게 없는 판(B3) · 긴 시도에 무게를 더 준 판(B3w · 채팅 Claude 제안 · 최대 5배) · 노이즈 표시 행도 학습한 판(B3n · 72,236행) × 씨앗 3개. train 안에서 끝나야 학습에 들어오므로 긴 시도일수록 적게 남는데, B3w 는 이것을 길이에 맞춘 무게로 메움.
