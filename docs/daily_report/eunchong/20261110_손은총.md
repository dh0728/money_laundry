## 실적

- 완료한 일 + 산출물 경로/이슈 번호 :
1. **끝난 날 나눔 6단계 — test 한 번 채점(재학습 없음)**: train + val 로 다시 학습하지 않고, val 로 고른 가중치 그대로 test 를 한 번 채점하기로 정함. 채점 방법을 test 를 열기 전에 글로 고정함(10:24). 옛 나눔 모델 둘(A · B)과 새 나눔 모델(B3 · B3w · B3n)을 같은 시험지에서 함께 채점함. test 7칸 정밀도 / 재현율(test 배정 행 전부 · 씨앗 3개 평균): A 0.517 / 0.510 · B 0.517 / 0.516 · B3 0.542 / 0.553 · B3w 0.534 / 0.551 · B3n 0.539 / 0.547. 날짜가 test 기간인 행만 보면 A 0.559 / 0.536 · B3 0.587 / 0.583. 판정 규칙으로는 B3 − A 만 '씨앗에 흔들리지 않고 오름'이고, 무게를 준 판(B3w) · 노이즈를 넣은 판(B3n)은 B3 와 '씨앗에 따라 달라짐'임. val 에서 낸 말과 같았음. val(B3 0.612 / 0.591)보다 test 가 낮음.
2. **유형 가중 판(B3c)을 더해 여섯 판으로 채점**: 유형별 거래 수의 역수로 손실에 무게를 준 판을 새로 학습함(무게는 train 행 수로만 셈 · GA-SC 9.85 · 무패턴 0.21 · 고른 epoch 13 · 7 · 9). 더하기로 한 것도 test 를 열기 전에 글로 고정함(10:46). val 0.598 / 0.602 · test 0.540 / 0.548 로, B3 와는 val · test 모두 '씨앗에 따라 달라짐'임. 전체 점수는 그대로이고 유형 사이에서 재현율만 옮겨 감(test: GA-SC 0.261 → 0.371 · RANDOM 0.188 → 0.400 · CYCLE 0.619 → 0.358 · SC-GA 0.443 → 0.333 · 패턴 행을 맞힌 몫 0.443 → 0.441).
3. **점검용 한 파일(21번)**: 다른 Claude 에게 점검을 맡기려고 끝난 날 나눔 실험의 코드 25개 · 바깥 모듈 7개 · 공통 코드 9조각 · 지시와 사전기록을 한 파일(4,916줄)로 묶음. 모두 서버 원본 글자 그대로이고, 파일을 돌리면 원본과 같은지 견줌.
4. **끝난 날 나눔 진단(새 학습 · test 계산 없음)**: 점수가 왜 0.6 안팎에 머무는지 저장된 그래프와 확률로 풀어 봄. 살펴볼 것을 val 정답을 읽기 전에 글로 고정함(15:43). ① 가짜 원장으로 그래프 코드를 확인함: 기대 214칸이 모두 같았고, 길이 5 이상인 고리는 그래프 안에서 돌아오는 길이 안 잡힘. ② val 패턴 행 16,245 가운데 0.849 가 '판정하는 날에 그 시도의 거래가 아직 다 일어나지 않은' 행임(대부분 절반쯤만 일어남). 일어난 거래가 그래프에 다 못 들어온 행은 0.312 임. ③ SC-GA 는 흩는 쪽 행의 재현율이 0.374(0.521 을 FAN-OUT 으로 답함) · 모으는 쪽은 0.869 임. GA-SC 는 모으는 쪽 0.022(0.819 를 FAN-IN 으로 답함) · 흩는 쪽 0.800 임. 시도의 앞 반쪽에서는 뒤 반쪽이 아직 안 일어나 입력이 FAN-OUT · FAN-IN 과 똑같이 생겼기 때문임. ④ CYCLE 은 돌아오는 길이 그래프에 있는 176행이 0.731, 없는 1,844행이 0.595 임. ⑤ 그 시도의 거래가 그 행 하나뿐인 칸(행의 0.120)은 다섯 유형에서 재현율이 0.00 ~ 0.19 임. ⑥ 고른 epoch 둘레의 확률을 평균 내도 점수는 거의 안 움직이고(정밀도 차 −0.001 ~ +0.004) 씨앗 사이 흔들림만 줄어듦.
- val · test 사용(11-10): val = B3c 의 epoch 고르기와 val 채점 한 번(B3 줄은 11-06 채점과 차 0) · 진단에서 val 정답을 읽음(묘사와 교차 겹 안 고르기에만 · 판을 고르지 않음). test = 6단계로 한 번 씀(여섯 판 · 재학습 없음 · TEST_OPENED.log 26 ~ 30줄 · test 개수는 적지 않음). 진단에서는 test 비율 표만 옮겨 적었고 봉인 폴더는 열지 않음.

## 문제 상황

- 막힌 내용 : test 점수가 0.54 / 0.55 로 팀 목표 0.7 / 0.7 에 못 미치고, 무게를 주거나 노이즈를 넣는 것으로는 움직이지 않음. 진단으로 보면 낮은 까닭의 큰 몫이 모델이 아니라 과제 정의에 있음: 판정하는 날에는 그 시도의 거래가 절반쯤만 일어나 있어서, SC-GA 의 앞쪽은 FAN-OUT · GA-SC 의 앞쪽은 FAN-IN 과 구별할 길이 없음. 그런데 정답은 다 끝난 뒤의 유형으로 채점하고 있음. 그래프를 바꿔도 이 몫은 줄지 않음. 그리고 실수 하나: test 원장의 전체 줄 수(test 개수에 해당)를 6단계 사전기록과 코드 한 줄에 적음. 사전기록은 고정된 파일이라 원본은 그대로 두고 21번 파일에서만 가림 → 원본을 어떻게 할지 정해야 함.
- 필요한 협업 또는 결정권자 : 팀 회의(쓸 판 · 정답을 '다 끝난 뒤의 유형'으로 둘지 '그날 보인 모양'으로 둘지 · 거래 하나씩 볼지 묶음으로 볼지 · test 개수가 적힌 원본 파일 처리)
