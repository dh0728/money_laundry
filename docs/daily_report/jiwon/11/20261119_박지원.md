## 실적

- 측정 흔들림 범위 확인과 분석 입력 조회 변경 효과 확인
  - 같은 코드를 한 번 더 돌려 9일 합 차이 약 3%를 측정 흔들림 범위로 확인
  - 분석 입력 조회 3개 기본키 변경은 시간이 흔들림 범위 안이나, 디스크 읽기 172GiB → 139.6GiB, 표 전체 훑기 113회 → 28회로 감소
- 대시보드 모델 집계가 그날 거래 점수만 읽도록 변경
  - 하루치 집계를 위해 점수 전체(308만 건)를 읽던 조회를 그날 거래 점수만 기본키로 읽도록 변경, Java 테스트 317개 통과
  - 집계 시간 9일 합 165초 → 55초(-67%), 결과 동일
- 누적 처리시간 최적화 결과 정리
  - 같은 9일(HI-Medium 20개 은행) 기준 1,025.3분 → 93.3분(-91%), 수정 전 값에는 디스크 버스트 소진과 시간 초과 재시도가 포함됨
  - 수정별 문제·원인·해결·실험 조건·결과를 실험 보고서로 정리

## 문제 상황
- 현재 DB 서버(db.t4g.small)는 메모리 2GB로 HI-Medium 원본 전체 전환 시 용량과 처리시간 한도를 넘을 수 있음
- 마지막 실행에서 모델 입력 준비가 16% 늘었으나 원인 미확인
