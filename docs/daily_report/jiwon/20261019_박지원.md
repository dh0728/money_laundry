## 실적

- 모델 교체 구조 정리 및 엔티티 유형·은행 국가 저장
  - 파이프라인 단계마다 입력·출력 계약을 고정하여 한 단계(특히 모델)만 바꿔 끼울 수 있도록, 모델 하나를 폴더 하나와 등록 한 줄로 관리하는 구조로 정리하고 모델이 권장하는 임계값을 그대로 사용하도록 변경
  - 팀원 모델 입력에 필요한 엔티티 유형과 은행 국가를 거래 통합 단계에서 저장하도록 구현(이름은 저장하지 않고 유형 분류만 보관)
  - 분석 계정은 서비스 소유주 ID 기준 엔티티 유형과 은행 국가만 읽을 수 있도록 DB 권한 제한
- 분석 DB 스키마 단순화
  - 여러 차례 덧붙인 스키마 변경을 초기 스키마 하나로 합치고, 장부 전환 이후 쓰지 않는 옛 실행별 사본 테이블과 보조 테이블을 제거하여 분석 테이블·뷰 32개 → 27개로 축소
  - 새 DB에서 데모 3일 연속 실행 결과가 기존 방식과 차이 0건임을 확인, Java 테스트 304개·worker 테스트 274개 통과
  - 데모 환경의 S3 주소 오류와 데모 계정 비밀번호 설정 수정
- 추론 서버 분리
  - 모델과 모델별 전처리를 외부 추론 서버(KubeSphere) 쪽으로 옮기고, 백엔드는 재료(통합·가명화된 거래와 엔티티 유형·국가)만 보내도록 계약을 정하여 모델이나 입력 특성이 바뀌어도 백엔드 계약은 그대로 유지되도록 설계
  - 추론 서버 코드를 별도 폴더로 분리하여 이미지 배포 없이 추론 서버에서 바로 실행하도록 하고, dev 분석은 KubeSphere 추론 서버만 사용하도록 설정
  - 백엔드 테스트 240개·추론 서버 테스트 37개·배포 도구 테스트 65개 통과
- dev 배포 실패 원인 분석 및 dev DB 재생성
  - dev 배포가 실패·롤백된 원인이 dev DB가 옛 스키마 이력을 가지고 있기 때문임을 확인
  - 배포 사전 점검이 빈 DB를 "진행 중 작업 없음"으로 판단하도록 수정하고, 운영 DB는 거부하고 dev DB만 백업·재생성하는 도구를 만들어 dev DB를 새 스키마로 재생성
- 이진분류 모델을 팀원 GNN 모델(v10)로 교체
  - 팀원 모델의 입력 생성(거래별 2홉 그래프)을 추론 서버에 구현하고, 거래마다 DB를 조회하던 방식(하루 약 4.5시간 예상)을 메모리 내 그래프 구성으로 바꿔 같은 결과를 내도록 개선
  - 로컬 데모 하루치(115,270건) 처리 12분(추론 약 7분, CPU), 의심 거래 1,690건·Alert 327건으로 기존 시연 모델(의심 34,664건·Alert 4,481건) 대비 현실적인 수준 확인
  - 추론 서버가 요청을 받지 못한 경우 같은 요청을 다시 보내고 대기하도록 하고, 서버가 요청을 거절하면 원인 코드와 함께 즉시 실패하도록 수정
- dev 환경 v10 모델 연동 및 연속 실행
  - Windows에서 업로드할 때 모델 설정 파일 줄바꿈이 바뀌어 검증에 실패하는 문제를 찾아 해결하고, dev와 KubeSphere 추론 서버 간 첫 분석을 성공
  - dev에서 9월 1일~8일 8일치 연속 분석 완료(하루 4.5~9.9분), 이력이 쌓여도 처리 시간이 늘지 않음을 확인
  - 조작패널의 실패 작업 재개 버튼이 자동 새로고침 때문에 동작하지 않던 문제를 수정하고, 추론 결과를 기다리는 정상 대기와 실패 후 재시도를 구분해 표시하도록 개선
- Alert 구성 근본 설계 검토
  - (진행 중) 장기 누적 시 Alert 구성 단계가 매일 전체 이력을 다시 묶는 것이 근본 문제임을 확인하고, 그날 새로 나온 의심 거래 주변(약 17일)만 읽어 기존 Alert에 붙이거나 새로 만드는 방식을 대안으로 정리
  - 파일 수집·적재, 거래 통합, 실행 관리, 분석 입력 장부, 추론 서버 분리는 유지하고 Alert 구성만 다시 만드는 방향 제안, 기존 방식 대비 품질 비교와 HI-Large 장기 비용 검증 방법 정리
- 프로젝트 문서 갱신
  - 저장소 README, API 문서, worker·은행 목업 문서와 작업 문서 목차를 현재 구조에 맞게 갱신
