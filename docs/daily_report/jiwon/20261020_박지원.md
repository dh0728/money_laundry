## 실적

- 추론 실패 날짜 이어서 재처리 기능 구현
  - 추론 서버에서 모델 계산이 실패하면 재개해도 같은 실패만 반복되고 남은 요청 기록 때문에 전체 초기화까지 막히던 문제를 확인
  - 재개 시 실패한 모델만 새 회차로 다시 계산하고, 이미 끝난 단계와 앞 날짜 결과는 그대로 두도록 백엔드와 추론 서버를 함께 수정(실패한 회차의 점수·Alert는 저장되지 않음)
  - 추론 서버가 다시 켜질 때 이전 계산이 남아 있지 않은지 확인한 뒤에만 새 회차를 받도록 하여 결과 덮어쓰기 방지
  - worker 테스트 239개·추론 서버 테스트 51개·Java 테스트 305개 통과, 계산 도중 추론 서버를 강제 종료한 뒤 재개하여 중단 없이 돌린 결과와 같음(의심 1,690건·Alert 327건)을 확인하고 dev에 배포
- 추론 서버 중단 원인 분석 및 복구
  - dev 9월 9일치 분석이 멈춘 원인이 KubeSphere 파드 재시작으로 손으로 띄워 둔 추론 서버와 앞단 HTTPS 프록시가 함께 사라진 것임을 확인
  - 추론 서버와 프록시를 다시 띄우고 멈춘 날짜만 재개하여 완료(의심 43건·Alert 6건), HI-Small 시연 10일치 dev 분석 전체 완료
- 시연 데이터 HI-Medium 전환
  - HI-Small은 시연에 쓸 수 있는 기간이 10일뿐이라, 앞쪽 예열 구간을 빼고도 시연할 날이 남도록 16일치를 쓸 수 있는 HI-Medium으로 전환 결정
  - 하루 거래량이 기존 시연과 비슷하도록 초대형 은행 1곳을 제외한 상위 10개 은행을 골라 16일치 시연 파일 생성(총 171만 건), 원본과 은행·날짜별 건수와 금액 대조 통과
  - 로컬에서 앞 3일 분석을 먼저 확인한 뒤, dev의 은행 설정을 HI-Medium 10개 은행으로 교체하고 데이터를 다시 적재
  - 첫 1~2일은 거래 이력이 짧아 의심 거래가 많이 나오므로, 분석은 그대로 하고 화면 조회 범위에서 제외하는 방식으로 정리
- dev HI-Medium 16일 연속 분석
  - 16일 모두 정상 완료, 예열 구간 이틀은 의심 1,937건·1,351건, 이후 하루 의심 57~100건·Alert 4~17건으로 안정
  - 하루 처리 시간은 주말 6.9분, 평일 14~27분

## 문제 상황
- 날짜가 쌓일수록 평일 하루 처리 시간이 14분 → 27분으로 늘어나 어느 단계에서 늘어나는지 확인 필요
- KubeSphere 파드가 재시작되면 추론 서버와 HTTPS 프록시가 자동으로 다시 뜨지 않아 팀원·관리자와 자동 실행 설정 필요
- Alert 구성 재설계 방향(새 의심 거래 기준으로 묶기) 결정 필요
