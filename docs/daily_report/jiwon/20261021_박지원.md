## 실적

- HI-Large 규모 분석 및 추론 입력 전송 구조 검토
  - 실서비스 규모 부하 테스트를 위해 HI-Large 원본을 집계하여 실거래 97일, 총 1억 8천만 건, 하루 중앙값 193만 건임을 확인
  - 현재 구조는 매일 그날까지의 누적 거래 전체를 추론 서버로 보내므로, 누적 약 300만 건에서 추론 서버 입력 한도(파일당 256MB)에 닿아 상위 10개 은행 기준 10일째 전후에 멈출 것으로 계산
  - 백엔드가 모델 피처를 계산해 보내는 방식과 추론 서버가 이력 사본을 보관하고 새 거래만 받는 방식의 장단점·리스크를 비교하여, 팀 회의에서 모델과 무관하게 계약을 유지할 수 있는 이력 사본 방식으로 합의
  - 의심 거래 기준은 모델 권장 임계값(0.434)을 그대로 사용하기로 확정
- 추론 서버 이력 사본 보관 및 변경 거래만 전송 구현
  - 추론 서버가 원장 사본을 보관하고, 백엔드는 지난 반영 위치 이후 바뀐 거래만 보내도록 변경, 위치가 맞지 않으면 그 모델만 전체 입력으로 다시 보내 사본을 새로 만들도록 처리
  - 같은 요청이 다시 와도 한 번만 반영되도록 하고, 새 사본을 다 쓴 뒤 한 번에 교체하며 파일 잠금과 전체 거래 수 대조로 사본 어긋남을 감지하도록 보강, 과거 거래 정정 시에는 사본 전체를 재구축
  - worker 테스트 243개·추론 서버 테스트 60개·Java 테스트 305개 통과
  - 로컬 HI-Medium 16일 연속 실행에서 첫날만 전체를 보내고 나머지 15일은 바뀐 거래만 보냈으며, 매일 사본으로 만든 모델 입력이 전체 전송 때와 완전히 같고 점수 차이 0건임을 확인한 뒤 dev와 추론 서버에 배포
- HI-Large 부하 테스트 준비
  - (진행 중) 초대형 은행을 포함한 상위 10개 은행 97일치 시연 파일 생성(거래 2,607만 건, CSV 970개, 5.5GB, 하루 중앙값 30만 건), 원본과 대조 통과
  - dev 은행 설정을 HI-Large 10개 은행으로 교체하는 절차를 정리하고, 30일치를 먼저 돌려 처리 시간과 DB 크기 추세를 확인하도록 계획

## 문제 상황
- dev와 운영 DB가 같은 RDS를 쓰고 있어, HI-Large 적재 시 DB 크기(추정 26~80GB)를 실측하며 저장 공간 확인 필요
- 같은 데이터를 다시 적재하면 v10 점수가 소폭 달라지는 현상(의심 1,352건 → 1,351건)이 있어 팀원 모델의 재현성 확인 필요
- KubeSphere 파드 재시작 시 추론 서버 자동 실행 설정 필요
