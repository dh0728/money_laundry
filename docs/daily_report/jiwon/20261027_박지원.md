## 실적

- 시연 데이터 LI-Large 전환 검토 및 시연 파일 생성
  - 학습(HI-Large)과 다른 데이터로 시연하기 위해 LI-Large를 쓸 때의 정답 누수·편향을 검토
  - 정답 열은 수집 단계에서 분리 저장되어 분석 계정이 읽을 수 없고, 모델 입력에 날짜·계좌 ID가 없어 364일 날짜 이동 후에도 정답 누수가 없음을 확인
  - LI-Large는 세탁 비율이 HI의 약 절반(0.0551% / 0.1120%)이고 패턴 세탁 비율이 16.29%(HI 56.47%)여서 시연 성능이 HI 테스트보다 낮을 것으로 추정(HI 탐지율 적용 시 재현율 15.8%·정밀도 34.7%), 세탁 비율이 58.34%로 왜곡된 원본 끝 구간은 제외
  - 은행 70을 포함한 상위 10개 은행 30일로 범위를 정하고 시연 파일 생성(거래 7,804,006건, 세탁 거래 8,120건, 하루 중앙값 289,124건, 1.61GB), 원본과 행 수·해시 대조 일치
- dev DB 용량 분석
  - 거래 1건당 DB 사용량이 3,585B임을 실측하고, 그중 은행 보고 원본 암호문이 약 942B(26%)로 가장 큰 비중임을 확인(테이블별 값은 마지막 통계 기준 추정)
  - 원본 암호문 제외, 분석용 거래 사본 축소, 점수 산출 후 모델 피처 삭제 등으로 거래당 약 2.2KB 이하까지 줄일 수 있는 절감안 정리(코드 변경 필요, 미적용)
- Alert 생성기 평가 기준 수립 및 평가
  - 포착·응집·순도·조사 부담·규칙 준수 다섯 기준을 세우고, 모델 의심 거래를 씨앗으로 쓴 경우와 세탁 거래 전체를 씨앗으로 넣은 경우를 나눠 재는 재현 도구 작성(운영 코드 변경 없음)
  - 규칙 위반 0건, 재실행·씨앗 순서 섞기 결과 100% 동일로 안정성 확인
  - HI-Medium·HI-Large(4개 은행) 기준 세탁 씨앗 포착률 65.35%·52.58%, 한 패턴이 한 Alert에 모이는 응집률 68.04%·16.40%, Alert 거래 중 세탁 거래 비율 22.40%·66.64%
- Alert 생성기 설정값 근거 검수
  - HI-Large 응집률이 낮은 원인을 찾기 위해 거래 간격·기간 상한을 30일까지 늘려 재현한 결과 씨앗 포착률 52.58% → 58.15%, 응집률 16.40% → 30.28%로 올랐으나, 설정값 출처를 다시 확인하여 시간 값이 세탁 행동이 아니라 합성 데이터의 기간 길이에 비례함을 확인(가장 긴 패턴 기간 HI-Small 96시간, HI-Medium 144시간, HI-Large 840시간)
  - 실데이터 조사 자료(대포통장 유출금 85% 이상이 24시간 안, 같은 상대와의 연속 거래 85%가 7일 안) 기준으로 현재 값(간격 7일·기간 14일)이 넉넉한 상한임을 확인하여 유지하고, HI-Large에 맞춘 30일 개선안은 철회
  - 금액 비율(0.8~1.25배)은 두 데이터셋 경유 거래의 96.3~98.6%를 담아 데이터와 무관하게 근거가 있음을 확인
  - 읽는 범위 30일은 응집률 +1.42%p, 하루 시간 8.74초 → 3.44초인 대신 여러 Alert로 나뉜 패턴이 57.52% → 59.28%로 늘어 60일 유지
  - 코드 주석과 API·worker 문서의 시간 값 근거 설명 수정(동작 변경 없음), 생성기 테스트 83개 중 82개 통과(1개는 추론 서버 폴더가 없는 실행 환경 문제)
- dev 배포 및 DB 재생성
  - dev 배포가 10/22 초기 스키마에 추가한 색인 때문에 스키마 체크섬 불일치로 실패하고 이전 버전으로 자동 복구된 것을 확인
  - 계정·은행 설정을 백업한 뒤 dev DB를 비우고 재배포, 설정 복원(계정 4, 은행 16,039, 보고 기간 10, 환율 15)과 분석 권한 부여까지 완료하여 Alert 구성 60일 범위·묶기 시간 상한 변경을 dev에 반영
- LI-Large dev 적재 및 은행 정보 충돌 해결
  - 첫 적재에서 10일치 보고 100개가 전부 보류되어 거래가 한 건도 통합되지 않은 원인이, DB 은행 표에 남은 HI 데이터셋 은행 이름과 LI-Large 은행 이름이 달라 거래 통합 단계가 신원 충돌로 판단한 것임을 확인(보고 은행 10곳 모두 이름 불일치)
  - 초기화로 보류 보고 348만 행·업로드 120개·작업 12개를 지워 RDS 5.30GB를 회수하고, 은행 16,039곳의 이름·국가를 비워 LI-Large 이름으로 다시 채워지도록 처리
  - 재적재 첫날 거래 384,844건이 원본과 같게 통합되고 보류 0건, 의심 기준값 0.434 적용 확인
- dev LI-Large 30일 연속 분석
  - (진행 중) 30일 중 5일 완료, 하루 처리 시간 30.3~60.4분 중 모델 추론이 약 80%
  - 1일째 의심 2,016건·Alert 379개, 2~4일째 하루 의심 7~17건·Alert 1~4개, 5일째(30일 중 최대 420,924건) 의심 1,431건·Alert 214개
- 조작패널 작업 관찰 시간 연장
  - 42만 건인 5일째 분석이 60.4분 걸려 패널의 1시간 관찰 한도를 넘기면서 자동 재생이 멈추는 문제를 확인
  - 하루 분석 시간 요구(6시간)에 맞춰 관찰 한도를 6시간으로 늘림, 패널 테스트 68개 통과

## 문제 상황
- dev RDS(30GB, 운영 DB와 공유)의 남은 공간 21.95GB가 남은 25일 필요량(약 21.7GB 추정)과 비슷하여, 마지막 1~2일 전에 저장 공간 증설 필요
- 5일째 의심 거래가 1,431건으로 2~4일째(7~17건)보다 크게 늘어 원인 확인 필요
- Alert 생성기가 정상 씨앗을 거의 걸러내지 못해(정상 씨앗의 Alert 포함 비율 HI-Medium 63.18%) HI-Medium Alert의 76.57%가 세탁 거래 없는 Alert임
- Alert 생성기의 시간 값은 합성 데이터로 검증할 수 없어 실제 기관 데이터 확보 전까지 현재 값 유지
