## 실적

- dev LI-Large 연속 분석 18일 완료
  - 은행 70을 포함한 10개 은행 데이터로 18일치(시연 날짜 07-31~08-17) 분석 완료, 점수 4,817,457건, 의심 3,745건, Alert 618개, 실패·보류 0건
  - 289,000건 규모 날의 하루 처리 시간이 29~36분 → 약 60분으로 늘었고, 이틀은 분석 입력 고정 구간이 7~10분 → 35~49분으로 늘어 90분대까지 걸림을 확인
  - 분석 입력 고정 단계가 처리 중 만드는 임시 공간이 누적량에 따라 1~1.5GB → 2.65~3.4GB로 커져, RDS(30GB)가 08-24분 전후에 찰 것으로 추정되어 08-18분에서 적재를 멈추기로 결정
- 추론 서버 결과 업로드 링크 만료 문제 해결
  - 30일 중 가장 큰 08-18분(420,739건)의 모델 추론이 61분 걸려, 추론 서버가 결과를 올릴 때 쓰는 S3 링크(유효 1시간)가 만료되어 실패한 원인 확인
  - 링크 유효시간을 하루 분석 시간 요구에 맞춰 6시간으로 늘림(서명 자격 증명 교체 주기상 최소 약 5시간 25분 보장), worker 테스트 249개·PostgreSQL 테스트 80개 통과
- Alert 유형 분류 결정트리 실험
  - Alert 생성기가 만든 거래 묶음을 그래프 단위로 세탁 8패턴과 비패턴 9종류로 분류하고, 판정 근거를 지나간 분기의 피처·임계값으로 남기는 결정트리 작성(운영 코드 변경 없음)
  - 처음에는 4개 은행으로 잘린 HI-Large 원장으로 시험하여 패턴 Alert 정답률이 11.53%였고, 원장에 패턴 거래의 19.82%만 남아 생성기가 완벽해도 정답률 상한이 61.81%임을 확인
  - 같은 실험에서 부채꼴 반대편의 단독 거래를 붙이도록 생성기를 고쳐 봤으나 정답률 변화가 없어(11.53% → 11.30%) 적용하지 않음
  - 학습은 HI-Large 정답 패턴(거래 3건 이상), 시험은 자르지 않은 LI-Small 원장 전체(6,924,049건)를 생성기에 넣어 만든 Alert로 다시 구성하여, 검증 정확도 98.50%, 거래 3건 이상 패턴 Alert 정답률 96.83%
  - 같은 시험에서 계좌로 이어진 패턴 묶음 166개 중 94.58%가 Alert 하나에 모두 들어가고 96.91%가 다른 거래와 섞이지 않아, 생성기가 패턴을 잘 묶음을 확인
- 중간발표 자료 정리
  - 발표 담당 팀원이 이해할 수 있도록 이력 누적에 따른 분석 속도 저하, 추론 서버 분리, Alert 묶기 기준 등 9가지 문제 상황별 접근 방식과 해결 방향 정리
