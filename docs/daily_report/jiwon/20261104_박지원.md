## 실적

- Alert 생성기 근본 설계 검토: 평가 기간 정정 후 재비교
  - 정상 거래가 끝난 9/16 이후 기간(9/17~9/28)이 평가에 섞인 것을 확인하여, 해당 기간을 빼고 HI-Medium(9/16까지)과 HI-Small(9/10까지) 비교 전체 재실행
  - HI-Medium 302개 기준 통째 포함 비율: 현재 생성기 56.62%, 금액 비율 연결 64.24%(Alert 거래 1.10배, 비세탁 비율 9.79%), 이중 임계값 0.1 69.21%(1.24배, 18.04%), 이중 임계값 0.05 70.20%(1.39배, 25.50%), 둘의 조합 72.85%(1.28배, 19.64%, 95% 신뢰구간 67.55~77.81)
  - HI-Small에서도 순위 동일(현재 생성기 57.89% → 조합 77.63%)
  - 기간 전체를 한 번에 묶는 방식은 59.93%로 매일 묶는 현재 방식(56.62%)과 3.31%p 차이
- Alert 생성기 근본 설계 검토: 다른 합성 데이터 검증과 최종 정리
  - SAML-D(거래 9,504,852건, 정답 라벨 입력)에서 통째 포함 비율 20.45%(95% 신뢰구간 14.77~26.70), 14일보다 긴 패턴 76개는 하나도 통째로 묶이지 않고 14일 이내 패턴은 36.00%
  - 묶음 기간 제한을 30일로 늘린 진단 실행에서 78.41%로, HI 데이터에 맞춘 14일·7일 제한이 다른 합성 데이터에는 그대로 맞지 않음 확인
  - 최종 추천: 현재 생성기 앞에 이중 임계값 0.1과 금액 비율 연결을 더하는 조합(56.62% → 72.85%, Alert 거래 1.28배, 비세탁 비율 7.76% → 19.64%), 차선은 금액 비율 연결 단독
  - 검토 문제, 방법, 결과, 한계를 문서로 정리
- 의심 기준 조절 시험
  - HI-Small에서 의심 기준만 올리면 0.434 57.89% → 0.8 35.53%로 떨어지나, 조합을 더하면 0.434~0.6 77.63%, 0.7~0.8 75.00% 유지
  - 조합 적용 시 의심 기준을 올릴수록 하루 Alert 거래 417.9건 → 287.2건, 비세탁 비율 40.77% → 21.58%로 감소
  - HI-Medium은 조합 적용 시 의심 기준 0.434·0.6·0.8 모두 72.85%, 하루 Alert 거래 1,545.2건 · 1,468.3건 · 1,366.2건, 비세탁 비율 19.64% · 16.04% · 11.82%
  - 의심 기준을 0.1로 낮추는 방식은 75.00%이나 Alert 거래 2.19배, 비세탁 비율 55.69%로 제외
- Alert 대표유형 집계 방식 변경 구현
  - 유형 1위 개수 세기를 확률 곱하기로 변경: 1위 유형이 NON_PATTERN인 SEED는 제외하고, 남은 SEED마다 6개 유형 확률의 로그(0 확률은 1e-6으로 대체)를 더해 가장 큰 유형을 대표유형으로 결정, 남은 SEED가 없으면 패턴 미특정, 동점이면 혼합
  - 대표유형 비율은 1위 유형이 대표유형과 같은 SEED의 비율로 정의
  - 신규 테스트 3개(기존 코드에서는 실패), 백엔드 테스트 308개 중 304개 통과(2개 건너뜀, 2개 실패는 변경 전 코드에서도 동일하게 실패), API 문서 수정
- dev 업로드 실패 원인 파악
  - dev HI-Medium 분석 중 은행 12 업로드 1건이 실패, 9/8까지 분석 결과는 정상 확인
  - 업로드 URL을 15분 안에 다시 요청하면 서버가 409로 거절하고, 조작패널이 이때 파일 업로드를 건너뛰고 완료 알림을 보내는 구조가 원인

## 문제 상황
- 묶음 기간 제한(14일·7일)이 HI 데이터에 맞춰져 있어 SAML-D처럼 패턴이 긴 데이터에서는 통째 포함 비율이 크게 떨어짐
- 통째 포함 비율이 높은 방법일수록 Alert 거래와 비세탁 비율이 늘며, 하루 검토량 한도는 아직 정하지 않음
- 업로드 URL 재요청 시 409로 파일이 빠지는 문제는 서버 수정 전까지 15분 뒤 재전송으로만 복구 가능
