## 실적

- Alert 생성기에 SEED 보강 단계 추가
  - 기존 Alert는 거의 SEED(의심 거래)만으로 구성되어 의심 기준 0.434 미만 거래가 Alert 거래의 3.54%에 그치고, 이진분류 입력에서 끊긴 패턴 131개 중 97개가 모델이 놓친 거래에서 끊김
  - 의심 기준은 0.434로 유지하고 구조만 추가하여, 기준 변경과 구조 변경의 효과가 섞이지 않도록 진행
  - 생성기 앞에서 SEED와 계좌를 공유하는 점수 0.1 이상 거래, SEED에서 7일 안에 받은 금액의 0.5~1.05배를 넘긴 거래를 최대 6단계까지 따라가 점수 0.01 이상인 거래를 SEED로 보강, 매 분석마다 60일 범위로 다시 계산
  - 보강 기준값은 이진분류 모델별 설정에 두고, 값이 없는 모델은 이 단계를 건너뛰도록 구현
  - 신규 테스트 7개, worker 테스트 256개 통과, HI-Medium 9/8~9/16 운영 코드 재실행 결과 Alert 3,014개의 구성 거래가 실험과 동일, 통째 포함 비율 56.62% → 72.85%, 하루 Alert 거래 1,545.2건(1.28배), 추가 시간 하루 5.7초 이내
- Alert 생성기·대표유형 변경 dev 반영
  - 유형 분류 모델 교체 후 맞지 않게 된 worker 파이프라인 테스트 기대값 수정(13개 통과)
  - Alert 대표유형 확률 곱하기, SEED 보강 단계, 테스트 수정을 dev에 병합하여 배포
  - 조작패널의 시연 데이터 초기화가 확인 단계에서 15초 제한을 넘겨 실패하여, 브라우저에서 같은 초기화를 직접 실행해 거래 3,871,444건, Alert 1,516개 정리
- 업로드 URL 재요청 시 업로드가 실패하는 문제 수정
  - dev 재생 중 은행 0·은행 20에서 재발, 은행 20은 업로드 URL이 발급됐으나 S3에 파일이 없음 확인
  - 원인: 조작패널이 URL 응답을 30초 안에 받지 못해 다시 요청하면 서버가 409로 거절하고, 패널은 파일 업로드 없이 완료 알림을 보내 400으로 실패
  - 같은 은행·파일명·기준일·크기이고 URL이 아직 유효하면 409 대신 기존 업로드 번호와 URL을 다시 주도록 수정, 진행 중·완료된 업로드는 409 유지
  - 신규 테스트 1개, 업로드 테스트 51개 통과, API 문서 수정 후 dev 병합

## 문제 상황
- 조작패널의 시연 데이터 초기화가 dev DB가 클 때 확인 단계에서 15초 제한을 넘겨 실패함(브라우저에서 직접 실행으로 우회)
- SEED 보강 단계를 넣은 뒤 Alert 대표유형 정확도 변화는 측정하지 않음
