## 실적

- 유형 분류 대상을 의심 거래로 제한
  - 분석 대상 거래 전부를 유형 분류 모델(SALT-GNN R)에 보내고 있었으나, 이 모델은 세탁 거래로만 학습된 모델임을 확인
  - 이진분류 점수를 받은 뒤 의심 기준 이상인 거래만 유형 분류를 요청하도록 순서 변경, 의심 거래가 없는 날은 요청하지 않음
  - 의심 기준은 이진분류 모델 설정 한 곳에서만 읽어, 의심 표시와 유형 분류 대상이 같은 값을 쓰도록 구현(기준 조정 시 한 곳만 수정)
  - HI-Medium 10개 은행 16일 기준 유형 분류 대상 1,710,041건 → 4,449건(0.26%), 가장 많은 날 170,961건 → 1,937건
  - worker 테스트 259개, 백엔드 테스트 310개 통과, dev 병합·배포
  - DB 초기 스키마 변경(정상 거래는 유형 값 없음)으로 dev DB를 비우고(거래 3,215,187건, Alert 3,569개) 보고 은행 설정 복원(은행 20, 보고 기간 20, 계정 4, 환율 15)
- 업로드 URL 재발급 수정 dev 배포
- 시연 dev 7일 백필 모드 추가
  - 11/03에 정한 7일 백필이 실험에만 적용되고 시스템에는 없음을 확인하여, 시연 조건을 측정 조건과 맞추도록 추가
  - 백필 날짜는 거래 통합과 분석 입력 고정까지만 하고 모델 호출 없이 완료, 그날 거래는 점수 대상에서 빠지고 이후 분석의 모델 이력과 Alert 연결 거래로만 사용, 분석을 한 번 시작한 뒤에는 백필 요청 거절
  - 조작패널에 백필 전송 추가, DB 구조와 모델 변경 없음
  - 신규 테스트 3개, 백엔드 테스트 312개(2개 건너뜀), 조작패널 테스트 69개 통과, dev 배포 후 8/31~9/6 백필 완료
- 백필 추가 후 일반 분석 요청이 400으로 거절되던 문제 수정
  - 원인: 요청 본문의 백필 값을 기본값 없는 타입으로 받아, 값을 보내지 않는 일반 분석 요청을 JSON 변환 단계에서 거절(기존 테스트는 JSON 변환을 거치지 않아 놓침)
  - 값이 없어도 되는 타입으로 바꾸고 값이 없으면 일반 분석으로 처리, JSON 변환까지 거치는 테스트 추가, 관련 테스트 34개 통과 후 dev 병합
