## 실적

- 시연 데이터 범위 비교(HI-Medium 원본 전체 vs 20개 은행)
  - 은행별로 나눴다가 거래 통합으로 다시 합치는 과정에서 빠지는 거래 0건 확인(dev 16일 모두 건수 일치)
  - 9/1~9/16 기준 원본 전체 31,891,251건 중 20개 은행 5,482,246건(17.19%), 세탁 거래 31,146건 중 7,766건(24.93%), 하루 거래 중앙값 1,930,330건 → 361,318건
  - Patterns.txt 패턴 중 거래가 빠짐없이 들어 있는 패턴은 원본 2,018개 → 20개 은행 145개(7.19%)로, 20개 은행 거래의 93.20%는 상대 은행이 20개 밖에 있음
- 팀원 새 이진분류 모델(Multi-FraudGT + HGB) 검토
  - 입력은 기존과 같은 거래·계좌 정보로 만들 수 있어 요청 형식, DB, 백엔드 변경 없이 추론 서버 모델 폴더와 worker 설정만 바꾸면 교체 가능함을 확인
  - 그대로 넣으면 내용이 완전히 같은 거래 중 하나에만 점수가 나와 그날 분석이 실패하는 문제 확인, 모델 입력은 그대로 두고 빠진 거래에 같은 점수를 붙이는 방식으로 정리
  - 의심 기준은 팀원 검증값 0.195로 결정(이후 조정 가능), SEED 보강 기준값은 기존 값(0.1, 0.01)을 임시로 두고 결과를 본 뒤 재조정하기로 결정
  - 팀 합의에 따라 성능 평가는 Patterns.txt 소속 여부로 패턴 세탁과 무패턴 세탁을 나눠 보기로 정리

## 문제 상황
