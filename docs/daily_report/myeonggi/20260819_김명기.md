## 실적

- 화면 설계서 Login part Flow Chart를 작성해 팀장 승인을 받음. 정상 로그인, 임시 비밀번호 최초 변경, 비밀번호 재설정, 로그인 3회 실패 시 접근 거부까지 네 개 경로를 그림

## 문제 상황

- 승인본을 자체 점검한 결과 다시 손볼 곳이 나옴. 임시 비밀번호 상태 판정이 비밀번호 검증보다 앞에 있어 인증을 건너뛸 수 있고, 계정 존재 여부에 따라 오류 문구가 갈리며, 3회 실패 카운트가 없는 이메일에만 걸려 있음. 내일 수정함
- 비밀번호 16자리·4종 조합 기준의 근거와, 인증 화면을 제출 문서용으로 둘지 9/30 구현 대상에 넣을지는 팀장 결정이 필요함
- 서브그래프의 lookback 기간과 hop 수가 정해지지 않아 관계 graph 화면에 무엇이 들어오는지 확정할 수 없음

## 내일 계획

- Login Flow Chart 수정. 완료 기준은 계정 확인과 비밀번호 확인을 자격증명 검증 한 단계로 합치고, 실패 카운트를 그 단계에 붙이고, 임시 비밀번호 판정을 검증 뒤로 옮기는 것
- 멘토링에서 서브그래프 lookback과 hop 수를 확인. 완료 기준은 graph 화면에 들어올 데이터 범위를 한 문장으로 적을 수 있는 상태
