## 실적

- 색 체계를 테두리·배경·글자 세 갈래로 다시 정리하고, 그 위에서 버튼을 다시 만들었다. 크기 세 가지와 채움 방식 세 가지, 색 일곱 가지의 조합으로 세웠고 같은 모양이 중복되지 않도록 전부 대조했다. 버튼을 쓰던 사이드바와 화면 위쪽도 새 버튼으로 교체했다.
- 모든 화면에서 아이콘이 안 보이거나 위치가 튀던 문제를 찾아 고쳤다. 아이콘 원본을 한곳에 정리하는 과정에서 정리용 상자가 크기를 제멋대로 늘려, 16과 24 크기 아이콘 400개가 전부 찌그러진 상태였다. 원본이 어긋난 것이라 화면 쪽에서는 고쳐지지 않았다. 크기를 직접 되돌리고 시연 화면에서 정상인 것까지 확인했다.
- 표는 직접 만들지 않고 검증된 공개 부품을 가져다 쓰기로 방향을 바꿔 테스트 중이다. 직접 만든 표는 열 너비가 계속 어긋났고, 앞으로 네 화면에 표가 여러 개 들어가므로 한 번 쓰고 마는 표보다 형태를 쉽게 바꿀 수 있는 부품이 낫다고 판단했다.

## 문제 상황

- 화면에서 보여주기로 한 판단 근거를 무엇이 만들어낼지가 정해져 있지 않다. 알림·에피소드 상세에 "이 패턴의 근거에 얼마나 해당하는지", "보낸 쪽과 받는 쪽이 서로 무관하다" 같은 항목을 넣어 뒀는데, **탐지 모델의 출력으로는 이런 문장이 나오지 않고 데이터베이스를 조회해도 거래 내역만 나온다**는 지적을 받았다. 규칙 기반으로 잡아 걸린 근거를 그대로 보여주거나, 설명 전용 모델을 따로 두거나, 거래 그래프를 언어 모델에 주고 설명을 생성하게 하는 세 가지 선택지가 있다. 정해지지 않으면 그 영역은 화면만 있고 채울 내용이 없다. 모델 담당자분들과 함께 정해야 한다.
- 멘토링에서 나온 모델 쪽 지적을 공유한다. 거래 한 건만 넣으면 모델이 판단할 정보 자체가 없으므로 그 계좌의 과거 이체 이력 요약값(최근 1일·3일·1개월 유입 계좌 수, 금액 합계, 빈도 등)을 함께 넣어야 한다. 학습과 검증을 무작위로 섞으면 결과가 의미 없으므로 시간 순서를 지켜 잘라야 한다. 테스트 데이터에는 개수를 늘리는 보정을 적용하면 안 된다. 이미 알려진 여덟 가지 패턴은 규칙으로 잡는 편이 낫고, 그러면 위에서 말한 근거 설명이 따라온다.
- 어제 계획한 알림 목록·에피소드 목록 본문 채우기와 에피소드 상세 배치를 하지 못했다. 버튼과 아이콘 기반이 어긋난 상태에서 화면을 쌓으면 다시 손봐야 해서 기반부터 정리했고, 아이콘 문제가 예상보다 커 시간이 더 들었다.

## 내일 계획

- 기존 서비스 조사를 화면 단위로 기록한다. 완료 기준은 화면마다 무엇을 하려는 화면인지, 무엇이 편하고 불편한지, 우리 화면에 채택할지를 직접 적은 기록이 남는 것이다. 우리 서비스가 웹이므로 모바일 앱 구조는 기준으로 삼지 않고 웹 화면과 관제·모니터링 계열을 본다.
- 사이드바에 역할별 표시 기능을 넣는다. 완료 기준은 조사관 화면과 관리자 화면의 메뉴가 설명 없이도 달라 보이는 것이다.
- 멘토링 사전 자료를 보낸다. 완료 기준은 토요일 저녁까지 현재 화면 상태와 질문을 정리해 전달하는 것이다. 9월 14일 월요일 밤 10시에 프론트엔드 멘토링이 있다.
- 중간 발표 시연 범위에서 데이터 적재 화면을 뺀다. 관리자용 화면이라 조사관 업무 흐름에 넣을 필요가 없다고 판단했다. 화면을 없애는 것이 아니라 관리자 화면 차례로 미루는 것이고, 처리 현황 요약은 대시보드에 남긴다. 멘토링에서도 같은 화면을 두고 "시스템 운영자가 보는 화면 같다"는 같은 지적이 나왔다.
