## 실적

- 화면 설계 초안을 다섯 차례 고쳐 만들었다. 처음에는 백엔드 참고안을 거의 그대로 옮겨 차이가 없었으므로, 직접 만든 화면 틀(상단 시계·업무 건수·접히는 메뉴)을 입히고 기존 서비스 7곳(Lucinity·elastic 등)의 화면을 모아 목록 옆 미리보기, 조건 필터, 자금 흐름도와 관계 그래프 구조를 가져왔다. 지금은 대시보드·알림·에피소드의 목록과 상세 14장이 디자인 파일에 있고, 중간 발표 시연 흐름에 맞춰 데이터 수집 화면은 뺐다.
- Jira의 프론트엔드 일감을 다시 정리했다. 지금 기준으로 무엇을 할지 불명확해 팀원들이 진행 중으로 오해할 수 있던 일감 20개를 지우고, 남은 일을 9월 16일까지의 사용자 흐름·화면 설계와 9월 30일까지의 중간 발표 준비 두 묶음으로 나눠 제목과 기간을 새로 잡았다. 화면설계서 작성 일감을 새로 추가했다.
- 금요일에 계획한 사이드바 역할별 표시와 멘토링 사전 자료 발송을 끝냈다. 관리자 전용 메뉴 세 개를 역할에 따라 켜고 끌 수 있게 했고, 디자인 파일은 기초·부품·화면 묶음으로 페이지를 다시 나눴다. 작업 중 화면 설계서와 흐름도 일부가 망가져 이전 버전으로 되돌린 뒤 직접 다시 손봤다.

## 문제 상황

- 알림·에피소드 상세에 보여줄 판단 근거를 무엇이 만들지 아직 정해지지 않았다. 화면 설계 초안에서는 해당 영역을 점선으로 두고 "생성 주체 미정"이라고 표시해 뒀다. 규칙으로 걸린 근거를 그대로 보여줄지, 설명 전용 모델을 둘지, 언어 모델이 설명을 만들게 할지 모델 담당자분들과 함께 정해야 한다.
- 관계 그래프와 자금 흐름도 화면을 채우려면 거래 데이터를 받는 형태가 정해져야 한다. 같은 이체가 보낸 은행과 받은 은행에 한 번씩 찍히는 중복을 어디서 합칠지, 그래프를 매번 계산할지 저장해 둘지는 조회 시간을 재 본 뒤 정하기로 했으므로 백엔드 담당자분의 결정을 기다린다.
- 에피소드 위험도를 소속 알림 중 가장 높은 점수로 쓸지 모델 담당자분들의 동의가 필요하다. 에피소드 목록 정렬과 상세 상단 표시에 이 값을 쓰고 있다.

## 내일 계획

- 오늘 밤 멘토링 답을 반영해 작업 순서와 지금 만든 디자인 부품을 계속 쓸지 정한다. 완료 기준은 명확해진 일만 기간과 함께 Jira에 다시 등록하는 것이다.
- 9월 16일 수요일 팀 공유 전에 화면 설계를 확정한다. 완료 기준은 팀원이 대시보드·알림·에피소드 화면만 보고 조사 흐름을 설명 없이 따라갈 수 있는 것이다.
- 기존 서비스 조사를 화면 단위로 기록한다. 완료 기준은 화면 설계에 가져온 구조마다 어느 서비스의 어떤 화면에서 왜 가져왔는지 직접 적은 기록이 남는 것이다.
