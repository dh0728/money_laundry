## 실적

- 시연용 프로토타입(v24)을 실제 웹앱으로 옮김. 대시보드, 거래 내역, Alert·Episode 목록과 상세, 자금 흐름 그래프, 전역 검색을 구현하고 9/28 회의에서 정한 판정 선택지(정상 / 이상거래 → Alert 단독·기존 Episode 연결·새 Episode 생성)와 처리 상태(처리 전·중·완료)를 반영함. 알림 네 종류와 사이드바 미처리 숫자를 추가하고, 화면을 반으로 나눠 쓰는 좁은 폭(640px)에서도 요소가 겹치지 않게 다듬음.
- 백엔드가 dev에 반영한 서버 로그인을 연결함. 로그인·로그아웃, 새로고침 뒤 로그인 유지, 조사자·관리자별 수정 권한을 넣고, 지금 제공되는 대시보드·거래·Alert/Episode API를 연결함. 알림과 AI 도우미는 API가 없어 시연용 데이터로 둠. 작업은 frontend에 병합했고 로컬 테스트 91개와 빌드를 통과함.
- 화면 설계서와 흐름도를 웹앱 기준으로 최신화함. 화면 설계서에 메뉴 구조도, 흐름도 5장, 화면 12장(로그인부터 계정까지)의 캡처와 설명, v01~v25 변경 이력을 채우고, 글꼴·색을 디자인 시스템에 맞췄으며 전체 26장의 머리글·페이지 번호를 정리함. 캡처가 설명을 가리던 배치도 고쳐 PDF로 내보내 팀 저장소 docs 브랜치에 올림. 흐름도에는 로그인·권한·판정·검수 넘기기 흐름을 새로 그리고 이전 기준은 지우지 않고 표시해 둠.

## 문제 상황

- 테스트 서버 주소와 조사자·관리자 계정이 없어 실제 서버에서 로그인·권한·조회·저장을 확인하지 못함. 백엔드 담당의 전달이 필요함.
- 알림·AI 도우미 API가 없고, 거래에서 원본 Alert와 조사 사건을 잇는 값도 정해지지 않음. 백엔드와 협의가 필요함.

## 내일 계획

- 서버 정보를 받는 대로 로그인 → 조회 → 본인 담당 건 수정 → 로그아웃과 권한 거부를 실제 서버에서 확인한다. 완료 기준은 두 역할 모두 기대대로 동작하는 것.
