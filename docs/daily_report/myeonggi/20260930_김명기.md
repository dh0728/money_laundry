## 실적

- 실제 API에 연결된 dev 대시보드를 확인하고, 로컬 화면과 live 화면의 차이를 검수함. 헤더 탐색·전역 검색, 대시보드, RDR 9000, Alert·Episode 상세의 배치·차트·선택 동작과 실데이터 표시를 점검함.
- mock과 live의 화면 경로를 통합하고 API 미제공 값을 빈 상태로 표시하는 방향을 정리함. 추가 검수에서 승인한 화면 구성과 다른 부분이 남아 있어, 기존 UI를 반복 수정하는 대신 화면 구성과 API 명세를 확정한 뒤 재구축하기로 결정함.
- 기존 웹앱의 소스·설정·자산 247개 경로를 백업하고 무결성을 확인함. 승인한 화면 구성과 수정 요구사항을 정리한 뒤, `fe/work`의 기존 UI를 제거하고 최소 실행 골격만 남김. 빌드·lint·diff 검사를 통과했으며, 재설계 준비 커밋 `69db9842`의 원격 반영을 확인함. `frontend` 통합은 보류함. 관련 이슈: MONEY17-167.
- 팀장 작성 구상을 바탕으로 [중간발표 슬라이드](https://www.figma.com/slides/r9io2JmaiCeoGtfaByIfDV) 16장과 발표자 대본을 정리함. 솔루션, 초기 모델 PoC 결과, 현재 MVP 구현 현황과 이번 시연 범위를 구분해 설명을 보강함.
- 중간발표 자료의 로컬 컴포넌트·Auto Layout·색상 변수·텍스트 스타일을 정리하고 기획발표의 시각 자료를 복원함. 검은 헤더와 진행 바를 유지하고 무채색 강조·주의용 빨강을 적용함. Pretendard 스타일, 5번 카드 모서리, 9번 화살표 수평 정렬, 10번 카드 높이를 수정하고 발표 화면을 검수함. 미사용 LIBRARY 요소를 정리하고 숨긴 슬라이드는 LIBRARY에만 두도록 확인함.

## 문제 상황

- 로컬 수정 화면과 기존 승인 화면 사이에 차이가 반복돼 웹앱 재구축 기준 정리가 필요함. 현재 dev 시연본은 Backend 담당자가 시연에 문제없다고 확인한 상태이며, 재설계 준비본은 통합·배포하지 않음.
- 일부 화면에 필요한 API와 데이터가 없어 빈 상태 처리가 필요함. 새 UI 구현 전 Backend 담당자와 응답 항목·저장 동작을 대조해야 함. RDR 9000은 LLM 연동 완료 상태가 아니므로 시연 설명에서 구분해야 함.
- 발표자료 편집 중 폰트 도구의 Pretendard 인식 제한과 헤더 글자 누락으로 검수 시간이 늘어남. 기존 스타일을 통해 서체를 적용하고 헤더 표시를 수정해 발표 화면에서 확인함.

## 내일 계획

- 팀과 중간발표 내용·대본을 최종 확인하고, 실제 dev에서 거래 조회 → Alert 검토 → Episode 생성·조회 시연 동선을 리허설함.
- 승인 화면 구성과 API 명세를 대조해 웹앱 재구축 기준을 확정함. API 미제공 항목과 저장 동작을 정리하고, 합의한 기준에 따라 새 UI를 구현할 준비를 마침.
