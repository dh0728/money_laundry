## 실적

- 실험 기준 5건 확정 (팀 협의) — 무패턴 양성은 학습·평가에서 전부 제외하고 패턴 재현율만 보기, 결제방식 피처 미포함, 계좌 피처는 구간 끝 한 번이 아니라 날짜별 누적, GPU 사용 제한, SALT 확인 후 Multi-FraudGT + HGB 순서
- 패턴 전용 피처 정리 — 무패턴을 빼고 보면 41종 중 23종을 제거해도 성능이 유지됨을 확인하고 18종 구성을 권장안으로 선정 (AP 0.966 / 재현율 99.1%, 41종과 사실상 동일). 입력은 HGB 22종 → 16종, GNN 33종 → 11종으로 축소
- 제거 대상의 성격 확인 — 빠지는 23종은 주로 GNN 전용 등록 정보(계좌 유형·국가)이고, HGB 전용 8종은 대부분 패턴 탐지에 기여. 41종 중 일별 누적형이 정확히 18종임도 정리
- 팀원 보고서와 대조 — 유형·국가 계열이 불필요하고 당일 흐름·금액 대비 계열이 필요하다는 결론은 일치. 결제방식이 없는 조건에서는 18종 구성이 팀원 공통 구성보다 정밀도가 크게 높음
- 세탁 묶음 구조를 세 데이터셋 비교 — HI-Large 패턴은 묶음당 여러 건으로 이어지는데, HI-Large 무패턴과 TransXion은 대부분 거래 1건짜리 단발 묶음이고 SAML-D는 반대로 거의 전부 여러 건으로 이어짐
- TransXion 세탁 표시의 구조적 문제 발견 — 단발 묶음 전부가 같은 두 계좌 사이에 정상 표시 거래를 8시간 내에 끼고 있고 순서·금액으로 구분되지 않음. 100건 이상 묶음 2개는 상인 한 명이 개인 다수에게 보내는 형태로 올바른 묶음임을 확인
- 묶음 유형별로 볼 수 있는 HTML 비교 화면과 그림·결과 문서 작성
- SALT-GNN 재학습 진행 — 원본 전처리부터 다시 돌려 5개 구성을 함께 학습 중이고, 중간 모니터 기준으로는 피처를 줄일수록 성능이 단계적으로 낮아지는 추세
- 후속 실험 연결 — SALT 종료 시 Multi-FraudGT + HGB가 자동으로 이어져 두 가지 피처 조합을 비교하도록 구성


## 문제 상황

- TransXion은 세탁 표시 거래의 대부분이 같은 계좌쌍의 정상 거래와 구분되지 않아, 이를 가르지 못하면 Test 정밀도 상한이 41.6%
- 검증에서 정밀도 70%로 맞춘 임계값이 Test에서는 61%대로 내려감
- 피처 축소 결론은 LightGBM 기준이라 HGB 쪽만 확정 상태이고, GNN 쪽은 재학습 결과를 봐야 확정 가능
- 계정 메모리 상한에 두 번 닿음 (넘친 것이 파일 캐시라 작업 중단은 없었음)
- SALT 전처리 산출물이 82GB를 점유 중이고, SAML-D 유형 설명은 2차 출처 기반이라 원 논문 확보 전까지 정의가 부정확할 수 있음
