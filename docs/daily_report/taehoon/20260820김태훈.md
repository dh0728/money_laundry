## 실적

- 모델 구성 방향
- 이진분류(라벨 식별) + 다중클래스 분류(패턴 분류) 2단계 구성 확인
- Transformer 계열 GNN 모델 검토 제안받음

- 라벨 단위 전환
- 데이터셋은 거래내역 단위로 라벨링되어 있으나, 실제로는 계좌 단위로 의심계좌 여부를 판정해야 함
- IBM 데이터셋으로 구성 가능한 노드·엣지 종류를 먼저 정리할 것

- 성능 개선 방법
- SMOTE로 의심거래 표본 증폭
- 하이퍼파라미터 튜닝과 threshold 조정 병행 — precision과 recall은 반비례 관계이므로 confusion matrix를 보며 조금씩 맞춰가되, recall을 올리는 방향으로
- 모델에서 feature importance를 뽑아 의심거래로 판정한 근거를 제시할 것. GNN도 중요도 산출이 가능함 (예: 매일 1천만 원 규모로 거래하던 계좌에 갑자기 1억 원 거래가 발생)

- 데이터 처리
- Large 데이터 3개월치 중 첫 1개월과 마지막 1개월만 사용하고 중간 기간은 비우는 시간 분할, 100만 건 샘플링
- 통화 정규화는 반드시 수행
- 전처리 모듈 별도 개발 필요

## 문제 상황

- 허브계좌를 왜 세탁계좌로 볼 수 있는지 근거 분석이 선행되어야 하며, 그 결과에 따라 제외 여부를 판단해야 함
- 거래 단위 라벨을 계좌 단위 라벨로 변환하는 기준이 아직 없음
