# 예상질문

## 클래스 불균형을 어떻게 해소할건가?

클래스 불균형에는 데이터와 모델 두 가지 관점에서 생각을 하고 있습니다.  

먼저 데이터 관점에서는 시간순으로 학습·검증·테스트 데이터를 분리한 뒤, 학습 데이터의 자금세탁 거래는 모두 유지하고 정상거래만 언더샘플링합니다. 단순 무작위 추출을 기준선으로 사용하되, 최종적으로는 날짜, 거래금액 구간, 최근 거래 횟수, 은행 간 거래 여부, 신규 계좌·거래쌍 여부 등을 기준으로 한 `다축 비례 층화 Reservoir Sampling`을 적용할 계획입니다. 이를 통해 대용량 데이터를 모두 메모리에 올리지 않으면서도 고액·신규·은행 간 거래와 같은 희귀 정상 패턴이 지나치게 제거되는 것을 방지하겠습니다. 초기 표본 비율은 정상 대 자금세탁을 10대 1로 설정하고, 5대 1·10대 1·20대 1을 비교해 볼려고 합니다.  

모델 관점에서는 GNN으로 학습에서 분류까지 모두 하는 `End-to-End 방식`이랑 최종 분류기를 분리하는 `GNN 임베딩+LightGBM`이 두가지 방식을 고려하고 있습니다. 
`End-to-End 방식`부터 말씀을 드리면 GNN으로 거래 내역을 임베딩하고 뒤에 Sigmoid나 Softmax같은 활성화 함수로 최종 분류 결과 산출하는 방식을 말하는데요. 저희가 수업시간에 배운 것처럼 모델이 학습을 할때 validation과의 로스를 통해서 백프로파게이션을 하면서 로스를 줄이는 방식으로 보통 학습이 됩니다. 이때 GNN으로 최종분류까지 하는 방식이 이 loss가 임베딩에 까지 영향을 주기 때문에 클래스 불균형이 심함때 정상 데이터를 중심으로 임베딩이 될 수 있습니다. 그렇지만 모델이 단순하고 목적에 맞게 최적화가 할 수 있다는 장점이 있고
 `GNN 임베딩+LightGBM`방식은 GNN 임베딩으로 거래라벨 대신에 거래에서 정답을 얻을 수 있는 예를 들면 `계좌 연결 예측` 같은 정답을 얻을 수 있는 문제로 먼저 학습을 시키고 임베딩을 고정한 다음에 LightGBM으로 최종 분류하는 방식입니다. 이렇게 하면 loss가 GNN임베딩으로 전달되지 않기 때문에 임베딩은 고정된 상태로 활용할 수 있어 부족한 양성 라벨이 GNN 전체의 학습을 좌우하지 않는 다는 장점이 있지만 모델이 복잡하고 임베딩이 문제를 푸는데 최적화된 상태는 아닐 수 있다. 라는 단점이 있습니다.

일단 현재는 말씀드린 샘플링 방법이나 클래스 가중치, 임계값을 검증 데이터에서 조정하면서 성능을 비교해볼 계획입니다. 

```
방식 A: End-to-End GNN

MLP 분류 헤드
    ├─ Sigmoid → 자금세탁 위험 점수
    └─ Softmax → 10개 클래스별 확률

방식 B: GNN + LightGBM

그래프 → GNN 임베딩 추출 → LightGBM → 확률
```
SMOTE : 두 개의 소수 클래스 데이터를 숫자 공간에서 연결하고, 그 중간값을 새로운 데이터로 만드는 방식


## 이런식으로 GNN뒤에 그냥 Sigmoid나 Softmax가 아니라 LightGBM를 사용한는 이유가 뭔가요? 더 장점이 있어서 그렇게 하는건가요?

`GNN+MLP`는 AML 분류 손실이 GNN까지 전달되는 End-to-End 구조입니다. 따라서 계좌 관계를 표현하는 임베딩 자체를 자금세탁 탐지 목적에 맞게 최적화할 수 있고 구조도 단순합니다. 다만 정상 데이터가 압도적으로 많으면 학습 손실이 정상 클래스 중심으로 계산되어, GNN과 MLP가 모두 정상으로 예측하는 방향으로 치우칠 수 있습니다. 이는 클래스 가중치나 Focal Loss 등으로 완화할 수 있습니다.  

반면 `GNN 임베딩과 LightGBM`을 결합하는 방식은 GNN을 거래 연결 예측이나 거래금액 예측처럼 라벨이 풍부한 보조 과제로 먼저 학습합니다. 이후 임베딩을 고정하고, SMOTE나 클래스 가중치를 적용한 뒤 LightGBM으로 최종 분류합니다. 따라서 부족한 AML 양성 라벨이 GNN 전체의 학습을 좌우하지 않고, 분류기만 별도로 빠르게 재학습할 수 있다는 장점이 있습니다.  
하지만 LightGBM 방식이 항상 더 좋은 것은 아닙니다. 학습이 두 단계로 복잡하고, 최종 AML 분류 손실이 GNN에 전달되지 않아 임베딩이 자금세탁 탐지에 완전히 최적화되지 않을 수 있습니다. 따라서 저희는 두 방식을 동일한 조건에서 비교하여 결정할 계획입니다.

다만 여기서 강조드리고 싶은 점은 LightGBM 자체가 클래스 불균형을 자동으로 해결하는 것은 아니라는 것입니다. LightGBM을 사용하더라도 SMOTE와 같은 오버샘플링이나 언더샘플링, 클래스 가중치 적용, 임계값 조정 등의 별도 처리가 필요합니다. 즉, 하이브리드 구조의 장점은 불균형을 자동으로 해결하는 것이 아니라, 그래프 학습과 최종 분류를 분리하여 불균형 처리를 별도의 분류 단계에서 적용하고 비교하기 쉽다는 점입니다.


임베딩을 고정하면 **클래스 불균형의 영향 범위를 최종 분류기로 제한할 수 있다**는 뜻
`GNN+MLP`를 End-to-End로 학습하면 불균형한 AML 라벨의 분류 손실이 MLP뿐 아니라 GNN까지 역전파된다. 따라서 정상 클래스가 압도적으로 많으면 GNN의 임베딩도 정상 클래스 중심으로 학습될 수 있는데
반면 `GNN 임베딩+LightGBM` 구조에서는 GNN을 링크 예측이나 거래금액 예측으로 먼저 학습한 뒤 임베딩을 고정된다. 따라서 AML 분류 손실이 GNN 임베딩에는 전달되지 않고 최종 분류기에만 영향을 줌.

## 왜 이진분류 + 다중클래스 두개의 모델을 사용하나?
- 일단 두 모델은 목적이 다릅니다. 이진분류 모델은 거래가 정상인지 자금세탁 위험이 있는지 판단해 조사 대상을 놓치지 않는데 집중하고, 반면 다중 분류 모델은 정상거래, 자금세탁 패턴, 무패턴 자금세탁 중 어디에 해당하는지 분류하고 탐지 이유를 제공합니다.
- 하나의 다중 분류 모델만 사용하면 클래스 불균형 때문에 소수 패턴을 구분하는 과정에서 자금세탁 자체를 놓칠 수 있기 때문에 두 모델을 병렬적으로 사용해 위험점수와 의심 패턴을 함께 제공하고, 담당자가 조사 우선순위와 원인을 동시에 확인하도록 구송했습니다.

### 꼬리 질문으로 “왜 순차가 아니라 병렬인가?”라고 물으면:
이진분류 이후에만 다중분류를 수행하면 이진분류에서 놓친 거래는 패턴분류 기회도 사라집니다. 병렬로 수행하면 두 모델의 신호를 독립적으로 확인하고, 결과가 불일치하는 거래도 추가 검토 대상으로 활용할 수 있습니다.


## 모델을 그래디언트 부스팅(XGBoost/LightGBM)을 사용하는데 이런 결정트리 모델을 사용하는 이유가 뭔가요?
- IBM AML 거래 데이터는 금액, 시간, 통화, 결제방식 등 정형 데이터로 구성되어 있습니다. XGBoost와 LightGBM은 이러한 표 형태의 데이터에서 변수 간 비선형 관계를 효과적으로 학습하고, 대규모 데이터도 비교적 빠르게 처리할 수 있습니다. 
- 또한 특성 중요도나 SHAP 등을 통해 어떤 거래 속성이 판단에 영향을 주었는지 확인할 수 있어 기준 모델로 활용하기 적합합니다. 저희는 이를 단순히 최종 모델로 정한 것이 아니라, GNN이 거래 관계를 학습했을 때 실제로 성능이 개선되는지를 검증하기 위한 비교 기준으로 사용합니다.

## GNN모델을 사용하는 이유가 뭔지?
- 자금세탁은 거래 한 건의 금액만으로 판단하기보다 여러 계좌로 분산되거나, 다시 모이거나, 순환하는 관계에서 특징이 나타납니다. 일반적인 정형 데이터 모델은 거래 한 행을 중심으로 분석하지만, GNN은 계좌를 노드로, 거래를 방향성을 가진 엣지로 표현하여 주변 계좌와 다단계 자금 이동 관계를 함께 학습할 수 있습니다.
- 이를 통해 다수 계좌 분산, 재집중, 순환 거래처럼 연결 구조에서 나타나는 패턴을 탐지하고, 관련 거래를 Alert와 Episode로 구성하는 데 활용할 수 있습니다.

## GNN은 계좌내역을 넣어주면 알아서 그래프를 만들주는건지 아니면 그래프로 만들어 넣어줘야 하는건지?
- 모델에 입력하기 전에 저희가 계좌를 노드로, 계좌 간 거래를 방향성을 가진 엣지로 변환해서 만들어진 GNN에 입력하는 구조입니다.

## GNN으로 했을때와 GBT로 했을 때 출력형태의 차이가 있나요?
- 모델의 내부 처리 방식은 다르지만, 최종 출력 형식은 동일하게 구성할 수 있습니다. 이진분류에서는 두 모델 모두 거래별 자금세탁 위험 확률을 출력하고, 다중분류에서는 각 패턴에 해당할 확률과 최종 예측 유형을 출력합니다.
- 이후에 모델이 출력한 거래별 위험 점수와 패턴 예측을 바탕으로 알고리즘을 통해 연관거래를 Alert와 Episode로 묶어야 합니다.


## 이진분류 다중클래스 분류 모두 GNN을 사용하나요?
- 이진분류와 다중분류 모두 GNN을 적용할 수 있지만, 두 모델을 모두 GNN으로 확정한 것은 아닙니다. 우선 XGBoost와 LightGBM을 기준 모델로 구축하고, 동일한 데이터 분할 조건에서 GNN과 성능을 비교할 계획입니다

## GNN과 GBT 모델로 했을 때의 차이가 뭔지?
- 일단 본질은 동일하다. "거래 주변의 시공간 이웃 구조를 숫자로 요약 하는데" 그 요약을 사람이 하느냐(GBT) vs 모델이 하느냐(GNN)인지 라고 볼 수 있고 요약이 좋으면 그릇?은 덜중요 IBM 벤치마크에서 둘 동급
- 쉽게 말해서 GBT는 입력을 피처 벡터 즉 표로 이고 GNN은 그래프 자체를 입력한다.
- 그래서 우리는 GBT + 수동 그래프 피처로 먼저 직접 해보면서 어떤 구조 신호가 판별력이 있는지 이해하고, GNN은 GBT와 비교해보면서 성능을 개선하는 것을 목표로 하고 있다.

## 데이터가 하루씩 입력이 된다고 하면 이 데이터 입력 주기에 따라서 판정이 달라질 거 같은데 어떻게 생각하냐?
맞습니다. 자금세탁 패턴은 여러 날에 걸쳐 완성될 수 있기 때문에, 하루 단위로 데이터가 들어오면 해당 시점까지 확인된 거래만으로 판정하게 됩니다. 초기에는 일부 거래만 관측되어 위험도가 낮거나 패턴 미매칭으로 분류될 수 있지만, 이후 거래가 추가되면 위험 점수와 패턴 판정이 달라질 수 있습니다.

따라서 매일 거래 그래프를 갱신하고, 이미 존재하는 Alert라면 새로운 Alert를 중복 생성하지 않고 위험도와 패턴, 관련 거래를 갱신합니다.

모델을 매일 다시 학습하는 것은 아닙니다. 매일 들어오는 데이터로 그래프와 추론 결과를 갱신하고, 모델 재학습은 일정 기간의 데이터와 성능 저하 여부를 확인한 뒤 별도로 수행합니다

## 그래프마다 시간 순서가 얽혀있는데 어떻게 시간순서로 넣는게 가능하냐?
그래프를 계좌 기준으로 나누는 것이 아니라, 거래 엣지의 발생 시각을 기준으로 잘라서 시점별 그래프를 만드는 방식을 사용해서 미래에 거래 연결선을 보지 못하게 합니다.

## AML 분야의 DELATOR 연구에서도 목적이 다른 판단을 두 개의 보완적 분류기로 분리하고 단일 분류기와 비교한 사례가 있습니다.라고 했는데 거기선 어떻게 했는지?
다른 연구에서 사용한 방식은 우리처럼 자금세탁 이진분류 + 패턴 다중분류가 아니었습니다. AML 업무의 두 의사결정을 순차적으로 나눈 구조였습니다.
먼저 의심 고객인지 아닌지를 분류하고 거기서 예라고 분류된걸 보고할것인지 종결할 것인지 이렇게 순차적으로 보는 구조였는데 해당 논문에서 이것을 단일 분류기 구조와 비교했을 때, 두 단계로 분리하면 각 단계를 개별 평가할 수 있고 클래스 불균형을 줄일 수 있다는 장점이 있었지만, 단일 분류기로 결합해서 분류한게 가장 성능이 좋았습니다.
그래서 희도 이진분류와 패턴분류를 무조건 확정하기보다, 단일 다중분류 방식과 병렬 방식을 비교하여 타당성을 검증할 계획입니다.

```
전체 고객
   ↓
C1: 의심 고객인가?
   ├─ 아니요 → 종료
   └─ 예
       ↓
C2: 이 의심사건을 COAF에 보고할 것인가?
       ├─ 아니요 → 종결
       └─ 예 → 당국 보고 검토
```
모델 구조
DELATOR-SAGE = GraphSAGE 임베딩 + SMOTE + LightGBM
DELATOR-GCN  = GCN 임베딩 + SMOTE + LightGBM
DELATOR-GAT  = GAT 임베딩 + SMOTE + LightGBM
