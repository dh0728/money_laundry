## 1. 문서 개요

### 1.1 작성 목적

본 문서는 AML-RADAR 프로토타입의 구성, 주요 기능, 시연 흐름 및 기술 검증 결과를 기록하기 위해 작성한다.

AML-RADAR는 여러 금융기관의 거래 데이터를 통합하고 계좌 간 자금 이동 관계를 그래프로 분석하여 거래별 위험 점수와 의심 유형을 제공하는 서비스다. 위험 거래를 시작점으로 주변 거래를 조사용 Alert로 구성하고, 조사자가 Alert를 검토하여 연관된 Alert를 Episode로 연결하는 업무 흐름을 지원한다.

본 보고서는 프로젝트 기획서, 요구사항 정의서, 데이터 분석 정의서 및 화면설계서의 내용이 프로토타입에 어떻게 반영되었는지 확인한다. 이번 시연은 **사전에 전달받은 거래별 판정 결과와 Alert를 조회할 수 있도록 준비한 상태**에서 로그인 화면부터 시작한다.

## 2. 프로토타입 구성 및 시연 흐름

### 2.1 시스템 구성

**목표 시스템의 전체 처리 흐름**은 다음과 같다.

> 금융기관별 거래 파일 업로드 → S3에 원본 저장 및 파일 도착 확인 → 데이터 검증·식별자 가명화·거래 통합 → 통합 산출물과 모델 입력 파일을 S3에 저장 → 데이터베이스의 Job 준비 상태 갱신 → GPU 서버에 입력 파일 다운로드용 Presigned URL과 결과 저장용 Presigned URL 전달 → 거래 단위 이진·유형 모델 추론 → 결과 파일 검증 및 거래별 점수 저장 → 위험 거래를 시작점으로 주변 거래 탐색 → 서브그래프·Alert 생성 → 조사자의 Alert 판정 및 Episode 연결·생성

**이번 시연의 흐름**은 다음과 같다.

> 로그인 → 대시보드 → 사전에 전달받은 판정 결과와 Alert 조회 → 거래 관계 확인 → Alert 판정 → Episode 연결·조회

GPU 서버 접근을 위한 IP 허용이 완료되지 않아 시연 중에는 실시간 추론 요청을 보내지 않는다. 시연 화면에 표시되는 거래별 판정 결과는 사전에 전달받아 준비한 결과다.

**[그림 삽입]** 시스템 구성도에는 목표 시스템의 전체 흐름과 이번 시연 구간을 서로 다른 색으로 표시한다.

### 2.2 시연 시나리오

| 순서 | 사용자·시스템 동작 | 확인할 결과 | 증빙 번호 |
|---|---|---|---|
| 1 | 조사자 계정으로 로그인한다. | 로그인 성공 및 대시보드 이동 | E-01 |
| 2 | 대시보드에서 우선 검토 대상과 업무 현황을 확인한다. | 담당 Alert·Episode 현황과 상세 화면 이동 | E-02 |
| 3 | Alert 목록에서 한 건을 선택해 거래별 위험 점수·유형과 거래 관계 그래프를 확인한다. | 위험 거래와 주변 거래, Alert 구성 근거 확인 | E-03 |
| 4 | Alert 전체의 거래 관계와 맥락을 검토한 뒤 판정 결과와 의견을 입력한다. | 정상 / Alert 단독 / 기존 Episode 연결 / 새 Episode 생성 중 선택한 결과 확인 | E-04 |
| 5 | Episode에 연결된 Alert와 자금 흐름을 확인한다. | Episode 상세, 관계 그래프 및 조사 이력 확인 | E-05 |

**시연 전제:** 팀이 사전에 전달받은 거래별 판정 결과를 조회할 수 있는 상태로 준비하고 로그인 화면부터 시연한다. 화면 일부가 모의 데이터로 동작한다면 해당 화면의 캡션에 적용 범위를 표시한다.

## 4. 핵심 기술 검증(PoC)

이 절의 모델 성능 수치는 **기존 실험 결과**다. 이번 화면 시연 중 GPU 서버에서 새로 생성한 결과로 표시하지 않는다. 검증 구간과 시험 구간, 피처 버전이 다른 수치는 각각 구분한다.

### 4.1 실험 개요

| 항목 | 작성 내용 |
|---|---|
| 예측 단위 | 거래 한 건을 예측 단위로 사용한다. 계좌 간 거래 관계는 모델 입력 그래프로 구성한다. |
| 데이터 분할 | 학습 2022.08.08~09.27, 검증 09.28~10.14, 시험 10.15~10.31로 시간순 분할한다. |
| 입력 정보 관리 | `Is Laundering`과 패턴명은 정답 생성 및 평가에만 사용하며 모델 입력 피처에는 포함하지 않는다. |
| 이진분류 실험 | 거래별 자금세탁 위험 여부를 예측한다. GNN 실험과 표형 기준 모델을 비교한다. |
| 유형분류 실험 | 정상 거래와 자금세탁 유형을 구분한다. 기존 실험에서는 9개 클래스를 대상으로 LightGBM과 TGNN을 비교했다. |
| Alert 구성 | 모델의 추론 결과에서 위험 거래를 선정한 **후**, 그래프 탐색 정책으로 주변 거래를 수집한다. Alert 구성은 거래별 모델 추론과 별도 단계다. |
| 재현 정보 | 전처리·피처·학습 코드 커밋, 시드, 모델 파일, 임계값 및 실험 ID를 기록한다. 실제 사용 버전은 [확인 후 입력]. |

### 4.2 모델·샘플링 평가 결과

| 실험 / 방법 | 주요 설정 | 평가 결과 | 해석 및 확인 사항 |
|---|---|---|---|
| 이진분류: TGNN + 군집 표본 | 거래별 분류, 시간순 분할, 시드 3개 비교 | **검증** AP 0.621124 ± 0.005864, Precision 0.807146, Recall 0.542733, F1 0.648871 | 검증 구간의 후보 결과다. 시험 구간 결과로 표기하지 않는다. 시험 성능은 [추가 입력]. |
| 9개 클래스 유형분류: LightGBM + CSSMC | 정상 거래 군집 층화 추출, 표본 비율 `r=300`, 자금세탁 클래스 가중치 `w=300` | **시험** macro-AP 0.2812, Macro-F1 0.3154 | 이전 피처 구성의 결과다. 최신 피처 구성으로 재학습한 결과와 구분한다. |
| 클래스 불균형 처리 비교 | CSSMC 적용 결과와 정상 거래 전체 사용·가중치 적용 결과 비교 | 학습 행 1,680만 대 9,138만 건, 학습 시간 4,358초 대 15,620초, 메모리 9.6GiB 대 21.1GiB, 시험 macro-AP 0.2812 대 0.2748 | 샘플링으로 학습 자원 사용을 줄인 사례다. 반복 시드 검증 전에는 성능 우위를 확정하지 않는다. |
| 유형분류 GNN 비교 | 이전 피처 구성의 TGNN 실험 | **시험** macro-AP 0.1684, Macro-F1 0.1457 | LightGBM과 피처·학습 조건이 같지 않으므로 이 수치만으로 모델 구조의 우열을 결론 내리지 않는다. |

피처는 계좌의 거래 활동을 나타내는 **노드 피처**와 개별 거래의 금액·시각·통화·반복 관계를 나타내는 **엣지 피처**로 구성한다. 실험 보고서마다 피처 수와 구성이 달라질 수 있으므로, 최종 제출본에는 위 성능 수치에 대응하는 피처 버전을 각각 기입한다.

### 4.3 추론 후 Alert 구성 검증

| 항목 | 설정·측정 결과 |
|---|---|
| 시작 거래 선정 | 거래별 이진 위험 점수가 설정한 임계값 이상인 거래를 Alert 탐색의 시작점으로 사용한다. 유형분류의 패턴명은 Alert 생성·병합의 직접 조건으로 사용하지 않는다. |
| 주변 거래 탐색 | 시작 거래에서 시간·거래 방향·계좌 연결 관계를 고려해 주변 거래를 탐색한다. 현재 정책의 탐색 범위는 과거 2일, 깊이 2단계, 최대 거래 100건·계좌 활동 100건이다. 이후 연결 거래를 반영하는 갱신 정책과 최대 범위는 최종 정책을 확인해 기입한다. |
| Alert 구성 | 탐색한 거래를 조사용 서브그래프로 묶고, 시작 거래와 추가된 거래의 역할 및 포함 근거를 함께 제공한다. |
| 품질 평가 | 시작 거래 보존 여부, 연관 거래 포함률, 비관련 거래 혼입률, 하나의 시나리오가 여러 Alert로 분리되는 정도, Alert별 거래 수를 확인한다. 최종 모델 결과를 적용한 수치는 [측정 후 입력]. |
| 사례 검증 | 데이터 분석 정의서의 사례 검증에서는 후보 병합·연쇄 병합 및 거래가 많은 계좌에 대한 탐색 제한을 확인했다. 이는 정책 동작 확인 사례이며 최종 Alert 품질 지표로 사용하지 않는다. |
| 남은 검증 | 실제 모델 점수를 동일 데이터 범위와 고정된 Alert 정책 버전에 적용해 연관 거래 회수, 혼입, 처리 시간 및 메모리를 다시 측정한다. |
