# 중간 발표 구상(우수프로젝트 발표)

# 1. 표지(기획발표 그대로)
- 안녕하세요. 그래프 신경망 기반 AML 의심거래 탐지 서비스를 기획한 기업 17조, 팀 자금세탁소의 발표를 맡은 송동현입니다.

# 2. 자금세탁이란? (기획발표 3페이지)
- 저희 서비스에 대해서 설명을 드리기전에 자금세탁에 대해서 부터 설명을 드리겠습니다. 자금세탁이란 범죄수익의 출처와 이동 경로를 숨겨 정상적인 자금처럼 보이게 만드는 과정입니다.

# 3. 자금세탁 흐름 (기획발표 4페이지)
- 앞에서 자금세탁이 범죄 수익의 이동경로를 숨겨 정상처럼 보이게 만든다고 말했습니다. 자금세탁은 이렇게 정상적으로 보이도록 만들기 하려다 보니 복수의 금융기관 혹은 계좌로 분산되는 흐름이 만들어집니다. 
이 과정에서 각각의 거래만 보면 일반적인 송금처럼 보일 수 있지만, 계좌와 거래를 서로 연결해서 보면 분산, 순환, 재집중과 같은 의심스러운 패턴이 나타납니다. 따라서 자금세탁을 효과적으로 탐지하려면 전체 거래 관계를 함께 분석해야 합니다.

# 4. 시장 규모 및 국내 도입 현황 (기획발표 5페이지)
- 현재 저희가 조사한 바에 따르면 전 세계 불법수익의 규모는 세계 GDP의 약 2~5%에 해당하고
국내에서도 금융정보분석원에 보고되는 의심거래보고 역시 지속적으로 증가하고 있습니다. 
상위기관이 검토하고 분석해야 하는 의심거래 정보가 계속 확대되고 있음을 보여줍니다.

국내 금융권에서도 기존 룰 중심 시스템에 AI를 결합하려는 시도가 진행되고 있습니다.

# 5. 현재 구조의 문제점 (기획발표 6페이지)
- 앞에서 살펴본 것처럼 금융기관들은 각자의 거래 데이터를 기반으로 자금세탁 모니터링 시스템을 운영하고 있습니다. 하지만 여기에는 한계점이 존재합니다.
화면에처럼 은행A, B, C로 흐르는 거래기록이 있다고 보시면 은행 A를 기준으로는 처음 거래에 대해서만 알수 있고 기 이후로는 알지 못합니다.  
그 결과 실제로는 하나로 연결된 자금 흐름이지만 시스템에서는 서로 다른 조사 대상으로 분리되거나 정상거래처럼 보일 가능성도 있습니다.  


# 6. 핵심 문제 (기획발표 7페이지)
첫째, 기관 별로 거래 정보가 분산되어 있어 흐름이 끓긴다.
둘째, 하나의 자금 흐름이 여러 개로 나뉠 수 있기 때문에 연계 분석 부담이 증가한다.  
셋째, 전체 이동 경로와 연관성을 설명하기 어렵다.

따라서 금융기관별로 분산된 거래를 통합하여 자금 흐름을 분석하는 서비스가 필요하다는 생각이 들었습니다.


# 7. 타겟층 (기획발표 8페이지)
- 그렇다면 이러한 통합 정보를 가장 필요로 하는 사용자는 누구일까요? 저희는 여러 금융기관의 거래를 종합적으로 분석하는 상위기관의 분석 담당자를 핵심 사용자로 설정했습니다.

# 8. Solution (기획 발표 9페이지에서 수정)
- 저희 서비스는 여러 금융기관의 거래를 통합하고 거래별 위험도와 유형을 분석합니다. 시스템은 위험 거래 주변의 관련 거래를 모아 Alert로 구성합니다. 담당자는 Alert의 거래 관계와 탐지 근거를 검토하고, 서로 연관된 Alert를 Episode로 묶어 전체 자금 흐름을 조사합니다.

# 9. 거래 그래프 기반 AI 분석

## 슬라이드 제목

거래 그래프 기반 AI 분석

## 슬라이드 핵심 문구

같은 거래 관계를 두 모델에 입력하여 거래별 위험도와 의심 유형을 산출합니다.

### 그래프 구성

- 노드: 계좌
- 간선: 송금 계좌에서 수취 계좌로 이동한 거래
- 간선 정보: 거래 시각·금액·통화·결제 수단

### 모델 출력

이진분류 모델

- 거래별 자금세탁 위험 점수

유형분류 모델

- 거래별 의심 유형과 유형별 점수

하단 설명:

정답 라벨과 패턴 정보는 모델 학습과 평가에만 사용하며 운영 입력에서는 제외합니다.

## 화면 구성

왼쪽에는 거래 데이터 예시, 가운데에는 계좌 노드와 거래 간선으로 구성한 그래프, 오른쪽에는 이진분류와 유형분류 결과를 배치합니다.

기존 기획발표 11페이지의 병렬 모델 그림과 13페이지의 그래프 변환 그림을 한 장으로 합치면 됩니다.

## 발표 멘트

앞에서 설명한 통합 거래 데이터는 계좌를 노드로, 거래를 방향이 있는 간선으로 변환합니다.

이렇게 구성한 거래 관계를 기반으로 두 가지 분석을 수행합니다. 이진분류 모델은 각 거래의 자금세탁 위험 점수를 계산하고, 유형분류 모델은 해당 거래가 어떤 의심 유형과 가까운지 점수를 제공합니다.

두 모델의 결과는 모두 거래 단위로 생성됩니다. 모델이 Episode를 직접 생성하는 것은 아니며, 이 결과를 바탕으로 다음 단계에서 조사용 Alert를 구성합니다.

정답으로 사용하는 자금세탁 여부와 패턴 정보는 학습과 평가에만 사용하고 실제 서비스의 분석 입력에서는 제외합니다.

# 10. Alert와 Episode

## 슬라이드 제목

Alert와 Episode

## 슬라이드 핵심 문구

모델의 거래별 분석 결과를 조사 가능한 단위로 구성합니다.

| 구분 | Alert | Episode |
|---|---|---|
| 생성 주체 | 시스템 | AML 담당자 |
| 구성 기준 | 위험 거래와 주변 관련 거래 | 서로 연관된 Alert 2건 이상 |
| 제공 정보 | 거래별 점수·유형·포함 근거·관계 그래프 | 포함 Alert·주요 계좌·전체 자금 흐름 |
| 목적 | 조사가 필요한 후보 범위 제공 | 여러 Alert를 하나의 조사 범위로 연결 |

하단 흐름:

거래별 모델 결과  
위험 거래 주변 탐색  
Alert 생성  
담당자 검토  
관련 Alert 선택  
Episode 생성

하단 주의 문구:

Alert와 Episode는 실제 자금세탁 여부를 자동 확정하는 결과가 아닙니다.

## 화면 구성

왼쪽에는 위험 거래와 관련 거래가 묶인 Alert 그래프를 배치합니다.

오른쪽에는 Alert 2건 이상이 하나의 Episode로 연결된 모습을 배치합니다.

가운데에는 `AML 담당자 검토 및 선택`을 표시해 Episode가 자동 생성되는 것처럼 보이지 않도록 합니다.

## 발표 멘트

여기서 Alert와 Episode의 차이를 구분할 필요가 있습니다.

Alert는 모델이 탐지한 위험 거래를 시작점으로 계좌 연결 관계와 거래 시각을 확인하여 주변 거래를 함께 묶은 조사 후보입니다. Alert에는 위험 거래뿐 아니라 자금 흐름을 설명하기 위한 연결 거래와 참고 거래도 포함될 수 있습니다.

담당자는 Alert의 거래 관계와 탐지 근거를 검토합니다. 서로 연관된 Alert가 확인되면 관련 Alert를 2건 이상 선택하여 하나의 Episode를 생성합니다.

즉, Alert는 시스템이 생성하는 조사 후보이고 Episode는 담당자가 여러 Alert의 연관성을 판단하여 구성하는 상위 조사 단위입니다.

예상 시간: 55초

# 12. 초기 모델 PoC 결과

## 슬라이드 제목

초기 모델 PoC 결과

## 슬라이드 부제

최종 모델 선정 전 기본 학습과 평가 과정의 동작을 확인했습니다.

## 슬라이드 핵심 내용

### 이진분류 초기 결과

TGNN 모델·검증 구간

- 평균정밀도 AP: 0.621 ± 0.006
- Precision: 0.807
- Recall: 0.543
- F1-score: 0.649

해석:

위험 거래를 구분할 가능성을 확인했으나, 재현율 개선이 필요합니다.

### 9개 클래스 유형분류 초기 결과

LightGBM 기준 모델·시험 구간

- Macro-AP: 0.281
- Macro-F1: 0.315

해석:

유형별 데이터 불균형과 유사한 거래 특성으로 인해 이진분류보다 난도가 높았습니다.

### 하단 주의 문구

현재 결과는 최종 성능이 아니라 초기 기준 결과입니다. 모델별 피처와 학습 조건이 다르므로 모델 구조의 우열을 직접 비교하지 않습니다.

## 화면 구성

왼쪽에는 이진분류 결과, 오른쪽에는 유형분류 결과를 배치합니다.

숫자를 큰 글자로 표시하되 상승 화살표나 우수 성능을 암시하는 표현은 사용하지 않습니다. 하단에는 `초기 기준 결과`라는 표시를 눈에 띄게 넣습니다.

## 발표 멘트

현재 모델 실험은 최종 모델 성능을 확정하는 단계가 아니라 데이터 전처리와 학습·평가 과정이 정상적으로 동작하는지를 확인하는 초기 PoC 단계입니다.

이진분류 실험에서는 검증 구간 기준 평균정밀도 0.621, F1-score 0.649를 확인했습니다. 정밀도는 0.807이었지만 재현율은 0.543으로, 더 많은 위험 거래를 탐지하기 위한 개선이 필요합니다.

9개 클래스를 구분하는 유형분류 기준 모델에서는 시험 구간 기준 Macro-AP 0.281, Macro-F1 0.315가 나왔습니다. 유형분류는 클래스 불균형이 크고 유형 간 특성이 유사하여 이진분류보다 어려운 문제라는 점을 확인했습니다.

현재 결과는 최종 성능이나 모델 간 우열을 의미하지 않습니다. 이후 동일한 데이터와 피처 조건에서 모델을 다시 비교할 계획입니다.

예상 시간: 1분

## 화면 구성

왼쪽부터 `시연 가능`, `부분 구현·검증 중`, `이번 시연 제외` 순서로 배치합니다.

완료율이나 전체 진행률은 근거가 없으면 표시하지 않습니다.

## 발표 멘트

현재 MVP에서는 조사자 로그인부터 기관 전체 현황과 개인 담당 업무 확인, 거래내역 조회, Alert 상세 분석, Episode 생성과 자금 흐름 조회까지의 핵심 화면 흐름을 시연할 수 있습니다.

Alert와 Episode의 조사 의견을 입력하는 화면도 구현되어 있지만, 입력한 내용의 저장과 상태 변경 및 감사 이력이 정상적으로 남는지는 추가 검증하고 있습니다.

현재는 변환기로 생성한 시연용 데이터를 사용합니다. 따라서 실제 모델 결과를 기반으로 Alert를 자동 생성하는 과정과 실시간 GPU 연동은 이번 시연에서 제외합니다.

오늘 시연에서는 모델의 최종 성능보다 조사자가 거래와 Alert를 확인하고 Episode를 구성하는 업무 흐름이 화면에서 어떻게 연결되는지를 중심으로 보여드리겠습니다.

예상 시간: 55초
