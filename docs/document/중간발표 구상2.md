


## AI 모델링에서 발생한 한계 및 해결 과정

### 이진분류

- 클래스 불균형 (양성 0.1%)
  - 다운샘플링 없이 전체 데이터로 학습, 가중 CE [1, 6.27] 트리는 scale_pos_weight 6
  - 예정: 정상 다운샘플링 조건(1:10, 1:100 …)

- 그래프 크기 (1.8억 간선, 메모리 25GB)
  - target 2048개가 서브그래프 하나를 공유하는 이웃 샘플링(2홉 타입별 [50, 50], FraudGT 방식). target 당 서브그래프를 따로 만들면 400건/초라 전체 테스트에 19시간 → 공유 방식으로 4시간
  - 에폭 = 256 배치(52만 target) 로 정의, EPOCHS 400 · 검증 4에폭마다 · patience 8 (FraudGT 의 iter_per_epoch)

- 방향 문제 - Reverse MP
  - 일반 메시지 패싱은 간선 방향대로만 흘러서(보낸 쪽 → 받은 쪽) 노드가 자기가 보낸 거래를 못 봐. FAN-OUT은 송신자 입장에서 "내가 여러 명에게 보냈다"는 구조인데 송신자 노드에는 그 정보가 안 보인다. 무방향으로 바꾸면 보이긴 하지만 들어온 돈과 나간 돈이 섞여서 GATHER-SCATTER(들어왔다 나감) 같은 방향 패턴이 사라진다. 그래서 역방향 간선을 별도 타입(rev_to)으로 추가해 양방향으로 흐르되 방향 정보는 유지하도록 한다.

- 사이클 문제 - Ego ID 
  - 서브그래프 안에서 노드는 익명이라, 2홉 돌아서 들어온 메시지가 출발점으로 되돌아온 건지 알 길이 없다. CYCLE은 정확히 "나한테서 나간 돈이 나한테 돌아옴"인데 1-WL 수준 GNN은 사이클과 긴 경로를 구분 못한다. target 간선의 두 끝 노드에 표시(ego=1) 를 붙이면 메시지에 "시작점" 정보가 실려서 되돌아옴을 셀 수 있다

- 다중 간선 문제 - Port numbering
  - 집계는 순열 불변이라 "같은 상대와 10번" 과 "다른 상대 10명과 1번씩"을 구분 못한다. FAN-IN(여러 송신자)과 STACK/반복 송금(한 송신자 반복)을 가르는 것. 노드마다 상대를 첫 거래 시각순으로 번호 매겨 간선에 붙이면(in_port/out_port), 메시지에 "몇 번째 상대"가 실려서 상대 수를 셀 수 있다.

- 이웃 집계의 표현력 — 어텐션 (FraudGT, GAT, SALT-GNN) (적용 중)
  - GINe 의 mean/sum 집계는 서브그래프의 이웃 거래를 전부 같은 비중으로 섞는다. 100개 이웃 중 세탁과 관련된 두세 개가 정상 거래에 묻히고, 간선 피처(금액·시각·방향)는 메시지에 더해질 뿐 "어느 이웃을 볼지" 를 정하는 데 쓰이지 않는다
  - FraudGT 는 간선 피처·방향·시간 차이를 어텐션 점수에 넣는 그래프 트랜스포머로 이웃마다 다른 가중치로 합산한다. GAT 는 어텐션만, SALT 는 어텐션 + 통계 채널

- 수신자 연결 정도(in-degree)가 높은 환경에서 세탁 탐지가 어려움 (적용 예정)
  - 허브 계좌로 들어가는 거래는 이웃이 수백 건이라 세탁 신호가 정상 거래에 묻힌다 (SALT-GNN 이 지적한 약점). 양성의 절반이 in-degree 100 이상 수신자에 몰려 있어 전체 성능을 좌우
  - 층마다 이웃 메시지를 두 갈래로 집계하고 다음 층 전에 합친다
    - 통계 채널: mean·std·min·max × degree 스케일러(1, log(d+1)/δ, δ/log(d+1)) → 이상치와 이웃 수를 벡터에 심음 (①②)
    - attention 채널: 이웃별 점수(Transformer 내적 또는 GAT 덧셈) → softmax 가중합 → 중요한 이웃을 고름
    - 층별 융합: [이전 벡터 ‖ 통계 ‖ attention] → MLP → 이전 벡터와 평균(residual). 다음 층 attention 이 분포 정보를 아는 상태에서 점수를 매기므로 눌린 신호가 홉을 건너 살아남음 (③). 끝에서만 합치면(late fusion) 효과 없음

### 유형분류

- train, val, test로 나누며 거래가 잘려버림
  - purged cross-validation(정화) 기법을 사용하였다. train 기간과 val 기간 동안 겹치는 데이터가 있다면, train에서는 학습을 제외하고, val에서는 채점 용으로 사용한다. val 기간과 test 기간 또한 마찬가지로 val에서는 데이터를 제외하고 test에는 사용한다.

- 유형의 정의에 부합하지 않는 노이즈 데이터 존재
  - IBM AML Kaggle 데이터의 공식 논문에서 정의하는 각 8개의 유형의 정의를 찾아보고, 그와 맞지 않는 데이터(예: stack인데 단 건 하나)들은 제외한다.

- gather scatter의 시작일이 뒤에 있음
  - gather scatter는 다른 유형들과 마찬가지로 기간의 첫날, 8월 1일부터 발생하기 시작하지만, 최대 시도 길이가 약 34일을 넘지 않는 7개의 유형에 반해, gather scatter는 55.7일로 거래 기간이 긴 편이다. 때문에 train과 val뿐만 아니라 test 까지도 걸치는 데이터가 많아 학습할 데이터 묶음이 252개로 매우 적다. 때문에 데이터 증강 기법 중 TimeGAN을 사용하여 Gather scatter 데이터만 늘리려 하였으나, 정밀도 및 재현율 그 어디에서도 개선된 점은 없었다. 때문에 Diffusion 기법 중 2026년 4월 최신 기법 EmDT(표 형식 데이터 생성용 디퓨전 트랜스포머)를 사용할 예정이다.
  (gather scatter에 가중치를 6으로 다른 유형보다 6배 더 무겁게 주었으나, 정밀도 및 재현율은 떨어졌다.)

- cycle과 random / bipartite와 stack 이 너무 비슷하게 생겨서 모델이 헷갈려 한다.
  - cycle과 random. bipartite와 stack은 서로 닮은 데이터다. random에서 한 단계 나아간 유형은 cycle. bipartite에서 한 단계 나아간 유형은 stack이다. 다만 현재 모델의 판정 방식으로는 cycle과 stack의 완전한 모습을 볼 수 없다. 완전한 거래 묶음 한 건으로 보는 것이 아니라 한 거래 묶음의 낱개 거래 하나하나씩을 전부 판별하기 때문이다.
