# 화면 구현 지침

대상: 프론트엔드·백엔드 팀원 · 언어: 한국어 · 구분: 팀 공유 구현 기준

갱신: 2026-11-16. 화면 레이아웃과 컴포넌트 사용 규칙이다. 함께 읽을 문서: [화면 목록](screens.md), [데이터 표시 규칙](data-rules.md), [API 요구사항](api.md).

[사용자 원본 Figma](https://www.figma.com/design/eHgUPAyr9bZ2UC7oTZNmwh)를 화면 구성·크기·프레임·노드 ID의 기준으로 삼는다. 이미지뿐 아니라 레이아웃 속성, 컴포넌트 인스턴스, 변수 연결, 상호작용을 확인한다. 원본과 요구사항이 충돌하거나 동작이 비어 있으면 임의로 고치지 않고 KMG에게 확인한다. 현재 다른 작업자가 Figma를 수정 중이므로 이번 문서 작업에서는 Figma에 접근하지 않는다.

<a id="current-implementation-boundary"></a>
## 현재 구현 범위

2026-11-15 확인된 기술 구성은 React + TypeScript + Vite이며, 팀의 왼쪽 사이드바와 작업 영역 구성을 유지한다. 앱은 `frontend/implementation/1.14.0/web-app`에 있다. 기존 미커밋 작업, Storybook, `src/next/styles`의 v3 토큰, `src/next/ShellChrome.stories.tsx`를 보존한다. 로컬에 있는 파일이 원격에도 올라가 있다고 단정하지 않는다.

화면 색은 v3 토큰을 사용하고 개별 색값을 넣지 않는다. Default Light, Default Dark, Solarized Light, Solarized Dark와 Sky, Violet, Pink, Lime을 조합한 16개 설정을 지원한다. 로그인은 Figma 원본이 없지만 구현 대상이다.

먼저 mock 데이터로 화면을 만들고 화면마다 필요한 데이터를 [화면 목록](screens.md)과 [API 요구사항](api.md)에 기록한다. 예전 백엔드 문서에 맞추려고 디자인을 바꾸지 않는다. 코드 구현, 테스트 통과, KMG의 디자인 승인은 각각 구분한다.

<a id="review-and-scope-update--2026-11-16"></a>
## 2026-11-16 변경 사항

- 이전 [Figma 구현 검수본](figma-review.md)은 팀 논의로 폐기됐다. 제작 이력은 보존하지만 새 작업의 디자인 기준으로 쓰지 않는다.
- 원본 초안을 기준으로 실행 가능한 코드를 준비하고, 검수하면서 다듬는다. 처음부터 디자인을 완벽히 끝내느라 구현을 미루지 않는다.
- 기존 코드 기능을 어디까지 재사용할지는 아직 확인 중이다. 검수본 폐기를 코드 전체 삭제로 해석하지 않는다.
- 모르는 기능·디자인은 추측하지 않고 KMG에게 묻는다. 이미 확인된 작업은 병행한다.
- 핵심 기능이 우선이다. 로그인 배경 장식은 기능 구현을 마치고 시간이 남을 때만 만든다.

<a id="frame"></a>
## 화면 틀

- PC 1920×1080 기준이다. 반응형 조정은 가능하지만 모바일 화면은 범위 밖이다.
- AppHeader는 두지 않는다. 각 화면은 너비 전체를 쓰는 PageHeader 하나로 시작한다.
- 페이지 푸터는 없다. 카드·패널·다이얼로그 안의 버튼 영역은 가능하다.
- 사이드바에는 전역 검색, 메뉴, 고정된 보고서 작성 탭을 둔다. AI 요약은 해당 화면의 요약 카드에 표시하며 사이드바에는 넣지 않는다.
- 사이드바는 펼친 형태만 있다. 숨기면 Sidebar 자체가 사라지고 PageHeader의 `showSidebarButtons`를 켜 `sidebar` 프레임을 보여준다. 별도의 접힌 Sidebar 변형은 만들지 않는다.
- 스크롤은 본문 `main` 하나에서 처리한다. 패널 안에 패널을 넣거나 표·카드 목록에 별도 스크롤을 만들지 않는다.
- 기존 StatusTag(상태·위험도·경과일·판정), PatternTag, ScoreTag, FilterTag를 사용한다. [StatusTag 프리셋](data-rules.md#statustag-presets)을 따른다.
- 검색·필터·정렬·기간 팝오버는 별도 컴포넌트로 유지한다. Dialog 인스턴스로 바꾸지 않되 헤더·모서리·여백·테두리·그림자·색 변수는 Dialog와 맞춘다.
- 화면 문구는 한국어로 쓴다. 고정 영문 패턴명(Fan-out, Cycle), ID, 코드는 예외다.
- 샘플 담당자·검토자 이름은 `김OO`처럼 가린다.

<a id="layout"></a>
## 레이아웃

- Alert·Episode 개요는 태그, AI 요약, KPI 순서다. 대시보드는 AI 요약과 KPI 영역으로 시작한다.
- AI 요약 카드는 너비 fill·높이 hug, KPI 카드는 너비 hug·높이 fill로 두어 행 높이를 맞춘다.
- 카드 목록은 최소 카드 너비와 fill을 함께 사용해 화면 너비에 따라 열 수가 바뀌게 한다.
- 표의 헤더와 각 행은 열 너비가 같아야 한다. fill 열을 추가하기 전에 기존 개수를 확인한다. fill 열이 늘면 각 열은 좁아진다.
- 표 전용 화면을 카드 목록 틀로 감싸거나 바깥 테두리를 두지 않는다. 제목의 개수와 표시 행 수를 맞춘다.
- 분석 화면은 고정 너비 옆 패널과 나머지를 채우는 그래프로 구성한다. 재생 막대는 하단, Zoom은 같은 줄에 둔다. 구조만으로 알 수 있는 `그래프`·`표` 제목은 넣지 않는다. 모든 표 패널에는 CSV 다운로드 버튼을 둔다.

<a id="verdict-and-lists"></a>
## 판정과 목록

- 판정 버튼은 PageHeader의 Primary 버튼 하나다. 탭 안에 별도 선택·묶기 버튼 줄을 만들지 않는다. 단건·복수 판정에 같은 다이얼로그를 사용한다.
- 조사 목록은 PageHeader의 두 탭으로 카드/표를 전환한다. 적용 필터는 FilterTag로 표시하고 두 개 이상이면 전체 해제를 제공한다.
- 관련 탭 헤더에는 개수와 필터 태그를 표시한다. 판정은 PageHeader 버튼에서 한다.
- 판정 창 하단은 취소, 판정 완료, 보고서 다운로드로 구성한다. 보고서 다운로드가 Primary이며 초기에는 비활성화한다.
- 비활성 판정 완료 버튼에는 클릭 처리나 프로토타입 연결을 넣지 않는다. 활성 조건이 충족된 후에만 동작한다.
- 보고서는 AI 작성 결과를 대상으로 한다. 보고서 작성 화면은 판정 이력을 표/카드로 보고 체크박스로 골라 PDF 하나로 내려받는 구성이다. 사람이 작성하는 입력 폼이나 초안/최종 단계는 없다. 판정 ID 형식은 `J-YYMMDD-NNNNNN`(예: `J-261111-000001`)이며 표와 판정 창 헤더에 표시할 수 있다. 모든 표 패널에 CSV 다운로드를 제공한다. 개요의 벡터 PDF는 검토 중이다. 현재 mock 보고서는 실제 AI 생성 결과가 아니다.
- 판정된 업무는 사람 판정을 먼저, 모델 점수를 그다음에 표시한다.
- 이전 구현 순서 Dashboard → Alert 목록 → Episode 목록 → Transactions → Rule engine은 11월 15일 계획으로 대체됐고, 현재 일정은 위 11월 16일 변경 사항을 따른다. 전달 자료는 화면 묶음별로 정리한다.

<a id="carried-over-ui-rules"></a>
## 이전부터 이어진 UI 규칙

아래는 과거 규칙이다. 현재 원본과 위 구현 범위에 대조해 사용한다. 충돌은 KMG에게 확인하며, 오래된 규칙이나 일관되지 않은 Figma 프레임을 승인으로 간주하지 않는다.

<a id="build"></a>
### 구현

- 검증된 기존 컴포넌트(shadcn/ui)부터 사용한다. 둘 이상의 화면에서 쓰일 때 공통 컴포넌트로 만든다.
- 색·간격·서체·크기는 토큰을 사용한다. 화면마다 임의 값을 넣지 않는다.
- 색이나 선 모양만으로 의미를 전달하지 않는다. 문구·값·방향·상태를 함께 표시한다.
- 숫자는 단위를 붙이고 비교하기 쉽게 정렬한다. `값 없음`·`오류`·`오래된 값`을 0과 구분한다.
- 실제 화면에서 사람이 검수한다. Full HD뿐 아니라 브라우저 확대 80%~150%, 분할 창도 확인한다.
- **과거 규칙의 충돌:** “사람의 Figma 스케치는 형태 참고이며 문구·수치·색·폰트를 복사하지 않는다”는 문장이 있었다. 현재는 사용자 원본 레이아웃·변수를 기준으로 구현하라는 지시가 우선이다. 표시 수치는 샘플 데이터에서 계산하며, 나머지 충돌은 임의로 판단하지 않고 확인한다.
- 요소 간 크기를 맞출 때는 실제 렌더링 크기를 측정한다. 눈대중으로 추정하지 않는다.

<a id="navigation-and-selection"></a>
### 이동과 선택

- 사이드바는 Dashboard, Transactions, Alert 목록, Episode 목록, 고정 보고서 작성 탭으로 구성한다는 이전 기록이 있다. 2026-11-11 결정에는 Dashboard·Rule engine·Investigation 다음 위치가 명시돼 있다. 메뉴 구조가 충돌하면 원본과 담당자에게 확인한다. 목록 화면에 큰 페이지 제목을 따로 넣지 않는다.
- 알림·설정은 사이드바 하단, 계정은 사용자 영역에 둔다.
- 현재 메뉴는 희미한 배경이 아니라 강한 대비로 표시한다.
- 선택한 행·카드·메뉴는 반대 테마 명도로 전환한다. 호버는 잠깐 나타나는 외곽선, 선택은 지속 상태로 구분한다. 읽기 전용 영역에는 호버 강조를 넣지 않는다. 빨강은 위험·오류에만 쓴다.
- 밑줄 탭은 내용 구조를 바꾸는 구분에 사용한다. 이전 예시는 Alert 상세의 개요·그래프·거래·검토다. 현재 탭명과 다르면 확인한다.

<a id="lists"></a>
### 목록

- `내 미처리`·`고위험`·`3일 이상` 등 같은 목록의 조건은 필터다. 별도 알약형 버튼이나 탭으로 만들지 않는다.
- 기간 선택은 팝오버 하나에 오늘·최근 3일·7일·30일·이번 달·직접 선택과 시작~종료일을 둔다. 적용을 눌렀을 때만 목록을 바꾼다.
- Alert 목록의 복수 선택은 Episode 묶기 모드에서만 제공한다. 그 외에는 행을 누르면 상세로 이동한다.

<a id="status-and-tags"></a>
### 상태와 태그

- Alert와 Episode는 같은 처리 상태 용어를 쓴다. Episode로 묶였다는 사실은 처리 단계가 아니다.
- 개수 배지와 패턴 태그는 중립색이다. 이미 글자로 구분되는 범주에 색을 추가하지 않는다. 빨강은 위험 표시용이다.
- 카드에서 경과일·위험도 색 태그와 중립 패턴 태그는 서로 다른 줄에 둔다. ID의 `A-`·`E-`로 구별되면 종류 태그를 추가하지 않는다.
- 탐지 패턴은 사실로 단정하지 않고 모델 확률과 함께 표시한다.
- 위험도 구간은 룰 엔진 설정에서 가져온다. 고정 수치로 넣지 않는다.

<a id="charts-and-graph"></a>
### 차트와 그래프

- 단위가 다른 값을 한 막대 길이로 비교하지 않는다. 행·패널마다 단위를 표시한다.
- 가로 막대는 이름, 고정 열의 숫자, 막대 순서다.
- 대시보드·요약의 패턴 차트와 유형 집계는 `NON_PATTERN`을 제외한다. 상세에서는 표시할 수 있다.
- 거래 선의 화살촉은 도착 노드 중심을 향한다. 노드·선·화살촉·레이블은 겹치지 않게 한다. 선 색은 위험도, 굵기는 금액, 건수는 `N건`으로 표시한다. 극단적으로 굵은 선은 상한을 둔다. 고/중/저 위험 체크박스로 필터링하며 기본은 모두 켬이다. 기본 계좌 노드는 테두리 없이, 선택·포커스만 테두리로 구분한다. 화면에 맞춤과 전체 화면 아이콘은 다르게 한다.
- SVG marker가 있다는 것만으로 통과 처리하지 않는다. 확대된 최종 화면에서 화살표를 확인한다.

<a id="detail-and-buttons"></a>
### 상세와 버튼

- 처리 이력은 별도 넓은 화면이 아니라 개요 아래 섹션이다. 업무명·담당자·시각·사유를 한 흐름으로 보여준다.
- 작업을 끝내는 버튼의 대비가 가장 강해야 한다. 이전 검토 화면 예시는 종결 확인 Primary, 초안 저장 Secondary, 저장 목록 텍스트 버튼이다. 현재 보고서의 초안 단계 제외 규칙과 혼동하지 않는다.
- 거래 판정을 바꿀 때는 반대 판정 버튼, 사유 필수 확인 창 순서로 진행하고 시각·처리자를 기록한다. 이상 거래 하나가 있으면 계좌를 빨강으로 표시한다는 이전 규칙을 보존한다.
- 자명한 탭·버튼·업무의 반복 설명은 줄인다. 근거·조회 범위·권한·오류·되돌릴 수 없는 행동에 필요한 안내는 남긴다.
