# AML RADAR 동일 구조 보존 묶음

정리 기준일: 2026-10-26. 팀 fe/work와 Archive 프로젝트 하위 `frontend/`에 **같은 상대 경로·같은 파일 bytes**를 보존한다. 이 묶음은 팀의 현재 확보 가능한 소스를 기준으로 하며 Mac 고유 자료 전체 수집 완료가 아니다. 현재 팀 사본 준비와 팀 원격 반영은 아래 원격 경계로 구분한다. external_brain은 이 정본 위치를 참조한다.

## 이 문서에서 확인하는 방법

0.x 원본 파일과 0.24.0 이후의 개별 문서·HTML·구현 갈래를 아래에서 바로 확인합니다. **GitHub blob의 HTML 링크는 원본 소스 보기이며 실행 미리보기가 아닙니다.** Markdown은 GitHub에서 읽을 수 있고 HTML·JS/CSS 묶음은 원본/이력·실행 제약과 직접 화면 열기를 별도 열로 표시합니다. 이번 수정은 새 사이트나 새 2.0.0을 만들지 않습니다.

현재 문서는 `main` 기준입니다. 예전 `blob/ba6119ee…/PRESERVATION.md` 주소는 고정 과거 기록이라 이후 수정을 반영하지 않습니다. [현재 main의 같은 문서](https://github.com/kmg200164/knowledge_archive/blob/main/Sources/Experience/2026%20%EC%9D%B8%EA%B3%B5%EC%A7%80%EB%8A%A5%EC%82%AC%EA%B4%80%ED%95%99%EA%B5%90%207%EA%B8%B0/%EC%9E%90%EA%B8%88%EC%84%B8%ED%83%81%EC%86%8C/frontend/PRESERVATION.md)를 사용합니다. 팀에 같은 파일을 둘 대응 경로는 `frontend/PRESERVATION.md`이며 Archive의 프로젝트 하위 `frontend/`와 동일 상대 구조를 유지합니다.

**표의 ‘화면 열기’는 기존 소유자 전용 호스팅의 해당 HTML로 바로 이동합니다. 목록을 다시 찾을 필요가 없으며 소유자 로그인이 필요합니다.** 원본·변경이력 링크는 GitHub 소스입니다. 화면 링크는 원본과 구분한 기존 파생 열람본이며, 게시 URL의 로그인 후 화면·개별 자산 인증은 이 작업에서 확인하지 못했습니다. 원본 SHA 또는 정확한 등록 경로가 대응하지 않는 행에는 화면 링크를 만들지 않았습니다.

## 0.24.0 이후 1.x 개별 개정 기록

`1.0.0`은 아래 전부를 뜻하는 정식 출시명이 아니라 현재 구현 폴더의 최초 관리 식별자입니다. 아래 `1.x-D/H/P/L`은 이 문서의 **기록 행 식별자**이며 새 SemVer를 부여한 것이 아닙니다. 정식 minor가 확인되지 않은 기록을 날짜·commit·원문 SHA로 펼쳤습니다. 문서 안의 승인/채택 표기, 부분 그래프 참조, 당시 테스트 통과를 전체 제품 승인으로 확대하지 않습니다. 같은 bytes의 복사·경로 변경·HTML/문서의 동시 변경을 여러 제품 버전으로 합산하지 않습니다.

날짜는 별도 표시가 없으면 **Git committer 시각(KST)**이며 제작·사용자 승인 시각을 뜻하지 않습니다. 원격 회수 보고서 [55a0e356](https://github.com/kmg200164/external_brain/blob/55a0e356e66357b4ecf927fbbcc8fcf4cbcc85dc/Workspace/Projects/money_laundry/Frontend/%EC%82%B0%EC%B6%9C%EB%AC%BC%20%EC%83%89%EC%9D%B8/%ED%9A%8C%EC%88%98%20%EA%B3%84%EB%B3%B4.json)와 [c8b07107 의미 대조](https://github.com/kmg200164/external_brain/blob/c8b07107a8af63807965075818a5573e41279390/Workspace/Projects/money_laundry/Frontend/%EC%82%B0%EC%B6%9C%EB%AC%BC%20%EC%83%89%EC%9D%B8/Mac%20%EC%9D%98%EB%AF%B8%20%EB%8C%80%EC%A1%B0.json)의 원문 식별값을 대조했습니다. 회의 원문·개인 조사 JSON·new/old 원문은 이 표에 복제하지 않습니다.

원본·소스·HTML·버전 기록·실행법·관련 설계·검증·출처의 기계 판독 표는 [versions.json](versions.json), 파일별 양쪽 대응과 SHA-256은 [preservation-manifest.json](preservation-manifest.json)이다. 기본 파일명 `package.json`·설정·컴포넌트는 유지한다. 이전 Archive `Prototype/`는 고유 노트와 원문을 포함하는 별도 역사 원본이며 이 공통 묶음을 만들기 위해 덮어쓰거나 팀으로 복사하지 않았다.

## 원본과 생성물

0.1.0부터 0.12.0까지은 원래 SVG이므로 당시 HTML은 없다. 오늘 만든 보존 HTML은 SVG를 그대로 불러오는 열람 문서다. 0.13.0부터 0.24.0까지의 기존 standalone HTML 13개(0.14.0 안의 0.13.0 역사 복사 포함)는 바이트를 보존한다. index.html 템플릿과 standalone HTML을 혼동하지 않는다. 구현 1.0.0의 오늘 정적 스냅샷은 현재 소스의 재현물이며 역사 원본 HTML이 아니다. 2.0.0은 시작 기록만 있고 없는 소스·HTML을 만들지 않았다.

원본 작성 당시와 현재 정규화 소스가 전부 같다는 뜻은 아니다. 앞선 정리에서 소스 import·경로·메타데이터가 정규화됐으며 그 전후는 artifact-paths.json과 Git 이력으로 추적한다. 이 보존 보완에서는 기능·디자인 코드를 수정하지 않는다. 코드의 과거 검증 기록 verification.json은 원래 팀 Git 문맥의 기록이고, 복사된 Archive에서 그 파일의 과거 팀 commit을 Archive 자체 commit으로 해석하지 않는다.

## 실행과 독립 검사

각 버전의 VERSION.md를 먼저 읽는다. React 원본은 별도 작업 복사본에서 빌드한다. 저장된 원본 HTML에 postbuild를 덮어쓰지 않는다. 구현 mock의 올바른 그래프는 `#alerts/3001` → 그래프 탭이고 fixture/live는 다른 분기다. `python tools/verify-preservation.py <팀 frontend> <Archive frontend>`로 모든 파일의 해시·매트릭스·생성 HTML의 로컬 링크를 재검증한다.

## 로컬 고유 자료의 다음 통합 규칙

검토된 Mac 고유 HTML 5개·필수 자산 4개와 독립 build 3개는 회수 영역에 보존되어 위 표에 연결했다. 그 밖의 설계 원문·QA·연구·외부 SDS 전체는 미통합이며, 이 원본 12개 확보를 전체 Mac 자료 확보로 확대하지 않는다. 0.21.0부터 0.24.0까지 원본 HTML은 팀 원격에 이미 존재하는 것으로 확인됐으므로 별도 Mac 중복 수집 대상으로 세지 않는다. 링크가 수정된 같은 와이어프레임을 해시 차이만으로 새 원본으로 복제하지 않는다.

기존 구현 계열의 고유 원본은 `implementation/1.0.0/supplements/<source-id>/` 아래에 원래 상대 경로와 의존 자산을 함께 보존한다. 새 디자인 자료는 실제 계보 확인 후 `design/2.0.0/supplements/<source-id>/`를 사용한다. 각각 원래 파일명·출처·시각·SHA-256·원본/후보/참고/미수용 상태를 manifest에 추가한다. 같은 경로에 다른 bytes가 있으면 덮어쓰지 말고 별도 source-id로 남긴다. 개인정보·회의 원문·개인 문서 전체·비밀값을 팀 묶음으로 옮기지 않는다. 사용자가 작업 중인 Figma는 전혀 건드리지 않는다. 서로 다른 writer의 통합 순서는 부모가 조율한다.
