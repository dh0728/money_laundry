## 3.x.y 리퀴드 글래스

`3.0.0`은 2.x.y React 앱을 이어 고친 버전이 아니라, 별도 웹 화면으로 처음부터 시작한 리퀴드 글래스 작업이다. 초기에 다른 화면과 Figma를 비교하거나 컴포넌트와 기능을 참고한 기록이 있다. 번호는 11월 18~20일 작업 대화와 검수 기록을 근거로 사후 부여했다. 주요 화면 계열이 바뀌면 첫 자리, 독립 화면이나 업무 흐름이 추가되면 둘째 자리, 기존 동작이나 외형을 수정하면 셋째 자리를 올린다. 상위 자리를 올리면 아래 자리는 0으로 돌아간다. 검수 요청과 문서 변경은 결과가 구현되기 전에는 번호를 올리지 않는다. 개별 실행본이나 커밋이 남아 있지 않은 구간은 작업 기록으로 표시한다.

- **작업 대상:** `frontend/implementation/1.14.0/web-app/live-layout`. `live-layout/index.html`이 `/layout.js`를 읽는다. [3.x.y 로컬 실행 안내](implementation/1.14.0/web-app/live-layout/README.md)
- **실행 확인:** 웹앱 폴더에서 `pnpm exec vite live-layout --config live-layout/vite.config.mjs`. 샘플 로그인 경로는 `/login?data=sample`이다. 개인 Mac 실행기는 원격 `frontend`에서 이 진입점을 연다.
- **번호와 경로:** `implementation/1.14.0`은 기존 구현 보존 경로다. 현재 Git에는 이 경로 아래 2.x.y React 앱과 3.x.y 팀 프리뷰가 함께 있다. 경로를 옮기지 않아 기존 커밋 링크와 빌드 경로를 그대로 사용할 수 있다.
- **확인한 원격 상태:** `frontend` [f3886b5c](https://github.com/dh0728/money_laundry/commit/f3886b5c00614bd6b8506b7387932222b023e273), `fe/work` [569f9a38](https://github.com/dh0728/money_laundry/commit/569f9a382c696b1203d941a396e1906865646207). 두 커밋의 웹앱 폴더는 동일하다. 실행기 정리와 루트 README 복원에는 새 UI 번호를 부여하지 않았다.
- **미커밋 작업:** Jecky가 두 진입점에서 시도한 로고 변경은 로컬 작업 상태다. 3.4.1은 리퀴드 글래스 로고 수정의 로컬 검수 번호다. Git에 반영될 때 같은 번호에 커밋을 연결한다.

## 원본과 검증 근거

- [기존 보존표](PRESERVATION.md)에는 0.x.y·1.x.y 총 39개 항목과 근거 153개가 있다. [버전 매트릭스](versions.json), [이전 경로와 해시](artifact-paths.json), [보존 파일 목록](preservation-manifest.json)은 당시 보존 기준으로 유지한다.
- 팀의 [2026-10-26 보존 커밋](https://github.com/dh0728/money_laundry/tree/ca4cae5b14f424c69ee2f5bf0d650b4faabe1a63/frontend)을 별도 디렉터리에 추출해 검증했다. 39개 항목, 보존 파일 2,130개와 생성 HTML의 로컬 링크 605개를 검증한 결과 오류는 0건이었다.
- 해시 검증은 해당 시점의 고정 스냅샷에 적용한다. 같은 경로에서 개발이 이어진 최신 소스의 변경 여부는 Git 커밋으로 확인한다.
- 이후 번호를 붙일 때 화면 계열, 진입점, 원본 커밋 또는 Figma 근거, 검수·배포 상태를 함께 기록한다. 문서·브랜치 동기화나 미커밋 작업에 UI 버전을 붙이지 않는다.
