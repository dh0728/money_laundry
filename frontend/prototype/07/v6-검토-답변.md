## 공통 annotation 원칙

- shadcn kit에 이미 있는 component 소개·variant·state·Autodocs를 AML 화면마다 반복하지 않는다.
- 화면·영역 단위의 AML 고유 계약만 annotation으로 남긴다: 사용자 판단, API field와 확정/후보, 상태·오류·권한, route·dialog·focus 전이, scroll·sticky·viewport, 계산 규칙, 금지할 대체 component·variant.
- React·TypeScript 구현 handoff에는 v7 SVG·annotation·이 검토 기록을 함께 제공하고, 1920×1080 기준 PNG와 실제 browser screenshot을 비교한다.
- grilling 질문은 매번 질문 제목에 `화면 번호 · 화면명 · 영역`을 명시해 사용자가 현재 검토 위치를 즉시 알 수 있게 한다.

## 01 로그인

### 합의한 수정

- 01은 일반 로그인만 담당한다. 세션 만료 안내와 이전 화면 복귀는 23에서 담당한다.
- 기존 번호를 유지하고 `01a 로그인`, `01b 최초 비밀번호 변경`, `01c 비밀번호 재발급 요청`으로 인증 흐름을 보강한다.
- 로그인 식별자는 중앙 AML 분석기관 사용자의 업무 이메일 또는 내부 사용자 ID를 모두 허용한다. 과거 은행 이메일 전제는 적용하지 않는다.
- 빈 값·형식 오류는 각 Field 아래, 인증 실패·비활성 계정과 서버·네트워크 오류는 입력 영역 위 Alert에 표시한다. 제출 중에는 로그인 Button을 비활성화하고 spinner를 표시한다.
- 384px Card 폭은 유지하고 `CardHeader → CardContent → CardFooter`로 나눈다. 순서는 제목·설명 → 조건부 오류 Alert → 식별자 → 비밀번호와 재발급 링크 → 로그인 Button이다.
- 비밀번호 표시 제어는 `Button / ghost / icon`으로 만든다.
- `Tab`, `Enter`, 비밀번호 표시 전환, 오류 초점 이동을 지원한다. 성공하면 일반 사용자는 역할별 진입 화면, 최초 로그인 사용자는 비밀번호 변경 화면, 재인증 사용자는 이전 경로로 이동한다.
- 제품 화면 아래의 회색 기술 메모는 제거하고 이 문서에서 관리한다.

### 보류

- 화면 최종 문구와 label은 사용자가 작성한다.
- 인증 API의 식별자 필드명·오류 code·session 응답 형식은 Backend contract에서 확정한다.
- 01a~01c의 최종 파일명과 Figma frame 이름은 v7 인증 묶음 생성 시 정한다.

### 미결

- 서버 session의 timeout, cookie, CSRF, 재인증, logout·폐기 정책.
- 비활성·잠금 계정의 복구 주체와 지원 경로.

### 검수 증거

- Chrome headless 1920×1080 렌더에서 겹침·넘침·잘림 없음.
- v6의 세션 만료 Alert는 23과 역할이 중복되고, 확정된 최초 비밀번호 변경·재발급 흐름은 빠져 있음.

## 02 대시보드

> 2026-09-15 사용자 완료 확인. 아래 `합의한 수정`을 v7 생성 기준으로 사용한다.

### 합의한 수정

- L1과 L2는 서로 다른 사람이 서로 다른 계정으로 사용한다. 한 계정의 역할 전환으로 구현하지 않는다.
- 실제 제품에서 다른 계정으로 바꾸려면 logout과 재인증을 거친다. 발표 prototype에서만 `오검토(L1)`와 `안분석(L2)` 사이를 즉시 전환하며, 이 동작은 데모 전용이라고 annotation한다.
- 계정 전환 뒤에는 새 계정의 Dashboard로 이동한다. 이전 계정의 현재 route와 검색 기록을 유지하지 않는다.
- 계정이 바뀌면 사용자 이름·avatar·역할·내 할 일 count를 함께 바꾼다.
- 역할 차이가 실제 콘텐츠를 바꾸는 화면만 `-L1`, `-L2` 변형을 만든다. 02는 `02-dashboard-L1_v7.svg`, `02-dashboard-L2_v7.svg` 두 장으로 만든다.
- L1 시연 이름 후보는 `오검토`, L2 시연 이름 후보는 `안분석`으로 둔다. 최종 화면 문구는 사용자가 작성하므로 현재는 후보다.
- L1 KPI는 현재 미처리 Alert, 미열람 Alert, 장기 미처리 Alert, 고위험 Alert, 선택 기간 내 처리 Alert의 5개다. L2 Episode KPI와 분모·기간이 불명확한 누적 오탐률은 L1 화면에서 제거한다.
- L2 KPI는 내 담당 조사 중 Episode, 미열람 Episode, 장기 미처리 Episode, 고위험 Episode, 선택 기간 내 종결 Episode의 5개다.
- KPI 후보 API 필드는 `count`, `comparisonCount/delta`, `asOf`, `roleScope`, `riskThreshold`, `agingThreshold`다. Backend 계약 전까지 후보로 annotation한다.
- 현재 업무량과 우선 작업은 최신 저장 결과의 snapshot으로, 추이·분포·기간 비교만 선택 기간의 영향을 받게 한다. 기간 제어는 전역 toolbar가 아니라 chart 묶음에 둔다.
- L1 우선 작업은 위험도 내림차순 → 경과일 내림차순으로 정렬하고, SLA가 도입되면 기한 초과를 최우선으로 재검토한다.
- L2 우선 작업은 위험도 내림차순 → 경과일 내림차순 → 배정 시각 오름차순으로 정렬한다. 표에는 Episode ID, 위험도, 유형 조합, 연결 Alert 수, 관련 은행 수, 금액, 경과, 상태를 둔다.
- KPI 클릭은 해당 조건의 역할별 목록, 우선 작업 행 클릭은 Alert 또는 Episode 상세로 이동한다.
- 유형 분포는 미처리 Alert 기준 상위 5개와 `기타`로 묶어 합계가 OPEN 전체와 일치하게 한다. bar 클릭은 해당 PatternType filter가 적용된 Alert 목록으로 이동한다.
- 일별 추이에는 x축 날짜, y축 건수와 tick, 생성·처분 series 구분, 날짜별 tooltip, 데이터 없는 날 표시, 마지막 갱신 시각을 제공한다.
- 일별 추이와 Alert 유형 분포는 기관 전체 현황으로 L1/L2에 공통 제공하고, KPI와 우선 작업 표만 역할별로 바꾼다.
- 위젯별 loading·empty·error·retry를 제공하고 성공한 영역은 유지한다. 오래된 데이터에는 기준 시각을 표시한다.
- Header task count, KPI, 유형 bar, 우선 작업 행을 각 목록·상세로 연결한다. 표 header 정렬, Dashboard 범위 새로고침, 집계 내보내기를 제공한다.
- 1920×1080에서 body scroll 없이 KPI → chart → 우선 작업 순서가 보이게 한다. KPI는 Card, 기간은 outline Button+Popover+Calendar, 새로고침은 outline icon Button+Tooltip, chart는 Card+Chart, 표는 Data Table을 사용한다.
- v6 하단 회색 기술 메모는 화면에서 제거하고 annotation·검토 기록으로 옮긴다.
- 모든 v6 아이콘이 같아 보이는 원인은 `kit6.py`가 지원하지 않는 이름을 동일한 generic glyph로 그리기 때문이다. v7은 각 용도에 대응하는 구별 가능한 Lucide icon을 그린다.
- Header 중앙의 실시간 시계는 제거한다. 은행 데이터는 일 1회 수신하므로 전역 실시간 시각을 표시하지 않는다.
- Header 중앙에는 항상 노출되는 전역 검색을 둔다. Windows 기준 `Ctrl+K`로 열거나 다시 focus한다.
- 전역 검색은 메뉴·설정·명령·Alert·Episode·계좌·은행 등 접근 가능한 전체 범위를 찾는 통합 `CommandDialog`다. 섹션 내부 검색은 해당 목록만 거르는 별도 filter다.
- 검색 결과는 바로가기, 조사 대상, 실행 명령, 설정 그룹으로 나누고 정확한 ID match를 우선한다. 권한 범위 밖의 결과는 존재 자체를 노출하지 않는다.
- 검색 후보 API 필드는 `query`, `type`, `id`, `title`, `summary`, `route`, `matchedField`, `permissionScope`다. API 계약 전까지 후보로 annotation한다.
- 검색은 세션 내 최근 방문·자주 쓰는 메뉴, 입력 중 Skeleton, 결과 없음, 일부 source 실패, 전체 오류, group별 retry 상태를 가진다. `↑/↓`, `Enter`, `Esc`, `Ctrl+K`를 지원한다.
- 통합 검색은 정확한 계좌번호로 match할 수 있지만 결과 목록에는 은행명과 masking된 계좌번호만 표시한다. 사용자 결과도 업무상 필요한 식별정보만 노출한다.
- SidebarTrigger는 접힌 Sidebar 영역 상단에 둔다. Header 왼쪽에는 검은 브랜드 mark와 `AML RADAR`를 하나의 브랜드 묶음으로 둔다.
- 전체화면 Button 옆에는 `Kbd F11`을 항상 노출하고 하나의 control처럼 묶는다. 진입 후 축소 icon으로 바꾸며 실제 구현은 클릭 Fullscreen API와 F11 입력을 지원한다.
- Header의 역할 Badge 앞에 `역할` label을 붙여 `내 할 일 + count`와 같은 정보 문법으로 맞춘다.
- 데이터 신선도는 전역 Header가 아니라 Dashboard 문맥 안에서 기준일과 최근 수신·batch 완료 시각으로 표시한다. 새로고침은 실시간 수집이 아니라 서버에 저장된 최신 일 배치 결과를 다시 불러온다.
- 일부 은행의 일 배치가 지연되거나 검증에 실패하면 페이지 상단의 비차단 Alert에 기준일, 대상 은행 수, 수신 완료 수, 지연 수, 검증 실패 수, 마지막 집계 시각, 마지막 성공 batch ID를 표시한다. 도착한 데이터 위젯은 `부분 집계` 상태로 유지하고 누락 은행 상세로 이동할 수 있게 한다.
- 최신 일 배치 전체가 실패하면 0이나 빈 Dashboard 대신 마지막 성공 결과를 유지하고 `stale` 상태, 기준일, 마지막 성공 시각, 실패한 최신 batch ID를 명시한다.
- 내보내기 Button은 형식 선택 Dialog를 연다. 기본값은 XLSX이고 선택지는 XLSX·CSV·PDF다.
- XLSX는 KPI·일별 추이·유형 분포·우선 작업을 sheet별로 구성하고, PDF는 현재 Dashboard 보고서 형태로 만든다. 현재 역할, 기준일, 선택 기간, 데이터 완전성, 생성 시각을 metadata로 포함한다.
- CSV를 선택하면 KPI·일별 추이·유형 분포·우선 작업 중 내보낼 단일 영역을 추가 선택한다.
- 내보내기는 중복 실행을 막는 Button loading/disabled 상태를 사용한다. 검색·내보내기 실패는 다른 Dashboard 기능과 독립 처리하고 해당 동작만 재시도한다.

### 보류

- 화면 최종 문구와 label은 사용자가 작성한다.
- Dashboard·통합 검색·내보내기 API의 field name, enum, 오류 code, pagination·permission contract는 Backend와 확정한다.
- `riskThreshold`, `agingThreshold`, SLA 기준은 확정 계약 전까지 후보로만 표시한다.

### 검수 증거

- Chrome headless 1920×1080 렌더에서 겹침·넘침·잘림 없음.
- v6 유형별 수치 합은 41로 OPEN 53과 일치하지 않아 12건이 누락되어 있다.
- v6 일별 chart에는 날짜·건수 축과 point 값이 없고, 기준일·최근 7일·누적 오탐률이 한 화면에서 서로 다른 기간 기준을 사용한다.
- v6 L1 Dashboard에 L2 Episode KPI가 섞여 있고 누적 오탐률은 분모와 기간이 정의되지 않았다.

## 03 Alert 목록 · 필터 열림

> 2026-09-15 사용자 완료 확인. 아래 `합의한 수정`을 v7 생성 기준으로 사용한다.

### 합의한 수정

- 상단에 적용된 filter를 chip/tag 형태로 나열하지 않는다. 세부 조건은 filter menu를 열었을 때만 보여준다.
- `필터` Button 귀퉁이에 적용된 filter 수를 Badge로 표시한다.
- filter menu는 표를 아래로 밀어내는 inline Collapsible가 아니라 content 위에 뜨는 overlay로 연다.
- 표는 가능한 한 항상 화면의 가용 영역을 채우고, filter를 열어도 보이는 Alert 행 수가 줄어들지 않게 한다.
- filter overlay는 `DropdownMenu`나 inline `Accordion`이 아니라 Button에 anchored된 560~640px `Popover`로 만든다. 주요 조건은 다시 접지 않고 한 번에 보여주며 viewport 높이를 넘을 때만 Popover 내부를 scroll한다.
- toolbar 바깥에는 목록 검색과 기간 선택만 유지한다. 상태·유형·위험도·은행·담당자 등 나머지 filter는 Popover 안으로 옮긴다.
- filter Badge는 선택 값이나 조건 행 수가 아니라 적용된 field 수를 센다. 바깥에 별도로 보이는 기간은 이 수에서 제외한다.
- Popover의 filter 변경은 초안이다. `적용` Button만 서버 요청과 목록 갱신을 실행하며, 바깥 클릭·`Esc`·`취소`는 마지막 적용 상태로 복원한다.
- 오른쪽 Alert preview는 table 폭을 차지하는 고정 panel이 아니라 행 클릭 시 오른쪽에서 table 위로 뜨는 `Sheet`로 바꾼다.
- checkbox는 일괄 작업 대상을 선택하고 행 클릭은 preview Sheet를 연다. 두 선택 상태를 분리한다.
- PageHeader와 toolbar 아래부터 pagination 위까지 table이 남은 높이와 전체 폭을 채운다. table header와 pagination을 고정하고 row 영역만 세로 scroll한다.
- 03은 L1의 Alert 검토·처분 queue로 한정하고 L2 변형을 만들지 않는다. L2는 Episode 문맥에서 연결 Alert 상세를 읽을 수 있지만 이 queue에는 진입하지 않는다.
- 기본 열은 선택, Alert ID, 위험도·백분위, 유형, masking된 대표 계좌, 관련 계좌 수, 관련 은행 수, 거래 수, 총액 USD, 발생 기간, 배정 후 경과, 상태·담당자, 행 menu다.
- `보기` menu로 열을 숨길 수 있지만 Alert ID·위험도·유형·상태는 숨길 수 없는 필수 열이다.
- 목록 내부 검색은 Alert ID·대표/관련 계좌·은행명/은행 code를 대상으로 한다. 담당자·유형·상태·위험도는 filter Popover에서 구조화 조건으로 선택한다.
- filter field끼리는 AND, 같은 field의 복수 값은 OR로 계산한다. 사용자가 AND/OR group을 중첩하는 query builder는 이번 범위에 포함하지 않는다.
- 저장 보기는 개인 보기만 지원한다. 검색어, 기간, filter, 정렬, 표시 열, page size를 저장한다. 기관 공용 보기는 관리자 권한·변경 이력 계약이 필요하므로 보류한다.
- checkbox 다중 선택 시 내보내기와 담당자 배정·재배정만 허용한다. 근거 확인이 필요한 정상 종결·오탐 종결은 일괄 작업으로 제공하지 않는다.
- 다중 선택 시 toolbar를 선택 건수, 배정, 내보내기, 선택 해제로 바꾼다.

- 09 Sankey를 대신해 10 관계 그래프를 Alert의 기본 자금 흐름 시각화로 사용한다.
- 조사 사용자에게 force·중력·반발력·link distance·node size 같은 물리 엔진 설정을 노출하지 않는다. 무료 graph library/component와 구현 난도가 아직 검증되지 않았으므로 사용자 자유도를 미리 약속하지 않는다.

- 집계 edge 상세는 그래프 위 오른쪽 `Sheet` overlay로 연다. 닫으면 기존 graph의 pan·zoom·선택 상태와 focus를 복원한다.

## 12 Alert 상세 · 이력 — 추천안 적용 완료

### 합의한 수정

- 생성·자동 배정·최초 열람·담당 변경·상태 변경·Episode 연결·종결·충돌 처리·계좌번호 공개 같은 audit event를 최신순 timeline으로 표시한다.
- `처분 이력 없음`이라는 대형 점선 Empty를 제거한다. event가 없으면 timeline 안의 작은 Empty를 사용하고, 사용자 의견과 시스템 event를 event type filter로 구분한다.

- 이력은 immutable이며 edit/delete action을 제공하지 않는다. loading·error·부분 event 상태는 timeline 영역 안에서 처리한다.

## 14 Alert → Episode 조사 Dialog — 추천안 적용 완료

### 합의한 수정

- L1이 `신규 Episode 생성` 또는 `기존 Episode 연결`을 Radio Group으로 선택한다. 기본값은 후보가 있으면 기존 연결, 후보가 없으면 신규 생성이다.
- 기존 후보는 Episode ID, 상태, 담당 L2, 겹치는 계좌·은행·pattern·기간과 마지막 활동을 표시하며 검색·선택은 `Command` 안의 Radio item으로 구성한다.

- 성공 결과에서 Episode ID·담당 L2를 알리고 해당 Episode로 이동하거나 Alert에 머무를 수 있게 한다.

### 검수 증거

- v6는 레이아웃 결함은 없지만 후보 근거가 공통 계좌·기간 정도로 좁고 성공·충돌·후보 0건 상태가 없다.

## v8 Episode detail · 결론 저장

### 합의한 수정

- v8에서 보장하는 초안 저장 동작은 사용자가 누르는 `임시 저장` Button으로 유지한다. (Q28 사용자 답변)

## v8 Episode detail · 관계 그래프 핵심 규칙

### 합의한 수정

- v7의 모든 관계를 비슷한 곡선으로 표현한 graph는 폐기한다. 두 계좌 사이 거래 건수에 따라 overview edge 표현을 구분한다.
- 단건은 방향을 읽을 수 있는 직선 1개로 표시한다.
- 2건은 서로 겹치지 않는 개별 곡선 2개로 표시하고 각 거래의 방향을 구분한다.
- 3건 이상은 overview에서 개별 화살표를 제거하고 두 node 사이를 잇는 굵은 직선 다리 1개로 집계한다.
- 굵은 다리를 click하면 오른쪽 거래 상세 panel을 연다.
- 상세 panel은 양쪽의 길고 굵은 세로 bar를 각각 계좌로 사용하고, 두 bar 사이에 거래별 가로 band를 날짜순으로 나열한다.
- 각 거래 band 내부에는 낮은 대비의 반투명 chevron을 반복해 송금 방향만 드러낸다. 날짜·금액은 band 위에서 읽을 수 있게 배치한다.
- 이 graph 표현은 AML RADAR의 핵심 정체성으로 취급하고 Alert/Episode의 관계 graph에 같은 의미 체계를 적용한다.

### 추가 확정

- 3건 이상 overview 집계 다리의 굵기는 `총 거래금액`을 나타낸다. 극단적인 금액 차이를 완화하는 log scale을 사용한다.
- 거래 건수는 다리 전환 조건과 label의 `건수 · 총액` 구조로 별도 표시한다. 최종 label 문구는 사용자가 작성한다.
- graph toolbar에 정보 label 표시 방식을 사용자가 바꾸는 2-state toggle을 추가한다.
- `항상 표시` 상태에서는 거래액 등 node/edge의 주요 label을 계속 노출한다.
- `필요할 때 표시` 상태에서는 기본 label을 감추고 해당 node/edge의 hover, keyboard focus 또는 선택 시에만 상세 정보를 표시한다. 마우스 hover에만 의존하지 않는다.
- 정보 label toggle의 초기 기본값은 `필요할 때 표시`로 한다. 사용자가 바꾼 값은 계정별 preference로 기억해 이후 graph에도 적용한다. (Q26 A 확정)
