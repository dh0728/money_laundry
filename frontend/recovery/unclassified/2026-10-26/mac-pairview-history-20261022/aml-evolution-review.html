1. 범위와 날짜의 신뢰도

탐색 스냅샷의 HTML/HTM 223개 경로를 바이트 해시로 묶은 83개 고유군 전체에 분류·출처·검토 깊이를 기록했다. 이전 감사의 27개 정확 SHA 근거를 재사용하고 남은 56개의 구조 경계를 추가 확인했다. 동일 해시는 묶고 유사본은 버전군·script·문서 구조를 대조했다. 모든 번들 내부 코드의 의미 정독이나 과거 런타임 전체 재현은 아니다.

파일 mtime는 제작일로 쓰지 않는다. Git 최초 유입, 내부 작성 표기, 내용 비교, 관측 경로를 구분한다. 개선 이유는 소스 변화와 당시 기록으로 확인되는 범위만 설명하며 클릭 수·효율·정확도 수치를 만들지 않는다. 다른 프로젝트 10경로·9해시는 내용 분석에서 제외했다. 접근 거부된 macOS 임시 경로는 우회하지 않았고 거대 파일의 내용 검색 한계를 내부 manifest에 기록했다. 이 보고 HTML처럼 탐색 후 생성된 산출물은 과거 223개 목록과 구분한다.

5. 현재 화면과 함께 검수

  1. 기존 PairView를 열면 같은 앱의 합성 fixture 5208에 연결된다. Alert 개요에서 기존 컴포넌트를 확인한다.
  2. 연결 목록에서 외부 유입액을 선택한다. 실제 요소와 GET money endpoint, minutes, 응답 필드를 함께 확인한다.
  3. 룰 결과·전체 관련 사건·모델 버전의 계약 없음/미연결 이유를 확인한다. 51개 매핑 중 현재 28행만 기존 요소에 대응하고 23행은 미연결로 남겼다. 이 수는 기능 완료율이 아니다.
  4. 원장의 소유주·계좌·거래 선택을 검수한다. fixture는 실제 인증·저장·모델 호출을 하지 않는다. 실제 HTTP용 로컬 5206과 혼동하지 않는다.

현재 보이는 요소 수는 viewport에 따라 다르다. 화면 밖 요소는 연결 선택 후 스크롤해 확인한다. 녹색 선은 계약 구절의 대응이며 Backend 성공 표시가 아니다.

6. 검증과 한계

실제 브라우저에서 현재 앱을 PairView에 연결하고 자금 항목 선택 시 좌표·endpoint·요청/응답 표시를 확인했다. 기존 개요 HTML 대표본은 브라우저로 확인했으며 스타일·합성 수치는 복사하지 않았다. 과거 모든 번들의 동작·원본 작성일·변경 이유를 복원한 것이 아니다. wrapper의 asset hash 차이를 동일 source 증거로 쓰지 않았고, QA DOM은 당시 화면 상태의 참고로 구분했다.

최종 소스 기준 앱 45파일 242/242 통과, TypeScript·관련 lint·live build 통과. PairView 62/62 통과이며 API snapshot 원본 Git 일치와 새 근거 패널 매핑 검사를 포함한다. 기존 대형 번들 경고는 남아 있다. 테스트 수는 UX 개선 수치나 실제 모델 검증을 대신하지 않는다.

독립 리뷰에서 대표 유형 비중의 연결이 거래별 점수 패널을 가리키는 오류를 찾았다. summary.typeShare가 실제 표시되는 기존 묶음 근거 패널로 고쳤다. 좌표를 구분하는 회귀가 수정 전 실패하고 수정 후 60/60 통과했으며 실제 브라우저에서도 해당 패널과 API 446행 연결을 확인했다. 앱 디자인·배치는 바꾸지 않았다.

공개 게시·외부 업로드·후속 commit/push는 하지 않았다. 로컬 후속 변경과 원격 fe/work를 구분한다. 실제 모델의 runId·검증 집합·평가 지표와 서비스 사건의 연결은 아직 확보되지 않았다.
