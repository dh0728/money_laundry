# 블록 재구성 층 설계 — 명세 + 정확도 실측

작성: 2026-08-30. 배경: run_114 혼동 분석 — 패턴 간 혼동 55%는 거래 단위 관측의
원리적 한계. 해법 = 블록 재구성 후 블록 단위 패턴 판정(사후, 인과 제약 없음).
아키텍처상 위치: 추론 서버 배치 잡 → DB block 테이블 (아키텍처 논의 2026-08-30).

## 1. 알고리즘 (설계)

- 입력: 의심 거래 집합 (서빙: 패턴 큐 히트 + 이웃. 설계 검증: 하위 §3 두 티어)
- 노드 = 거래, 연결 = **같은 계좌를 공유하고 시간 간격 ≤ W** 인 거래 쌍
  (계좌별 거래 타임라인에서 인접 거래를 gap ≤ W 일 때 union — union-find, O(n log n))
- 블록 = 연결요소. 꼬리(11-06~) 원장 포함(Phase 0 방침 — 걸침 블록 완결부).
- 파라미터 W(연결 시간창) 하나 — 실측으로 결정한다.

## 2. 판정 지표 (사전 등록)

정답 = Patterns.txt attempt (16,467블록, 거래 137,936).
- **1:1 복원율**: attempt 의 거래 전부가 한 블록을 이루고 그 블록에 타 attempt
  거래가 없는 비율 (주지표)
- 병합률(블록에 2개+ attempt), 분열률(attempt 가 2개+ 블록으로), pairwise F1
- W 후보: {1, 3, 7, 14, 30}일. 선정 기준: 1:1 복원율 최대, 동률이면 작은 W
  (서빙에서 W = 블록 확정 지연이므로 작을수록 좋다)

## 3. 검증 두 티어

- **티어 A (오라클 입력, 이번 실측)**: 진짜 패턴 거래 전량을 입력 — 알고리즘
  자체의 상한. 여기서 W 확정.
- **티어 B (모델 입력, 블록 분류 실험과 함께)**: Σp_패턴 임계 초과 거래를 입력 —
  누락(분열 유발)·오탐(가짜 다리) 포함 end-to-end. run_114 모델의 val 점수 덤프
  필요 → run_115 계열에서 수행.

## 4. 사전 실측 항목 (W 의 근거)

1. attempt 내부의 계좌 공유 인접 거래 gap 분포 → W 하한
2. 계좌의 attempt 간 재사용(서로 다른 attempt 가 계좌 공유 + 시간 근접) → W 상한
   (재사용이 많으면 큰 W 에서 병합 폭발)

## 5. 실측 결과 (티어 A — 2026-08-30)

### 5.1 소박한 설계(§1) 기각

- attempt 내 계좌공유 인접 gap: p50 2.9일 / p99 **28.8일** → W 하한이 크다.
- 그런데 **attempt 간 계좌공유 접점 60,285개, gap p50 1.2일** — 두 분포가 완전히
  겹쳐 시간창만으로 분리 불가. W 전 구간에서 실패(최선 pairF1 0.046, W=3d;
  W=30d 는 병합 연루 84.5%).

### 5.2 규칙 정교화(자금 흐름·금액 매칭)도 부족

| 간선 유형 (≤30d) | 간선수 | attempt 내 비율 |
|---|---|---|
| 체인(V_i=U_j) | 525k | 17.7% |
| 〃 + 금액 \|logdiff\|≤0.4 | 192k | 29.3% |
| 동일송신/동일수신 (+금액+14d) | ~107k | 36~37% |

규칙 조합 복원 최선 1:1 복원율 15%, pairF1 0.032 — 실패.

### 5.3 원인 규명 + 돌파구: 허브 계좌

- 패턴 계좌 115,129개 중 **86.3%는 단일 attempt 소속**. 오염원은 2개+ attempt 에
  재사용되는 허브 계좌 13.7%.
- **양끝이 단일-attempt 계좌인 체인 간선 = 순도 100.0%** (60,306개 전수).
  attempt-degree ≤2 완화 시 94.3%.

### 5.4 개정 설계 (v2)

1. **비허브 뼈대 CC**: 허브가 아닌 계좌 사이의 체인·형제 간선만으로 연결요소 →
   순수 블록 뼈대.
2. **허브 거래 사후 부착**: 허브를 지나는 거래는 금액 매칭·시간 인접·클래스 확률
   서명 유사도로 가장 가까운 뼈대 블록에 배정.
3. **미해결 — 관측 가능한 허브 판별**: 위 실측은 정답 라벨 기준(오라클 상한).
   서빙에서 쓸 판별 기준이 다음 과제: 후보 = 의심 거래 밀도·상대 수·활동 기간
   분산, 또는 정답 16,467블록으로 지도학습하는 **동일블록 간선 분류기**(간선
   피처: gap·금액 diff·유형·양끝 계좌 활동 프로파일·p_k 서명 유사도).
4. 다음 실측: 관측 가능 허브 프록시의 오라클 대비 일치도 → 프록시 기반 전체
   복원 지표(1:1·분열·병합) → 부족하면 간선 분류기로.

### 5.5 프록시 실측 — 임계 방식은 취약, 간선 분류기로 확정

- 프록시 판별력(허브 여부 AUC): **활동기간 0.951** · 거래수 0.908 · 상대수 0.907
  · 에피소드수 0.889 — 순위 신호는 충분.
- 그러나 **임계 + CC 는 취약**: 오라클 허브 제외(상한)가 1:1 39.6%·병합 0%·
  pairF1 0.664 인데, 최선 프록시(span>40d)는 1:1 24.3%·병합 40.6%·F1 0.398.
  허브 하나만 놓쳐도 CC 가 전이적으로 블록을 붙여버림 — 계좌 단위 하드 컷은
  구조적으로 불안정.
- 오라클 상한의 분열 60.4%는 뼈대 단계의 본질(허브 경유 거래가 뼈대에서 고아가
  됨) — **2단계 부착이 회복해야 할 몫**이며 상한 자체는 부착 포함 시 더 높다.

### 6. 확정 방향 (다음 실험 = run_115 계열)

**동일블록 간선 분류기**: 후보 간선(계좌 공유 ≤30d)에 대해 "같은 블록인가"를
지도학습 — 라벨은 정답 attempt (간선 후보 ~120만, 양성 ~40만 규모).
간선 피처: gap · 금액 logdiff · 간선 유형(체인/형제) · 양끝 계좌 활동 프로파일
(거래수·상대수·기간·에피소드 — 위 프록시들을 피처로) · p_k 서명 유사도(모델 출력).
분류기 확률로 가중 그래프를 만들고 임계 CC(또는 확률 기반 병합)로 재구성 →
동일 지표(1:1·분열·병합·pairF1)로 오라클 상한 대비 평가. 그 후 2단계 부착.
간선 단위 결정이라 계좌 하드 컷의 전이적 취약성이 없다.
