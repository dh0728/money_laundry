# HI-Large 전환 계획 — 새 세션 핸드오프

작성: 2026-08-27 (HI-Small 세션 마감 시점). 이 문서 하나로 새 세션이 시작할 수
있도록, HI-Small 에서 발견한 문제 전부를 전환 설계에 반영했다. 실행 순서는
Phase 0 → 4. 각 Phase 는 §9 규율(명세 먼저, 결과 덧붙임)을 따른다.

## 0. 전환 근거 (완료된 판단)

- 파라미터 사다리 종결(run_001~013): 기준선 run_011b (λ=100, `min_sum_hessian`
  1.0, 리프 31, 상한 1000, 세탁점수=확률합).
- 평가 방법론 완성: 층화(걸침/포함)·포함 닻·purge 진단·순위 보존 검증.
- **결정타: 클래스별 일반화 평가가 HI-Small 에서 통계적으로 불가** — 포함(신규
  수법) 표본이 클래스당 7~73건(G-SCATTER·RANDOM 7건). 다음 작업(features_v2)이
  클래스 타깃이므로 측정기(HI-Large)가 먼저다.
- HI-Large 실측: **2022-08-01 ~ 11-05 (97일), 16.3GB ≈ 1.8억 건** (HI-Small 의
  36배). HI-Medium 은 기간이 HI-Small 과 같은 16일이라 걸침 문제를 해결하지
  못함 — 파이프라인 리허설용으로만 가치.

## 1. Phase 0 — 전환 EDA (실측 없이는 아무것도 확정하지 않는다)

전부 스트리밍/청크로 (16GB 파일을 통째로 로드하지 않는다. §8: 메모리 15.6GB):

1. **꼬리 소멸 구간**: 일자별 전체/세탁 거래 수. HI-Small 은 09-11 부터 정상
   트래픽이 붕괴(일 48만→400건, 세탁 기저율 0.02%→59%)했다 — Large 의 같은
   지점을 찾아 평가 창의 끝을 정한다. 머리 쪽 warm-up 특성도 확인.
2. **블록 기간 분포**: attempt 별 span 의 max/p95. HI-Small 은 max 110h(4.6일)
   — embargo 갭 폭의 근거. 기간이 길어진 만큼 블록도 길 수 있으므로 **실측 필수**.
3. **클래스별 블록 수·거래 수**: Patterns.txt(13MB) 파싱. val/test 창 크기를
   "클래스별 포함 블록 ≥ 수십 개"가 되도록 역산.
4. **라벨 매칭 검증**: build_labels.py 의 라인 매칭 규칙(중복 라인 처리 포함)이
   Large 에서 성립하는지 표본 대조. accounts.csv 크기·계좌 수(피처 상태 딕셔너리
   메모리 상한)도 실측.
5. **정렬 확인**: Trans.csv 가 시간순인지 (단일 패스 피처 빌더의 전제).

## 2. Phase 1 — 분할 + embargo 설계 (팀 안건)

- **원칙: 경계마다 갭 ≥ 최대 블록 기간** → 걸침 블록이 구조적으로 0 —
  aggregate 지표가 그 자체로 일반화(inductive) 지표가 된다. HI-Small 에서
  못 쓴 이유(이틀 창에 5일 갭 불가)가 97일 창에서는 사라진다.
- 가안 (Phase 0 실측으로 갭 폭·꼬리 컷 확정 후 조정):
  `train 08-01~10-08 │ 갭 ~5일 │ val 10-14~10-23 │ 갭 ~5일 │ test 10-29~(꼬리 전)`
- **확정 (2026-08-27, Phase 0 실측 후 사용자 승인)**: 가안 기각(포함 블록 미달 —
  [hi_large_phase0_eda.md](hi_large_phase0_eda.md) §3).
  `train 08-01~09-23 │ val 09-24~10-14 │ test 10-15~11-05`, **무갭**(블록 span
  max 70.5d로 걸침 0 불가 — 갭 원칙 폐기, 층화+포함 닻으로 관리), 꼬리 11-06~
  원장 보존. CLAUDE.md §6 갱신은 팀 합의 후.
- **꼬리 처리**: 평가 분모에서 제외하되 **원장으로 보존** — 삭제 금지. 근거:
  HI-Small 꼬리는 기저율 59% 인공물이라 지표 분모로는 무효지만, 컷에 걸친 블록
  102개의 완결부가 담겨 있어 블록 재구성·블록 단위 패턴 판정에 필요하다.
- 검증: 분할 확정 후 걸침 블록 수 = 0 을 실측으로 확인(층화 열이 자동 검증).
- **트랙 공통 계약이므로 팀 합의 후 CLAUDE.md §6 갱신** (HI-Small 분할 규칙 대체).

## 3. Phase 2 — 파이프라인 청크화

현 스크립트는 전체 인메모리(HI-Small 피크 RSS 3.8GB). 1.8억 건은 원본 df 만
~36GB 로 **불가**. 재작성 대상:

- `build_features.py`: 시간순 단일 패스 설계는 유지한 채 **입력 청크 스트리밍 +
  출력 parquet append**. 계좌 상태 딕셔너리는 메모리 상주(계좌 수 실측으로 상한
  확인). 인과성 검증(컷 날짜 재계산 대조)도 동일하게 이식.
- `build_labels.py`: 스트리밍 매칭으로.
- 학습: **train 은 세탁 전량 + NORMAL 다운샘플**. §6 명시 근거 — 다운샘플링은
  개입이 아니라 전처리이며 train 에만 적용, val/test 는 원본 분포 유지. 비율은
  첫 기준선에서 고정하고 이후 단일 변인으로만 조정.
- 평가: 청크 단위 predict (val/test 전 행 점수는 필요).
- 자원 추정: 피처 parquet ~17GB(디스크 여유 180GB OK), 학습 run 당 수십 분
  예상. §8 수칙(무거운 작업 하나씩, 사전 메모리 확인) 그대로.
- 권장: **HI-Medium(2.9GB)으로 파이프라인 드라이런** 후 Large 실행.

## 4. Phase 3 — 평가 계약 이식 (HI-Small 에서 확정된 규칙)

1. **일반화 성능 정본 = 포함 닻 지표** (`P@포함패턴R0.9` 등). aggregate 는 모델
   선택용 상대 지표 — 단, 걸침=0 분할이 확정되면 aggregate = inductive 가 되어
   구분이 소멸한다(층화 열은 그 검증용으로 유지).
2. **패턴 큐 점수 = `Σp_패턴`** (run_014 발견: 세탁점수 대비 P@패턴R0.9
   79.7→93.1%). Large 에서는 처음부터 이 정의로 시작 — 두 큐 서빙(패턴 큐
   `Σp_패턴` / 배경 큐 `p_NONPAT`).
3. **패턴 분류(클래스 ID) 주장은 포함 기준으로만** — Large 에서 처음으로
   클래스별 일반화 평가가 유효해진다. features_v2 판정 기준을 실험 전에 사전
   등록할 것.
4. 지표·기록 인프라 재사용: `run_ladder.py`(층화·포함 닻·OVR 자동 기록),
   `summarize_runs.py`, 보드/뷰어 생성기. run 번호는 **run_101 부터**(Large
   시리즈), §9 기록 구조 동일.

## 5. Phase 4 — 첫 실험

- **run_101 = 무개입 기준선**: run_011b 설정 승계(λ=100, H≥1.0, 리프 31, 상한
  1000 + 조기종료 30, seed 42, 스레드 12) + NORMAL 다운샘플 비율 고정.
- **주의 — HI-Small 결론의 이식 한계**: λ=100 은 HI-Small 크기에서의 국소
  최적이다. 데이터 34배에서 정규화 최적점이 이동할 수 있으므로, 기준선 직후
  **미니 사다리 1회**(λ ∈ {10, 100} 정도)로 재확인하고 끝낸다 — 전체 사다리
  재실행은 불필요.
- 이후 순서: features_v2(클래스 타깃: FAN-IN·BIPARTITE·RANDOM·중계층 신호 —
  bp_stack_case_analysis.md 참고) → 개입 실험(NONPAT train 제거) → 캐스케이드
  2단 검증(run_015 상당 — HI-Small 에서 미실행으로 이월).
