# 분할 경계 걸침 편향 노트

작성: 2026-08-27. 근거 실험: run_013(purge). 상세 수치·상설 지표는
[metrics_summary.md](metrics_summary.md) B 표(탐지@R0.7걸침/포함)와
[../runs/run_013_purge.md](../runs/run_013_purge.md).

## 1. 문제 정의

시간순 분할(train 09-01~06 / val 09-07~08 / test 09-09~10)에서 세탁 패턴 블록
(attempt)은 44~110시간에 걸치므로 경계에 자주 걸린다. 걸침은 두 가지 다른 문제를
만든다:

- **절단(truncation)**: 경계 너머 거래가 잘려 블록이 부분만 보임 — 누수가 아니라
  난이도 문제. 꼬리 컷(09-11)도 같은 성질.
- **연속(continuation)**: 같은 블록의 앞부분이 train 에 라벨로 들어가고 뒷부분이
  val 에서 채점됨 — 편향 의심 지점. 이 노트의 주제.

주의: train 에 블록 조각이 있는 것 자체는 시간 규칙(§7) 위반이 아니다. 그 거래들은
실제로 train 기간에 일어났고, 운영에서도 어제까지의 라벨로 학습한다. 문제는 val
측정의 해석 — 걸친 거래는 "신규 수법 일반화"의 측정으로 무효라는 것.

## 2. 규모 (HI-Small val 실측)

- val 패턴 블록 157개 중 **93개(59%)**가 train 에서 시작한 블록. 거래로는 657건 중
  420건(64%).
- train 패턴 거래 1,312건 중 val 로 이어지는 블록 소속 **535건(41%)**.
- val 블록 중 test 로 이어지는 것 **92개** — test 개봉 시 같은 문제 재현.

## 3. 성능 격차 (run_011b, val)

| | 걸친 블록 (420건) | 완전 포함 (237건) | 격차 |
|---|---|---|---|
| 탐지율@R0.7 | 97.1% | 92.4% | +4.7%p |
| argmax 세탁 | 77.9% | 60.8% | +17.1%p |
| argmax 정답클래스 | 39.3% | 22.8% | +16.5%p |

극단 사례: FAN-IN 분류 정확도 걸침 60.5% vs 포함 5.9%, G-SCATTER 55.1% vs 0%.

## 4. 성질 분리 실험 — run_013 (purge)

val 로 이어지는 블록의 train 거래 535건을 **학습 표본에서만** 제거(피처 이력은
유지 — 거래는 실제로 일어났으므로)하고 재학습. López de Prado 의 purge 개념의 번역.

| | run_011b (전체 train) | run_013 (purge) |
|---|---|---|
| 탐지@R0.7 걸침 / 포함 | 97.1 / 92.4% | 95.2 / 89.5% |
| argmax 정답 걸침 / 포함 | 39.3 / 22.8% | **6.4 / 12.7%** |
| P@패턴R0.9 | 79.7% (755건) | 36.8% (1,815건) |

## 5. 결론 — 지표별로 성질이 다르다

- **탐지(알람)의 걸침 우위는 정당하다.** 라벨을 한 건도 안 보고 학습해도 걸침이
  포함을 5.7%p 앞선다. 우위의 원천은 계좌 이력 피처(24h/72h 버스트 등) — 진행
  중인 수법의 계좌는 이미 수상한 이력을 달고 있고, 이는 운영에서도 합법적으로
  보이는 정보다.
- **분류(패턴 ID)의 걸침 우위는 암기다.** 라벨 제거로 39.3% → 6.4% 붕괴(포함보다
  낮아짐). 메커니즘: 계좌 ID 피처는 없지만 계좌의 최근 활동 시그니처가 지문
  역할을 한다 — train 에서 "이 지문 = STACK" 을 배우고 val 에서 같은 지문을
  재인식한 것이지, 블록 구조를 보고 맞춘 게 아니다.
- **조각은 오염원이기 이전에 희소 학습 데이터다.** purge 는 포함 블록 성능까지
  깎았다(탐지 -2.9%p, P@패턴R0.9 반토막) — 제거분이 train 패턴 표본의 41%.

## 5.5 그래서 과거 판정은 오염됐는가 — 순위 보존 검증

걸침 편향이 keep/discard 를 뒤집으려면 모델마다 걸침 이득을 **다른 크기로**
누렸어야 한다. 실측: 경쟁 모델군(run_002~013) 전체의 걸침-포함 격차는
**4.7~6.6%p 의 좁은 띠** 안 — 전원이 거의 같은 보정 상수를 받았다(예외인
run_005 +7.8, run_003 +2.2 는 애초에 큰 차이로 discard). 포함 기준으로 재검하면
λ 사다리 방향 유지(002 89.5 → 007c 91.6%), **현 기준선 run_011b 가 포함 기준
1등(92.41%)**, 009·012·013 discard 도 유지 — 뒤집힌 판정 없음. 상위권 차이는
0.85%p = 포함 237건에서 거래 2건 수준의 노이즈 띠다.

정리: 편향은 절대 수치(특히 패턴 분류)를 부풀렸지만 모델 간 비교는 보존했다.
미래의 박빙 판정(주지표 1~2%p 이내)에서 탐지@R0.7포함 열을 공동 판정자로 쓰는
규칙의 명문화를 §7 안건으로 제안한다.

## 6. 문헌 근거

- **처리하는 쪽 — purged CV + embargo**: López de Prado, *Advances in Financial
  Machine Learning* (Wiley, 2018), **Ch.7 "Cross-Validation in Finance"**
  (§7.4.1 Purging, §7.4.2 Embargo). 라벨 사건이 경계에 걸치면 겹치는 train 표본
  제거 + 완충 구간. 금융 ML 의 표준 기법(독립 논문이 아니라 책 챕터가 정본). 단, 원 동기는
  "라벨이 미래 정보로 계산되는" 경우라 우리보다 강한 오염 — 우리 라벨은 거래에
  내재적이라 purge 는 필수가 아닌 진단 도구.
- **처리 안 하는 쪽 — AML 벤치마크 관행**: 이 데이터셋의 원 논문(AMLworld,
  NeurIPS 2023)은 시간순 60/20/20 분할이며 패턴 걸침을 언급·처리하지 않는다.
  근거는 동적 그래프 스냅샷 = 실제 은행 시나리오 모사(transductive 평가).
  후속 GNN 논문들도 동일.
- **그래프 학습의 언어**: transductive(본 적 있는 개체의 미래) vs inductive(신규
  개체) 구분. 걸침 = transductive, 포함 = inductive 성능.
- **실무 라벨 지연**: 실제 AML 은 SAR 확정이 수 주~수 개월 지연되므로 "어제
  라벨로 오늘 채점" 가정 자체가 낙관적 — 분류 능력 주장에 포함 기준을 쓰는 것이
  배포 현실과도 정합.

## 5.7 일반화 성능의 정직한 수치 — 닻을 포함 블록으로 다시 박으면

aggregate 지표가 답하는 질문은 "진행 중 수법 64% + 신규 36% 혼합에서, 어제 시작된
수법의 라벨을 이미 갖고 있다는 가정 하의 성능"이다. 그 가정은 실무에서 거짓
(라벨 지연)이므로, **일반화 성능의 객관적 진술로 aggregate 는 무효**다. 운영점의
닻(recall 기준)을 신규 수법(포함 블록 237건)으로 다시 박아 재계산한 run_011b:

| 운영점 (닻 = 신규 수법 recall) | 알람(2일) | precision | 신규 블록 attempt 커버 |
|---|---|---|---|
| 패턴점수 Σp, 신규패턴 90% | 765 | **81.6%** | 95.3% |
| 패턴점수 Σp, 신규패턴 70% | 552 | 96.6% | 78.1% |
| (참고) 세탁점수, 신규패턴 90% | 1,506 | 45.1% | 93.8% |

aggregate 닻의 "P@패턴R0.9 93.1%" 는 정직한 닻에서 **81.6%** — 11.5%p 부풀림.
한계: NONPAT 은 attempt 구조가 없어 층화 불가 — 계정 수준 연속성의 미측정
불확실성이 남는다.

## 7. 채택 정책

1. **학습은 전체 train 유지** — purged 학습 미채택(§5 셋째 항).
2. **일반화 성능(외부 보고·객관 평가)은 포함 닻 지표만 쓴다** — §5.7 표가 정본.
   aggregate 는 모델 선택용 상대 지표로 강등, 외부 인용 금지.
3. **패턴 분류 능력 주장은 포함 블록 기준으로만** — aggregate 는 ~1.7배 부풀림.
4. **keep/discard 판정 시 탐지@R0.7포함 열 교차 확인** — run_ladder 가 매 실험
   자동 기록. 박빙(1~2%p 이내)이면 포함 열이 공동 판정자.

미채택 대안과 이유: purged 학습(데이터 41% 손실, 전 지표 하락) / 블록 단위 분할
(블록 전체를 한쪽에 배정 — 시간 인과와 충돌) / embargo(이틀짜리 분할에선 손실
과대 — HI-Large 에서 재검토).
