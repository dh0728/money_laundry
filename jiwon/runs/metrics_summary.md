# 지표 총정리 — run_001~009b (val 재평가)

작성: 2026-08-25. 저장된 모델 전부를 val(09-07~08)에 재예측해 계산했다.
세탁점수 `1 - P(NORMAL)`, 고정점 threshold 는 전체 세탁 recall 기준.
run 판정(keep/discard)의 정본은 [README.md](README.md) 인덱스.

읽는 법:
- **B 표** `P@R{t}` = 전체 recall t 지점의 precision, `alarm@R{t}` = 그 지점 알람 건수,
  `attempt@R0.7` = recall 0.7 지점에서 1건 이상 잡힌 attempt 비율(157개 중).
- **C 표** 값 = 그 threshold 에서 클래스별 잡힌 비율. **NORMAL 열은 오경보율(FPR)** —
  낮을수록 좋다. 나머지 열은 recall — 높을수록 좋다.
- 포화 모델(001·004, 006 은 R0.9 에서)은 threshold 가 0 으로 떨어져 **전량 알람**
  상태다 — C 표의 100% 줄은 "다 잡았다"가 아니라 "전부 알람"이라는 뜻이다.
  B 표의 alarm 수(965,524 = val 전체)로 구분할 수 있다.

## 관찰 요약

- **주지표 P@R0.7 최고는 run_007c(32.96%)** = 현 기준선. λ 사다리 종결:
  1→13.6 / 10→28.1 / 50→29.5 / **100→33.0** / 200→30.1 / 500→30.3(상한 오염).
- 지표별 최적이 갈린다: PR-AUC 는 009a(0.6531), max-F1 은 002(67.06%),
  P@R0.5 는 009a(96.28%), P@R0.7 은 007c. §7 계약대로 P@R0.7 로 판정한다.
- **precision 을 가르는 건 NONPAT 추격이다.** recall 0.5 까지는 패턴 세탁만으로
  채워지고(NONPAT 0~14%) 알람 ~550건에 precision 95%+. recall 0.7 로 가려면
  NONPAT 을 26~39% 잡아야 해서 알람이 2.2천~2.6천 건으로 늘고 precision 이
  28~33% 로 떨어진다. recall 0.9 는 NONPAT 73%+ 요구 → 알람 4.6만+ 건.
- 클래스별로는 λ 값(10~500) 간 차이가 작다 — recall 0.7 지점에서 패턴 recall 은
  대부분 86~98% 구간. 007c 가 이기는 이유는 패턴을 더 잡아서가 아니라
  같은 recall 을 더 적은 알람(2,203건)으로 달성해서다.
- 최약 패턴은 BIPARTITE(R0.7 에서 85.7%), 최강은 S-GATHER·FAN-OUT(96~98%).
- attempt 단위로는 어느 정상 모델이든 94~98% — attempt 하나에 거래가 여러 건이라
  한 건만 걸려도 잡힌다.
