# 지표 총정리 — run_001~009b (val 재평가)

작성: 2026-08-25, 재평가 2026-08-26 (run_001~012b, 17개 모델). 저장된 모델 전부를 val(09-07~08)에 재예측해 계산했다.
세탁점수 `1 - P(NORMAL)`, 고정점 threshold 는 전체 세탁 recall 기준.
run 판정(keep/discard)의 정본은 [README.md](README.md) 인덱스.

읽는 법:
- **B 표** `P@R{t}` = 전체 recall t 지점의 precision, `alarm@R{t}` = 그 지점 알람 건수,
  `attempt@R0.7` = recall 0.7 지점에서 1건 이상 잡힌 attempt 비율(157개 중).
- **C 표** 값 = 그 threshold 에서 클래스별 잡힌 비율. **NORMAL 열은 오경보율(FPR)** —
  낮을수록 좋다. 나머지 열은 탐지율(그 클래스 거래 중 세탁 알람이 울린 비율) — 높을수록 좋다. C·D-1 표 끝의 **(건수)** 줄은
  val 클래스 건수 = 탐지율·recall 의 분모다. RANDOM 38건은 1건당 2.6%p 씩 움직이므로
  소수 클래스의 몇 %p 차이는 노이즈로 읽는다. 세탁 합계 1,036건(0.107%)이
  precision 의 기저율이다.
- **C 표는 세탁 탐지 채점이지 패턴 분류 채점이 아니다.** `세탁점수 ≥ threshold` 면
  잡힌 것으로 친다 — CYCLE 거래를 FAN-OUT 으로 예측했어도 세탁으로 알람만 울리면
  정답이다. "무슨 패턴인지"를 맞히는 채점은 **D 절**(argmax confusion)에 있다.
- **D 표** 는 argmax 채점 — 10개 확률 중 최댓값 클래스를 예측으로 친다. D-1 대각선
  recall 은 "패턴까지 맞힌" 비율이라 C 표보다 크게 낮은 것이 정상이다.
  이것이 정식 의미의 클래스별 recall 이다 — 외부 보고 시 "recall" 은 D-1 을,
  C 표 값은 "탐지율(알람 커버리지)" 로 부른다.
- **D-4** 는 클래스별 one-vs-rest PR-AUC — 각 클래스 자기 확률 `p_k` 를 점수로 그
  클래스만 골라내는 순위 능력. threshold 무관·클래스 간 독립이라 피처 방향 진단의
  정본이다. 판정(keep/discard)에는 쓰지 않는다. run_011 부터 기계 기록에도 남는다.
- 포화 모델(001·004, 006 은 R0.9 에서)은 threshold 가 0 으로 떨어져 **전량 알람**
  상태다 — C 표의 100% 줄은 "다 잡았다"가 아니라 "전부 알람"이라는 뜻이다.
  B 표의 alarm 수(965,524 = val 전체)로 구분할 수 있다.

### 변인 설명

리프 보정값 공식 `w = -G/(H+λ)` (G=그래디언트 합, H=헤시안 합, λ=lambda_l2) 이
사다리 전체의 배경이다. NORMAL 99.9% 불균형에서 모델이 금방 확신에 도달하면
H 가 0 으로 소멸하고, λ=0 이면 리프 값이 폭주해 점수가 0/1 로 포화된다(run_001).
run_003~005 는 이 폭주/무학습을 다른 손잡이로 막으려던 시도다.

| 변인 | 무엇인가 | 이 데이터에서의 동작 |
|---|---|---|
| `lambda_l2` | L2 정규화. 리프 값 분모에 더해지는 상수 | H 소멸에도 리프 값을 `-G/λ` 로 유계화 — 폭주를 뿌리에서 차단한 유일한 손잡이(지배적 변인). 클수록 보정이 소극적이라 수렴 라운드 증가(10→87, 100→315). 과하면 분리력 하락(200부터 주지표 꺾임) |
| `min_sum_hessian_in_leaf` | 리프의 H 합 하한 — H 소멸 리프를 아예 만들지 않는 분할 조건 | 같은 병을 다른 각도로 공격하나, 소수 세탁 샘플 영역도 H 가 작아 필요한 분할까지 금지 — λ 만 못함(run_003) |
| `min_data_in_leaf` | 리프의 최소 샘플 수. 통상적 과적합 방지 | 세탁 클래스는 건수 자체가 적어 소수 클래스 분리 분할을 봉쇄 — 사실상 무학습(run_004, PR-AUC 0.0011) |
| 클래스 가중치(역빈도) | 손실에서 소수 클래스 오차를 빈도 역수만큼 증폭 | 그래디언트·헤시안을 함께 증폭해 폭주를 자극하고, 확률 눈금 왜곡이 순위 평가에 손해(run_005) |
| 조기종료 지표 | 매 라운드 val 성능으로 정지 시점 판단 — 그 기준 지표 | PR-AUC 는 초기 라운드 분산이 커서 1라운드 오발 정지(run_006). 좋은 평가지표 ≠ 좋은 종료신호 |
| `num_boost_round` | 트리 개수 상한. 학습 내용이 아니라 조기종료가 작동할 공간 | λ 가 클수록 수렴이 밀려 상한과 λ 는 짝으로 움직임. λ=100 수렴점 315 확인(run_008) |
| `num_threads` | 계산 병렬화만 담당 | 결과 무영향 — 002b 와 이식 검증(4/8/12/14 동일 PR-AUC)으로 2회 확인 |

BASE 고정값: `learning_rate` 0.1(트리 보정 일괄 축소), `num_leaves` 31(트리 복잡도
— 다음 후보 축), `max_bin` 255(피처 이산화 해상도), `feature/bagging_fraction`
1.0(무작위화 끔).

### 지표 설명

| 지표 | 뜻 | 읽는 법 |
|---|---|---|
| PR-AUC | precision-recall 곡선 아래 면적 | threshold 전 구간을 아우르는 순위 품질 종합. 무작위 바닥 = 기저율 0.00107 |
| max-F1 | threshold 를 F1 최대가 되게 잡았을 때의 F1 | precision·recall 조화평균의 최대치. 단일 숫자 요약용 |
| F1-P / F1-R | 그 max-F1 지점의 precision / recall 분해 | 같은 F1 이라도 P 쪽 우위인지 R 쪽 우위인지 확인 |
| P@R0.5 / 0.7 / 0.9 | 전체 세탁 recall 이 50/70/90% 되는 threshold 에서의 precision | **P@R0.7 이 주지표(§7 계약)**. 0.5·0.9 는 보조 운영점 |
| alarm@R0.5 / 0.7 / 0.9 | 같은 지점에서 울리는 알람 총 건수 | 조사 업무량. 참고: val 세탁 총량 1,036건. 965,524 = 전량 알람(포화) |
| attempt@R0.7 | recall 0.7 지점에서 거래 1건 이상 걸린 세탁 블록 비율 | 분모 157개 블록. 블록엔 거래가 여러 건이라 거래 recall 보다 높게 나옴 |
| P@패턴R0.9 / alarm@패턴R0.9 | 패턴 8클래스 recall 이 90% 되는 threshold 에서의 precision / 알람 수 | NONPAT 을 닻에서 뺀 보조 운영점 — "패턴 세탁은 놓치지 않는다"의 비용. 판정은 여전히 P@R0.7 |
| iter | 조기종료가 고른 최적 부스팅 라운드 | 라운드 상한(300 또는 1000)에 닿았다면 조기종료 미작동 = 상한 오염 의심 |
| train_s | 학습 시간(초) | 환경 의존 참고값 — run_001~007c 는 옛 4코어 컨테이너, 이후는 현 12스레드 |

## 관찰 요약

- 기준선 이력: 001 → 002(λ=10) → 007c(λ=100) → **011b(λ=100 + H하한 1.0)**.
  주지표 P@R0.7 은 007c 32.96% 와 011b 32.94% 동률(알람 2,200건 중 1건 차이 =
  노이즈), 011b 가 PR-AUC(0.6652)·max-F1(68.98%)·P@R0.5(97.0%)·attempt@R0.7
  (98.1%) 전면 우위로 채택.
- 파라미터 사다리 종결(run_001~012): λ 최적 100(007~009), 라운드 상한은 병목
  아님(008), 리프 확장은 손해(012 — H≥1.0 이 분할을 먼저 막아 127↔512 동일 거동,
  리프 상한 비바인딩).
- **정규화 손잡이는 상호작용한다.** H하한 1.0 은 λ=0 단독(003)에선 참사, λ=100
  위(011b)에선 전면 개선. 단독 실험에서 discard 된 변인도 조합에서 재검 가치.
- **precision 을 가르는 건 NONPAT 추격.** recall 0.5 까지는 패턴 세탁만으로
  채워지고(NONPAT 0~14%) 알람 ~540건에 precision 94~97%. recall 0.7 은 NONPAT
  26~39% 를 요구해 알람 2.2천 건·precision 30~33%, recall 0.9 는 NONPAT 73%+ →
  알람 4.2만+ 건. 개입 실험 1호(배경 세탁 train 행 제거)의 근거.
- **보조 운영점 P@패턴R0.9** (recall 닻을 패턴 8클래스로 한정, NONPAT 제외):
  기준선 011b 는 **알람 755건에 precision 79.7%** — 패턴 세탁 90% 를 전체 닻
  (P@R0.7: 2,204건·33%)보다 훨씬 싸게 잡는다. 업계 규칙 기반 오탐률 85~99% 와
  비교하면 매우 정예한 큐. run_005 는 여기서도 완패(6,817건·11%) — 클래스
  식별력(D-4)이 순위 품질로 이어지지 않는다는 재확인. 패턴R=1.0 닻은 꼬리가
  깊어 무너진다(알람 4.8만) — 닻은 0.9~0.95 가 현실적.
- 클래스별 탐지(C)는 정상 모델 간 차이가 작다 — R0.7 에서 패턴 탐지율 대부분
  86~98%. 기준선들이 이기는 건 같은 recall 을 더 적은 알람으로 달성해서다.
  최약 패턴 BIPARTITE(85.7~87.8%), 최강 S-GATHER·FAN-OUT. attempt 단위는 어느
  정상 모델이든 94~98%.
- **D-4(OVR PR-AUC)가 피처 방향을 가리킨다.** 전 모델 공통 최약 신호 NONPAT(~3),
  RANDOM(~10), BIPARTITE(~13), FAN-OUT(~23). λ·리프 변인은 이 진단을 거의 못
  움직였고, 유일하게 움직인 파라미터는 H하한(011b: FAN-OUT +7.2, FAN-IN +7.5,
  STACK +6.0). 큰 도약은 피처(features_v2)의 몫. discard 된 run_005(가중치)가
  다수 클래스 최고(G-SCATTER 74.2)인 점도 유효 — 클래스 신호와 탐지 성능은 별개 축.
- **분할 경계에 걸친 블록이 지표를 부풀린다 — 특히 패턴 분류.** val 패턴 블록
  157개 중 93개(59%, 거래로는 64%)가 train 에서 시작해 이어진 블록이다. 걸친
  블록 소속 거래는 완전 포함 블록 대비 탐지율 +4.7%p(97.1 vs 92.4%), argmax

  원래 잡기 쉽다"(운영상 실재)와 "train 에서 본 그 수법을 이어서 채점"(일반화
  과대평가)이 섞여 있다. 같은 분할을 공유하는 run 간 비교는 유효하지만, 절대
  성능 보고 시 완전 포함 블록 지표를 병기할 것. test 로 이어지는 val 블록도
  92개 — test 개봉 때 같은 주의. 분리 검증은 purge 재학습(다음 후보 참고).
- **패턴 분류(D)는 탐지(C)와 완전히 다른 그림.** run_011b 분류 recall 0~51%
  (G-SCATTER 51, FAN-IN 45, RANDOM·NONPAT 0). 오분류 최대 목적지는 NORMAL,
  NONPAT 379건 전원 NORMAL(007c 와 동일 — 세탁점수로만 걸리는 클래스). 011b 는
  CYCLE→STACK 혼동(28.8%)이 007c(7.6%)보다 커지는 등 패턴 간 혼동이 재배치됨.
