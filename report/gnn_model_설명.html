“시간은 피처가 기억하고, 어텐션은 구조를 읽는다”

KYC-TGNN(final_pipeline.ipynb)의 정체: 인과적 시간 피처를 먹인 정적 Transformer GNN

KYCTransformerGNN · TransformerConv 2층 · 멀티헤드 어텐션(2) · 엣지 피처 어텐션 주입

01두 개의 분류 축 — “Temporal”과 “Transformer”는 다른 기준이다

Temporal GNN은 “시간에 따라 변하는 그래프를 다루는가”(문제 축)이고, Transformer GNN은 “이웃을 모을 때 어텐션을 쓰는가”(구조 축)입니다. 배타적 관계가 아니라 조합 가능한 속성입니다.

💡 TGAT(Temporal Graph Attention Network)는 이름 그대로 두 축의 교집합입니다 — 시간 인코딩으로 과거 이웃만 모으고, 그 안에서 self-attention으로 중요한 이웃을 고릅니다.

02우리 모델의 실제 구조 (코드 기준)

final_pipeline.ipynb의 KYCTransformerGNN 클래스를 그대로 도해했습니다.

# final_pipeline.ipynb §6 — 모델 정의 (실제 코드 요약)
class KYCTransformerGNN(torch.nn.Module):
    conv1 = TransformerConv(node_dim=24, hidden=128//2, heads=2, edge_dim=16)
    conv2 = TransformerConv(hidden=128, hidden=128//2, heads=2, edge_dim=16)
    head  = MLP([ h_src ‖ h_dst ‖ edge_feat ] → hidden → 1)  # 거래 단위 이진분류

    # forward: x(노드피처) → conv1 → conv2 → [송신h·수취h·엣지] → sigmoid
왜 엣지 피처를 어텐션에 넣나

어텐션의 Key를 만들 때 엣지 피처를 더하면, 모델이 “어떤 거래로 연결된 이웃인가”를 보고 이웃의 중요도를 정합니다. 세탁 신호가 노드(계좌)보다 엣지(거래 리듬·same_entity·국가 위험도)에 실려 있는 이 문제에 잘 맞는 선택입니다.

판정 헤드가 보는 것

한 거래(A→B)를 채점할 때 송신 계좌의 상태 + 수취 계좌의 상태 + 거래 자체의 16종 단서를 이어 붙여 MLP에 넣습니다. 즉 “주변 맥락이 섞인 두 계좌”와 “거래 자체”를 동시에 봅니다.

03모델 입력 피처 명세 — 엣지 16종 + 노드 24종

모델의 실제 입력은 x(노드 피처 [계좌수 × 24]), edge_index(송신·수취), edge_attr(엣지 피처 [거래수 × 16]) 세 가지입니다. 각 피처의 의미와 선택 근거는 다음과 같습니다.

📦 A. 엣지 피처 16종 = lean 11(시간·금액 이력) + KYC 5(신원)

#이름특징 · 계산 방식선택 근거
0쌍 과거 건수이 (송신→수취) 조합의 과거 거래 수, log1p“처음 보는 조합”은 세탁 사슬의 전형. 정상 거래는 반복되는 쌍이 많음
1쌍 Δt이 쌍의 마지막 거래 후 경과 시간(분), log1p(+2)오래 잠들었던 쌍의 갑작스런 재개는 의심 신호
2쌍 1시간 건수직전 1시간 이 쌍의 거래 수, log1p짧은 시간의 연쇄 송금(smurfing·릴리이) 포착
3송신 계좌 Δt송신 계좌의 마지막 송금 후 경과 시간계좌의 “송금 리듬” — 평소와 다른 급격한 송금 빈도는 layering의 신호
4송신 계좌 1시간 건수직전 1시간 송신 계좌의 송금 수
5수취 계좌 Δt수취 계좌의 마지막 수금 후 경과 시간계좌의 “수금 리듬” — fan-in(돈 모으기) 패턴 감지
6수취 계좌 1시간 건수직전 1시간 수취 계좌의 입금 수
7통화 z-scorelog 금액을 통화별 median/IQR로 정규화(8월 통계만), clip ±8원화·달러·코인은 스케일이 달라 생값 비교 불가. 통화 내 이상 금액을 공정하게 측정
8쌍 총건수쌍의 누적 거래 규모 (pairagg 캐시, 8월 z-표준화)관계의 “깊이” — 얕은 관계의 대액 이동은 의심
9쌍 역방향 건수반대 방향(B→A) 거래 수왕복 거래는 자전거래·순환(cycle)의 직접 신호
10쌍 최근성쌍 관계의 최근 활동도(recency)오래된 관계의 재가동 vs 활발한 관계를 구분
11same_entity송·수취가 같은 엔티티(주인) 소유면 1자기 계좌 간 이동 = 세탁의 전형적 첫 단계. 무패턴 검출 0.5%→50.1% 개선의 주역
12same_country같은 국가 내 거래면 1국경 간 이동은 자금 추적 회피 신호
13·14송·수취 국가 위험도국가별 세탁 비율을 8월 라벨로만 target-encoding, 스묌딩 200조세피난처 등 지리적 위험을 압축. 10월은 매핑만 → 누수 차단
15유형쌍 위험도계좌 유형 조합(개인→법인 등)의 위험도, 스묌딩 500“개인→유령법인” 같은 위험 조합을 포착. 희소 조합은 스묌딩으로 과신 방지
🧹 선정 과정 — 초기 81종에서 ablation으로 축약했습니다. 계좌 피처 제거 시 F1이 0.0398→0.0으로 붕괴해 계좌(노드) 피처는 필수로 확인됐고, 중복·무기여 열을 제거해 최종 16종으로 압축했습니다. 표준화는 8월 50만 표본의 mean/std만 사용해 10월에 그대로 적용(clip ±10)합니다.

🏦 B. 노드(계좌) 피처 24종 = 그래프 14 + KYC 10

그룹피처선택 근거
그래프 14
창(월)별 재집계, 대부분 log1p		 송/수신 건수·총액(4), 고유 송/수신 상대 수(2), 자기이체 수, 왕복 상대 수, 순유출 비율, 평균 송/수취액(2), 상호성 비율, PageRank, log 총송금액 계좌의 구조적 역할 — 허브(fan-in/out), 중계 계좌(순유출≈0), 순환 참여자(왕복·상호성)를 구분. PageRank는 자금이 모이는 중심을 포착. 8월 프로필은 8월 거래로만, 10월은 10월로만 계산해 상태 누수 차단

04어텐션은 이웃을 어떻게 고르는가 (인터랙티브)

계좌 C에 4개의 이웃이 있다고 합시다. 단순 GNN(GCN)은 이웃을 거의 균등하게 합치지만, Transformer GNN은 엣지 피처를 본 뒤 중요한 이웃에 큰 가중치를 줍니다. 버튼을 눌러 비교해 보세요.

A (평범한 이웃)
0.08
B (어제 개설 계좌)
0.19
D (3분 릴리이 송신)
0.52
E (같은 엔티티 계좌)
0.21

TransformerConv는 엣지 피처(3분 릴리이·same_entity 등)를 보고 D에 0.52의 가중치를 줍니다 — 세탁 신호가 증폭됩니다.

05시간은 어디서 처리되는가 — 모델이 아니라 피처에서

문헌의 Temporal GNN(TGAT·TGN)은 모델 안에 시간 장치가 있습니다. 우리 모델에는 없고, 대신 2단계(prep_feat_matrix_stream)가 시간을 피처로 요약해 넣습니다.

장치진짜 Temporal GNN (TGAT·TGN)우리 v2 모델
시간 인코딩 레이어있음 (Time2Vec 등)없음 — Δt·윈도우 피처로 대체
시간순 이웃 샘플링있음 (최근 이웃 k개)없음 — 배치는 무작위 60개 서로소 그래프
노드 메모리(상태 갱신)있음 (TGN의 memory module)없음
미래 누수 차단모델 구조가 강제피처 생성 단계(searchsorted)가 강제
어텐션 집계있음있음 (TransformerConv 2층, 2헤드)
엣지 피처 → 어텐션 주입모델에 따라 다름있음 (edge_dim)

06이 설계의 장단점

장점
  • 가볍다 — 시간축 샘플링·메모리 갱신이 없어 1.8억 엣지 규모에서 현실적
  • 시간 정보의 해석이 쉽다 — Δt·1h 윈도우 등 피처가 명시적이라 디버깅·검증 가능
  • 엣지 어텐션 주입 — 거래 단서 중심의 AML 문제에 구조적으로 적합
  • 누수 차단이 데이터 단계에서 검증 가능 — searchsorted 집계는 코드로 확인 가능
단점
  • 피처에 안 잡히는 시간 패턴은 놓침 — 요일 주기성, 특정 간격의 암호적 반복 등
  • 모델이 시간 순서를 구조적으로 추론 못함 — “A→B가 B→C보다 먼저”라는 인과 자체는 피처 요약에 의존
  • 2-Hop 제한 — 3단계 이상의 긴 세탁 사슬은 맥락이 옅어짐
  • 명칭 혼동 — “TGNN”이지만 문헌의 Temporal GNN이 아니라 “Temporal-featured Transformer GNN”이 정확
⚠️ 명칭 정리 — 노트북은 “TGNN = Transformer 기반 GNN”이라고 쓰지만, 문헌에서 TGNN은 보통 Temporal GNN(TGAT·TGN 계열)을 가리킵니다. 보고서·논문에 쓸 때는 혼동을 피하기 위해 “시간 인과 피처를 사용하는 정적 그래프 트랜스포머”로 명시하는 것이 안전합니다.
🎯 한 줄 요약 — 우리 모델은 어텐션(Transformer)으로 이웃을 골라 읽되, 시간은 모델이 아니라 데이터가 기억하는 실용적 하이브리드입니다. 가벼운 대신 시간 추론 깊이는 피처 설계 품질에 달려 있습니다.
