## 1. 공통 파이프라인 (모든 모델 공유)

### 1.1 전처리 방식과 이유

| 단계 | 방식 | 이유 |
|---|---|---|
| 분할 | 타임스탬프 순 60/20/20 (train/valid/test), 셔플 없음 | 미래 정보가 과거로 새는 데이터 누수를 구조적으로 차단. 금융 시계열에서 랜덤 분할은 성능을 부풀림 |
| 피처 통계 | 표준화·원핫 범주·USD 환산율 전부 **train 분할만**으로 계산 후 고정 | valid/test 분포를 미리 보는 누수 방지 |
| 롤링 피처 | 타깃 시각 **이전** 거래만 집계 (24h·1주 윈도우) | 당해 거래 이후 정보 사용 금지 |
| 쌍 집계 | train 구간 고정 집계 → valid/test에 고정 매핑 | 롤링이 아니라 시간 드리프트·누수가 없고 서빙 재현이 쉬움 |
| 임계값 | valid에서 F1 최적 교차 임계값 결정, test는 1회만 평가 | test로 운영점을 맞추는 선택 편향 방지 |
| 입력 | 엣지 81 + 노드 9×2 = 99차원 (상세: `feature_spec.md`) | 개별 거래 속성 + 관계형(사이클·자금통과·쌍집계) + 계좌 행동을 한 벡터로 |

### 1.2 학습 프레임 공통 사항

- 1단계 과업: 거래 단위 이진분류 (세탁=1, 양성 비율 0.08~0.16%의 극심한 불균형)
- 평가 지표: PR-AUC(AP) 중심 + Precision/Recall/F1 쌍 — ROC-AUC는 극심한 불균형에서 부풀려져 참고만
- 공통 하드웨어 제약: 컨테이너 cgroup 메모리 27.3GB (OOM 대응이 여러 설계를 바꿈, §6-4)

## 2. G31 — 최종 채택 모델 (HI-Small HGB)

### 전처리·피처 (방식 → 이유)

- HI-Small v2 (5,078,345거래, 2022-09-01~18), 공통 파이프라인 99차원
- 세탁 전수(2,297건) + 정상 40만 건 다운샘플로 학습셋 구성 → 전수 학습(500만) 대비 12배 빠르면서 양성 신호 보존. 다운샘플 시드 3개로 분산 흡수

### 학습 방식 (방식 → 이유)

- HistGradientBoosting (scikit-learn, CPU): LR 0.005 / 최대 8,000트리 / 63리프 / 조기종료(30)
- **3시드 앙상블 (42/1042/2042)**: 시드별 A모델(train-only→valid 교차 임계값), B모델(train+valid 재학습→test), 예측 평균 → 단일 시드 분산과 다운샘플 우연을 평균으로 상쇄
- GPU 미사용 이유: XGBoost CUDA는 SM75+ 전용, 보유 GPU는 V100(SM70). HGB CPU가 프로토콜 재현성도 확보

### TEST 데이터셋과 결과

- **HI-Small v2 test 1,015,882건 (세탁 1,798, 0.177%)** — 학습과 같은 도메인, 시간상 미래 구간

| 지표 | 값 |
|---|---|
| AP (PR-AUC) | **0.7570** |
| F1 (임계값 0.368) | **0.7471** |
| Precision / Recall | 0.907 / 0.635 |
| 시드별 F1 | 0.7372~0.7442 (분산 작음) |

### 장단점·문제·해결

- 장점: 현재 전 실험 최고 성능, CPU만으로 서빙 가능, MVP 지연 검증 완료
- 문제 ① 허브 관여 세탁 129건 전량 누락 (AP 0.0017) → 원인 진단 완료(피처 희석), 해결은 허브 전용 피처 공학 과제로 분리
- 문제 ② test를 50+ 실험에서 반복 참조한 선택 편향 → 실성능 0.70~0.75로 보수 추정, 운영 데이터 재검증 필요
- 문제 ③ 리콜 0.635 — 세탁의 36% 미탐. 패턴 외 세탁(35~81%)이 구조적 한계

## 3. G34/G35 — Medium 학습 + Small 전이 (기각)

### 방식과 이유

- 사용자 지시 "Medium으로 학습 → Small 테스트 경로 검증"에 대응. HI-Medium(3,189만 거래, small의 6.3배)으로 데이터를 늘려 일반화를 노림
- 전처리: G31과 동일 파이프라인이나 3,200만 행이라 메모리 초과 → **memmap 피처 행렬 + 청크 스트리밍**(prep_feat_matrix.py, gbt_final_gpu.py) 신규 개발. 학습은 G31 프로토콜 그대로
- G35 전이 평가: 원핫 컬럼을 medium train 기준으로 정렬해 small에 적용, 임계값 2종(순수 전이 / small valid 재조정)

### TEST와 결과

- G34 자체: HI-Medium test 12,411,112건 — AP 0.6756 / F1 0.6328 (시드 0.6115~0.6510)
- G35 전이: **HI-Small test** — AP 0.6261 / F1 0.6081 (small valid 임계값 0.672), 순수 전이 F1 0.4494

| 비교 | G31 (small 직접) | G34→small |
|---|---|---|
| small test F1 | **0.7471** | 0.6081 (-0.139) |

### 장단점·기각 사유

- 장점: 같은 도메인(HI)이라 전이가 부분 성립함을 확인, Precision 0.94의 보수적 운영점 가능
- 기각: 양성 +6배에도 스케일 시프트(계좌 분포·금액 스케일·임계값 어긋남)로 small 성능 열위. "데이터 증가 이득 > 스케일 시프트 손실" 불성립 — 이후 Large(5.7배) 검토도 같은 논리로 보류

## 4. G33 — LI-Small 전이 (기각)

- 방식: G31(HI 학습)을 LI-Small에 그대로 적용 → "HI 모델이 저은행권역(LI)에 통하는가" 검증
- TEST: LI-Small test 1,385,052건 (세탁 925, 0.067%)
- 결과: **AP 0.0599 / F1 0.1620 — 탐지 불능**
- 교훈: HI와 LI는 세탁 패턴·거래 특성이 다른 별개 과업. 이 결과가 이후 모든 작업을 HI로 집중시킨 근거. LI 지원은 LI 전용 학습이 별도 과제로 필요

## 5. G36m/G37m — GNN (PNA) Medium 학습 (기획서 검증 축, 현재 열위)

### 방식과 이유

- 기획서의 핵심 검증 질문 "GNN 관계형 탐지가 기존 거래 단위 분석을 보완하는가"에 대응
- 모델: PyG PNAConv 2층 메시지패싱 (degree-scaler 집계로 허브 차수 대응 의도), 120에포크, GPU V100
- G36m: T3 피처(시간·빈도+통화z) / G37m: 전체 81피처 — 피처 기여도 비교

### TEST와 결과 (HI-Medium test)

| 모델 | 피처 | test AP | test F1 |
|---|---|---|---|
| G37m | 전체 81 | **0.2905** | **0.3362** |
| G36m | T3 | 0.2379 | 0.2883 |
| (참고) G34 HGB | 전체 81 | 0.6756 | 0.6328 |

### 장단점·문제·해결방안

- 장점: 그래프 구조를 직접 학습, 기획서 2단계(관계 그래프)와 아키텍처 정합
- 문제: 같은 데이터의 HGB 대비 AP 절반 이하 — 현재 PNA 2층 구성으로는 관계형 이득 미확인. v1 소규모 시절 최고치(AP 0.326)와 같은 수준에서 정체
- 해결방안(후보): 레이어 확장·이웃 샘플링(NeighborLoader)·학습 스케줄러 개선 / HGB 점수를 노드 피처로 주는 하이브리드 / 2단계 패턴 분류에서 GNN 역할 재탐색
- 운영 이슈: medium 그래프 구축 시 OOM 1회 — 체인 감시 껍데기만 남는 좀비 상태를 수동 재시작으로 해결

## 6. G38/G39 — HI+LI Medium 합성 (기각) / G40 — 허브 피처 (효과 없음)

### G38/G39 합성

- 방식: 양성 +54%(17,534건)를 노려 HI+LI medium 합성. 계좌 ID 충돌(14,414개, 라벨 모순 2,521개) → **LI 노드 +오프셋 분리**, `is_li` 도메인 플래그, split 재분할 금지 (설계: `hili_combine_design.md`)
- TEST: G38 자체 = 합성 test 24.5M (AP 0.5040/F1 0.4493) → G39 = **HI-Small test** (AP 0.6010 / F1 0.5790)
- 기각 사유: 비교 기준 G35(0.6081) 대비 F1 -0.029 — 도메인 결정경계 차이를 is_li 플래그로는 상쇄 불가. G33과 일관된 결론
- 부산물: featmat 63M행 OOM 2회 → **단계별 프로세스 분리** 해결, 학습 OOM 1회 → GBT_LOW_MEM 모드 추가

### G40 허브 피처

- 방식: G31 + hub_src/hub_dst 플래그 2개(101차원) — 허브 탐지 구멍(H-2 발견) 회복 시도
- TEST: HI-Small test — **G31과 모든 지표가 소수점까지 동일** (전체 0.7570/0.7471, 허브 AP 0.0017)
- 진단: train에 허브 세탁 359건 있음에도 3시드 전부 플래그 미사용 — 피처 부재가 아니라 **허브 세탁이 모든 피처에서 허브 정상과 불구분**(17만 이웃 희석)
- 해결방안: 허브 입출금을 금액·시간으로 짝짓는 가상 경유 피처(허브 투명화) — 별도 과제(3~5시간 추정), MVP에선 "알려진 한계"로 명문화
