1. 데이터셋 — IBM AMLSim HI-Small (v2 분할)

원천: IBM AMLSim 합성 자금세탁 벤치마크, HI-Small (HI = 고은행권역/High-income bank 그룹 내 다계좌 패턴). 계좌를 노드, 거래를 엣지로 보는 directed multigraph 형태의 거래 로그.

▶ 분할은 타임스탬프 순 60/20/20, 셔플 없음. 미래 정보가 과거로 새는 데이터 누수를 구조적으로 차단하기 위함이다. 금융 시계열에서 랜덤 분할은 성능을 부풀린다. v2 = 이 원칙으로 재분할(resplit_602020)한 버전.

▶ 양성 비율 0.08~0.18%의 극심한 불균형이므로 ROC-AUC 대신 PR-AUC(AP)를 주 지표로 쓴다.

2. 전처리 파이프라인 — 5가지 누수 방지 원칙

원시 거래 로그→ 시간순 60/20/20 분할→ 피처 산출 (과거만)→ train 통계로 표준화→ 99차원 벡터 캐시
단계방식이유
① 분할타임스탬프 순 60/20/20미래→과거 누수를 구조적으로 차단
② 피처 통계표준화·원핫 범주·USD 환산율 전부 train 분할만으로 계산 후 고정valid/test 분포를 미리 보는 누수 방지
③ 롤링 피처타깃 시각 이전 거래만 집계 (1h·24h·1주 윈도우)당해 거래 이후 정보 사용 금지
④ 쌍 집계train 구간 고정 집계 → valid/test에 고정 매핑롤링이 아니므로 드리프트·누수 없고 서빙 재현이 쉬움
⑤ 임계값valid에서 F1 최적 교차 임계값 결정, test는 최종 1회만 평가test로 운영점을 맞추는 선택 편향 방지 (in-sample 임계값 적용 시 F1 0.71로 붕괴 확인)

검증: 전 구간 데이터 누수 감사(작업기록 §16)에서 누수 없음 확인. 과정에서 발견·수정된 결함 — passthru 캐시 교차 오염(18.4% 엣지 정정), pairagg#4 퇴화 컬럼, float32 표준화 오차(→ float64 스트리밍 파이프라인으로 정확화).

3. 입력 피처 99차원 — 엣지 81 + 노드 9×2

모든 표준화는 train 통계, 모든 시계열 집계는 타깃 시각 이전만 사용. 상세는 docs/feature_spec.md.

3-1. 엣지 피처 81개 (8개 블록)

블록개수내용설계 의도
A. 기본 엣지43수치 6(log금액, 환전·자기이체 여부, 시각 sin/cos, 요일) + 원핫 37(결제형식 7종, 송금·수취 통화 15종씩)개별 거래의 기본 속성. 범주는 train 기준 고정
B. 시간/빈도10동일 쌍 과거 횟수·간격·1h/24h 수, 송금자 출금 간격·빈도, 수취자 입금 간격·빈도단기 반복·급증 패턴 포착
C. 통화 robust z1통화별 중앙값/IQR 기반 robust z-score (±8 클립)통화마다 다른 금액 스케일을 이상치에 강건하게 정규화
D. USD 환산1train 환전 거래의 중앙값 비율 → BFS로 전 통화 USD 환산율, log1p(금액×환산율)통화가 달라도 금액 크기 비교 가능
E. 패턴 근사8역방향 이력(왕복), 송금자 신규 상대 수(fan-out), 수취자 신규 상대 수(fan-in), 양방향 공존(2-hop 사이클)scatter/gather/왕복 등 AMLSim 패턴 근사
F. 사이클 모티프8윈도우 2종(24h·1주) × 모티프 4종(3노드 순환, 공통 수취처/송금처/매개)순환 자금 흐름 탐지 (GPU 산출)
G. 자금통과4직전 입금과의 시간 간격, 금액/직전입금액 비율, 24h 유출/유입 비율 등레이어링 핵심 신호 — 받은 즉시 전달하는가
H. 쌍 집계6train 고정 집계: 쌍 거래 횟수·합계·최대·역방향 횟수·최종 시각·신규쌍 플래그베이스라인 최대 중요도 피처(pair_prior_count) 계열. 서빙 재현 용이

3-2. 노드 피처 9개 × 2 (송금 계좌 + 수취 계좌)

피처의미
입금/출금 차수 (log1p)계좌의 연결 규모
총 송금액 / 총 수취액 (log1p)계좌의 자금 규모
거래 수 (log1p)활동량
자기이체 수 (log1p)자금 순환 위장 신호
사용 통화 종류 수 / 결제형식 수다채널 사용 — 레이어링 계좌 특성
순자금 흐름 (부호보존 log)유입-유출 균형 — 통과 계좌는 ≈0

▶ 노드 피처는 노드×split 3행 구조 — 각 split 구간의 계좌 행동만으로 집계해 구간 간 누수를 막는다. test용 노드 피처도 train+valid 기간까지만 집계.

▶ 실험으로 확인: 전체 81개가 최적(부분집합 대비 우위, G37m vs G36m). 허브 계좌 관여 거래는 그래프 계열 피처(E·F·G)가 17만 이웃에 희석되는 한계가 있다(§6 참조).

4. 학습 모델과 학습 방식 — gbt_tov_ensemble

4-1. 모델: HistGradientBoostingClassifier (scikit-learn, CPU)

하이퍼파라미터값선정 근거
learning_rate0.005학습률 하향이 최대 레버. LR 0.05에서는 조기종료로 31~71트리에서 과소수렴했고, 0.005로 1,000개+ 확보 시 F1 +0.10 (G29 실험)
max_leaf_nodes63저LR 환경에서 31리프 대비 소폭 우위 (G30 실험). G31 = G29+G30 우승 조합
max_iter (트리 상한)8,000상한은 넉넉히 두고 조기종료에 맡김 — 실제 수렴 1,058~1,499트리
early_stoppingvalidation_fraction 0.1, n_iter_no_change 30과적합 자동 방지
GPU 미사용CPU HGBXGBoost CUDA는 SM75+ 전용인데 보유 GPU가 V100(SM70). CPU HGB가 프로토콜 재현성도 확보

4-2. 학습셋 구성: 양성 전수 + 음성 40만 다운샘플

학습셋 = 세탁 전수(train 2,297건) + 정상 40만 건 무작위 다운샘플. ▶ 전수 학습(500만 건) 대비 12배 빠르면서 양성 신호는 보존. 다운샘플 우연은 3개 시드로 분산 흡수.

4-3. 3시드 앙상블 + train+valid 재학습(TOV) + 교차 임계값

시드 42 / 1042 / 2042→ A모델: train-only 학습→ valid 예측으로 F1 최적 임계값(교차)→ B모델: train+valid 재학습→ test 확률 3개 평균
장치방식이유
시드 앙상블3개 시드의 B모델 test 확률 평균단일 시드 분산·다운샘플 우연을 평균으로 상쇄. 시드별 F1 0.737~0.744로 분산 작음. (9모델 확장 G32는 동률이라 3시드 유지)
TOV 재학습B모델은 train+valid 합쳐 재학습valid 구간(시간상 최신) 정보까지 흡수해 test(미래) 적응력 향상 — F1 +0.10 규모의 핵심 장치 (G20 0.6505 달성 요인)
교차 임계값임계값은 A모델의 valid 예측으로만 결정, B모델 test에 적용B모델은 valid를 학습에 썼으므로 valid 인샘플 임계값은 부풀려진다(적용 시 0.7111로 붕괴 확인). 교차 방식이 정직한 추정치

구현: src/gnn/gbt_final.py · 학습 시간 약 23분(CPU) · 저장: checkpoint_gbt_ens3.joblib (HGB 3개)

6. 장단점 · 알려진 한계

장점

  • 전 실험 최고 성능 (대안 전부 기각: 규모 확대·전이·합성·GNN·논문 재현)
  • CPU만으로 서빙 가능, MVP 5분 마이크로배치 지연 검증 완료(최대 배치 0.9초)
  • 시드 분산 작음(0.737~0.744), 교차 임계값으로 정직한 운영점 확보

한계

  • 허브 사각: 초대형 허브 계좌 경유 세탁 129건 전량 누락(해당 부분 AP 0.0017) — 그래프 피처가 17만 이웃에 희석. 허브 전용 가상 경유 피처 과제로 분리(hub_subgraph_spec.md)
  • 선택 편향: test를 50+ 실험에서 반복 참조 — 실성능은 F1 0.70~0.75로 보수 추정, 운영 데이터 재검증 필요
  • 리콜 0.635: 세탁의 36% 미탐. FN은 기존쌍·소액·비ACH에 집중 — 학습 데이터에 유사 신호가 희박해 현 피처셋의 구조적 한계 (oracle 상한 F1 0.7502)
  • LI 도메인 미지원: HI→LI 전이 AP 0.0599로 실패 확정. LI 대응은 LI 네이티브 학습 필요
